#### 注意：此错误代码已不再由编译器生成。

返回值的生命周期不会超过函数调用的时间。

错误的代码示例：

```compile_fail,E0700
fn prefix<'a>(
    words: impl Iterator<Item = &'a str>
) -> impl Iterator<Item = String> { // error!
    words.map(|v| format!("foo-{}", v))
}
```

要解决此错误，需明确指定返回值的生命周期：

```
fn prefix<'a>(
    words: impl Iterator<Item = &'a str> + 'a
) -> impl Iterator<Item = String> + 'a { // ok!
    words.map(|v| format!("foo-{}", v))
}
```

在示例中，`[impl Trait]` 特性在返回类型中使用了隐式的 `'static` 生命周期限制。然而，传递给函数的实现 `Iterator` 的类型所拥有的生命周期与 `'a'` 相同，这还不够长。

解决方案是为函数参数和返回值添加生命周期约束，以确保当函数超出作用域时，迭代器中的值不会被丢弃。

另一种解决方案是确保迭代器中的 `Item` 引用在整个程序生命周期内都是有效的。

```
fn prefix(
    words: impl Iterator<Item = &'static str>
) -> impl Iterator<Item = String> {  // ok!
    words.map(|v| format!("foo-{}", v))
}
```

返回闭包时也可能出现类似的生命周期问题：

```compile_fail,E0700
fn foo(
    x: &mut Vec<i32>
) -> impl FnMut(&mut Vec<i32>) -> &[i32] { // error!
    |y| {
        y.append(x);
        y
    }
}
```

类似地，这里的解决方案是使用明确的返回生命周期，并将变量的所有权移交给闭包。

```
fn foo<'a>(
    x: &'a mut Vec<i32>
) -> impl FnMut(&mut Vec<i32>) -> &[i32] + 'a { // ok!
    move |y| {
        y.append(x);
        y
    }
}
```

如需更好地了解 `[impl Trait]` 中的生命周期处理机制，请参考 [RFC 1951]。
