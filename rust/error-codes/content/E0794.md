如果函数的生命周期参数同时满足以下两个条件，则称为*晚期绑定*：

1. 出现在参数类型中；2. 没有出现在泛型类型约束中。

对于晚期绑定的生命周期参数，无法指定生命周期参数。

错误的代码示例：

```compile_fail,E0794
fn foo<'a>(x: &'a str) -> &'a str { x }
let _ = foo::<'static>;
```

泛型函数的具体实例的类型需要对晚期绑定生命周期参数进行普遍量化。这是因为我们希望该函数在任何被实例化的晚期绑定生命周期处都能正常工作，无论函数是在何处被调用。因此，为晚期绑定生命周期参数指定参数是没有意义的，因为这些参数直到函数调用点才会被解析。

为了解决这个问题，需要移除指定的生命周期：

```
fn foo<'a>(x: &'a str) -> &'a str { x }
let _ = foo;
```

### 附加信息

不是晚期绑定的生命周期参数称为*早期绑定*。由于晚期绑定和早期绑定生命周期参数在函数定义中声明方式相同，可能会产生混淆。当涉及函数指针类型时，可以对晚期绑定生命周期参数进行明确的普遍量化：

```
trait BarTrait<'a> {}

struct Bar<'a> {
    s: &'a str
}

impl<'a> BarTrait<'a> for Bar<'a> {}

fn bar<'a, 'b, T>(x: &'a str, _t: T) -> &'a str
where T: BarTrait<'b>
{
    x
}

let bar_fn: for<'a> fn(&'a str, Bar<'static>) -> &'a str = bar; // OK
let bar_fn2 = bar::<'static, Bar>; // Not allowed
let bar_fn3 = bar::<Bar>; // OK
```

在 `bar` 的定义中，生命周期参数 `'a'` 是晚期绑定的，而 `'b'` 是早期绑定的。这反映在 `bar_fn` 的类型注解中，`'a'` 进行了普遍量化，而 `'b'` 则使用特定的生命周期进行实例化。当存在晚期绑定生命周期参数时，不允许明确指定早期绑定生命周期参数（如 `bar_fn2`，参见 [issue #42868](https://github.com/rust-lang/rust/issues/42868)），尽管由早期绑定参数约束的类型可以指定（如 `bar_fn3`）。
