根据 [RFC 401][rfc401]，如果你有一个名为 `foo` 的函数声明：

```
struct S;

// For the purposes of this explanation, all of these
// different kinds of `fn` declarations are equivalent:

fn foo(x: S) { /* ... */ }
# #[cfg(for_demonstration_only)]
extern "C" {
    fn foo(x: S);
}
# #[cfg(for_demonstration_only)]
impl S {
    fn foo(self) { /* ... */ }
}
```

`foo` 的类型 **不是** `fn(S)`，正如人们所期望的。实际上，它是一个独特的、零大小的标记类型，在这里被表示为 `typeof(foo)`。然而，`typeof(foo)` 可以被 _强制转换为_ 函数指针 `fn(S)`，因此你很少注意到这一点：

```
# struct S;
# fn foo(_: S) {}
let x: fn(S) = foo; // OK, coerces
```

原因在于 `fn(S)` 这种类型并不特定于任何特定的函数：它是一个函数 _指针_。因此调用 `x()` 会进行虚拟调用，而 `foo()` 则是静态分派的，因为 `foo` 的类型明确告诉我们正在调用哪个函数。

如上所述，强制转换意味着大多数代码不必关注这种区别。但是，当使用 **transmute** 将 fn 项转换为 fn 指针时，你可以区分两者。

这有时是 FFI 的一部分：

```compile_fail,E0591
extern "C" fn foo(userdata: Box<i32>) {
    /* ... */
}

# fn callback(_: extern "C" fn(*mut i32)) {}
# use std::mem::transmute;
unsafe {
    let f: extern "C" fn(*mut i32) = transmute(foo);
    callback(f);
}
```

在这里，使用 transmute 来转换 fn 参数的类型。这种模式是不正确的，因为 `foo` 的类型是一个函数 **项** (`typeof(foo)`)，它是零大小的，而目标类型 (`fn()`) 是一个函数指针，它不是零大小的。这种模式应该被重写。有几种可能的实现方式：

- 将原始的 fn 声明改为符合预期的签名，并在 fn 体内进行转换（这是首选方案） - 在调用 transmute 之前将 fn 指针的 fn 项进行转换，如这里所示：

```
# extern "C" fn foo(_: Box<i32>) {}
# use std::mem::transmute;
# unsafe {
let f: extern "C" fn(*mut i32) = transmute(foo as extern "C" fn(_));
let f: extern "C" fn(*mut i32) = transmute(foo as usize); // works too
# }
```

同样的情况也适用于实践中观察到的 `*mut fn()` 的 transmute。不过请注意，使用这种类型通常是不正确的。其目的通常是描述函数指针，而单独的 `fn()` 就足够了。`*mut fn()` 是指向 fn 指针的指针。（由于这些值通常只是传递给 C 代码，因此实际上很少产生差异。）

[rfc401]: https://rust-lang.github.io/rfcs/0401-coercions.html
