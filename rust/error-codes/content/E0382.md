在变量内容被移动到其他位置后，仍使用了该变量。

错误的代码示例：

```compile_fail,E0382
struct MyStruct { s: u32 }

fn main() {
    let mut x = MyStruct{ s: 5u32 };
    let y = x;
    x.s = 6;
    println!("{}", x.s);
}
```

由于 `MyStruct` 是一个未被标记为 `Copy` 的类型，当我们将 `y` 设置时，数据会从 `x` 中移出。这是 Rust 所有权系统的核心原则：除了像 `Rc` 这样的解决方案外，一个值不能由多个变量拥有。

有时我们不需要移动该值。使用引用，我们可以让另一个函数借用该值而不改变其所有权。在下面的示例中，我们实际上不需要将字符串移动到 `calculate_length`，只需用 `&` 给出对其的引用即可。

```
fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{}' is {}.", s1, len);
}

fn calculate_length(s: &String) -> usize {
    s.len()
}
```

可以使用 `&mut` 创建可修改的引用。

有时我们不想使用引用，而是想要副本。所有被标记为 `Clone` 的类型都可以通过调用 `.clone()` 来复制。对副本的后续更改不会影响原始变量。

标准库中的大多数类型都被标记为 `Clone`。下面的示例演示了在字符串上使用 `clone()`。首先将 `s1` 设置为 "many"，然后将其复制到 `s2` 中。之后移除 `s1` 的第一个字符，而 `s2` 不受影响。最终在控制台输出 "any many"。

```
fn main() {
    let mut s1 = String::from("many");
    let s2 = s1.clone();
    s1.remove(0);
    println!("{} {}", s1, s2);
}
```

如果我们能控制类型的定义，可以使用 `#[derive(Clone)]` 自行实现 `Clone` 特性。

有些类型根本没有所有权语义，复制起来非常简单。例如 `i32` 和其他数字类型。我们不必调用 `.clone()` 来复制它们，因为它们同时被标记为 `Copy` 和 `Clone`。在这种情况下，隐式复制更为方便。如果所有成员也都被标记为 `Copy`，我们可以将自己的类型标记为 `Copy`。

在下面的示例中，我们实现了 `Point` 类型。因为它只存储两个整数，所以我们选择使用 `Copy` 来放弃所有权语义。然后我们可以执行 `let p2 = p1`，而 `p1` 不会被移动。

```
#[derive(Copy, Clone)]
struct Point { x: i32, y: i32 }

fn main() {
    let mut p1 = Point{ x: -1, y: 2 };
    let p2 = p1;
    p1.x = 1;
    println!("p1: {}, {}", p1.x, p1.y);
    println!("p2: {}, {}", p2.x, p2.y);
}
```

或者，如果我们无法控制结构的定义，或者确实需要可变的共享所有权，我们可以使用 `Rc` 和 `RefCell`。

```
use std::cell::RefCell;
use std::rc::Rc;

struct MyStruct { s: u32 }

fn main() {
    let mut x = Rc::new(RefCell::new(MyStruct{ s: 5u32 }));
    let y = x.clone();
    x.borrow_mut().s = 6;
    println!("{}", x.borrow().s);
}
```

采用这种方式，x和y通过`Rc`（引用计数类型）共享数据的所有权。`RefCell`主要在运行时进行借用检查：确保任何时候最多只有一个写入者或多个读取者可以访问数据。
