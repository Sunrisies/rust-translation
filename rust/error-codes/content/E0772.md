#### 注意：此错误代码不再由编译器生成。

一个特质对象具有特定的生命周期 `'1'，但其在使用方式上要求它具有 `'static` 生命周期。

错误代码示例：

```compile_fail
trait BooleanLike {}
trait Person {}

impl BooleanLike for bool {}

impl dyn Person {
    fn is_cool(&self) -> bool {
        // hey you, you're pretty cool
        true
    }
}

fn get_is_cool<'p>(person: &'p dyn Person) -> impl BooleanLike {
    // error: `person` has an anonymous lifetime `'p` but calling
    //        `print_cool_fn` introduces an implicit `'static` lifetime
    //        requirement
    person.is_cool()
}
```

在 `get_is_cool` 函数中，特质对象 `person` 已经以具有生命周期 `'p'` 的引用形式存在，同时它自身也拥有隐式的生命周期 `'2'`。

生命周期 `'2'` 表示特质对象可能包含的数据内容。

```
trait MyTrait {}

struct MyStruct<'a>(&'a i32);

impl<'a> MyTrait for MyStruct<'a> {}
```

在这种情况下，如果 `dyn MyTrait + '2` 类型的特质对象是由 `MyStruct<'a>` 创建的，那么 `'a'` 的生命周期必须至少与 `'2'` 相同长。这允许从任何特质方法安全地访问特质对象的内部数据。这一规则也适用于由特质对象转换成的任何结构可能具有的任意生命周期。

在 `dyn Person` 的实现中，表示内部数据的 `'2'` 生命周期被省略了，这意味着编译器推断为 `'static'`。因此，实现中的 `is_cool` 也被编译器推断为如下形式：

```
# trait Person {}
#
# impl dyn Person {
fn is_cool<'a>(self: &'a (dyn Person + 'static)) -> bool {unimplemented!()}
# }
```

而 `get_is_cool` 函数的推断形式则如下：

```
# trait Person {}
# trait BooleanLike {}
#
fn get_is_cool<'p, R: BooleanLike>(person: &'p (dyn Person + 'p)) -> R {
    unimplemented!()
}
```

这引出了问题的核心：将类型 `&'_ (dyn Person + '_)` 赋值给类型 `&'_ (dyn Person + 'static)` 是不可能的。

修复它只需对生命周期 `'2'` 进行泛型化，以防止编译器将其推断为 `'static'`：

```
# trait Person {}
#
impl<'d> dyn Person + 'd {/* ... */}

// This works too, and is more elegant:
//impl dyn Person + '_ {/* ... */}
```

有关特质对象生命周期限制的更多信息，请参阅 [Rust 关于特质对象生命周期限制的参考文档][trait-objects]。
