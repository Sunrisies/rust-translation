闭包中的捕获变量可能存活的时间不够长。

错误的代码示例：

```compile_fail,E0373
fn foo() -> Box<dyn Fn(u32) -> u32> {
    let x = 0u32;
    Box::new(|y| x + y)
}
```

当尝试使用由闭包捕获的数据，而该数据可能已经不存在时，就会出现此错误。这种情况在之前示例中的返回闭包时最为常见。

请注意，`x` 是由 `foo()` 分配到的栈内存。默认情况下，Rust 通过引用来捕获被封闭的数据。这意味着一旦 `foo()` 返回，`x` 就不存在了。因此，在闭包内部访问 `x` 是不安全的。

另一种可能遇到此情况的情况是在创建线程时：

```compile_fail,E0373
fn foo() {
    let x = 0u32;
    let y = 1u32;

    let thr = std::thread::spawn(|| {
        x + y
    });
}
```

由于新创建的线程是并行运行的，包含 `x` 和 `y` 的栈帧可能在我们尝试使用它们之前就已经消失了。即使我们在 `foo` 中调用 `thr.join()`（该调用会阻塞直到 `thr` 完成，从而确保栈帧不会消失），我们也无法成功：编译器无法证明这种行为是安全的，因此不允许这样做。

解决此问题的通常方法是改用 `move` 闭包。这种方法将数据移动到闭包中（或尽可能复制数据），而不是通过引用访问它。例如：

```
fn foo() -> Box<dyn Fn(u32) -> u32> {
    let x = 0u32;
    Box::new(move |y| x + y)
}
```

现在闭包拥有自己的数据副本，就无需担心安全性问题了。

在使用 `async` 块时也可能遇到此错误：

```compile_fail,E0373,edition2018
use std::future::Future;

async fn f() {
    let v = vec![1, 2, 3i32];
    spawn(async { //~ ERROR E0373
        println!("{:?}", v)
    });
}

fn spawn<F: Future + Send + 'static>(future: F) {
    unimplemented!()
}
```

与闭包类似，`async` 块不会立即执行，也可以通过引用捕获被封闭的数据。有关更多信息，请参阅
<https://rust-lang.github.io/async-book/03_async_await/01_chapter.html>.
