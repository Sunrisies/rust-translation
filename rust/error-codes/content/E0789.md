#### 该错误代码是编译器内部使用的，不会在普通的 Rust 代码中被输出。

必须在具有 `stable` 属性的项上使用内部的 `rustc_allowed_through_unstable_modules` 属性。

错误的代码示例：

```compile_fail,E0789
// NOTE: both of these attributes are perma-unstable and should *never* be
//       used outside of the compiler and standard library.
#![feature(rustc_attrs)]
#![feature(staged_api)]
#![allow(internal_features)]

#![unstable(feature = "foo_module", reason = "...", issue = "123")]

#[rustc_allowed_through_unstable_modules(
    message = "deprecation message",
    module = "stable_module",
)]
// #[stable(feature = "foo", since = "1.0")]
struct Foo;
// ^^^ error: `rustc_allowed_through_unstable_modules` attribute must be
//            paired with a `stable` attribute
```

通常，当某个项被标记为 `stable` 时，包含该项的模块也必须被标记为 `stable`，否则该项将变得*实际上*不稳定。 `#[rustcallowed_through_unstable_modules]` 是一种解决方案，允许该项“避开”其不稳定的父模块。当某个项被标记为 `#[rustc_allowed_through_unstable_modules]`，但不存在额外的 `stable` 属性时，就会出现此错误。请参阅 [#99288](https://github.com/rust-lang/rust/pull/99288) 以了解 `#[rustcallowed_through_unstable_modules]` 的实际使用示例。
