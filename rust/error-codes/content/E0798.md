标记为 `cmse-nonsecure-call` 的函数会对其输入和输出施加限制。

- 输入必须适应4个可用的32位参数寄存器，对齐方式很重要。 - 输出必须适应4字节，或者为大小为8的基础类型（`i64`、`u64`、`f64`）。 - 签名中不能使用泛型。

如需更多信息，请参阅 [arm的aapcs32](https://github.com/ARM-software/abi-aa/releases)。

错误的代码示例：

```ignore (host errors will not match for target)
#![feature(abi_cmse_nonsecure_call)]

#[no_mangle]
pub fn test(
    f: extern "cmse-nonsecure-call" fn(u32, u32, u32, u32, u32) -> u32,
) -> u32 {
    f(1, 2, 3, 4, 5)
}
```

输入的对齐方式得到了遵守。在下面的示例中，插入了填充数据，使得 `u64` 参数通过r2和r3寄存器传递。此时便没有空间留给最后的 `f32` 参数了。

```ignore (host errors will not match for target)
#![feature(abi_cmse_nonsecure_call)]

#[no_mangle]
pub fn test(
    f: extern "cmse-nonsecure-call" fn(u32, u64, f32) -> u32,
) -> u32 {
    f(1, 2, 3.0)
}
```
