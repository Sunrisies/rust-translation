当尝试在实现 `Drop` trait 的类型生命周期结束之后借用状态时，就会出现此错误。

错误的代码示例：

```compile_fail,E0713
pub struct S<'a> { data: &'a mut String }

impl<'a> Drop for S<'a> {
    fn drop(&mut self) { self.data.push_str("being dropped"); }
}

fn demo<'a>(s: S<'a>) -> &'a mut String { let p = &mut *s.data; p }
```

在此示例中，`demo` 试图借用其参数 `s` 中存储的字符串数据，然后返回该借用。然而，`S` 被声明为实现了 `Drop` trait。

实现 `Drop` trait 的结构在超出作用域时会调用一个隐式析构函数。当该析构函数运行时，它会获得对结构字段的独占访问权。

这意味着当 `s` 到达 `demo` 的生命周期终点时，其析构函数将获得对其 `&mut` 借用字符串数据的独占访问权。允许另一个对该字符串数据 (`p`) 的借用在 `s` 被丢弃之后仍然存在，这违反了 `&mut` 借用应拥有独占、无别名访问权的原则。

可以通过修改 `demo` 来修复此错误，使得在借用字符串数据时析构函数不执行；例如通过引用 `S`：

```
pub struct S<'a> { data: &'a mut String }

impl<'a> Drop for S<'a> {
    fn drop(&mut self) { self.data.push_str("being dropped"); }
}

fn demo<'a>(s: &'a mut S<'a>) -> &'a mut String { let p = &mut *(*s).data; p }
```

请注意，这种方法需要一个具有生命周期 `'a'` 的 S 的引用。任何比 `'a'` 更短的生命周期都不可行：更短的生命周期意味着在 `demo` 执行完成后，其他对象（如析构函数！）可以在该较短生命周期结束后访问 `s.data`，这同样会违反 `&mut` 借用的独占访问权。
