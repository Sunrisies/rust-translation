为 `impl` 指定的类型、const 参数或生命周期参数不受限制。

错误代码示例：

```compile_fail,E0207
struct Foo;

impl<T: Default> Foo {
    // error: the type parameter `T` is not constrained by the impl trait, self
    // type, or predicates [E0207]
    fn get(&self) -> T {
        <T as Default>::default()
    }
}
```

`impl` 中的任何类型或 const 参数必须满足以下至少一个条件：

 - 出现在 `impl` 的_实现类型_中，例如 `impl<T> Foo<T>`；对于 trait 实现，则出现在_实现的 trait_中，例如 `impl<T> SomeTrait<T> for Foo`；或者作为关联类型被绑定，例如 `impl<T, U> SomeTrait for T where T: AnotherTrait<AssocType=U>`

如果 `impl` 中的生命周期参数被关联类型使用，则不受限制的生命周期参数将不被支持。

### 错误示例 1

假设我们有一个结构体 `Foo`，并希望为其定义一些方法。之前的代码示例中存在一个定义，导致编译器报错：

问题在于参数 `T` 没有出现在 `impl` 的实现类型（`Foo`）中。在这种情况下，可以通过将类型参数从 `impl` 移动到方法 `get` 来修复错误。

```
struct Foo;

// Move the type parameter from the impl to the method
impl Foo {
    fn get<T: Default>(&self) -> T {
        <T as Default>::default()
    }
}
```

### 错误示例 2

另一个例子是，假设我们有一个 `Maker` trait，并希望定义一个类型为 `FooMaker` 的结构体，该结构体用于生成 `Foo`：

```compile_fail,E0207
trait Maker {
    type Item;
    fn make(&mut self) -> Self::Item;
}

struct Foo<T> {
    foo: T
}

struct FooMaker;

impl<T: Default> Maker for FooMaker {
// error: the type parameter `T` is not constrained by the impl trait, self
// type, or predicates [E0207]
    type Item = Foo<T>;

    fn make(&mut self) -> Foo<T> {
        Foo { foo: <T as Default>::default() }
    }
}
```

由于 `T` 既没有出现在 trait 中，也没有出现在实现类型中，因此代码无法编译。

一种解决方法是向 `FooMaker` 引入一个幻影类型参数，例如：

```
use std::marker::PhantomData;

trait Maker {
    type Item;
    fn make(&mut self) -> Self::Item;
}

struct Foo<T> {
    foo: T
}

// Add a type parameter to `FooMaker`
struct FooMaker<T> {
    phantom: PhantomData<T>,
}

impl<T: Default> Maker for FooMaker<T> {
    type Item = Foo<T>;

    fn make(&mut self) -> Foo<T> {
        Foo {
            foo: <T as Default>::default(),
        }
    }
}
```

另一种方法是不使用 `Maker` 中的关联类型，而是使用输入类型参数：

```
// Use a type parameter instead of an associated type here
trait Maker<Item> {
    fn make(&mut self) -> Item;
}

struct Foo<T> {
    foo: T
}

struct FooMaker;

impl<T: Default> Maker<Foo<T>> for FooMaker {
    fn make(&mut self) -> Foo<T> {
        Foo { foo: <T as Default>::default() }
    }
}
```

### 错误示例 3

假设我们有一个结构体 `Foo`，并希望为其定义一些方法。以下代码示例中存在一个定义，导致编译器报错：

```compile_fail,E0207
struct Foo;

impl<const T: i32> Foo {
    // error: the const parameter `T` is not constrained by the impl trait, self
    // type, or predicates [E0207]
    fn get(&self) -> i32 {
        i32::default()
    }
}
```

问题在于 const 参数 `T` 没有出现在 `impl` 的实现类型（`Foo`）中。在这种情况下，可以通过将类型参数从 `impl` 移动到方法 `get` 来修复错误。


```
struct Foo;

// Move the const parameter from the impl to the method
impl Foo {
    fn get<const T: i32>(&self) -> i32 {
        i32::default()
    }
}
```

### 错误示例 4

假设我们有一个结构体 `Foo` 和一个使用生命周期 `'a` 的结构体 `Bar`。我们希望为 `Foo` 实现 trait `Contains`。该 trait 具有关联类型 `B`。以下代码示例中存在一个定义，导致编译器报错：

```compile_fail,E0207
struct Foo;
struct Bar<'a>;

trait Contains {
    type B;

    fn get(&self) -> i32;
}

impl<'a> Contains for Foo {
    type B = Bar<'a>;

    // error: the lifetime parameter `'a` is not constrained by the impl trait,
    // self type, or predicates [E0207]
    fn get(&self) -> i32 {
        i32::default()
    }
}
```

请注意，如果关联类型使用无约束生命周期参数，则不支持此类参数。

当关联类型的生命周期需要与自身类型绑定，且特质上的方法不需要拥有权或不同的可变性时，可以在借用类型上实现该特质作为一种选择：

```rust
struct Foo(i32);

trait Contents {
    type Item;

    fn get(&self) -> Self::Item;
}

// Note the lifetime `'a` is used both for the self type...
impl<'a> Contents for &'a Foo {
    // ...and the associated type.
    type Item = &'a i32;

    fn get(&self) -> Self::Item {
        &self.0
    }
}
```
