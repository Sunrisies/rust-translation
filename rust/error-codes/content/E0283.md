编译器无法推断类型，因此要求添加类型注解。

错误的代码示例：

```compile_fail,E0283
let x = "hello".chars().rev().collect();
```

此错误表明类型推理未能产生唯一的可能类型，需要额外信息。通常可以通过添加类型注解来提供这些信息。有时则需要手动指定泛型类型参数。

一个常见的例子是 `Iterator` 上的 `collect` 方法。它有一个带有 `FromIterator` 约束的泛型类型参数，对于 `char` 迭代器来说，该实现包括 `Vec` 和 `String` 等。考虑以下反转字符串字符的代码片段：

在第一个代码示例中，编译器无法推断 `x` 的类型应为：`Vec<char>` 和 `String` 都是合适的候选类型。为了指定使用哪种类型，可以在 `x` 上添加类型注解：

```
let x: Vec<char> = "hello".chars().rev().collect();
```

无需对完整类型进行注解。一旦歧义得到解决，编译器就可以推断出其余部分。

```
let x: Vec<_> = "hello".chars().rev().collect();
```

另一种向编译器提供足够信息的方式是明确指定泛型类型参数：

```
let x = "hello".chars().rev().collect::<Vec<char>>();
```

同样，如果编译器能够推断完整类型，则无需手动指定。

```
let x = "hello".chars().rev().collect::<Vec<_>>();
```

下面有一个自包含的示例：

```compile_fail,E0283
struct Foo;

impl Into<u32> for Foo {
    fn into(self) -> u32 { 1 }
}

let foo = Foo;
let bar: u32 = foo.into() * 1u32;
```

通过添加提供缺失信息的类型注解来解决此错误。在这种情况下，解决方案就是明确指定 trait 的类型参数：

```
struct Foo;

impl Into<u32> for Foo {
    fn into(self) -> u32 { 1 }
}

let foo = Foo;
let bar: u32 = Into::<u32>::into(foo) * 1u32;
```
