如果某个lint检查属性被作为属性设置在包含作用域中，或通过`-F`选项在命令行上设置的`forbid`指令所覆盖，则该指令将优先生效。

错误代码示例：

```compile_fail,E0453
#![forbid(non_snake_case)]

#[allow(non_snake_case)]
fn main() {
    // error: allow(non_snake_case) incompatible with previous forbid
    let MyNumber = 2;
}
```

`forbid` lint设置类似于`deny`，会将相应的编译器警告转换为严重错误。与`deny`不同，`forbid`不会被内部属性所覆盖。

如果您确定要覆盖lint检查，可以将`forbid`改为`deny`（如果`forbid`设置为命令行选项，则可以使用`-D`代替`-F`）以允许内部lint检查属性生效：

```
#![deny(non_snake_case)]

#[allow(non_snake_case)]
fn main() {
    let MyNumber = 2; // ok!
}
```

否则，请修改代码以通过lint检查，并删除被覆盖的属性。

```
#![forbid(non_snake_case)]

fn main() {
    let my_number = 2;
}
```
