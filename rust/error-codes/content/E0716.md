当一个借用还在活跃使用时，临时值会被释放。

错误的代码示例：

```compile_fail,E0716
fn foo() -> i32 { 22 }
fn bar(x: &i32) -> &i32 { x }
let p = bar(&foo());
         // ------ creates a temporary
let q = *p;
```

在这里，表达式 `&foo()` 正在借用表达式 `foo()`。由于 `foo()` 是对函数的调用，而不是变量的名称，因此会创建一个**临时变量**——该临时变量存储了 `foo()` 的返回值，以便被借用。你可以想象 `let p = bar(&foo());` 等同于使用显式临时变量的以下代码。

错误的代码示例：

```compile_fail,E0597
# fn foo() -> i32 { 22 }
# fn bar(x: &i32) -> &i32 { x }
let p = {
  let tmp = foo(); // the temporary
  bar(&tmp) // error: `tmp` does not live long enough
}; // <-- tmp is freed as we exit this block
let q = p;
```

每当创建临时变量时，它会根据固定规则自动被释放（释放）。通常，临时变量在包含它的语句结束时被释放——在这种情况下，是在 `let p` 之后。上面的示例说明了当我们离开块时，`tmp` 会被释放。

要解决这个问题，你需要创建一个局部变量来保存值，而不是依赖临时变量。例如，你可以将原始程序改为如下形式：

```
fn foo() -> i32 { 22 }
fn bar(x: &i32) -> &i32 { x }
let value = foo(); // dropped at the end of the enclosing block
let p = bar(&value);
let q = *p;
```

通过引入显式的 `let value`，我们分配了直到包含块结束（当 `value` 超出作用域时）才被释放的存储空间。当我们借用 `&value` 时，我们实际上是在借用一个已经存在的局部变量，因此不会创建临时变量。

临时变量并不总是在包含语句结束时被释放。在简单的情况下，如果 `&` 表达式立即被存储到变量中，编译器会自动延长临时变量的生命周期，直到包含块结束。因此，修复原始程序的另一种方法是写 `let tmp = &foo()` 而不是 `let tmp = foo()`。

```
fn foo() -> i32 { 22 }
fn bar(x: &i32) -> &i32 { x }
let value = &foo();
let p = bar(value);
let q = *p;
```

在这里，我们仍然在借用 `foo()`，但由于借用直接赋值到了一个变量中，临时变量不会在包含块结束时被释放。当临时变量被存储到元组或结构等聚合结构中时，也适用类似的规则。

```
// Here, two temporaries are created, but
// as they are stored directly into `value`,
// they are not dropped until the end of the
// enclosing block.
fn foo() -> i32 { 22 }
let value = (&foo(), &foo());
```
