#### 注意：此错误代码不再由编译器生成。

子绑定，例如 `ref x @ Some(ref y)`，现在在 `#![feature(bindings_after_at)]` 下被允许，并且会进行检查以确保内存安全得到保障。

--------------

在某些情况下，子绑定可能会违反内存安全。未来版本的 Rust 中，借用检查器 的更新可能会移除这一限制，但目前必须重新编写代码以不使用子绑定。

Before:

```compile_fail
match Some("hi".to_string()) {
    ref op_string_ref @ Some(s) => {},
    None => {},
}
```

After:

```
match Some("hi".to_string()) {
    Some(ref s) => {
        let op_string_ref = &Some(s);
        // ...
    },
    None => {},
}
```

在两种情况下，`op_string_ref` 的绑定类型均为 `&Option<&String>`。

另请参阅 [Issue 14587][issue-14587]。
