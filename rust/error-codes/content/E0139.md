#### 注意：此错误代码已不再由编译器生成。

在 Rust 中，类型之间的转换存在多种限制；例如，被转换的类型必须具有相同的大小。为了应用所有这些限制，编译器必须知道确切可以转换的类型。当涉及类型参数时，这并不总是能够做到。

因此，例如以下情况是不允许的：

```
use std::mem::transmute;

struct Foo<T>(Vec<T>);

fn foo<T>(x: Vec<T>) {
    // we are transmuting between Vec<T> and Foo<F> here
    let y: Foo<T> = unsafe { transmute(x) };
    // do something with y
}
```

在这种特定情况下，转换可能是无害的（但 Rust 并不保证这一点）。然而，当涉及到对齐和枚举优化时，不同类型参数的实例化可能导致大小不匹配。无法对所有可能的类型进行检查，因此 `transmute()` 仅接受没有未实例化类型参数的类型。

如果您需要这种功能，很可能您做错了什么。请记住，Rust 并不保证不同结构体的布局一致（即使两个声明相同的结构体也可能有不同的布局）。如果有一个可以完全避免转换的解决方案，请尝试使用它。

如果可能的话，可以通过为每种可能的类型实例化编写函数来手动单态化代码。可以使用特质来干净地实现这一点，例如：

```
use std::mem::transmute;

struct Foo<T>(Vec<T>);

trait MyTransmutableType: Sized {
    fn transmute(_: Vec<Self>) -> Foo<Self>;
}

impl MyTransmutableType for u8 {
    fn transmute(x: Vec<u8>) -> Foo<u8> {
        unsafe { transmute(x) }
    }
}

impl MyTransmutableType for String {
    fn transmute(x: Vec<String>) -> Foo<String> {
        unsafe { transmute(x) }
    }
}

// ... more impls for the types you intend to transmute

fn foo<T: MyTransmutableType>(x: Vec<T>) {
    let y: Foo<T> = <T as MyTransmutableType>::transmute(x);
    // do something with y
}
```

每个 `impl` 都会像通常那样被检查大小是否匹配，由于没有未绑定的类型参数，除非某个 `impl` 存在大小不匹配的情况，否则应该可以编译通过。

也可以手动进行转换：

```
# use std::ptr;
# let v = Some("value");
# type SomeType = &'static [u8];
unsafe {
    ptr::read(&v as *const _ as *const SomeType) // `v` transmuted to `SomeType`
}
# ;
```

请注意，这与 `transmute()` 不同，它不会移动 `v`，如果您希望避免析构函数的调用，可能需要调用 `mem::forget(v)`。
