此错误表明违反了 Rust 中针对 trait 实现的孤儿规则。该规则涉及在实现外部 trait（由其他 crate 定义的 trait）时使用类型参数，并规定类型参数必须被局部类型“覆盖”。

当为外部类型实现外部 trait 时，该 trait 必须包含一个或多个类型参数。您 crate 中的类型必须在任何类型参数的使用之前出现。

为了理解这意味着什么，通过几个示例可能更容易说明。

如果 `ForeignTrait` 是定义在外部 crate `foo` 中的 trait，那么以下这种 `impl` 形式会导致错误：

```compile_fail,E0210
# #[cfg(for_demonstration_only)]
extern crate foo;
# #[cfg(for_demonstration_only)]
use foo::ForeignTrait;
# use std::panic::UnwindSafe as ForeignTrait;

impl<T> ForeignTrait for T { } // error
# fn main() {}
```

为了解决这个问题，可以使用局部类型 `MyType` 来覆盖它：

```
# use std::panic::UnwindSafe as ForeignTrait;
struct MyType<T>(T);
impl<T> ForeignTrait for MyType<T> { } // Ok
```

请注意，类型别名并不足以满足要求。

再举一个错误的例子，假设 `foo` 中还有另一个名为 `ForeignTrait2` 的 trait，该 trait 需要两个类型参数。那么这种 `impl` 同样会违反该规则：

```ignore (cannot-doctest-multicrate-project)
struct MyType2;
impl<T> ForeignTrait2<T, MyType<T>> for MyType2 { } // error
```

原因是 `impl` 头部出现了两次类型参数 `T`，分别作为 `ForeignTrait2` 的参数。第一次出现未被覆盖，因此违反了孤儿规则。

再考虑一个例子：

```ignore (cannot-doctest-multicrate-project)
impl<T> ForeignTrait2<MyType<T>, T> for MyType2 { } // Ok
```

与之前的 `impl` 不同之处在于，`ForeignTrait2` 中的参数 `T` 和 `MyType<T>` 被交换了位置。这个示例并不违反孤儿规则；它是允许的。

要理解最后一个示例为何被允许，您需要了解一般规则。不幸的是，这条规则有点难以表述。考虑一个 `impl`：

```ignore (only-for-syntax-highlight)
impl<P1, ..., Pm> ForeignTrait<T1, ..., Tn> for T0 { ... }
```

其中 `P1, ..., Pm` 是 `impl` 的类型参数，`T0, ..., Tn` 是类型。其中一个类型 `T0, ..., Tn` 必须是局部类型（这是另一个孤儿规则，请参阅解释 E0117）。

以下两点必须成立：1. 至少有一个类型 `T0..=Tn` 是局部类型。设 `Ti` 为第一个这样的类型。2. 在 `T0..Ti`（不包括 `Ti`）中不得出现未被覆盖的类型参数 `P1..=Pm`。

有关孤儿规则设计的更多信息，请参阅 [RFC 2451] 和 [RFC 1023]。
