## 四、部署到 47.111.168.59

服务器：root 免密 22 端口；Caddy 跑在 Docker 容器 `caddy`；站点目录主机 `/var/www/rust-docs`。

### 1. 打包上传

```bash
cd D:/hy-mt2-bench/nuxt-docs/rust
tar -czf rust-docs-zh.tar.gz -C deploy .
scp rust-docs-zh.tar.gz root@47.111.168.59:/tmp/
```

### 2. 主机 + 容器解压（bind mount 不同步，两份都要更新）

```bash
ssh root@47.111.168.59 '
D=/var/www/rust-docs
[ -d "$D" ] && mv "$D" "${D}_old_$(date +%Y%m%d-%H%M%S)"
mkdir -p "$D" && tar -xzf /tmp/rust-docs-zh.tar.gz -C "$D"
docker exec caddy mkdir -p "$D"
docker cp "$D/." caddy:"$D/"
'
```

### 3. Caddy 配置（已加，仅首次需要）

主机 `/home/www/caddy/Caddyfile` 已追加：

```caddyfile
rust.sunrise1024.top {
    root * /var/www/rust-docs
    encode gzip zstd
    try_files {path} {path}.html {path}/ =404
    handle_errors {
        rewrite * /404.html
        file_server
    }
    file_server {
        index index.html
    }
}
```

同步进容器（**关键坑**：不能直接 docker cp 到 /etc/caddy/Caddyfile，bind mount 会 Resource busy；要先 cp 到 /tmp 再 cat 覆写 inode）：

```bash
ssh root@47.111.168.59 '
docker cp /home/www/caddy/Caddyfile caddy:/tmp/Caddyfile.new
docker exec caddy sh -c "cat /tmp/Caddyfile.new > /etc/caddy/Caddyfile"
docker exec caddy caddy validate --config /etc/caddy/Caddyfile
docker exec caddy caddy reload --config /etc/caddy/Caddyfile
'
```

静态文件更新**不需要 reload Caddy**（只有 Caddyfile 变了才 reload）。

### 4. DNS（腾讯云 DNSPod）

域名 `sunrise1024.top` 托管在 DNSPod（NS: river/daikon.dnspod.net）。
需在 DNSPod 控制台加一条 A 记录：

| 主机记录 | 类型 | 记录值 | 线路 |
|---|---|---|---|
| `rust` | A | `47.111.168.59` | 默认 |

生效后 Caddy 会自动申请 Let's Encrypt 证书（当前因无 DNS 记录，证书申请一直重试，HTTPS 返回 000；HTTP 返回 308 正常）。

## 六、链接引用定义外露问题（2026-11-23 修复）

**现象**：The Book 第 2 章等页面底部出现一长串 `[prelude]: url [变量与可变性]: url ...` 文本。

**根因**：翻译器把源文件里每行一个的 Markdown 引用定义 `[label]: url` 合并成一行、并把 label/url 翻成中文（如 `struct.String`→`结构体.String`），合并后不再是合法定义，于是作为正文显示；正文里少量 `[text][label]` 的 label 也被误译。

**修复**（`_shared/fix_link_refs.py`，五本书都要跑）：
```bash
python fix_link_refs.py ../book      # 各本都跑
```
脚本从译文自己/源文件重建定义区为每行一个，并把正文里与定义对不上的纯中文 label 映射回对应英文 label。幂等可重复跑。

> 修复后需走完「构建五站 → inject_site_chrome.py → make_deploy_bundle.py → 上传服务器」全流程。
> 验证：`grep -c '\[prelude\]:' deploy/book/ch02-00-guessing-game-tutorial.html` 应为 0，
> 且能 grep 到 `href="../std/prelude/index.html"`。

### 补充：中文冒号变体（2026-11-23 二次修复）

翻译器还会把引用定义生成成 `[中文label]：url`（**中文冒号**）并合并成一行。
`fix_link_refs.py` 已升级：定义行同时识别英文 `:` 和中文 `：` 冒号（冒号后须为
`.html`/`.md`/`/`/`#`/`http` 的 URL），统一替换为源文件的英文规范定义；正文里
纯中文 label 映射回英文。

全量验证（4288 条定义）：中文 label 0、中文冒号 URL 0。
注意 `[^1]：脚注说明` 是正常脚注，不是外露定义，勿误删。

## 七、DNS 生效与证书签发（2026-11-23 完成）

DNS A 记录 `rust → 47.111.168.59` 加好后，Caddy 自动申请证书时遇到：
- 阿里云对未备案新域名的 HTTP(80) 返回 403（Server: Beaver / Non-compliance ICP Filing），
  HTTP-01 挑战路径 `.well-known/acme-challenge/` 被拦，挑战失败。
- 解法：DNS 生效后**重启 Caddy 容器**清掉失败状态，让其改用 **TLS-ALPN-01**（全程走 443，
  不碰 80）申请——成功签发。

```bash
ssh root@47.111.168.59 'docker restart caddy'   # 清失败状态，触发 TLS-ALPN 重试
```

证书有效期：notBefore Nov 23 2026 / notAfter Feb 21 2027（Let's Encrypt 90 天，Caddy 自动续期）。
