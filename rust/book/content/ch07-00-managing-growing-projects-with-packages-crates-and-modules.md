# 包、Crate和模块

当编写大型程序时，代码的组织变得至关重要。通过将相关功能分组并分离具有不同功能的代码，你可以明确知道哪里有实现特定功能的代码，以及如何修改该功能的实现方式。

到目前为止，我们编写的程序都包含在一个模块中的一个文件中。随着项目的增长，你应该将代码拆分为多个模块和多个文件。一个包可以包含多个二进制Crate，并且可选包含一个库Crate。当包逐渐扩大时，你可以将部分内容提取到独立的Crate中作为外部依赖。本章将介绍所有这些技术。对于由一组相互关联的包组成的非常大型项目，Cargo提供了工作空间功能，我们将在第14章的“Cargo工作空间”中讨论。

我们还将讨论封装实现细节的方法，这允许你在更高层次上复用代码：一旦实现了某个操作，其他代码可以通过其公共接口调用你的代码，而无需了解其实现方式。代码的编写方式决定了哪些部分对其他代码是公开的，哪些部分是私有的实现细节，你可以有权更改这些细节。这是另一种减少需要记住的细节数量的方法。

一个相关的概念是作用域：代码编写的嵌套上下文有一组被定义为“在作用域内”的名称。当阅读、编写和编译代码时，程序员和编译器需要知道某个特定位置的特定名称指的是变量、函数、结构体、枚举、模块、常量还是其他项，以及该项的含义是什么。你可以创建作用域并改变哪些名称在作用域内，哪些不在作用域内。同一个作用域内不能有两个具有相同名称的项；有工具可以解决名称冲突问题。

Rust 拥有许多用于管理代码组织的特性，包括哪些细节被公开、哪些细节是私有的，以及程序中每个作用域中的名称是什么。这些特性有时统称为 _模块系统_，包括：

* **包 (Packages)**：Cargo 功能，允许你构建、测试和共享库 * **库 (Crates)**：模块树，生成库或可执行文件 * **模块与使用 (Modules and use)**：让你控制路径的组织结构、作用域和隐私性 * **路径 (Paths)**：一种命名方式，例如结构体、函数或模块的名称

在本章中，我们将介绍所有这些特性，讨论它们之间的相互作用，并解释如何利用它们来管理作用域。最后，你应该对模块系统有扎实的理解，并能像专业人士一样处理作用域！
