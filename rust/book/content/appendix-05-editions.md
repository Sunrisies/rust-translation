## 附录 E：版本说明

在第一章中，您了解到 `cargo new` 会在 `_Cargo.toml_` 文件中添加关于版本的元数据。本附录将解释这意味着什么！

Rust 语言和编译器采用六周一次的发布周期，这意味着用户会不断获得新功能。其他编程语言则较少发布大规模变更；而 Rust 则更频繁地发布小更新。随着时间的推移，这些微小的变更累积起来也会很大。但从一次发布到下一次发布之间，很难回过头来说：“哇，从 Rust 1.10 到 Rust 1.31，Rust 发生了很大的变化！”

大约每三年左右，Rust 团队会推出一个新的 Rust _版本_。每个版本将相关的功能整合到一个清晰的包中，并附带完全更新的文档和工具支持。新版本同样遵循六周一次的发布流程。

不同版本对不同的人有不同的意义：

- 对于活跃的 Rust 用户来说，新版本将逐步变更整合为一个易于理解的包。
- 对于非用户而言，新版本表明有一些重大进展，这可能会让人们重新关注 Rust。
- 对于开发 Rust 的人来说，新版本为整个项目提供了一个统一的参考点。

在撰写本文时，已有四个 Rust 版本可供选择：Rust 2015、Rust 2018、Rust 2021 和 Rust 2024。本书则采用 Rust 2024 版本的语法编写。

`_Cargo.toml_` 中的 `edition` 键指示编译器应使用哪个版本。如果该键不存在，出于向后兼容的原因，Rust 会使用 `2015` 作为版本值。

每个项目可以选择非默认 2015 版本的版本。不同版本可能包含不兼容的变更，例如引入与代码中的标识符冲突的新关键字。然而，除非您选择这些变更，否则即使升级了 Rust 编译器版本，您的代码仍然可以编译通过。

所有 Rust 编译器版本都支持该编译器发布前存在的任何版本，并且可以将任何受支持的版本的 crate 链接在一起。版本变更仅影响编译器对代码的初始解析方式。因此，如果您使用 Rust 2015，而某个依赖项使用 Rust 2018，您的项目将能够编译并使用该依赖项。相反的情况，即您的项目使用 Rust 2018，而一个依赖项使用 Rust 2015，同样可以正常工作。

明确地说：大多数功能在所有版本中都是可用的。使用任何 Rust 版本的开发者在发布新的稳定版本时将继续获得改进。然而，在某些情况下，尤其是当添加新关键字时，某些新功能可能仅在后续版本中可用。如果您想利用这些功能，则需要切换版本。

更多详情请参阅[_Rust 版本指南]_[edition-guide]。这是一本完整的书籍，详细列举了各版本之间的差异，并解释了如何通过 `cargo fix` 自动将代码升级到新版本。
