## 循环与迭代器的性能对比

要判断使用循环还是迭代器，你需要知道哪种实现更快：带有显式 `for` 循环的 `search` 函数版本，还是使用迭代器的版本。

我们进行了一次基准测试，将阿瑟·柯南·道尔所著的《夏洛克·福尔摩斯冒险记》的全部内容加载到 `String` 中，并在其中查找单词 _the_。以下是使用 `for` 循环和迭代器版本的 `search` 函数的测试结果：

```text
test bench_search_for  ... bench:  19,620,300 ns/iter (+/- 915,700)
test bench_search_iter ... bench:  19,234,900 ns/iter (+/- 657,200)
```

这两种实现的性能相似！这里不解释基准测试代码，因为重点不是证明两种版本等价，而是了解这两种实现在性能上的差异。

为了进行更全面的基准测试，你应该使用不同大小的各种文本作为 `contents`，不同的单词和不同长度的单词作为 `query`，并尝试各种其他变体。关键在于：尽管迭代器是一种高级抽象机制，但其编译后的代码大致与你自己编写低级代码相同。迭代器是 Rust 的 _零成本抽象_ 之一，这意味着使用这种抽象不会增加额外的运行时开销。这类似于 C++ 的原始设计者及实现者 Bjarne Stroustrup 在2012年ETAPS主题演讲“C++ 基础”中提出的零开销概念：

> 一般来说，C++ 实现遵循零开销原则：你不使用的部分不需要付费。此外，你使用的部分也无法写出更高效的代码。

在许多情况下，使用迭代器的 Rust 代码可以编译成与手动编写相同的汇编代码。诸如循环展开和取消数组访问的边界检查等优化措施使得最终代码极其高效。现在你知道了这一点，就可以放心地使用迭代器和闭包了！它们让代码看起来更高级，但并不会造成运行时性能损失。

## 总结

闭包和迭代器是 Rust 的特性，其设计灵感来源于函数式编程语言。它们有助于 Rust 以低性能水平清晰表达高级概念。闭包和迭代器的实现不会影响运行时性能。这是 Rust 致力于提供零成本抽象的目标之一。
