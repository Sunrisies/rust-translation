# 错误处理

在软件开发中，错误是不可避免的，因此 Rust 提供了多种机制来处理出现问题的场景。在许多情况下，Rust 要求你在代码无法编译之前承认存在错误并采取相应措施。这一要求使得程序更加健壮，因为你可以提前发现错误并进行适当处理，从而避免在将代码部署到生产环境时出现问题！

Rust 将错误分为两大类：可恢复的错误和不可恢复的错误。对于可恢复的错误，例如“文件未找到”错误，通常只需向用户报告问题并重新尝试操作即可。不可恢复的错误总是错误的表现，比如试图访问数组末尾之后的位置，因此必须立即终止程序。

大多数语言不会区分这两种类型的错误，而是以相同的方式处理它们，使用异常机制。Rust 没有异常机制。相反，它使用 `Result<T, E>` 类型来处理可恢复的错误，当程序遇到不可恢复的错误时，会使用 `panic!` 宏来停止执行。本章将首先介绍调用 `panic!`，然后讨论返回 `Result<T, E>` 值的方法。此外，我们还将探讨在决定是尝试从错误中恢复还是终止执行时的考虑因素。
