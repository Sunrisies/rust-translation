## 无法修复的 `panic!` 错误

有时代码中会出现问题，而您无能为力。在这种情况下，Rust 提供了 `panic!` 宏。实际上有两种方式会导致程序崩溃：一种是通过执行导致程序崩溃的操作（如访问数组的末尾部分），另一种则是直接调用 `panic!` 宏。在这两种情况下，程序都会发生崩溃。默认情况下，这些崩溃会打印错误信息、回溯堆栈并终止程序。通过环境变量，您还可以让 Rust 在崩溃时显示调用栈，从而更容易定位崩溃原因。

> ### 回溯堆栈或响应于崩溃中止程序
>
> 默认情况下，当发生崩溃时，程序会开始_回溯_，这意味着 Rust 会沿着堆栈向上移动并清理每个函数中的数据。然而，回溯和清理工作非常繁琐。因此，Rust 允许您选择立即_中止_程序，从而无需清理即可结束程序。
>
> 此时，程序使用的内存需要由操作系统进行清理。如果您希望项目生成的二进制文件尽可能小，可以在 `_Cargo.toml` 文件的相应 `[profile]` 部分添加 `panic = 'abort'` 选项，以在崩溃时选择回溯或中止方式。例如，如果您希望在发布模式下发生崩溃时立即中止程序，可以添加如下配置：
>
> ```toml
> [profile.release]
> panic = 'abort'
> ```

这里，我们试图访问向量的第 100 个元素（因为索引从零开始，所以位于索引 99），但向量只有三个元素。在这种情况下，Rust 会触发恐慌。使用 `[]` 应该返回一个元素，但如果传入无效的索引，Rust 无法返回正确的元素。

在 C 语言中，试图读取数据结构末尾的数据属于未定义行为。你可能会得到内存中与该数据结构中的元素对应的内容，即使该内存并不属于该数据结构。这被称为 _缓冲区溢出_，如果攻击者能够操纵索引以读取不应被允许的数据，则可能导致安全漏洞。

为了保护程序免受这种漏洞的影响，如果你尝试读取不存在的索引处的元素，Rust 会停止执行并拒绝继续运行。让我们试试看：

这会产生大量的输出！您看到的确切输出可能会因您的操作系统和 Rust 版本而异。为了获取包含这些信息的回溯信息，必须启用调试符号。当使用 `cargo build` 或 `cargo run` 且未添加 `--release` 标志时，默认就会启用调试符号，就像我们这里所做的那样。
