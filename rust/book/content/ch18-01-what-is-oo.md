## 面向对象语言的特性

在编程社区中，对于一种语言必须具备哪些特征才能被视为面向对象语言，目前尚无共识。Rust受到多种编程范式的影响，包括OOP；例如，我们在第13章探讨了来自函数式编程的特性。可以说，OOP语言具有某些共同特性——即对象、封装和继承。让我们来看看这些特性的含义以及Rust是否支持它们。

### 对象包含数据和行为

Erich Gamma、Richard Helm、Ralph Johnson和John Vlissides所著的《设计模式：可复用面向对象软件的基础》（Addison-Wesley, 1994），通常被称为“四人小组”书籍，是一本面向对象设计模式的目录。它这样定义OOP：

> 面向对象程序由对象组成。一个**对象**将数据以及操作该数据的过程封装在一起。这些过程通常称为**方法**或**操作**。

根据这一定义，Rust是面向对象的：结构体和枚举具有数据，而`impl`块为结构体和枚举提供方法。尽管带有方法的结构和枚举并非真正的“对象”，但根据“四人小组”对对象的定义，它们提供了相同的功能。

### 隐藏实现细节的封装

与OOP相关的另一个常见概念是**封装**，这意味着对象的实现细节无法被使用该对象的代码访问。因此，与对象交互的唯一方式是通过其公共API；使用该对象的代码不应能够直接访问对象的内部结构并更改数据或行为。这使得程序员可以在不修改使用该对象的代码的情况下更改和重构对象的内部结构。

我们在第7章中讨论了如何控制封装。我们可以使用 `pub` 关键字来决定代码中的哪些模块、类型、函数和方法应该是公开的，而默认其他所有内容都是私有的。例如，我们可以定义一个名为 `AveragedCollection` 的结构体，该结构体包含一个包含 `i32` 值的向量字段。该结构体还可以有一个包含向量中值平均值的字段，这意味着平均值不必在需要时按需计算。换句话说，`AveragedCollection` 会为我们缓存已计算的平均值。列表18-1展示了 `AveragedCollection` 结构体的定义。

公共方法 `add`、`remove` 和 `average` 是访问或修改 `AveragedCollection` 实例中数据的唯一方式。当使用 `add` 方法将项目添加到 `list` 或使用 `remove` 方法移除项目时，这些实现都会调用私有的 `update_average` 方法来更新 `average` 字段。

由于我们封装了 `AveragedCollection` 结构体的实现细节，因此未来可以轻松更改诸如数据结构之类的方面。例如，我们可以将 `list` 字段使用 `HashSet<i32>` 代替 `Vec<i32>`。只要 `add`、`remove` 和 `average` 公共方法的签名保持不变，使用 `AveragedCollection` 的代码就无需修改。但如果我们将 `list` 设为公开（public），情况则不一定如此：因为 `HashSet<i32>` 和 `Vec<i32>` 在添加和移除项目时有不同的方法，如果外部代码直接修改 `list`，则可能需要进行更改。

如果封装是语言被视为面向对象所需具备的特性之一，那么 Rust 就符合这一要求。通过选择使用 `pub` 或不使用 `pub`，可以实现对实现细节的封装。

### 继承作为类型系统和代码共享

继承是一种机制，通过这种机制，一个对象可以从另一个对象的定义中继承元素，从而获得父对象的数据和行为，而无需再次定义它们。

如果一种语言必须依赖继承才能成为面向对象语言，那么 Rust 就不是这样的语言。如果没有使用宏，就无法定义一个继承父结构体字段和方法实现的结构体。

然而，如果你已经习惯了在编程工具箱中使用继承，可以根据你最初选择继承的原因，在 Rust 中使用其他解决方案。

您选择继承主要有两个原因。其一是为了代码复用：您可以为一种类型实现特定行为，而通过继承则可以将该实现复用于另一种类型。在 Rust 代码中，可以通过默认特质方法实现来有限地实现这一点，正如我们在 Listing 10-14 中为 `Summary` 特质添加 `summarize` 方法的默认实现时所看到的那样。任何实现 `Summary` 特质的类型都无需额外代码即可获得 `summarize` 方法。这类似于父类拥有某个方法的实现，而继承的子类也拥有该方法的实现。当我们实现 `Summary` 特质时，也可以覆盖 `summarize` 方法的默认实现，这类似于子类覆盖从父类继承来的方法实现。

使用继承的另一个原因与类型系统有关：使子类型能够在与父类型相同的位置被使用。这也被称为_多态性_，意味着如果多个对象具有某些共同特性，则可以在运行时用它们替代彼此。

> ### 多态性
>
> 对许多人来说，多态性与继承同义。但实际上，它是一个更通用的概念，指的是能够处理多种类型数据的代码。对于继承而言，这些类型通常是子类。
>
> Rust 则使用泛型来抽象不同的可能类型，并通过特质边界对这些类型必须提供的功能施加约束。这有时被称为_有界参数多态性_。

Rust 选择了不同的权衡策略，没有提供继承机制。使用继承往往会导致共享不必要的代码。子类并不总是需要共享父类的所有特性，但通过继承却会如此。这可能会降低程序的设计灵活性。此外，它还会引入一种可能性：调用子类上的方法可能毫无意义或导致错误，因为这些方法不适用于该子类。另外，某些语言仅允许_单继承_（即一个子类只能从一个类继承），从而进一步限制了程序设计的灵活性。

出于这些原因，Rust 采用了不同的方法，使用特质对象而非继承来实现运行时多态性。让我们来看看特质对象的工作原理。
