# 无畏并发

安全且高效地处理并发编程是 Rust 的主要目标之一。当更多计算机利用其多处理器时，独立执行的程序不同部分进行的_并发编程_以及同时执行的程序不同部分进行的_并行编程_变得越来越重要。历史上，在这些环境下编程既困难又容易出错。Rust 希望改变这一现状。

最初，Rust 团队认为确保内存安全与防止并发问题是两个需要分别用不同方法解决的挑战。随着时间的推移，团队发现所有权和类型系统是一组强大的工具，可以帮助管理内存安全和并发问题！通过利用所有权和类型检查，许多并发错误在 Rust 中都是编译时错误，而非运行时错误。因此，与其花费大量时间尝试重现运行时并发错误的具体情况，错误的代码会拒绝编译并显示错误提示以说明问题。这样，你可以在编写代码的过程中就修复它，而不是可能在代码发布到生产环境后才发现问题。我们将这一特性称为_无畏并发_。无畏并发使你能够编写没有微妙错误的代码，并且易于重构而不引入新错误。

> 注意：为了简单起见，我们将许多问题称为_并发_，而不是更精确地使用_并发和/或并行_。在本章中，当我们使用_并发_时，请在心中替换成_并发和/或并行_。在下一章中，当这种区别更为重要时，我们会更加具体说明。

许多语言在处理并发问题时对解决方案有着严格的限制。例如，Erlang 提供了优雅的消息传递并发机制，但在线程间共享状态方面却只有晦涩难懂的方法。对于高级语言而言，仅支持部分可能的解决方案是一种合理的策略，因为高级语言通过放弃一些控制来获得抽象性，从而带来优势。然而，低级语言则被期望在任何特定情况下都能提供最佳性能，并且对硬件的抽象程度较低。因此，Rust 提供了多种工具，可以根据您的情况和需求以适当的方式建模各种问题。

本章将涵盖以下主题：

- 如何创建线程以同时运行多段代码 - _消息传递_ 并发，即通道在线程间传递消息 - _共享状态_ 并发，即多个线程可以访问某些数据 - `Sync` 和 `Send` 特质，这些特质将 Rust 的并发保证扩展到用户定义类型以及标准库提供的类型
