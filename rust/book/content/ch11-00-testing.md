# 编写自动化测试

在1972年的文章《谦逊的程序员》中，埃德斯格·W·迪杰斯特拉指出：“程序测试是一种非常有效的发现错误的方法，但对于证明没有错误则远远不够。”这并不意味着我们不应该尽可能多地进行测试！

我们的程序中的_正确性_是指代码能够按预期执行的程度。Rust 设计时就高度重视程序的正确性，但正确性很复杂且难以证明。Rust 的类型系统承担了大部分责任，然而类型系统并不能捕捉所有问题。因此，Rust 提供了编写自动化软件测试的支持。

假设我们编写一个名为 `add_two` 的函数，该函数将传入的数字加2。该函数的签名接受一个整数作为参数，并返回一个整数作为结果。当我们实现并编译该函数时，Rust 会执行所有你之前学过的类型检查和借用检查，以确保例如我们没有传递 `String` 值或无效的引用给该函数。但是 Rust_无法_确保该函数确实按预期执行，即返回参数加2，而不是比如参数加10或参数减50！这就是测试的作用所在。

我们可以编写测试来验证，例如，当我们将 `3` 传递给 `add_two` 函数时，返回值为 `5`。每当我们对代码进行更改时，都可以运行这些测试，以确保任何现有的正确行为没有发生变化。

测试是一项复杂的技能：虽然我们无法在某一章中详细阐述如何编写良好的测试，但在本章中我们将讨论 Rust 测试功能的机制。我们将介绍编写测试时可使用的注释和宏、运行测试的默认行为和选项，以及如何将测试组织为单元测试和集成测试。
