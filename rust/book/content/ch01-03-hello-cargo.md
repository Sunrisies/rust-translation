## 你好，Cargo！

Cargo是Rust的构建系统和包管理器。大多数Rust开发者使用此工具来管理他们的Rust项目，因为Cargo会处理许多任务，例如编译代码、下载代码所依赖的库以及编译这些库。（我们称代码所需的库为_依赖项_。）

最简单的Rust程序，比如我们目前编写的那个，没有任何依赖项。如果我们用Cargo构建“Hello, world!”项目，它只会使用Cargo中用于编译代码的模块。当你编写更复杂的Rust程序时，就会添加依赖项，如果你使用Cargo开始一个项目，添加依赖项会更容易。

由于绝大多数Rust项目都使用Cargo，本书的其余部分假设你也使用Cargo。如果你使用了[“安装”][installation]<!-- ignore -->章节中讨论的官方安装程序，则Cargo会随Rust一起安装。如果你通过其他方式安装了Rust，可以在终端中输入以下命令检查是否安装了Cargo：

```console
$ cargo --version
```

如果你看到版本号，说明你已经成功安装！如果看到错误提示，例如`command not found`，请查阅你安装方式的文档，以了解如何单独安装Cargo。

### 使用Cargo创建项目

让我们使用Cargo创建一个新项目，并看看它与我们最初的“Hello, world!”项目有何不同。返回到你的_projects_目录（或你决定存储代码的任何位置）。然后在任何操作系统上运行以下命令：

```console
$ cargo new hello_cargo
$ cd hello_cargo
```

第一个命令会创建一个名为_hello_cargo_的新目录和项目。我们将项目命名为_hello_cargo_，而Cargo会在同名目录中创建文件。

进入_hello_cargo_目录并列出文件。你会看到Cargo为我们生成了两个文件和一个目录：一个_Cargo.toml_文件和一个包含`_main.rs_`文件的`_src_`目录。

它还初始化了一个新的 Git 仓库以及一个 _.gitignore_ 文件。如果你在现有的 Git 仓库中运行 `cargo new`，则不会生成 Git 文件；你可以通过使用 `cargo new --vcs=git` 来覆盖此行为。

> 注意：Git 是一种常见的版本控制系统。你可以使用 `--vcs` 标志将 `cargo new` 改为使用不同的版本控制系统或不使用版本控制系统。运行 `cargo new --help` 可以查看可用的选项。

在你选择的文本编辑器中打开 _Cargo.toml_ 文件。它的外观应该与列表 1-2 中的代码相似。

<Listing number="1-2" file-name="Cargo.toml" caption="Contents of *Cargo.toml* generated by `cargo new`">

```toml
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]
```

</Listing>

此文件采用 [_TOML_][toml]<!-- ignore --> (_Tom’s Obvious, Minimal Language_) 格式，这是 Cargo 的配置格式。

第一行 `[package]` 是一个章节标题，表示接下来的内容是在配置一个包。当我们向此文件中添加更多信息时，会添加其他章节。

接下来的三行设置了 Cargo 编译你的程序所需的配置信息：名称、版本以及要使用的 Rust 版本。我们将在 [附录 E][appendix-e]<!-- ignore -->中讨论 `edition` 键。

最后一行 `[dependencies]` 是一个章节的开始，用于列出项目的依赖项。在 Rust 中，代码包被称为 _crates_。对于这个项目我们不需要其他 crates，但在第 2 章的第一个项目中我们会使用它们，因此我们将使用这个依赖项章节。

现在打开 _src/main.rs_ 并查看一下：

<span class="filename">Filename: src/main.rs</span>

```rust
fn main() {
    println!("Hello, world!");
}
```

Cargo 为你生成了一个“Hello, world!”程序，就像我们在列表 1-1 中编写的那样！到目前为止，我们的项目与 Cargo 生成的项目之间的区别是，Cargo 将代码放在 _src_ 目录中，而我们则在顶层目录中有 _Cargo.toml_ 配置文件。

Cargo 期望你的源文件位于 _src_ 目录内。顶层项目目录仅用于 README 文件、许可证信息、配置文件以及与代码无关的其他内容。使用 Cargo 可以帮助你组织项目。每样东西都有它的位置，而且每样东西都放在正确的地方。

如果您启动了一个不使用 Cargo 的项目，就像我们做的“Hello, world!”项目那样，您可以将其转换为使用 Cargo 的项目。将项目代码移动到 _src_ 目录中，并创建合适的 _Cargo.toml_ 文件。一种简单的方法是运行 `cargo init`，它会自动为您生成该文件。

### 构建和运行 Cargo 项目

现在让我们看看使用 Cargo 构建和运行“Hello, world!”程序时有什么不同！从 _hello_cargo_ 目录中，通过输入以下命令来构建您的项目：

```console
$ cargo build
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs
```

此命令会在 _target/debug/hello_cargo_（或 Windows 下的 _target\debug\hello_cargo.exe_）中创建可执行文件，而不是在您当前目录中。由于默认构建是调试版本，Cargo 会将二进制文件放在名为 _debug_ 的目录中。您可以使用此命令运行可执行文件：

```console
$ ./target/debug/hello_cargo # or .\target\debug\hello_cargo.exe on Windows
Hello, world!
```

如果一切顺利，`Hello, world!` 应该会在终端中显示。第一次运行 `cargo build` 时，Cargo 还会在顶层创建一个新文件：_Cargo.lock_。该文件记录了项目中依赖项的确切版本。由于这个项目没有依赖项，因此该文件内容较少。您永远不需要手动修改此文件；Cargo 会自行管理其内容。

我们刚刚使用 `cargo build` 构建了一个项目，并使用 `./target/debug/hello_cargo` 运行它，但也可以使用 `cargo run` 一次性编译代码并运行生成的可执行文件：

```console
$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
     Running `target/debug/hello_cargo`
Hello, world!
```

使用 `cargo run` 比记住要运行 `cargo build` 然后使用完整的二进制文件路径更方便，因此大多数开发者都使用 `cargo run`。

请注意，这次我们没有看到表明 Cargo 正在编译 `hello_cargo` 的输出。Cargo 判断文件没有变化，因此没有重新构建，只是直接运行了二进制文件。如果您修改了源代码，Cargo 会在运行前重新构建项目，此时您会看到这种输出：

```console
$ cargo run
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs
     Running `target/debug/hello_cargo`
Hello, world!
```

Cargo 还提供了一个名为 `cargo check` 的命令。该命令可以快速检查代码是否可编译，但不会生成可执行文件：

```console
$ cargo check
   Checking hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs
```

为什么你不想要可执行文件呢？通常，`cargo check` 比 `cargo build` 更快，因为它跳过了生成可执行文件的步骤。如果你在编写代码时不断检查工作成果，使用 `cargo check` 可以加快流程，让你知道项目是否仍在编译！因此，许多 Rustacean 会在编写程序时定期运行 `cargo check`，以确保代码能够编译成功。然后，当他们准备使用可执行文件时，再运行 `cargo build`。

让我们回顾一下目前关于 Cargo 学到的内容：

- 我们可以使用 `cargo new` 创建项目。
- 我们可以使用 `cargo build` 构建项目。
- 我们可以使用 `cargo run` 一步完成项目的构建和运行。
- 我们可以使用 `cargo check` 在不生成二进制文件的情况下检查错误。
- 与将构建结果保存在代码所在目录不同，Cargo 将其保存在 _target/debug_ 目录中。

使用 Cargo 的另一个优势是，无论你在哪种操作系统上工作，命令都是相同的。因此，目前我们不再提供针对 Linux、macOS 和 Windows 的具体说明。

### 为发布版本构建

当你的项目最终准备好发布时，你可以使用 `cargo build --release` 进行优化编译。此命令会在 _target/release_ 中生成可执行文件，而不是 _target/debug_。优化会使你的 Rust 代码运行得更快，但开启这些优化会延长程序编译的时间。这就是为什么存在两种不同配置的原因：一种用于开发阶段，此时你需要频繁重新构建；另一种用于构建最终版本的程序，这种程序不会反复重建，并且会尽可能快速地运行。如果你正在对代码的运行时间进行基准测试，请确保使用 `cargo build --release` 并使用 _target/release_ 中的可执行文件进行测试。

### 利用 Cargo 的约定

对于简单的项目，Cargo 相比直接使用 `rustc` 并没有太多价值，但当程序变得复杂时，它将会发挥重要作用。当程序包含多个文件或需要依赖项时，让 Cargo 来协调构建过程会容易得多。

尽管 `hello_cargo` 项目很简单，但它现在使用了你在后续 Rust 学习过程中会使用的许多实际工具。实际上，要处理任何现有项目，你可以使用以下命令通过 Git 获取代码、切换到该项目的目录并构建：

```console
$ git clone example.org/someproject
$ cd someproject
$ cargo build
```

有关 Cargo 的更多信息，请查看 [其文档][cargo]。

## 总结

你的 Rust 学习之旅已经开始了很棒的第一步！在本章中，你学习了如何：

- 使用 `rustup` 安装最新稳定的 Rust 版本。
- 升级到更新的 Rust 版本。
- 打开本地安装的文档。
- 直接使用 `rustc` 编写并运行“Hello, world!”程序。
- 按照 Cargo 的规范创建并运行新项目。
