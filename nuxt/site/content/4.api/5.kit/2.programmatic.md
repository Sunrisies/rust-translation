当您希望以程序化方式使用 Nuxt 时，例如构建 [CLI 工具](https://github.com/nuxt/cli) 或 [测试工具](https://github.com/nuxt/test-utils)，程序化使用会非常有用。

## `loadNuxt`

以程序化方式加载 Nuxt。它将加载 Nuxt 配置，实例化并返回包含 Nuxt 实例的 Promise。

### 类型

```ts
function loadNuxt (loadOptions?: LoadNuxtOptions): Promise<Nuxt>
```

### 参数

**`loadOptions`**：Nuxt 的加载条件。`loadNuxt` 在底层使用 [`c12`](https://github.com/unjs/c12)，因此它接受与 `c12.loadConfig` 相同的选项，但还有一些额外的选项：

| 属性 | 类型 | 是否必填 | 描述                                                                                                                                                       |
| -------- | --------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`    | `boolean` | `false`  | 如果设置为 `true`，Nuxt 将在开发模式下加载。                                                                                                        |
| `ready`  | `boolean` | `true`   | 如果设置为 `true`，在 `loadNuxt` 调用后 Nuxt 将准备好使用。如果设置为 `false`，您需要调用 `nuxt.ready()` 以确保 Nuxt 已准备好使用。 |

## `buildNuxt`

以程序化方式构建 Nuxt。它将调用构建器（当前为 [@nuxt/vite-builder](https://github.com/nuxt/nuxt/tree/main/packages/vite) 或 [@nuxt/webpack-builder](https://github.com/nuxt/nuxt/tree/main/packages/webpack)）来打包应用程序。

### 类型

```ts
function buildNuxt (nuxt: Nuxt): Promise<any>
```

### 参数

**`nuxt`**：要构建的 Nuxt 实例。可以通过 `useNuxt()` 调用从上下文中获取。

## `loadNuxtConfig`

加载 Nuxt 配置。它将返回包含配置对象的 Promise。

### 类型

```ts
function loadNuxtConfig (options: LoadNuxtConfigOptions): Promise<NuxtOptions>
```

### 参数

**`options`**：控制配置如何定位、合并和加载的选项。

| 属性 | 类型 | 默认值 | 描述                                                                                                                                        |
| ------------------- | --------------------------------------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cwd`               | `string` | `process.cwd()` | 从该目录加载 `nuxt.config` 的目录。                                                                                                              |
| `configFile`        | `string`                                            | `'nuxt.config'`  | 要加载的配置文件名称，不包含扩展名。                                                                                             |
| `rcFile`            | `string \| false`                                   | `'.nuxtrc'`      | 要加载的 `.rc` 文件名称，与配置文件一起加载；设置为 `false` 则不加载任何文件。                                                                  |
| `globalRc`          | `boolean`                                           | `true`           | 同时加载用户级和工作区级的 `.nuxtrc` 文件。                                                                                       |
| `overrides`         | `NuxtConfig`                                        | `undefined`      | 在每一层之上应用的配置，包括根项目的自身 `nuxt.config`。                                                                                |
| `defaults`          | `NuxtConfig`                                        | `undefined`      | 在每一层之下、schema 默认配置之前应用的配置。                                                                                       |
| `dotenv`            | `boolean \| NuxtDotenvOptions`                      | `true`           | 在解析配置之前将 `.env` 文件加载到 `process.env` 中。当环境已设置时，设置为 `false`。                |
| `envName`           | `string \| false`                                   | `undefined`      | 用于选择 `$env.*` 配置覆盖的环境名称。其优先级高于在 `nuxt.config` 中设置的 `envName`。                             |
| `resolve`           | `(source, context) => ResolvedNuxtLayer \| nullish` | `undefined`      | 自行将 `extends` 条目解析为一个层。返回一个空值，以回退到该源的默认解析方式。                      |
| `import`            | `(id: string) => Promise<unknown>`                  | `undefined`      | 使用自定义加载器导入配置文件，而不是默认加载器，例如加载 TypeScript 配置而不让 Nuxt 调用 `jiti`。       |
| `onConfigResolved` | `(context: ResolvedNuxtConfigContext) => void` | `undefined` | 在配置成功加载后调用一次并等待执行。如果加载过程中发生异常，则不会调用此函数。 |

### `onConfigResolved`

传递给 `onConfigResolved` 的上下文描述了已加载的内容：

| 属性         | 类型                | 描述                                                                                                                               |
| ------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rawConfig`  | `NuxtConfig`        | 所有层级的用户配置被合并，没有应用任何模式默认设置，且排除了 `overrides`、`defaults` 和 `defaultConfig`，因此未更改的项目重复加载会生成相同的快照。 |
| `layers`     | `NuxtConfigLayer[]` | 已解析的配置层级，按优先级从高到低排列。                                                                                     |
| `configFile` | `string?`           | 如果找到，则根 `nuxt.config` 文件的绝对路径。                                                                                 |
| `cwd`        | `string`            | 配置加载所在的目录。                                                                                                             |

## `diffNuxtConfig`

比较两个 `rawConfig` 快照（作为 `onConfigResolved` 的参数提供），并返回它们之间的差异。当您自己查看配置文件时，此功能非常有用，有助于确定哪些键已更改，从而决定是否需要重启。

### 类型

```ts
function diffNuxtConfig (oldConfig: NuxtConfig, newConfig: NuxtConfig): NuxtConfigDiffEntry[]
```

### 参数

**`oldConfig`**：之前的 `rawConfig` 快照。

**`newConfig`**：当前的 `rawConfig` 快照。

### 返回值

一个条目数组，每个条目对应一个差异。每个条目包含：

| 属性       | 类型                     | 描述                                                                                                                               |
| ---------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`     | `'added' \| 'removed' \| 'changed'` | 值变化的类型。                                                                                                          |
| `path`     | `Array<string \| number>`  | 被修改值的属性路径，数组索引以数字形式表示，例如 `['runtimeConfig', 'public', 'foo']`。在从配置对象中读取值时，建议使用此路径。 |
| `label`    | `string`                   | `path` 作为属性访问器书写，用于显示或与已知键进行匹配，例如 `runtimeConfig.public.foo` 或 `modules[0]`。 |
| `newValue` | `unknown`                  | 适用于 `added` 和 `changed` 条目。 |
| `oldValue` | `unknown`                  | 适用于 `removed` 和 `changed` 条目。 |

源未改变的函数不会被报告为变更，因此声明内联函数的配置在每次加载时不会与自身产生差异。

### 示例

```ts
import { diffNuxtConfig, loadNuxtConfig } from '@nuxt/kit'

let previous

async function load () {
  await loadNuxtConfig({
    cwd: process.cwd(),
    onConfigResolved ({ rawConfig }) {
      if (previous) {
        for (const entry of diffNuxtConfig(previous, rawConfig)) {
          console.log(`${entry.label} was ${entry.type}`)
        }
      }
      previous = rawConfig
    },
  })
}
```

## `writeTypes`

生成 `tsconfig.json` 并将其写入项目构建目录。

### 类型

```ts
function writeTypes (nuxt?: Nuxt): void
```

### 参数

**`nuxt`**: 用于构建的 Nuxt 实例。可以通过 `useNuxt()` 调用从上下文中获取。
