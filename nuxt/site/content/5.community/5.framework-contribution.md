一旦您阅读了[通用贡献指南](/docs/community/contribution)，以下是关于向 [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 仓库贡献的一些具体要点。

## 单仓库指南

- `packages/kit`: 用于编写 Nuxt 模块的工具包，以 [`@nuxt/kit`](https://www.npmjs.com/package/@nuxt/kit) 形式发布。
- `packages/nuxt`: Nuxt 的核心部分，以 [`nuxt`](https://www.npmjs.com/package/nuxt) 形式发布。
- `packages/schema`: 跨版本的 Nuxt 类型定义和默认值，以 [`@nuxt/schema`](https://www.npmjs.com/package/@nuxt/schema) 形式发布。
- `packages/rspack`: 用于 Nuxt 的[Rspack](https://rspack.rs) 打包工具，以 [`@nuxt/rspack-builder`](https://www.npmjs.com/package/@nuxt/rspack-builder) 形式发布。
- `packages/vite`: 用于 Nuxt 的[Vite](https://vite.dev) 打包工具，以 [`@nuxt/vite-builder`](https://www.npmjs.com/package/@nuxt/vite-builder) 形式发布。
- `packages/webpack`: 用于 Nuxt 的[webpack](https://webpack.js.org) 打包工具，以 [`@nuxt/webpack-builder`](https://www.npmjs.com/package/@nuxt/webpack-builder) 形式发布。

## 设置

要向 Nuxt 贡献代码，您需要设置本地环境。

1. [ Fork](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/fork-a-repo) [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 仓库到您的 GitHub 账户，然后[克隆](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)它到本地设备。
2. 确保使用最新版本的[Node.js](https://nodejs.org/en)。
3. 启用[Corepack](https://github.com/nodejs/corepack)以使用 `pnpm` 和 `yarn`。
    ```bash [Terminal]
    corepack enable
    ```
4. 运行 `pnpm install --frozen-lockfile` 以使用 pnpm 安装依赖项：
    ```bash [Terminal]
    pnpm install --frozen-lockfile
    ```
    ::note
    如果您正在添加依赖项，请使用 `pnpm add`。:br
    `pnpm-lock.yaml` 文件是所有 Nuxt 依赖项的权威来源。
    ::
5. 激活被动开发系统。
    ```bash [Terminal]
    pnpm dev:prepare
    ```
6. 查看一个您可以工作的分支并提交您的更改：
    ```bash [Terminal]
    git checkout -b my-new-branch
    ```

然后，在提交拉取请求之前，请通过[游戏场](/docs/community/framework-contribution#playground)和[测试](/docs/community/framework-contribution#testing)您的更改进行测试。

### 游乐场

在提交拉取请求时，你可能会希望检查你的更改是否正常工作。

你可以在 `playground/` 中修改示例应用，并运行：

```bash [Terminal]
pnpm dev
```

::important
请确保不要将其提交到你的分支，但在 PR 描述中添加一些示例代码可能会有所帮助。这可以帮助审查者和其他 Nuxt 用户理解你深入构建的功能。
::

### 测试

每个新功能都应有相应的单元测试（如果可能）。此仓库中的 `test/` 目录目前仍在开发中，但请尽量按照现有的示例创建新的测试。

在创建 PR 或标记为待审查之前，通过运行以下命令确保所有测试都通过：

```bash [Terminal]
pnpm test
```

### 代码检查

你可能已经注意到我们使用 ESLint 来强制执行编码标准。

在提交你的更改之前，为了验证代码风格正确，请运行：

```bash [Terminal]
pnpm lint
```

::note
你可以使用 `pnpm lint --fix` 来修复大部分样式问题。 :br
如果仍然有错误，你必须手动修正它们。
::

### 文档

如果你正在添加新功能、重构或以其他方式改变 Nuxt 的行为，你可能会希望记录这些更改。请将任何更改都包含在同一个 PR 中。你不必在第一次提交时编写文档（但请在你的拉取请求足够成熟后尽快完成）。

::important
请确保按照 [文档风格指南](/docs/community/contribution#documentation-style-guide) 进行更改。
::

### 最终检查清单

在提交 PR 时，有一个简单的模板需要填写。请在所有相应的“选项”上打勾。

## 文档指南

如果你发现我们可以改进文档或错误信息的方面，请打开一个 PR——即使只是修正一个拼写错误！

::important
请确保按照 [文档风格指南](/docs/community/contribution#documentation-style-guide) 进行更改。
::

### 快速编辑

如果你发现拼写错误或想重新表述句子，可以点击 **Community** 部分右侧的 **Edit this page** 链接。

直接在 GitHub 界面中进行更改，然后打开一个拉取请求。

### 长期编辑

文档内容位于 [nuxt/nuxt](https://github.com/nuxt/nuxt) 仓库的 `docs/` 目录中，使用 Markdown 编写。

::note
要在本地预览文档，请按照 [nuxt/nuxt.com](https://github.com/nuxt/nuxt.com) 仓库中的步骤操作。
::

::note
我们建议您在 VS Code 中安装 [MDC 扩展](https://marketplace.visualstudio.com/items?itemName=Nuxt.mdc)。
::

### 文档检查

文档使用 [MarkdownLint](https://github.com/DavidAnson/markdownlint) 和 [case police](https://github.com/antfu/case-police) 进行检查，以确保文档的一致性。

```bash [Terminal]
pnpm lint:docs
```

::note
您还可以运行 `pnpm lint:docs:fix` 来高亮并修复任何检查问题。
::

### 打开 PR

请确保您的 PR 标题遵循 [conventional commits](https://www.conventionalcommits.org) 规范。

```bash [Example of PR title]
docs: update the section about the nuxt.config.ts file
```
