## 移除模块

- 移除 `@nuxt/typescript-build`：Bridge 提供相同的功能。
- 移除 `@nuxt/typescript-runtime` 和 `nuxt-ts`：Nuxt 2 已内置运行时支持。

### 设置 `bridge.typescript`

```ts
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    typescript: true,
    nitro: false, // If migration to Nitro is complete, set to true
  },
})
```

## 更新 `tsconfig.json`

如果您使用 TypeScript，可以编辑您的 `tsconfig.json` 以利用自动生成的 Nuxt 类型：

```diff [tsconfig.json]
{
+ "extends": "./.nuxt/tsconfig.json",
  "compilerOptions": {
    ...
  }
}
```

::note
由于 `.nuxt/tsconfig.json` 是自动生成的且未提交到版本控制中，您需要在运行测试前生成该文件。请将 `nuxi prepare` 作为测试前的步骤，否则会看到 `TS5083: Cannot read file '~/.nuxt/tsconfig.json'` 错误。

对于现代 Nuxt 项目，我们建议使用 [TypeScript 项目引用](/docs/directory-structure/tsconfig) 而不是直接扩展 `.nuxt/tsconfig.json`。
::

::note
请注意，从 `./.nuxt/tsconfig.json` 扩展的所有选项将被您的 `tsconfig.json` 中定义的选项覆盖。
使用您自己的配置覆盖诸如 `"compilerOptions.paths"` 之类的选项会导致 TypeScript 不考虑 `./.nuxt/tsconfig.json` 中的模块解析规则。这可能导致如 `#imports` 这样的模块解析无法被识别。

如果您需要进一步扩展 `./.nuxt/tsconfig.json` 提供的选项，可以在 `nuxt.config` 中使用 `alias` 属性。`nuxi` 会捕获这些配置并相应地扩展 `./.nuxt/tsconfig.json`。
::
