---
title: 传统组合式 API
description: 了解如何使用 Nuxt Bridge 迁移到组合式 API。
---

Nuxt Bridge 提供了对组合式 API 语法的访问权限。它专为与 Nuxt 3 对齐而设计。因此，如果您之前使用过组合式 API，启用 Nuxt Bridge 时还需要执行一些额外的步骤。

## 移除模块

- 从依赖列表中移除 `@vue/composition-api`。
- 从依赖列表中移除 `@nuxtjs/composition-api`（以及 `nuxt.config` 中的模块）。

## 使用 `@vue/composition-api`

如果您只使用了 `@vue/composition-api` 而未使用 `@nuxtjs/composition-api`，那么操作非常简单。

1. 首先，移除手动注册组合式 API 的插件。Nuxt Bridge 会自动处理这一点。

   ```diff
   - import Vue from 'vue'
   - import VueCompositionApi from '@vue/composition-api'
   -
   - Vue.use(VueCompositionApi)
   ```

2. 否则，无需做任何操作。不过，如果您愿意，可以移除从 `@vue/composition-api` 中直接导入的内容，并依赖 Nuxt Bridge 自动导入这些内容。

## 从 `@nuxtjs/composition-api` 迁移

Nuxt Bridge 对组合式 API 的实现与 `@nuxtjs/composition-api` 略有不同，并提供不同的组合式函数（旨在与 Nuxt 3 提供的组合式函数保持一致）。

由于某些组合式函数已被移除且尚未有替代方案，因此这一过程会稍微复杂一些。

### 从 `buildModules` 中移除 `@nuxtjs/composition-api/module`

您不必立即更新导入内容——Nuxt Bridge 将自动为当前大多数导入提供“shim”，以便您有时间迁移到新的、与 Nuxt 3 兼容的组合式函数，但有以下例外情况：

- `withContext` 已被移除。请参阅 [下方](/docs/bridge/nuxt3-compatible-api#usecontext-and-withcontext)。
- `useStatic` 已被移除。目前没有替代方案。如果您有相关用例，欢迎讨论。
- 已废弃的 `reqRef` 和 `reqSsrRef` 现已完全移除。请遵循关于 [ssrRef](/docs/bridge/nuxt3-compatible-api#ssrref-and-shallowssrref) 的说明来替换它们。

### 设置 `bridge.capi`

```ts
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    capi: true,
    nitro: false, // If migration to Nitro is complete, set to true
  },
})
```

对于从 `@nuxtjs/composition-api` 使用的每个组合式函数，请遵循以下步骤。

### useFetch

`$fetchState` 和 `$fetch` 已被移除。

```diff
const {
- $fetch,
- $fetchState,
+ fetch,
+ fetchState,
} = useFetch(() => { posts.value = await $fetch('/api/posts') })
```

### `defineNuxtMiddleware`

这是一个类型辅助函数 stub，现在已被移除。

移除 `defineNuxtMiddleware` 包装器：

```diff
- import { defineNuxtMiddleware } from '@nuxtjs/composition-api`
- export default defineNuxtMiddleware((ctx) => {})
+ export default (ctx) => {}
```

为了获得 TypeScript 支持，你可以使用 `@nuxt/types`：

```ts
import type { Middleware } from '@nuxt/types'

export default <Middleware> function (ctx) { }
```

### `defineNuxtPlugin`

这是一个类型辅助函数 stub，现在已被移除。

你也可以继续使用 Nuxt 2 风格的插件，只需移除该函数（如同 [defineNuxtMiddleware](/docs/bridge/bridge-composition-api#definenuxtmiddleware) 一样）。

移除 `defineNuxtPlugin` 包装器：

```diff
- import { defineNuxtPlugin } from '@nuxtjs/composition-api'
- export default defineNuxtPlugin((ctx, inject) => {})
+ export default (ctx, inject) => {}
```

为了获得 TypeScript 支持，你可以使用 `@nuxt/types`：

```ts
import type { Plugin } from '@nuxt/types'

export default <Plugin> function (ctx, inject) {}
```

::warning
虽然这个示例仍然有效，但 Nuxt 3 引入了一个新的 `defineNuxtPlugin` 函数，其签名略有不同。
::

:ReadMore{link="/docs/directory-structure/app/plugins#creating-plugins"}

### `useRouter` 和 `useRoute`

Nuxt Bridge 通过 [`useRouter`](/docs/api/组合式函数/use-router) 和 `useRoute` 提供了这些组合式函数的直接替代方案。

唯一的区别是 [`useRoute`](/docs/api/组合式函数/use-route) 不再返回计算属性。

```diff
- import { useRouter, useRoute } from '@nuxtjs/composition-api'

  const router = useRouter()
  const route = useRoute()

- console.log(route.value.path)
+ console.log(route.path)
```
