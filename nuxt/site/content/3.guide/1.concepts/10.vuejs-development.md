Nuxt 集成了 Vue 3，这是 Vue 的新主要版本，为 Nuxt 用户提供了新的使用模式。

::note
虽然不需要深入了解 Vue 就能使用 Nuxt，但我们建议您阅读文档并浏览 [vuejs.org](https://vuejs.org) 上的一些示例。
::

Nuxt 一直将 Vue 作为前端框架使用。

我们选择在 Vue 之上构建 Nuxt 的原因如下：

- Vue 的反应性模型，即数据的变化会自动触发界面变化。
- 基于组件的模板系统，虽然保持 HTML 为网络的通用语言，但能实现直观的布局模式，使界面既一致又强大。
- 从小型项目到大型 Web 应用，Vue 在大规模应用中仍能保持良好的性能，确保您的应用能够为用户带来价值。

## Nuxt 与 Vue

### 单文件组件

[Vue 的单文件组件](https://vuejs.org/guide/scaling-up/sfc)（SFC 或 `*.vue` 文件）封装了 Vue 组件的标记（`<template>`）、逻辑（`<script>`）和样式（`<style>`）。Nuxt 为 SFC 提供了无需配置的体验，并支持 [热模块替换](https://vite.dev/guide/features#hot-module-replacement)，从而提供无缝的开发体验。

### 自动导入

在 Nuxt 项目的 [`app/components/`](/docs/directory-structure/app/components) 目录中创建的每个 Vue 组件，都无需导入即可在您的项目中使用。如果某个组件未被任何地方使用，您的生产环境代码将不会包含该组件。

:read-more{to="/docs/guide/concepts/auto-imports"}

### Vue Router

大多数应用需要多个页面以及在不同页面之间导航的方式。这被称为 **路由**。Nuxt 使用 [`app/pages/`](/docs/directory-structure/app/pages) 目录和命名规范来直接创建与您的文件对应的路由，使用官方的 [Vue Router 库](https://router.vuejs.org)。

:read-more{to="/docs/getting-started/routing"}

:link-example{to="/docs/examples/features/auto-imports"}

## Vapor 模式

::warning
Vapor 模式支持是实验性功能，需要 Vue 3.6 或更高版本。API 可能会发生变化。
::

[Vapor 模式](https://github.com/vuejs/core/releases/tag/v3.6.0-rc.1#about-vapor-mode) 是 Vue 3.6 引入的一种替代编译策略，它在不使用虚拟 DOM 的情况下渲染组件，从而降低内存占用并提高运行性能。

Nuxt 在 **interop 模式**下支持 Vapor 模式：你的应用仍然使用 Virtual DOM 渲染，你可以通过将组件或页面写成 Vapor 单文件组件来将其设置为 Vapor 组件。这样你可以逐步采用 Vapor，而 Nuxt 的其余功能（路由、`useAsyncData`、`useLayout` 以及大多数内置组件）则保持原样运行。

### 启用 Vapor 模式

在你的 Nuxt 配置中启用 `vue.vapor` 选项：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vue: {
    vapor: true,
  },
})
```

这将安装 Vue 的 `vaporInteropPlugin`，使 Vapor 和 Virtual DOM 组件能够同时渲染。然后你可以通过在 `<script setup>` 中添加 `vapor` 属性来将任何组件或页面标记为 Vapor：

```vue [app/pages/index.vue]
<script setup vapor lang="ts">
const count = ref(0)
</script>

<template>
  <button @click="count++">
    count is {{ count }}
  </button>
</template>
```

### 尝试使用

Vapor 模式需要包含 Vapor 及其互操作修复的 Vue 版本。虽然 Vue 3.6 处于预发布阶段，但请安装包含这些修复的正式候选版本（或更新版本）：

```json [package.json]
{
  "dependencies": {
    "vue": "^3.6.0-rc.6"
  }
}
```

如果你在旧版本的 Vue 上启用 `vue.vapor`，Nuxt 会发出警告并禁用该选项。

我们建议在一个新的项目中使用 Vapor 模式，而不是在现有项目上添加。你也可以在 [Nuxt Vapor 演示](https://github.com/danielroe/nuxt-vapor-demo) 中探索一个可用的设置。

### 已知限制

由于 Nuxt 在 interop 模式下运行 Vapor，一些依赖 Virtual DOM 的模式在 Vapor 组件中的行为会有所不同：

- **完整的 Vapor 应用目前不受支持**。应用根节点仍然是 Virtual DOM，你需要逐个组件启用；我们可能会在以后支持完整的 Vapor 应用。
- **Vapor 组件上的 Template refs** 不会暴露 `$el`。
- **某些内置组件会检查其 slot 内容**，无法读取 Vapor slot 的子元素。`<ClientOnly>` 会跳过属性传递，而 `<NuxtIsland>`、服务器组件以及读取文本子元素的头部组件（如 `<Title>`、`<Style>` 和 `<Noscript>`）会在传递 Vapor slot 时发出警告。可以直接传递值（例如将字符串传递给 `<Title>`）。
- **Options API** 在 Vapor 组件中不受支持，因此 `asyncData` 和通过 `defineNuxtComponent` 的 `fetchKey` 不可用。应使用带有 `useAsyncData` 的 `<script setup>`。
- **带键的 `onPrehydrate`** 会回退到无键形式（在开发模式下会发出警告），因为没有组件实例来绑定键。
- 在 Vapor `<script setup>` 中，调用 `await` 之后的 Nuxt 组合式函数可能会丢失 Nuxt 上下文。尽可能在第一个 `await` 之前调用它们。

大多数其他 Nuxt 组合式函数和内置组件仍然正常工作，因为它们依赖于注入机制而非组件实例。

## 与 Nuxt 2 / Vue 2 的差异

Nuxt 3+ 基于 Vue 3。新的主要 Vue 版本引入了若干变化，Nuxt 利用了这些变化：

- 更好的性能
- 组合 API
- TypeScript 支持

### 更快速的渲染

Vue Virtual DOM (VDOM) 从零开始被重写，从而实现了更好的渲染性能。此外，在处理编译后的单文件组件时，Vue 编译器可以通过分离静态和动态标记，在构建时进一步优化它们。

这导致首次渲染（组件创建）和更新更快，且内存使用更少。在 Nuxt 3 中，这也使得服务器端渲染更快。

### 更小的包大小

随着 Vue 3 和 Nuxt 3 的推出，重点放在了包大小的减少上。在版本 3 中，Vue 的大部分功能，包括模板指令和内置组件，都可以进行摇树优化。如果你不使用这些功能，生产环境包中就不会包含它们。

这样，一个极简的 Vue 3 应用可以缩小到 12 kb gzipped 的大小。

### 组合 API

在 Vue 2 中，向组件提供数据和逻辑的唯一方式是通过 Options API，该接口允许你通过 `data` 和 `methods` 等预定义属性将数据和方法返回给模板：

```vue twoslash
<script>
export default {
  data () {
    return {
      count: 0,
    }
  },
  methods: {
    increment () {
      this.count++
    },
  },
}
</script>
```

Vue 3 引入的 [组合 API](https://vuejs.org/guide/extras/composition-api-faq) 并不是 Options API 的替代方案，但它使得整个应用中的逻辑复用更加高效，并且是复杂组件中按关注点分组代码的更自然方式。

使用 `<script>` 定义中的 `setup` 关键字，以下是使用组合 API 和 Nuxt 3 自动导入的反应性 API 重写的上述组件：

```vue twoslash [components/Counter.vue]
<script setup lang="ts">
const count = ref(0)
const increment = () => count.value++
</script>
```

Nuxt 的目标是在组合 API 周围提供出色的开发体验。

- 使用来自 Vue 和 Nuxt 的自动导入的 [反应性函数](https://vuejs.org/api/reactivity-core) 以及 [内置组合式函数](/docs/api/组合式函数/use-async-data)。
- 在 [`app/composables/` 目录](/docs/directory-structure/app/组合式函数)中编写自己可重用的自动导入函数。

### TypeScript 支持

Vue 3 和 Nuxt 3+ 均使用 TypeScript 编写。完全类型化的代码库能够避免错误并记录 API 使用方式。但这并不意味着你必须使用 TypeScript 来开发应用才能利用它。在 Nuxt 3 中，你可以通过将文件从 `.js` 重命名为 `.ts`，或在组件中添加 `<script setup lang="ts">` 来选择使用 TypeScript。

::read-more{to="/docs/guide/concepts/typescript"}
请阅读关于 Nuxt 中 TypeScript 的详细信息
::
