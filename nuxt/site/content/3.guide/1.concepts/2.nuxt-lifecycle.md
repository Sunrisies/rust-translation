本章的目标是提供框架各部分的概述、执行顺序以及它们如何协同工作。

## 服务器生命周期

在服务器上，每次对应用程序的初始请求都会执行以下步骤：

::steps
### 服务器插件 :badge[一次]{color="info" class="align-middle"}

Nuxt 由 [Nitro](https://nitro.build/) 这一现代服务器引擎驱动。

当 Nitro 启动后，它会初始化并执行位于 [`/server/plugins`](/docs/directory-structure/server#server-plugins) 目录下的插件。这些插件可以：
- 捕获并处理全局应用程序错误。
- 注册在 Nitro 关闭时执行的钩子。
- 注册用于请求生命周期事件的钩子，例如修改响应内容。

::callout{icon="i-lucide-lightbulb"}
Nitro 插件在服务器启动时仅执行一次。在无服务器环境中，每次接收请求时服务器都会启动，Nitro 插件也会随之启动。但是，它们不会被等待。
::

:read-more{to="/docs/directory-structure/server#server-plugins"}

### 服务器中间件

在初始化 Nitro 服务器后，每个请求都会执行 `server/middleware/` 下的中间件。中间件可用于执行认证、日志记录或请求转换等任务。

::warning
从中间件返回值会终止请求，并将返回值作为响应发送。通常应避免此行为，以确保正确的请求处理！
::

:read-more{to="/docs/directory-structure/server#server-middleware"}

### 应用插件

首先创建 Vue 和 Nuxt 实例。之后，Nuxt 执行其应用插件。这包括：
- 内置插件，如 Vue Router 和 `unhead`。
- 位于 `app/plugins/` 目录中的自定义插件，包括没有后缀的插件（例如 `myPlugin.ts`）以及带有 `.server` 后缀的插件（例如 `myServerPlugin.server.ts`）。

插件按特定顺序执行，并可能相互依赖。有关更多细节，包括执行顺序和并行性，请参阅 [插件文档](/docs/directory-structure/app/plugins)。

::callout{icon="i-lucide-lightbulb"}
在此步骤之后，Nuxt 调用 [`app:created`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子，该钩子可用于执行额外逻辑。
::

:read-more{to="/docs/directory-structure/app/plugins"}

### 路由验证

在初始化插件之后但在执行中间件之前，Nuxt 会调用 `validate` 方法，如果该方法定义在 `definePageMeta` 函数中。`validate` 方法可以是同步或异步的，常用于验证动态路由参数。

- 如果参数有效，`validate` 函数应返回 `true`。
- 如果验证失败，应返回 `false` 或包含 `status` 和/或 `statusText` 的对象，以终止请求。

有关更多信息，请参阅 [路由验证文档](/docs/getting-started/routing#route-validation)。

:read-more{to="/docs/getting-started/routing#route-validation"}

### 应用中间件

中间件允许你在导航到特定路由之前运行代码。它常用于认证、重定向或日志记录等任务。

在 Nuxt 中，有三种类型的中间件：
- **全局路由中间件**
- **命名路由中间件**
- **匿名（或内联）路由中间件**

Nuxt 在初始页面加载时执行所有全局中间件（服务器和客户端均执行），然后在任何客户端导航之前再次执行。命名和匿名中间件仅在对应页面组件中定义的页面（路由）meta 的 中间件 属性指定的路由上执行。

关于每种类型的详细信息及示例，请参阅 [中间件文档](/docs/directory-structure/app/中间件)。

服务器上的任何重定向都会向浏览器发送 `Location:` 标题；然后浏览器会向这个新位置发出新请求。当发生这种情况时，除非存储在 Cookie 中，否则所有应用状态都会被重置。

:read-more{to="/docs/directory-structure/app/middleware"}

### 页面和组件

Nuxt 在此步骤中使用 `useFetch` 和 `useAsyncData` 渲染页面及其组件，并获取所需数据。由于没有动态更新且在服务器上没有 DOM 操作，Vue 生命周期钩子如 `onBeforeMount`、`onMounted` 及后续钩子在 SSR 期间**不会**被执行。

默认情况下，Vue 在 SSR 期间暂停依赖跟踪以提高性能。

::callout{icon="i-lucide-lightbulb"}
因为 Vue SSR 以静态 HTML 的形式从顶部渲染应用，因此无法回到已渲染的内容进行修改。所以服务器端没有响应式特性。
::

::important
你应该避免在 `<script setup>` 的根作用域中产生需要清理的副作用代码。例如使用 `setInterval` 设置计时器就是此类副作用。在仅客户端端的代码中，我们可以在 `onBeforeUnmount` 或 `onUnmounted` 中设置计时器并在之后取消设置。但由于 SSR 期间永远不会调用卸载钩子，计时器将永远存在。为了避免这种情况，请将副作用代码移到 `onMounted` 中。
::

::tip{icon="i-lucide-video" to="https://youtu.be/dZSNW07sO-A" target="_blank"}
观看 Daniel Roe 的视频，了解服务器渲染和全局状态的概念。
::

### HTML 输出

当所有必要数据被获取且组件被渲染后，Nuxt 会将渲染后的组件与 `unhead` 提供的设置结合，生成完整的 HTML 文档。这个 HTML 以及相关数据随后会被发送回客户端，以完成 SSR 过程。

::callout{icon="i-lucide-lightbulb"}
将 Vue 应用渲染为 HTML 后，Nuxt 会调用 [`app:rendered`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子。
::

::callout{icon="i-lucide-lightbulb"}
在最终确定并发送 HTML 之前，Nitro 会调用 [`render:html`](/docs/api/advanced/hooks#nitro-app-hooks-runtime-server-side) 钩子。此钩子允许你操作生成的 HTML，例如注入额外的脚本或修改元标签。
::

::

## 客户端生命周期

无论你选择哪种 Nuxt 模式，这部分生命周期都在浏览器中完全执行。

::steps

### 应用插件

此步骤与服务器端执行类似，包括内置和自定义插件。

位于 `app/plugins/` 目录中的自定义插件，例如没有后缀的文件（如 `myPlugin.ts`）以及带有 `.client` 后缀的文件（如 `myClientPlugin.client.ts`），会在客户端执行。

::callout{icon="i-lucide-lightbulb"}
此步骤之后，Nuxt 会调用 [`app:created`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子，可用于执行额外的逻辑。
::

:read-more{to="/docs/directory-structure/app/plugins"}

### 路由验证

此步骤与服务器端执行相同，包括如果在 `definePageMeta` 函数中定义的 `validate` 方法。

### 应用中间件

Nuxt 中间件在服务器和客户端都运行。如果你希望某些代码在特定环境中运行，可以考虑使用 `import.meta.client` 针对客户端，使用 `import_meta server` 针对服务器来拆分代码。

:read-more{to="/docs/directory-structure/app/middleware#when-middleware-runs"}

### 挂载 Vue 应用并 hydration

调用 `app.mount('#__nuxt')` 会将 Vue 应用挂载到 DOM 中。如果应用使用 SSR 或 SSG 模式，Vue 会执行 hydration 步骤，使客户端应用具有交互性。在 hydration 过程中，Vue 会重新创建应用（排除 [服务器组件](/docs/directory-structure/app/components#server-components)），将每个组件与对应的 DOM 节点匹配，并添加 DOM 事件监听器。

为了确保正确的 hydration，保持服务器和客户端之间的数据一致性非常重要。对于 API 请求，建议使用 `useAsyncData`、`useFetch` 或其他适合 SSR 的组合式函数。这些方法确保从服务器端获取的数据在 hydration 过程中被重复使用，避免重复请求。任何新请求应在 hydration 之后触发，以防止 hydration 错误。

::callout{icon="i-lucide-lightbulb"}
在挂载 Vue 应用之前，Nuxt 会调用 [`app:beforeMount`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子。
::

::callout{icon="i-lucide-lightbulb"}
在挂载 Vue 应用之后，Nuxt 会调用 [`app:mounted`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子。
::

### Vue 生命周期

与服务器不同，浏览器会执行完整的 [Vue 生命周期](https://vuejs.org/guide/essentials/lifecycle)。

::
