title: 自动导入
description: Nuxt 会自动导入组件、组合式函数、辅助函数和 Vue API。
---

Nuxt 会自动导入组件、组合式函数和 [Vue.js API](https://vuejs.org/api/)，无需显式导入即可在应用程序中使用。

```vue twoslash [app/app.vue]
<script setup lang="ts">
const count = ref(1) // ref is auto-imported
</script>
```

得益于其有主意的目录结构，Nuxt 可以自动导入 [`app/components/`](/docs/directory-structure/app/components)、 [`app/composables/`](/docs/directory-structure/app/组合式函数) 和 [`app/utils/`](/docs/directory-structure/app/utils)。

与传统的全局声明不同，Nuxt 保留类型信息、IDE 补全功能和提示，并且**仅包含你在生产代码中实际使用的内容**。

::note
在文档中，所有未显式导入的函数都会被 Nuxt 自动导入，可以直接在代码中使用。你可以在 [API 部分](/docs/api)找到关于自动导入的组件、组合式函数和工具参考。
::

::note
在 [`server`](/docs/directory-structure/server) 目录中，Nuxt 会自动从 `server/utils/` 导入导出的函数和变量。
::

::note
你也可以通过配置 `nuxt.config` 文件中的 [`imports`](/docs/api/nuxt-config#imports) 部分，来自动导入来自自定义文件夹或第三方包的函数的导出内容。
::

## 内置自动导入

Nuxt 会自动导入用于 [数据获取](/docs/getting-started/data-fetching)、访问 [应用上下文](/docs/api/组合式函数/use-nuxt-app) 和 [运行时配置](/docs/guide/going-further/runtime-config)、管理 [状态](/docs/getting-started/state-management) 或定义组件和插件的函数及组合式函数。

```vue twoslash
<script setup lang="ts">
/* useFetch() is auto-imported */
const { data, refresh, status } = await useFetch('/api/hello')
</script>
```

Vue 提供了如 `ref` 或 `computed` 这样的反应性 API，以及生命周期钩子和辅助函数，这些都会被 Nuxt 自动导入。

```vue twoslash
<script setup lang="ts">
/* ref() and computed() are auto-imported */
const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Vue 和 Nuxt 组合式函数

<!-- TODO: move to separate page with https://github.com/nuxt/nuxt/issues/14723 and add more information -->

当你使用 Vue 和 Nuxt 提供的内置 Composition API 组合式函数时，请注意许多组合式函数依赖于在正确的 _上下文_ 中调用。

在组件生命周期期间，Vue 通过全局变量跟踪当前组件的临时实例（类似地，Nuxt 也跟踪 `nuxtApp` 的临时实例），然后在同一时刻将其取消设置。这在服务器渲染中非常重要，既可以避免跨请求状态污染（两个用户之间共享引用），也可以避免不同组件之间的数据泄露。

这意味着（除了极少数情况外），你不能在 Nuxt 插件、Nuxt 路由中间件或 Vue setup 函数之外使用它们。此外，你必须同步使用这些组合式函数——也就是说，在调用组合式函数之前不能使用 `await`，除非在 `<script setup>` 块中、使用 `defineNuxtComponent` 声明的组件的 setup 函数中、使用 `defineNuxtPlugin` 或 `defineNuxtRouteMiddleware` 中，我们在进行转换时保持同步上下文。

如果你收到如 `Nuxt instance is unavailable` 这样的错误消息，那可能意味着你在 Vue 或 Nuxt 生命周期中的错误位置调用了 Nuxt 组合式函数。

:video-accordion{title="亚历山大·利希特视频：如何避免“Nuxt实例不可用”错误" videoId="ofuKRZLtOdY"}

::tip
当使用需要在非 SFC 组件中访问 Nuxt 上下文的组合式函数时，你需要用 `defineNuxtComponent` 包裹你的组件，而不是 `defineComponent`。
::

::read-more{to="/docs/guide/going-further/experimental-features#asynccontext" icon="i-lucide-star"}
查看 `asyncContext` 实验性功能，以便在异步函数中使用 Nuxt 组合式函数。
::

::read-more{to="https://github.com/nuxt/nuxt/issues/14269#issuecomment-1397352832" target="_blank"}
请参考此 GitHub 评论中的完整说明。
::

**破坏代码的示例：**

```ts twoslash [composables/example.ts]
// trying to access runtime config outside a composable
const config = useRuntimeConfig()

export const useMyComposable = () => {
  // accessing runtime config here
}
```

**正常使用的代码示例：**

```ts twoslash [composables/example.ts]
export const useMyComposable = () => {
  // Because your composable is called in the right place in the lifecycle,
  // useRuntimeConfig will work here
  const config = useRuntimeConfig()

  // ...
}
```

## 基于目录的自动导入

Nuxt 会直接自动导入在定义目录中创建的文件：

- `app/components/` 用于 [Vue 组件](/docs/directory-structure/app/components)。
- `app/composables/` 用于 [Vue 组合式函数](/docs/directory-structure/app/组合式函数)。
- `app/utils/` 用于辅助函数和其他工具。

:link-example{to="/docs/examples/features/auto-imports"}

::warning
**自动导入的 `ref` 和 `computed` 不会在组件 `<template>` 中被解包。** :br
这是由于 Vue 处理非顶级级别的 ref 的方式导致的。你可以从 [Vue 文档](https://vuejs.org/guide/essentials/reactivity-fundamentals#caveat-when-unwrapping-in-templates)中了解更多相关信息。
::

### 显式导入

Nuxt 通过 `#imports` 别名暴露所有自动导入，如果需要，可以使用该别名进行显式导入：

<!-- TODO:twoslash: Twoslash does not support tsconfig paths yet -->

```vue
<script setup lang="ts">
import { computed, ref } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### 禁用自动导入

如果你想禁用组合式函数和工具的自动导入，可以在 `nuxt.config` 文件中将 `imports.autoImport` 设置为 `false`。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false,
  },
})
```

这将完全禁用自动导入，但仍然可以从 `#imports` 进行 [显式导入](/docs/guide/concepts/auto-imports#explicit-imports)。

### 部分禁用自动导入

如果你希望框架特定的函数如 `ref` 保持自动导入，但想禁用自己代码的自动导入（例如自定义组合式函数），可以在 `nuxt.config.ts` 文件中将 `imports.scan` 选项设置为 `false`。

```ts
export default defineNuxtConfig({
  imports: {
    scan: false,
  },
})
```

采用此配置后：
- 如 `ref`、`computed` 或 `watch` 这样的框架函数仍然可以正常工作，无需手动导入。
- 自定义代码，例如组合式函数，则需要在文件中手动导入。

::warning
**注意：** 此设置存在某些限制：
- 如果你使用层结构来组织项目，则需要显式从每个层导入组合式函数，而不是依赖自动导入。
- 这会破坏层系统的覆盖功能。如果你设置 `imports.scan: false`，请确保理解此副作用并相应调整你的架构。
::

## 自动导入的组件

Nuxt 还会自动从 `~/components` 目录导入组件，尽管此设置与组合式函数和实用函数的自动导入是分开配置的。

:read-more{to="/docs/directory-structure/app/components"}

要禁用从自身 `~/components` 目录自动导入组件，可以将 `components.dirs` 设置为空数组（但请注意，这不会影响由模块添加的组件）。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: {
    dirs: [],
  },
})
```

## 从第三方包自动导入

Nuxt 还允许从第三方包自动导入。

::tip
如果你使用该包的 Nuxt 模块，很可能该模块已经为该包配置了自动导入。
::

例如，你可以像这样启用从 `vue-i18n` 包导入的 `useI18n` 组合式函数的自动导入：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    presets: [
      {
        from: 'vue-i18n',
        imports: ['useI18n'],
      },
    ],
  },
})
```
