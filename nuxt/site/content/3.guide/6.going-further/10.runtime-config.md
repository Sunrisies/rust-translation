## 暴露方式

若要将配置和环境变量暴露给应用程序的其他部分，您需要在 [`nuxt.config`](/docs/directory-structure/nuxt-config) 文件中定义运行时配置，并使用 [`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig-1) 选项。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // The private keys which are only available within server-side
    apiSecret: '123',
    // Keys within public, will be also exposed to the client-side
    public: {
      apiBase: '/api',
    },
  },
})
```

当将 `apiBase` 添加到 `runtimeConfig.public` 时，Nuxt 会将其添加到每个页面负载中。我们可以在服务器和浏览器中通用地访问 `apiBase`。

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

::tip
在 Vue 模板中，通过 `$config.public` 可以访问公共运行时配置。
::

### 应用程序密钥

以 `app` 开头的运行时配置键为 Nuxt 保留（当前为 `runtimeConfig.app` 和 `runtimeConfig.appSecret）。不要使用这些键来存放您自己的值。

Nuxt 提供私有的 `runtimeConfig.appSecret` 作为应用程序的根密钥。模块和服务器功能通过 [`deriveSecret`](/docs/guide/going-further/server-imports#deriving-secrets) 从它派生自己的密钥，[会话辅助函数](/docs/guide/going-further/server-imports#sessions) 默认使用其中一个。该值默认为空字符串，仅在服务器上可用，您可以通过 `NUXT_APP_SECRET` 设置它，而无需在 `nuxt.config` 中声明该键。

生成一个至少包含 32 个随机字节的密钥：

```bash [Terminal]
openssl rand -base64 32
```

::important
为每个环境使用不同的值，但需确保其在部署和该环境中的服务器实例之间保持稳定。更改值会使依赖它的任何会话或签名失效。
::

Nitro 解析环境覆盖设置，因此仅由数字组成的密钥或看起来像 JSON 的密钥会被转换为数字、布尔值或对象，而非字符串。请将此类值用引号括起来（`NUXT_APP_SECRET='"12345..."'`），或直接在 `nuxt.config` 中设置 `runtimeConfig.appSecret`。

在开发过程中，Nuxt 会生成随机密钥，并在 `appSecret` 未设置时将其存储在 `.nuxt/app-secret` 中，因此依赖它的功能无需任何配置即可正常工作。已配置的值始终按原样使用。首次使用派生密钥时，Nuxt 会记录警告信息。构建过程从不生成此类密钥：在您部署的每个环境中设置 `NUXT_APP_SECRET`。

除非模块或服务器功能使用 `NUXT_APP_SECRET`，否则 Nuxt 不要求使用该键。

### 序列化

你的运行时配置在被传递给 Nitro 之前会被序列化。这意味着任何无法被序列化再反序列化的内容（如函数、Set、Map等）都不应被设置到 `nuxt.config` 中。

你不必通过 `nuxt.config` 将不可序列化对象或函数传入应用程序，可以将此代码放在 Nuxt 或 Nitro 插件或中间件中。

### 环境变量

提供配置的最常见方式是通过使用环境变量。

::note
Nuxt CLI 在开发、构建和生成过程中内置支持读取 `.env` 文件。但是当你运行已构建的服务器时，**`.env` 文件将不会被读取**。
:read-more{to="/docs/directory-structure/env"}
::

运行时配置值会在运行时**自动被匹配的环境变量替换**。

有两个关键要求：

1. 自定义运行时配置变量必须在 `nuxt.config` 中定义。这可以确保任意环境变量不会暴露到应用程序代码中。

1. 只有特定命名的环境变量才能覆盖运行时配置属性。即以 `NUXT_` 开头的大写环境变量，使用 `_` 分隔键并改变大小写。

::warning
将 `runtimeConfig` 值的默认值设置为*不同名称的环境变量*（例如将 `myVar` 设置为 `process.env.OTHER_VARIABLE`）仅在构建时有效，在运行时会失效。
建议使用与 `runtimeConfig` 对象结构匹配的环境变量。
::

::warning
环境变量值会使用 [`destr`](https://github.com/unjs/destr) 自动转换为其 JavaScript 类型。例如，`NUXT_MY_VAR=4848e0` 会转换为数字 `4848`。若希望值为字符串，环境变量值本身必须包含双引号：在 `.env` 文件中，请写 `NUXT_MY_VAR='"4848e0"'`；在直接设置变量时（在 shell、Dockerfile 或托管仪表板中），确保引号是值的一部分且不会被 shell 去除（例如 `NUXT_MY_VAR='"4848e0"' node .output/server/index.mjs`）。
::

::tip{icon="i-lucide-video" to="https://youtu.be/_FYV5WfiWvs" target="_blank"}
观看 Alexander Lichter 的视频，了解开发者使用运行时配置时常见的错误。
::

#### 示例

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // can be overridden by NUXT_API_SECRET environment variable
    public: {
      apiBase: '', // can be overridden by NUXT_PUBLIC_API_BASE environment variable
    },
  },
})
```

## 读取

### Vue 应用

在 Nuxt 应用的 Vue 部分中，你需要调用 [`useRuntimeConfig()`](/docs/api/组合式函数/use-runtime-config) 来访问运行时配置。

::important
客户端端和服务器端的行为有所不同：

- 在客户端端，只有 `runtimeConfig.public` 和 `runtimeConfig.app`（Nuxt 内部使用）中的键是可用的，且该对象既可写入也可响应变化。

- 在服务器端，整个运行时配置都可用，但设置为只读以避免上下文共享。
::

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

console.log('Runtime config:', config)
if (import.meta.server) {
  console.log('API secret:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>Check developer console!</div>
  </div>
</template>
```

::caution
**安全提示：** 注意不要通过渲染或传递给 `useState` 来将运行时配置键暴露给客户端端。
::

### 插件

如果您希望在任何（自定义）插件中使用运行时配置，可以在 `defineNuxtPlugin` 函数内部使用 [`useRuntimeConfig()`](/docs/api/组合式函数/use-runtime-config)。

```ts [app/plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API base URL:', config.public.apiBase)
})
```

### 服务器路由

您也可以使用 `useRuntimeConfig` 在服务器路由中访问运行时配置。

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig(event)
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`,
    },
  })
  return result
})
```

::note
将 `event` 作为参数传递给 `useRuntimeConfig` 是可选的，但建议对于服务器路由，通过[环境变量](/docs/guide/going-further/runtime-config#environment-variables)在运行时传递参数，以便覆盖运行时配置。
::

## 为运行时配置添加类型注解

Nuxt 尝试使用 [unjs/untyped](https://github.com/unjs/untyped) 从提供的运行时配置自动生成 TypeScript 接口。

但您也可以手动为运行时配置添加类型注解：

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface RuntimeConfig {
    apiSecret: string
  }
  interface PublicRuntimeConfig {
    apiBase: string
  }
}
// It is always important to ensure you import/export something when augmenting a type
export {}
```

::note
`nuxt/schema` 作为便利提供，方便最终用户访问其项目中使用的 Nuxt 版本 schema。模块作者应修改为扩展 `@nuxt/schema`。
::
