---
title: 功能特性
description: 启用或禁用可选的 Nuxt 功能，以解锁新的可能性。
---

Nuxt 的一些功能可以按需选择启用或禁用，以满足您的需求。

## `features`

### devLogs

在开发过程中将服务器日志流式传输给客户端。这些日志可以在 `dev:ssr-logs` 钩子中处理。

默认情况下，在开发模式下（测试模式未激活时）此功能处于启用状态。

如果设置为 `silent`，日志将不会显示在浏览器控制台中。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    devLogs: true,
  },
})
```

### inlineStyles

在渲染 HTML 时内联样式。目前仅在使用 Vite 时可用。

您还可以传递一个函数，该函数接收 Vue 组件的路径，并返回一个布尔值，指示是否内联该组件的样式。

默认值为 `(id) => id.includes('.vue')`。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    inlineStyles: false, // or a function to determine inlining
  },
})
```

### noScripts

关闭 Nuxt 脚本和 JavaScript 资源提示的渲染，使页面以纯 HTML 和 CSS 形式发布。

可能的值：

- `false`（默认）：脚本正常渲染。
- `'production'`（或 `true`，归一化为 `'production'`）：仅在生产构建中省略脚本，因此热模块替换和其他开发功能在 `nuxt dev` 中仍然有效。
- `'all'`：在开发和生产环境中都省略脚本。

未包含脚本的页面在全页加载时进行导航。为了保持导航速度，Nuxt 会在这些页面上发出 [推测规则](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API) 标签，使支持该标签的浏览器在用户点击链接之前预取和预渲染目标。该标签是声明性 JSON 格式，不执行任何 JavaScript 代码。这些规则仅适用于您的页面路由（安全通过 `GET` 请求），而不是所有相同源链接，因此指向服务器路由（如 `/logout`）的链接永远不会被推测获取。通用页面（例如 `pages/[...slug].vue`）匹配所有路径，这又使得所有相同源链接都受到影响。

客户端导航到受 `noScripts` 规则覆盖的路由时，会触发完整的文档加载，因此该路由实际上在没有脚本的情况下提供，而不是由客户端路由器渲染。在构建时已知其路由受此类规则覆盖的页面也完全被排除在客户端包之外。

包含脚本的页面会发出自己的推测规则标签，该标签适用于 `noScripts` 路由模式，因此浏览器可以在全页导航之前预取和预渲染这些目标。当视图过渡功能启用时，这些页面还会选择声明性跨文档视图过渡来动画化导航过程。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    noScripts: 'production', // or 'all' | false
  },
})
```

您还可以通过 `noScripts` [路由规则](/docs/guide/concepts/rendering#hybrid-rendering)禁用每条路由的脚本，该规则在所有模式下均适用：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { noScripts: true },
  },
})
```

当 `noScripts` 应用于渲染页面时，以下内容将从 HTML 中省略：

- Nuxt 入口 `<script>` 标签
- 入口块的 import map
- 内联有效载荷 `<script>`（以及当有效载荷提取被启用时的有效载荷预加载链接）
- JavaScript 资源提示（`preload` 和 `prefetch` 链接用于 JS 块）

CSS 不受影响：样式表链接和内联样式仍然会被渲染，因此页面外观相同。只是页面永远不会进行 hydration 操作，这意味着页面上的所有内容都不具有交互性。

需要注意的一些交互行为：

- 使用 `noScripts` 路由规则的路由始终通过缓冲（非流式）渲染器进行渲染。
- 仅渲染静态 HTML 的 [服务器组件](/docs/guide/concepts/server-components)可以正常工作，但使用 `nuxt-client` 进行 hydration 的组件和交互式岛屿插槽依赖于内联脚本来重新定位传送内容，因此它们在 `noScripts` 路由下不会具有交互性。当 `features.noScripts` 在全局设置且组件岛屿处于活动状态时，Nuxt 也会出于此原因退回到缓冲渲染。

::read-more{to="/docs/guide/recipes/mostly-static-sites"}
请参阅关于将 `noScripts` 与预渲染、岛屿和延迟 hydration 结合使用的静态站点指南。
::

## `future`

还有一个 `future` 命名空间，用于早期启用新功能，这些功能将在框架的将来版本（可能是主要版本）中成为默认设置。

### compatibilityVersion

这允许您早期访问 Nuxt 功能或标志。

将 `compatibilityVersion` 设置为 `5` 会更改整个 Nuxt 配置的默认设置，以启用 Nuxt v5 的行为，包括启用 [Vite Environment API](/docs/guide/going-further/experimental-features#viteenvironmentapi)。

```ts
export default defineNuxtConfig({
  future: {
    compatibilityVersion: 5,
  },
})
```

::read-more{to="/docs/getting-started/upgrade#testing-nuxt-5"}
了解更多关于测试 Nuxt 5 的信息。
::

### multiApp

这允许您早期访问实验性的多应用支持。您可以关注 [跟踪器问题 #21635](https://github.com/nuxt/nuxt/issues/21635) 以了解 Nuxt 中多应用支持的进展。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    multiApp: true,
  },
})
```

### typescriptBundlerResolution

这启用了 TypeScript 的‘Bundler’模块解析模式，这是像 Nuxt 和 [Vite](https://vite.dev/guide/performance#reduce-resolve-operations)这样的框架推荐的设置。

当使用 `exports` 时，它能提升现代库的类型支持。

请参阅 [原始的 TypeScript 提交请求](https://github.com/microsoft/TypeScript/pull/51669)。

你可以将其设置为 false，以使用传统的 'Node' 模式，这是 TypeScript 的默认设置。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    typescriptBundlerResolution: false,
  },
})
```
