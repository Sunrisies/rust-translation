以下是模块作者常用的几种模式。

## 修改 Nuxt 配置

模块可以读取并修改 Nuxt 配置。以下是一个启用实验性功能的模块示例。

```js
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // We create the `experimental` object if it doesn't exist yet
    nuxt.options.experimental ||= {}
    nuxt.options.experimental.componentIslands = true
  },
})
```

当需要处理更复杂的配置修改时，应考虑使用 [defu](https://github.com/unjs/defu)。

## 将选项暴露给运行时

由于模块不属于应用运行时，其选项也不属于运行时。然而，在许多情况下，你可能需要在运行时代码中访问这些模块选项。我们建议使用 Nuxt 的 [`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig-1) 来暴露所需的配置。

<!-- TODO: Update after #18466 (or equivalent) -->

```js
import { defineNuxtModule } from '@nuxt/kit'
import { defu } from 'defu'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.options.runtimeConfig.public.myModule = defu(nuxt.options.runtimeConfig.public.myModule, {
      foo: options.foo,
    })
  },
})
```

请注意，我们使用 [`defu`](https://github.com/unjs/defu) 来扩展用户提供的公共运行时配置，而不是覆盖它。

然后你可以在插件、组件或应用中访问你的模块选项，就像访问其他运行时配置一样：

```js
import { useRuntimeConfig } from '@nuxt/kit'

const options = useRuntimeConfig().public.myModule
```

::warning
注意不要在公共运行时配置中暴露任何敏感的模块配置，例如私有 API 密钥，因为这些信息会进入公共包中。
::

## 添加插件

插件是模块添加运行时逻辑的常见方式。你可以使用 `addPlugin` 工具从模块中注册它们。

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // Create resolver to resolve relative paths
    const resolver = createResolver(import.meta.url)

    addPlugin(resolver.resolve('./runtime/plugin'))
  },
})
```

:read-more{to="/docs/guide/going-further/kit"}

## 添加组件

如果你的模块需要提供 Vue 组件，可以使用 `addComponent` 工具将它们作为 Nuxt 解析的自动导入添加。

```ts twoslash
import { addComponent, createResolver, defineNuxtModule, useRuntimeConfig } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    // From the runtime directory
    addComponent({
      name: 'MySuperComponent', // name of the component to be used in vue templates
      export: 'MySuperComponent', // (optional) if the component is a named (rather than default) export
      filePath: resolver.resolve('runtime/app/components/MySuperComponent.vue'),
    })

    // From a library
    addComponent({
      name: 'MyAwesomeComponent', // name of the component to be used in vue templates
      export: 'MyAwesomeComponent', // (optional) if the component is a named (rather than default) export
      filePath: '@vue/awesome-components',
    })
  },
})
```

或者，你可以使用 `addComponentsDir` 添加整个目录。

```ts
import { addComponentsDir, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addComponentsDir({
      path: resolver.resolve('runtime/app/components'),
    })
  },
})
```

::tip{icon="i-lucide-lightbulb"}
强烈建议对导出项加前缀，以避免与用户代码或其他模块冲突。

:read-more{to="/docs/guide/modules/best-practices#prefix-your-exports"}
::

::note
请注意，所有通常位于 `app/` 文件夹中的组件、页面、组合式函数和其他文件都需要放在 `runtime/app/` 中。这样就能正确进行类型检查。
::

## 添加组合式函数

如果你的模块需要提供组合式函数，可以使用 `addImports` 工具将它们作为 Nuxt 解析的自动导入添加。

```ts
import { addImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImports({
      name: 'useComposable', // name of the composable to be used
      as: 'useMyComposable', // optional alias that will be available for the consuming apps
      from: resolver.resolve('runtime/app/composables/useComposable'), // path of composable
    })
  },
})
```

多个条目可以作为一个数组传递：

```ts
import { addImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImports([
      { name: 'useFirstComposable', from: resolver.resolve('runtime/composables/useFirstComposable') },
      { name: 'useSecondComposable', from: resolver.resolve('runtime/composables/useSecondComposable') },
    ])
  },
})
```

或者，你可以使用 `addImportsDir` 添加整个目录。

```ts
import { addImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImportsDir(resolver.resolve('runtime/composables'))
  },
})
```

::tip{icon="i-lucide-lightbulb"}
强烈建议对导出项添加前缀，以避免与用户代码或其他模块产生冲突。

:read-more{to="/docs/guide/modules/best-practices#prefix-your-exports"}
::

::note
请注意，所有通常放置于 `app/` 文件夹中的组件、页面、组合式函数及其他文件必须位于 `runtime/app/` 中。这样就能正确进行类型检查。
::

### 添加带键的函数

有时，您需要在服务器和客户端之间保持状态一致性。例如 Nuxt 内置的 `useState` 或 `useAsyncData` 组合式函数。Nuxt 提供了一种注册此类函数的方式，以实现自动键注入。

当函数被注册后，如果调用该函数的参数少于指定数量，Nuxt 编译器会自动注入一个唯一的键作为额外参数。这个键在服务器端渲染和客户端 hydration 过程中保持稳定。

::tip
注入的键是从文件路径和调用位置生成的哈希值。
::

使用 `keyedComposables` 选项来注册您的函数：

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.options.optimization.keyedComposables.push({
      name: 'useMyState',
      source: resolver.resolve('./runtime/composables/state'),
      argumentLength: 2,
    })
  },
})
```

`keyedComposables` 配置接受一个包含以下属性的对象数组：

| 属性         | 类型     | 描述                                                                                                                |
|------------------|----------|----------------------------------------------------------------------------------------------------------------------------|
| `name`           | `string` | 函数名称。对于默认导出，使用 `'default'`（可调用名称将以驼峰格式从文件名派生）。
| `source`         | `string` | 定义该函数的文件解析路径。支持 Nuxt 别名（`~`、`@` 等）。
| `argumentLength` | `number` | 函数允许的最大参数数量。当调用时参数少于此数量，将注入一个唯一的键。

例如，当 `argumentLength: 2` 时：

```ts
useMyState() // useMyState('$HJiaryoL2y')
useMyState('myKey') // useMyState('myKey', '$HJiaryoL2y')
useMyState('a', 'b') // not transformed (already has 2 arguments)
```

::warning
键注入插件会验证每个函数调用的确切解析导入源。它不遵循 barrel 导出方式。函数必须从 `source` 属性中指定的确切源文件导出。

```ts
// ✅ Works - direct import matches the configured source
import { useMyState } from 'my-module/runtime/composables/state'

// ❌ Won't work - re-exported through a barrel file
import { useMyState } from 'my-module/runtime/composables' // index.ts barrel
```
::

::warning
函数调用必须是静态可分析的。编译器无法为动态或间接函数调用注入键。

```ts
import { useMyState } from 'my-module/runtime/composables/state'
import * as composables from 'my-module/runtime/composables/state'

// ✅ Works - direct function call
useMyState()

// ✅ Works - called on namespace import
composables.useMyState()

// ❌ Won't work - dynamic property access
const name = 'useMyState'
composables[name]()

// ❌ Won't work - reassigned to a variable
const myFn = useMyState
myFn()

// ❌ Won't work - passed as a callback
someFunction(useMyState)

// ❌ Won't work - destructured with renaming in a nested scope
function setup () {
  const { useMyState: localState } = composables
  localState() // not transformed
}

// ...
```
::

## 添加路由中间件

```ts
import { addRouteMiddleware, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    // example to add a global route middleware
    addRouteMiddleware({
      global: true,
      name: 'name-of-your-middleware',
      path: resolver.resolve('./runtime/middleware/name-of-your-middleware'),
    })
  },
})
```

## 添加服务器路由

```ts
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addServerHandler({
      route: '/api/_my-module/hello',
      handler: resolver.resolve('./runtime/server/api/hello/index.get'),
    })
  },
})
```

您也可以添加动态服务器路由：

```ts
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addServerHandler({
      route: '/api/_my-module/hello/:name',
      handler: resolver.resolve('./runtime/server/api/hello/[name].get'),
    })

    // Or using a catch all route
    addServerHandler({
      route: '/api/_my-module/files/**:path',
      handler: resolver.resolve('./runtime/server/api/files/[...path].get'),
    })
  },
})
```

::tip{icon="i-lucide-lightbulb"}
强烈建议对服务器路由添加前缀，以避免与用户定义的路由产生冲突。常见的路径如 `/api/auth`、`/api/login` 或 `/api/user` 可能已被应用程序使用。

:read-more{to="/docs/guide/modules/best-practices#prefix-your-exports"}
::

## 添加其他资源

如果您的模块需要提供其他类型的资源，也可以进行注入。以下是一个通过 Nuxt 的 `css` 数组注入样式表的简单示例模块。

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.options.css.push(resolver.resolve('./runtime/style.css'))
  },
})
```

还有一个更高级的例子，通过 [Nitro](/docs/guide/concepts/server-engine) 的 `publicAssets` 选项来暴露一个资源文件夹：

```js
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.hook('nitro:config', (nitroConfig) => {
      nitroConfig.publicAssets ||= []
      nitroConfig.publicAssets.push({
        dir: resolver.resolve('./runtime/public'),
        maxAge: 60 * 60 * 24 * 365, // 1 year
      })
    })
  },
})
```

## 使用其他模块

如果您的模块依赖于其他模块，可以使用 `moduleDependencies` 选项来指定它们。

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
  },
  moduleDependencies: {
    '@nuxtjs/tailwindcss': {},
  },
})
```
