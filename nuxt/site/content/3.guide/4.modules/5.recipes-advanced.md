以下是一些编写模块的高级模式，包括 hooks、模板和类型增强。

## 使用生命周期 Hooks

[生命周期 hooks](/docs/guide/going-further/hooks) 允许你扩展 Nuxt 的几乎每个方面。模块可以通过编程方式或在其定义中的 `hooks` 映射来绑定这些 hooks。

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  // Hook to the `app:error` hook through the `hooks` map
  hooks: {
    'app:error': (err) => {
      console.info(`This error happened: ${err}`)
    },
  },
  setup (options, nuxt) {
    // Programmatically hook to the `pages:extend` hook
    nuxt.hook('pages:extend', (pages) => {
      console.info(`Discovered ${pages.length} pages`)
    })
  },
})
```

::note
**模块清理**
:br
:br
如果您的模块打开、处理或启动了观察者，当 Nuxt 生命周期结束时，您应该将其关闭。为此提供了 `close` hook。

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.hook('close', async (nuxt) => {
      // Your custom code here
    })
  },
})
```

### 创建自定义 Hooks

模块还可以定义和调用自己的 hooks，这是使模块可扩展的强大模式。

如果您希望其他模块能够订阅您的模块 hooks，应在 `modules:done` hook 中调用它们。这确保所有其他模块都有机会在各自的 `setup` 函数中设置并注册其监听器到您的 hook。

```ts
// my-module/module.ts
import { defineNuxtModule } from '@nuxt/kit'

export interface ModuleHooks {
  'my-module:custom-hook': (payload: { foo: string }) => void
}

export default defineNuxtModule({
  setup (options, nuxt) {
    // Call your hook in `modules:done`
    nuxt.hook('modules:done', async () => {
      const payload = { foo: 'bar' }
      await nuxt.callHook('my-module:custom-hook', payload)
    })
  },
})
```

## 添加虚拟文件

如果您需要添加一个可以导入到用户应用中的虚拟文件，可以使用 `addTemplate` 工具。

```ts
import { addTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // The file is added to Nuxt's internal virtual file system and can be imported from '#build/my-module-feature.mjs'
    addTemplate({
      filename: 'my-module-feature.mjs',
      dependsOn: [],
      getContents: () => 'export const myModuleFeature = () => "hello world !"',
    })
  },
})
```

示例中使用 `dependsOn: []` 在开发过程中编辑现有文件时跳过重新生成。仅当输出不依赖于被观察文件内容时使用此方式。对于读取这些内容的模板，应声明命名依赖或谓词以避免陈旧输出。

:read-more{to="/docs/api/kit/templates#skipping-regeneration-in-development"}

对于服务器环境，您应该使用 `addServerTemplate` 工具。

```ts
import { addServerTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // The file is added to Nitro's virtual file system and can be imported in the server code from 'my-server-module.mjs'
    addServerTemplate({
      filename: 'my-server-module.mjs',
      getContents: () => 'export const myServerModule = () => "hello world !"',
    })
  },
})
```

## 更新虚拟文件

如果您需要更新模板/虚拟文件，可以像这样利用 `updateTemplates` 工具：

```ts
nuxt.hook('builder:watch', (event, path) => {
  if (path.includes('my-module-feature.config')) {
    // This will reload the template that you registered
    updateTemplates({ filter: t => t.filename === 'my-module-feature.mjs' })
  }
})
```

## 添加类型声明

您可能还希望向用户项目添加类型声明（例如，扩展 Nuxt 接口或提供自定义全局类型）。为此，Nuxt 提供了 `addTypeTemplate` 工具，该工具既
or provide a global type of your own). For this, Nuxt provides the `addTypeTemplate` utility that both
将模板写入磁盘，并在生成的 `nuxt.d.ts` 文件中添加对其的引用。

如果您的模块需要扩展 Nuxt 处理的类型，可以使用 `addTypeTemplate` 来执行此操作：

```js
import { addTemplate, addTypeTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    addTypeTemplate({
      filename: 'types/my-module.d.ts',
      getContents: () => `// Generated by my-module
        interface MyModuleNitroRules {
          myModule?: { foo: 'bar' }
        }
        declare module 'nitropack/types' {
          interface NitroRouteRules extends MyModuleNitroRules {}
          interface NitroRouteConfig extends MyModuleNitroRules {}
        }
        export {}`,
    })
  },
})
```

如果您需要更细粒度的控制，可以使用 `prepare:types` hook 注册一个回调函数来注入您的类型。

```ts
const template = addTemplate({ /* template options */ })
nuxt.hook('prepare:types', ({ references }) => {
  references.push({ path: template.dst })
})
```

## 扩展 TypeScript 配置

您可以通过模块的方式从您的项目中扩展 TypeScript 配置，有多种方法。

最简单的方法是直接像这样修改 Nuxt 配置：

<!-- @case-police-ignore tsConfig -->
```ts
// extend tsconfig.app.json
nuxt.options.typescript.tsConfig.include ??= []
nuxt.options.typescript.tsConfig.include.push(resolve('./augments.d.ts'))

// extend tsconfig.shared.json
nuxt.options.typescript.sharedTsConfig.include ??= []
nuxt.options.typescript.sharedTsConfig.include.push(resolve('./augments.d.ts'))

// extend tsconfig.node.json
nuxt.options.typescript.nodeTsConfig.include ??= []
nuxt.options.typescript.nodeTsConfig.include.push(resolve('./augments.d.ts'))

// extend tsconfig.server.json
nuxt.options.typescript.serverTsConfig.include ??= []
nuxt.options.typescript.serverTsConfig.include.push(resolve('./augments.d.ts'))
```

或者，您可以使用 `prepare:types` 和 `nitro:prepare:types` 钩子来扩展特定类型上下文的 TypeScript 引用，或者像上面的示例那样修改 TypeScript 配置。

```ts
nuxt.hook('prepare:types', ({ references, sharedReferences, nodeReferences }) => {
  // extend app context
  references.push({ path: resolve('./augments.d.ts') })
  // extend shared context
  sharedReferences.push({ path: resolve('./augments.d.ts') })
  // extend node context
  nodeReferences.push({ path: resolve('./augments.d.ts') })
})

nuxt.hook('nitro:prepare:types', ({ references }) => {
  // extend server context
  references.push({ path: resolve('./augments.d.ts') })
})
```

::note
TypeScript 引用会将文件添加到类型上下文中[而不受 `tsconfig.json` 中 `exclude` 选项的影响](https://www.typescriptlang.org/tsconfig/#exclude)。
::

## 增强类型

Nuxt 会自动将您的模块目录包含到相应的类型上下文中。要增强模块中的类型，您只需根据增强后的类型上下文将类型声明文件放置在相应的目录中即可。或者，您也可以[扩展 TypeScript 配置](#extend-typescript-config)以从任意位置进行增强。

- `my-module/runtime/` - 应用类型上下文（`runtime/server` 目录除外）
- `my-module/runtime/server/` - 服务器类型上下文
- `my-module/` - Node 类型上下文（`runtime/` 和 `runtime/server` 目录除外）

```bash [Directory Structure]
-| my-module/   # node type context
---| runtime/   # app type context
------| augments.app.d.ts
------| server/ # server type context
---------| augments.server.d.ts
---| module.ts
---| augments.node.d.ts
```

### 已知限制

#### 在应用上下文中对服务器路由进行类型检查

除了使用 `tsconfig.server.json` 之外，服务器路由还会通过 `tsconfig.app.json` 进行类型检查。

这是必需的，因为 Nuxt 会推断服务器端端的返回类型，以便在 [`$fetch`](/docs/api/utils/dollarfetch) 和 [`useFetch`](/docs/api/组合式函数/use-fetch) 中提供响应类型。

::warning
当在路由文件中使用**仅服务器可见的类型**时，这可能会导致问题。例如，如果某个模块使用 [`addServerTemplate`](/docs/api/kit/templates#addservertemplate) 创建仅服务器可见的虚拟文件，而您在 `tsconfig.server.json` 中声明了该类型的类型，那么这些类型声明将仅在服务器上下文中可用。当应用上下文对服务器路由进行类型检查时，它将无法识别这些仅服务器可见的类型，并会报告错误。为了解决这个问题，您需要在应用上下文中也声明此类类型。
::
