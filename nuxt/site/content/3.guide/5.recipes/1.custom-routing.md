## 添加自定义路由

在 Nuxt 中，路由由 [app/pages 目录](/docs/directory-structure/app/pages) 中的文件结构定义。然而，由于其底层使用 [vue-router](https://router.vuejs.org)，Nuxt 提供了多种方式在项目中添加自定义路由。

### 路由器配置

通过使用 [router options](/docs/guide/recipes/custom-routing#router-options)，你可以选择使用接受扫描出的路由并返回自定义路由的函数来覆盖或扩展路由。

如果返回值为 `null` 或 `undefined`，Nuxt 将回退到默认路由（适用于修改输入数组）。

```ts [router.options.ts]
import type { RouterConfig } from '@nuxt/schema'

export default {
  // https://router.vuejs.org/api/interfaces/routeroptions#routes
  routes: _routes => [
    {
      name: 'home',
      path: '/',
      component: () => import('~/pages/home.vue'),
    },
  ],
} satisfies RouterConfig
```

::note
Nuxt 不会使用你从 `routes` 函数返回的新的路由，除非你在提供的组件中定义 `definePageMeta` 来添加元数据。如果你希望这样操作，应该使用 `pages:extend` 钩子，该钩子在 [构建时调用](/docs/api/advanced/hooks#nuxt-hooks-build-time)。
::

### Pages Hook

你可以使用 `pages:extend` nuxt hook 从扫描出的路由中添加、更改或移除页面。

例如，为了防止为任何 `.ts` 文件创建路由：

```ts [nuxt.config.ts]
import type { NuxtPage } from '@nuxt/schema'

export default defineNuxtConfig({
  hooks: {
    'pages:extend' (pages) {
      // add a route
      pages.push({
        name: 'profile',
        path: '/profile',
        file: '~/extra-pages/profile.vue',
      })

      // remove routes
      function removePagesMatching (pattern: RegExp, pages: NuxtPage[] = []) {
        const pagesToRemove: NuxtPage[] = []
        for (const page of pages) {
          if (page.file && pattern.test(page.file)) {
            pagesToRemove.push(page)
          } else {
            removePagesMatching(pattern, page.children)
          }
        }
        for (const page of pagesToRemove) {
          pages.splice(pages.indexOf(page), 1)
        }
      }
      removePagesMatching(/\.ts$/, pages)
    },
  },
})
```

### Nuxt 模块

如果你计划添加与特定功能相关的整套页面，可以使用 [Nuxt 模块](/modules)。

[Nuxt 工具包](/docs/guide/going-further/kit)提供了几种 [添加路由的方式](/docs/api/kit/pages)：
- [`extendPages`](/docs/api/kit/pages#extendpages) (callback: pages => void)
- [`extendRouteRules`](/docs/api/kit/pages#extendrouterules) (route: string, rule: NitroRouteConfig, options: ExtendRouteRulesOptions)

## 路由器选项

除了自定义 [vue-router](https://router.vuejs.org/api/interfaces/routeroptions) 的选项外，Nuxt 还提供 [额外选项](/docs/api/nuxt-config#router)来进一步定制路由器。

### 使用 `router.options`

这是指定 [router options](/docs/api/nuxt-config#router) 的推荐方式。

```ts [app/router.options.ts]
import type { RouterConfig } from '@nuxt/schema'

export default {
} satisfies RouterConfig
```

可以通过在 `pages:routerOptions` 钩子内添加文件来添加更多的路由器选项文件。数组中的后续项会覆盖之前的项。

::callout
在此钩子中添加 router options 文件将启用基于页面的路由，除非设置了 `optional`，此时仅当已启用基于页面的路由时才会生效。
::

```ts [nuxt.config.ts]
import { createResolver } from '@nuxt/kit'

export default defineNuxtConfig({
  hooks: {
    'pages:routerOptions' ({ files }) {
      const resolver = createResolver(import.meta.url)
      // add a route
      files.push({
        path: resolver.resolve('./runtime/router-options'),
        optional: true,
      })
    },
  },
})
```

### 使用 `nuxt.config`

**注意：** 只有可序列化的 JSON [选项](/docs/api/nuxt-config#router)是可以配置的：

- `linkActiveClass`
- `linkExactActiveClass`
- `end`
- `sensitive`
- `strict`
- `hashMode`
- `scrollBehaviorType`

```ts [nuxt.config]
export default defineNuxtConfig({
  router: {
    options: {},
  },
})
```

::note
当设置 `future.compatibilityVersion: 5` 时，默认情况下路由区分大小写以匹配 Nitro 的行为。将 `router.options.sensitive` 设置为 `false` 可以禁用此功能。
::

#### 不区分大小写的路由规则

除非 `router.options.sensitive` 为 `true`，否则 Nuxt 会将请求路径和规则模式都转换为小写来匹配 [路由规则](/docs/guide/concepts/rendering#route-rules)。模式中的正则表达式约束保持不变，因此必须针对小写字母编写： `/products/:id([a-z0-9]+)` 匹配 `/Products/ABC1`。

如果约束条件匹配到大写字母但其小写形式不匹配，例如 `[A-Z]`、`\x41` 或 `(?:FOO)`，或者是一个排除其中一种情况的否定类，如 `[^a-z]`，则构建会失败。应使用 `[a-z]` 或 `[^a-zA-Z]` 代替。如果 `nuxt.config` 中的 `sensitive` 为 `true`，或 `app/router.options.ts` 中设置了该值，检查将在应用加载时执行，且除非 `sensitive` 为 `true`，否则应用会抛出错误。

### Hash Mode (SPA)

在 SPA 模式下，可以使用 `hashMode` [配置](/docs/api/nuxt-config#router)来启用哈希历史记录。在此模式下，路由器在实际 URL 之前使用哈希字符 (#) 进行内部传递。启用后，**URL 永远不会发送到服务器**，且**不支持 SSR**。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ssr: false,
  router: {
    options: {
      hashMode: true,
    },
  },
})
```

### Hash 链接的滚动行为

你可以选择性地自定义 hash 链接的滚动行为。当将 [配置](/docs/api/nuxt-config#router)设置为 `smooth`，并使用 hash 链接加载页面时（例如 `https://example.com/blog/my-article#comments`），你会看到浏览器平滑地滚动到该锚点。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  router: {
    options: {
      scrollBehaviorType: 'smooth',
    },
  },
})
```

#### 自定义历史记录（高级）

你可以使用一个接受基础 URL 并返回历史模式的函数来选择性地覆盖历史模式。如果该函数返回 `null` 或 `undefined`，Nuxt 将回退到默认的历史记录模式。

```ts [router.options.ts]
import type { RouterConfig } from '@nuxt/schema'
import { createMemoryHistory } from 'vue-router'

export default {
  // https://router.vuejs.org/api/interfaces/routeroptions
  history: base => import.meta.client ? createMemoryHistory(base) : null, /* default */
} satisfies RouterConfig
```
