## 引言

在本教程中，我们将使用 [Nuxt Auth Utils](https://github.com/Atinux/nuxt-auth-utils) 在全栈 Nuxt 应用中设置认证功能，该工具提供了管理客户端和服务器端会话数据的便捷工具。

该模块使用加密且密封的 Cookie 来存储会话数据，因此您无需设置数据库来存储会话数据。

## 安装 `nuxt-auth-utils`

使用 `nuxt` CLI 安装 `nuxt-auth-utils` 模块。

```bash [Terminal]
npx nuxt module add auth-utils
```

::callout
此命令将把 `nuxt-auth-utils` 作为依赖项安装，并将其添加到 `nuxt.config.ts` 的 `modules` 部分中。
::

## Cookie 加密密钥

由于 `nuxt-auth-utils` 使用密封 Cookie 存储会话数据，因此会话 Cookie 会使用 `NUXT_SESSION_PASSWORD` 环境变量中的密钥进行加密。

::note
如果未设置该变量，在开发模式运行时会自动添加到您的 `.env` 文件中。
::

```ini [.env]
NUXT_SESSION_PASSWORD=a-random-password-with-at-least-32-characters
```

::important
在部署之前，您需要在生产环境中添加此环境变量。
::

## 登录 API 路由

本教程中，我们将创建一个简单的 API 路由，根据静态数据进行用户登录。

让我们创建一个 `/api/login` API 路由，该路由将接收包含电子邮件和密码的 POST 请求。

```ts [server/api/login.post.ts]
import { z } from 'zod'

const bodySchema = z.object({
  email: z.email(),
  password: z.string().min(8),
})

export default defineEventHandler(async (event) => {
  const { email, password } = await readValidatedBody(event, bodySchema.parse)

  if (email === 'admin@admin.com' && password === 'iamtheadmin') {
    // set the user session in the cookie
    // this server util is auto-imported by the auth-utils module
    await setUserSession(event, {
      user: {
        name: 'John Doe',
      },
    })
    return {}
  }
  throw createError({
    status: 401,
    message: 'Bad credentials',
  })
})
```

::callout
请确保您在项目中安装 `zod` 依赖项（`npm i zod`）。
::

::tip{to="https://github.com/atinux/nuxt-auth-utils#server-utils"}
更多关于 `nuxt-auth-utils` 提供的 `setUserSession` 服务器辅助函数的信息请参考相关文档。
::

## 登录页面

该模块提供了一个 Vue 组合式函数，用于判断用户是否在应用程序中处于认证状态：

```vue
<script setup>
const { loggedIn, session, user, clear, fetch } = useUserSession()
</script>
```

让我们创建一个登录页面，包含一个表单，用于将登录数据提交到 `/api/login` 路由。

```vue [app/pages/login.vue]
<script setup lang="ts">
const { loggedIn, user, fetch: refreshSession } = useUserSession()
const credentials = reactive({
  email: '',
  password: '',
})
async function login () {
  try {
    await $fetch('/api/login', {
      method: 'POST',
      body: credentials,
    })

    // Refresh the session on client-side and redirect to the home page
    await refreshSession()
    await navigateTo('/')
  } catch {
    alert('Bad credentials')
  }
}
</script>

<template>
  <form @submit.prevent="login">
    <input
      v-model="credentials.email"
      type="email"
      placeholder="Email"
    >
    <input
      v-model="credentials.password"
      type="password"
      placeholder="Password"
    >
    <button type="submit">
      Login
    </button>
  </form>
</template>
```

## 保护 API 路由

保护服务器路由是确保数据安全的关键。客户端中间件对用户有帮助，但如果没有服务器端保护，数据仍可能被访问。对于包含敏感数据的任何路由进行保护至关重要，如果用户未登录，应返回 401 错误。

`auth-utils` 模块提供了 `requireUserSession` 实用函数，帮助确保用户已登录并拥有活跃的会话。

让我们创建一个 `/api/user/stats` 路由的示例，只有经过身份验证的用户才能访问该路由。

```ts [server/api/user/stats.get.ts]
export default defineEventHandler(async (event) => {
  // make sure the user is logged in
  // This will throw a 401 error if the request doesn't come from a valid user session
  const { user } = await requireUserSession(event)

  // TODO: Fetch some stats based on the user

  return {}
})
```

## 保护应用路由

我们的数据在服务器端路由保护下是安全的，但如果不采取其他措施，未经过身份验证的用户尝试访问 `/users` 页面时可能会得到一些异常数据。我们应该创建一个 [客户端侧中间件](/docs/directory-structure/app/中间件) 来在客户端保护该路由，并将用户重定向到登录页面。

`nuxt-auth-utils` 提供了一个方便的 `useUserSession` 组合式函数，我们将使用它来检查用户是否登录，如果未登录则将其重定向。

我们将在 `/middleware` 目录中创建中间件。与服务器端不同，客户端侧中间件不会自动应用于所有端点，我们需要指定希望其应用的位置。

```typescript [app/middleware/authenticated.ts]
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn } = useUserSession()

  // redirect the user to the login screen if they're not authenticated
  if (!loggedIn.value) {
    return navigateTo('/login')
  }
})
```

## 首页

现在我们已经有了用于保护路由的应用中间件，可以在显示经过身份验证用户信息的首页中使用它。如果用户未登录，他们将被重定向到登录页面。

我们将使用 [`definePageMeta`](/docs/api/utils/define-page-meta) 将中间件应用于我们想要保护的路由。

```vue [app/pages/index.vue]
<script setup lang="ts">
definePageMeta({
  middleware: ['authenticated'],
})

const { user, clear: clearSession } = useUserSession()

async function logout () {
  await clearSession()
  await navigateTo('/login')
}
</script>

<template>
  <div>
    <h1>Welcome {{ user.name }}</h1>
    <button @click="logout">
      Logout
    </button>
  </div>
</template>
```

我们还添加了一个退出按钮，以清除会话并将用户重定向到登录页面。

## 结论

我们成功地在 Nuxt 应用中设置了非常基础的用户认证和会话管理功能。我们也对服务器和客户端侧的敏感路由进行了保护，确保只有经过身份验证的用户才能访问它们。

作为下一步，你可以：
- 使用 [20多种支持的 OAuth 提供程序](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#supported-oauth-providers)添加认证功能。
- 添加数据库以存储用户信息，参见 [Nitro SQL 数据库](https://nitro.build/guide/database) 或 [NuxtHub SQL 数据库](https://hub.nuxt.com/docs/database)。
- 允许用户使用 [密码哈希](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#password-hashing)通过电子邮件和密码进行注册。
- 添加对 [WebAuthn / Passkeys](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#webauthn-passkey)的支持。

请查看开源 [atidone 仓库](https://github.com/atinux/atidone)，那里有一个完整的 Nuxt 应用示例，包含 OAuth 认证、数据库和 CRUD 操作。
