---
title: 大部分静态站点
description: 对于内容和营销网站，使用接近零的 JavaScript 来构建页面，同时保留交互功能。
---

默认情况下，Nuxt 会先服务器渲染页面，然后完成所有内容的加载。对于 95% 为静态文本和图片的页面，这种加载 JavaScript 主要是额外开销：它会延迟交互性，并与内容争夺带宽和 CPU 资源，这可能会降低移动页面速度等指标。

Nuxt 拥有多种机制可以在不需要时避免这些开销。以下方法将这些机制结合使用：

1. 在构建时**预渲染**内容路由。
2. 使用 `noScripts` 路由规则将这些路由上的脚本移除。
3. 对于需要服务器渲染但无需交互性的小部件，使用**服务器组件**。
4. 对于保留脚本的路由，采用**延迟加载**方式，仅在特定时候提供交互功能。

## 预渲染与移除脚本

对于完全没有客户端交互的路由，在 [`routeRules`](/docs/guide/concepts/rendering#hybrid-rendering) 中结合使用 `prerender` 和 `noScripts`：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { prerender: true, noScripts: true },
    '/about': { prerender: true, noScripts: true },
  },
})
```

这些路由在构建时会被渲染为纯 HTML，渲染后的页面会省略 Nuxt 入口脚本、导入映射、负载脚本以及 JS 资源提示。CSS 仍然包含在内。最终得到的页面几乎没有 JavaScript 开销。

::read-more{to="/docs/guide/going-further/features#noscripts"}
了解更多关于 `noScripts` 具体省略了什么内容，以及全局 `features.noScripts` 选项的信息。
::

::important
`noScripts` 页面不会进行加载。页面上没有任何交互功能：没有 `@click` 处理程序，没有 `<NuxtLink>` 预取（链接仍作为普通 `<a>` 标签工作），也没有离开页面的客户端导航。仅应在需要此功能时使用。
::

## 从无脚本路由到该路由的导航

由于 `noScripts` 页面没有客户端路由器，从某个有脚本的路由到该路由的每次导航都会触发全页面加载。Nuxt 会自动处理双向导航：

- 从有脚本的路由**导航**到 `noScripts` 路由（使用 `navigateTo`、`<NuxtLink>` 或 `router.push`），会触发文档加载，因此目标页面由服务器提供无脚本版本，而非由客户端路由器渲染。
- 由于这些路由在客户端永远不会被渲染，当覆盖它们的路由规则可以在构建时解析时，其页面组件会被从客户端包中移除。
- 无论是脚本注入页面还是无脚本页面，都会生成声明式 [推测规则](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API) 标签，因此支持浏览器的浏览器会在用户点击链接之前预加载和预渲染目标内容。此操作不会在页面本身执行任何 JavaScript，且这些规则仅适用于页面路由，因此指向如 `/logout` 这样的服务器路由的链接永远不会被推测加载。

当启用 [实验性视图过渡](/docs/getting-started/transitions#view-transitions-api-experimental) 后，这些页面还会支持跨文档视图过渡，因此全页导航动画会进行动画效果处理，而非瞬间切换：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    viewTransition: true,
  },
})
```

## 服务器渲染小部件的独立模块

静态页面的某些部分仍然适合作为具有实际逻辑的组件：渲染后的 Markdown 内容、语法高亮代码、CMS 内容。对于这些内容，应使用 [服务器组件](/docs/guide/concepts/server-components)。它们会在服务器上渲染，其依赖项不会进入客户端包中：

```bash [Directory Structure]
-| app/
---| components/
-----| HighlightedMarkdown.server.vue
```

```vue [app/pages/blog/[slug\\].vue]
<template>
  <article>
    <h1>{{ post.title }}</h1>
    <HighlightedMarkdown :markdown="post.body" />
  </article>
</template>
```

此类静态独立模块在 `noScripts` 路由下可以正常工作，因为其 HTML 在渲染时即被嵌入。

::warning
位于独立模块内的完全交互式小部件（标有 [`nuxt-client`](/docs/guide/concepts/server-components#selective-hydration-with-nuxt-client）的组件或交互式模块槽位）在 `noScripts` 路由下无法工作。在 hydration 之前，小的内联脚本会将模块移动位置；当脚本被禁用时，这种移动操作无法执行，因此没有内容被渲染。如果页面需要至少一个交互式小部件，请在该路由上保持启用脚本，并使用延迟 hydration 方式。
::

## 其余部分的延迟 Hydration

对于需要一定交互性的路由，保持脚本启用，但使用 [延迟 Hydration](/docs/directory-structure/app/components#delayed-or-lazy-hydration) 来控制组件何时进行 hydration：

```vue [app/pages/index.vue]
<template>
  <div>
    <HeroSection />
    <!-- static content that never needs to become interactive -->
    <LazyTestimonials hydrate-never />
    <!-- hydrate only when scrolled into view -->
    <LazyNewsletterSignup hydrate-on-visible />
    <!-- hydrate when the browser is idle -->
    <LazyCookieBanner hydrate-on-idle />
  </div>
</template>
```

`hydrate-never` 在内容网站中特别有用：组件的 HTML 由服务器渲染，但永远不会进行 hydration，因此其 JavaScript 也永远不会执行（尽管 prop 变化仍会触发 hydration）。

## 综合应用

典型的大部分静态站点最终会呈现如下情况：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    // pure content: prerendered, zero JS
    '/': { prerender: true, noScripts: true },
    '/blog/**': { prerender: true, noScripts: true },
    // pages with an interactive widget: prerendered, scripts kept
    '/contact': { prerender: true },
  },
})
```

- 内容路由仅提供纯 HTML 和 CSS，访问这些内容的导航属于推测预加载文档操作。
- 独立模块（`.server.vue` 组件）负责所有服务器渲染的小部件，从而将重依赖项排除在客户端包之外。
- 少数交互式路由保留脚本，通过 `hydrate-on-visible` / `hydrate-on-idle` / `hydrate-never` 限制浏览器在初始阶段的处理工作量。
