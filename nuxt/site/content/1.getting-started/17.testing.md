Nuxt 通过 `@nuxt/test-utils` 为你的 Nuxt 应用的端到端测试和单元测试提供一流支持。`@nuxt/test-utils` 是一个测试工具和配置库，目前用于运行 [我们在 Nuxt 本身进行的测试](https://github.com/nuxt/nuxt/tree/main/test) 以及整个模块生态系统中的测试。

:video-accordion{title="Watch a video from Alexander Lichter about getting started with @nuxt/test-utils" videoId="yGzwk9xi9gU"}

## 安装

为了让你能够管理其他测试依赖项，`@nuxt/test-utils` 包含多种可选的 peer 依赖项。例如：

- 你可以选择 `happy-dom` 或 `jsdom` 来创建运行时 Nuxt 环境。
- 你可以选择 `vitest`、`cucumber`、`jest` 或 `playwright` 作为端到端测试运行器。
- 如果你希望使用内置的浏览器测试工具，并且不使用 `@playwright/test` 作为测试运行器，则只需要 `playwright-core`。

::code-group{sync="pm"}
```bash [npm]
npm i --save-dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [yarn]
yarn add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [pnpm]
pnpm add -D @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [bun]
bun add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
::

## 测试环境

`@nuxt/test-utils` 为两种不同的测试环境提供辅助工具：

- **Nuxt 环境**：测试在 Nuxt 应用内部运行，使用 [`happy-dom`](https://github.com/capricorn86/happy-dom) 或 [`jsdom`](https://github.com/jsdom/jsdom) 环境，可以访问自动导入、插件和注入功能。来自 `@nuxt/test-utils/runtime` 的辅助函数（如 `mountSuspended` 和 `mockNuxtImport`）需要此环境，目前仅适用于 Vitest。
- **Node 环境**：测试在纯 Node 环境中运行。使用 `@nuxt/test-utils/e2e` 的端到端测试需要此环境，因为它们从外部通过 HTTP 或浏览器测试你的 Nuxt 应用。不需要 Nuxt 的单元测试也可以在此环境中运行。

测试文件只能在一个环境中运行，因此 `@nuxt/test-utils/runtime` 和 `@nuxt/test-utils/e2e` 不能在同一文件中使用。使用 Vitest 时，你可以利用 [项目](https://vitest.dev/guide/projects.html#test-projects) 来确保每个测试文件在正确的环境中运行，如下面的 [设置](#setup) 所示。

## 单元测试

我们目前提供了一个用于需要 [Nuxt](https://nuxt.com) 运行时环境的代码单元测试环境。目前它仅支持 `vitest`（不过欢迎贡献以添加其他运行时）。

### 设置

1. 将 `@nuxt/test-utils/module` 添加到你的 `nuxt.config` 文件中（可选）。它会在 Nuxt DevTools 中添加 Vitest 集成，从而支持在开发过程中运行单元测试。

   ```ts twoslash
   export default defineNuxtConfig({
     modules: [
       '@nuxt/test-utils/module',
     ],
   })
   ```

2. 创建一个 `vitest.config.ts` 文件，内容如下：

   ```ts twoslash
   import { defineConfig } from 'vitest/config'
   import { defineVitestProject } from '@nuxt/test-utils/config'

   export default defineConfig({
     test: {
       projects: [
         {
           test: {
             name: 'unit',
             include: ['test/unit/*.{test,spec}.ts'],
             environment: 'node',
           },
         },
         {
           test: {
             name: 'e2e',
             include: ['test/e2e/*.{test,spec}.ts'],
             environment: 'node',
           },
         },
         await defineVitestProject({
           test: {
             name: 'nuxt',
             include: ['test/nuxt/*.{test,spec}.ts'],
             environment: 'nuxt',
           },
         }),
       ],
     },
   })
   ```

    ::note
    `defineVitestProject` 仅用于 Nuxt环境测试。端到端测试应作为普通的 `test.environment: 'node'` 项目进行配置。
    ::

3. 如果你的 Nuxt环境测试位于 `test/nuxt/` 之外，请参见 [测试中的 TypeScript 支持](#typescript-support-in-tests) 以将其添加到 TypeScript 环境中。

::tip
在你的 vitest 配置中导入 `@nuxt/test-utils` 时，必须在 `package.json` 中指定 `"type": "module"`，或适当重命名你的 vitest 配置文件。
> 即 `vitest.config.m{ts,js}`。
::

::tip
可以通过使用 `.env.test` 文件为测试设置环境变量。
::

### Nuxt 环境选项

你可以通过 `test.environmentOptions.nuxt` 将 Nuxt 特定的选项传递给 `defineVitestProject` 项目。

```ts twoslash
import { fileURLToPath } from 'node:url'
import { defineConfig } from 'vitest/config'
import { defineVitestProject } from '@nuxt/test-utils/config'

export default defineConfig({
  test: {
    projects: [
      await defineVitestProject({
        test: {
          name: 'nuxt',
          include: ['test/nuxt/*.{test,spec}.ts'],
          environmentOptions: {
            nuxt: {
              rootDir: fileURLToPath(new URL('./playground', import.meta.url)),
              domEnvironment: 'happy-dom', // 'happy-dom' (default) or 'jsdom'
              overrides: {
                // other Nuxt config you want to pass
              },
            },
          },
        },
      }),
    ],
  },
})
```

### 组织测试

在基于项目的设置中，每个项目的 `include` glob 决定了测试文件在哪种环境中运行：

- `test/unit/` 中的 **单元测试** 在 Node 环境中运行。
- `test/nuxt/` 中的 **Nuxt 测试** 在 Nuxt 环境中运行。
- `test/e2e/` 中的 **端到端测试** 在 Node 环境中运行。

```bash [Directory structure]
test/
├── e2e/
│   └── ssr.test.ts
├── nuxt/
│   ├── components.test.ts
│   └── composables.test.ts
├── unit/
│   └── utils.test.ts
```

如果你希望将测试文件与源代码文件放在同一位置，可以使用如 `*.unit.spec.ts`、`*.nuxt.spec.ts` 和 `*.e2e.spec.ts` 这样的文件后缀，并对应地设置 `include` glob（例如，`include: ['**/*.nuxt.{test,spec}.ts']`）。请参见 [共同位置示例](https://github.com/nuxt/test-utils/tree/main/examples/app-vitest-co-location) 以获取完整配置。

当然，你可以选择任何测试结构，但每个测试文件应严格对应一个项目。特别是，将 Nuxt环境测试与端到端测试分开对于测试稳定性非常重要。

::warning
使用项目的 `include` glob 来选择测试文件的环境，而不是使用 `// @vitest-environment` 注释。该注释会改变环境，而无需添加或移除由 `defineVitestProject` 配置的 Nuxt Vite 插件。
::

#### 测试中的 TypeScript 支持

默认情况下，`test/nuxt/` 和 `tests/nuxt/` 目录中的测试文件被包含于 [Nuxt 应用 TypeScript 环境中](/docs/guide/concepts/typescript#how-nuxt-uses-project-references)。这意味着它们会识别 Nuxt 别名（如 `~/`、`@/`、 `#imports`），并且 TypeScript 会知道在 Nuxt 应用中有效的自动导入。

::tip
这种结构符合推荐做法，只有需要 Nuxt 运行时环境的测试才被放在这些目录中。如果需要，其他目录中的单元测试（如 `test/unit/`）也可以手动添加。
::

##### 添加其他测试目录

如果您有其他目录中的测试将在 Nuxt Vitest 环境中运行，可以通过将其添加到配置中，从而将其纳入 Nuxt 应用 TypeScript 环境：

<!-- @case-police-ignore tsConfig -->

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    tsConfig: {
      include: [
        // this path is relative to the generated .nuxt/tsconfig.json
        '../test/other-nuxt-context/**/*',
      ],
    },
  },
})
```

::important
单元测试不应依赖 Nuxt 运行时特性，如自动导入或组合式函数。仅当您的测试从源文件导入时（例如 `~/utils/helpers`），才添加 TypeScript 路径别名支持，而非针对 Nuxt 特有的功能。
::

#### 运行测试

项目设置完成后，您可以运行不同的测试套件：

```bash
# Run all tests
npx vitest

# Run only unit tests
npx vitest --project unit

# Run only Nuxt tests
npx vitest --project nuxt

# Run only end-to-end tests
npx vitest --project e2e

# Run tests in watch mode
npx vitest --watch
```

::warning
当您在 Nuxt 环境中运行测试时，它们将在 [`happy-dom`](https://github.com/capricorn86/happy-dom) 或 [`jsdom`](https://github.com/jsdom/jsdom) 环境中运行。在测试开始之前，全局 Nuxt 应用将被初始化（包括例如运行您在 `app.vue` 中定义的任何插件或代码）。

这意味着您应特别小心，不要在测试中修改全局状态（如果需要，之后也可以重置它）。
::

### 🎭 内置模拟对象

`@nuxt/test-utils` 提供了一些用于 DOM 环境的内置模拟对象。这些仅在 Nuxt 环境中可用。

#### `intersectionObserver`

默认值为 `true`，会创建一个没有任何功能的虚拟类，用于 IntersectionObserver API。

#### `indexedDB`

默认值为 `false`，使用 [`fake-indexeddb`](https://github.com/dumbmatter/fakeIndexedDB) 来创建 IndexedDB API 的功能性模拟。

这些可以在您的 `vitest.config.ts` 文件的 [Nuxt 环境选项](#nuxt-environment-options) 中配置：

```ts twoslash
import { defineConfig } from 'vitest/config'
import { defineVitestProject } from '@nuxt/test-utils/config'

export default defineConfig({
  test: {
    projects: [
      await defineVitestProject({
        test: {
          name: 'nuxt',
          include: ['test/nuxt/*.{test,spec}.ts'],
          environmentOptions: {
            nuxt: {
              mock: {
                intersectionObserver: true,
                indexedDb: true,
              },
            },
          },
        },
      }),
    ],
  },
})
```

### 🛠️ 辅助工具

`@nuxt/test-utils` 提供了许多辅助工具，以简化 Nuxt 应用的测试。

#### `mountSuspended`

`mountSuspended` 允许您在 Nuxt 环境中挂载任何 Vue 组件，从而支持异步设置并访问来自 Nuxt 插件的注入项。

::note
在底层，`mountSuspended` 包装了 `@vue/test-utils` 中的 `mount` 函数，您可以通过 [Vue Test Utils 文档](https://test-utils.vuejs.org/guide/) 了解您可以传递的选项以及如何使用此工具。
::

例如：

```ts twoslash [tests/components/SomeComponents.nuxt.spec.ts]
// @noErrors
import type { Component } from 'vue'

declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
import { expect, it } from 'vitest'
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'

it('can mount some component', async () => {
  const component = await mountSuspended(SomeComponent)
  expect(component.text()).toMatchInlineSnapshot(
    '"This is an auto-imported component"',
  )
})
```

```ts twoslash [tests/App.nuxt.spec.ts]
import { expect, it } from 'vitest'
import { mountSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

it('can also mount an app', async () => {
  const component = await mountSuspended(App, { route: '/test' })
  expect(component.html()).toMatchInlineSnapshot(`
      "<div>This is an auto-imported component</div>
      <div> I am a global component </div>
      <div>/</div>
      <a href="/test"> Test link </a>"
    `)
})
```

如果您需要监视组件设置状态，可以将 `spy` 选项设置为 `true`，并通过 `setupState` 访问 `setup` 的返回值。

```ts twoslash [tests/components/SomeComponents.nuxt.spec.ts]
// @noErrors
import type { Component } from 'vue'

declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
import { expect, it, vi } from 'vitest'
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'

it('can spy on setup state', async () => {
  const component = await mountSuspended(SomeComponent, { spy: true })
  vi.mocked(component.setupState.someMethod).mockImplementation(() => 'mocked')
})
```

options 对象接受 `@vue/test-utils` 挂载选项和以下属性：

  - `route`: 初始路由，或设置为 `false` 以跳过初始路由变化（默认为 `/`）。
  - `spy`: 启用对组件设置状态的监视（默认为 `false`）。

返回对象包含 `@vue/test-utils` 挂载结果和以下属性：

  - `setupState`: 组件设置的返回值。

#### `renderSuspended`

`renderSuspended` 允许您使用 `@testing-library/vue` 在 Nuxt 环境中渲染任何 Vue 组件，支持异步设置，并可以访问来自 Nuxt 插件的注入值。

此选项应与 Testing Library 的工具一起使用，例如 `screen` 和 `fireEvent`。请在项目中安装 [@testing-library/vue](https://testing-library.com/docs/vue-testing-library/intro/) 以使用这些工具。

此外，Testing Library 还依赖测试全局变量进行清理。您应在 [Vitest 配置](https://vitest.dev/config/globals) 中启用这些变量。

传入的组件将在 `<div id="test-wrapper"></div>` 内渲染。

示例：

```ts twoslash [tests/components/SomeComponents.nuxt.spec.ts]
// @noErrors
import type { Component } from 'vue'

declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
import { expect, it } from 'vitest'
import { renderSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'
import { screen } from '@testing-library/vue'

it('can render some component', async () => {
  await renderSuspended(SomeComponent)
  expect(screen.getByText('This is an auto-imported component')).toBeDefined()
})
```

```ts twoslash [tests/App.nuxt.spec.ts]
import { expect, it } from 'vitest'
import { renderSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

it('can also render an app', async () => {
  const html = await renderSuspended(App, { route: '/test' })
  expect(html).toMatchInlineSnapshot(`
    "<div id="test-wrapper">
      <div>This is an auto-imported component</div>
      <div> I am a global component </div>
      <div>Index page</div><a href="/test"> Test link </a>
    </div>"
  `)
})
```

options 对象接受 `@testing-library/vue` 渲染选项和以下属性：

  - `route`: 初始路由，或设置为 `false` 以跳过初始路由变化（默认为 `/`）。
  - `spy`: 启用对组件设置状态的监视（默认为 `false`）。参见上面的 [`mountSuspended`](#mountsuspended) 示例。

返回对象包含 `@testing-library/vue` 渲染结果和以下属性：

  - `setupState`: 组件设置的返回值。

#### `mockNuxtImport`

`mockNuxtImport` 允许您模拟 Nuxt 的自动导入功能。例如，要模拟 `useState`，可以这样做：

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useState', () => {
  return () => {
    return { value: 'mocked storage' }
  }
})

// your tests here
```

您可以显式指定模拟类型以确保类型安全，并在模拟复杂功能时使用传入的原始实现到工厂函数。

```ts twoslash [test/nuxt/import.test.ts]
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport<typeof useState>('useState', (original) => {
  return (...args) => {
    return { ...original('some-key'), value: 'mocked state' }
  }
})

// or specify the target to mock
mockNuxtImport(useState, (original) => {
  return (...args) => {
    return { ...original('some-key'), value: 'mocked state' }
  }
})

// your tests here
```

::note
`mockNuxtImport` 在每个测试文件中的每个被模拟导入中只能使用一次。实际上它是一个宏，会被转换为 `vi.mock`，而 `vi.mock` 会被提升，具体说明请参考 [Vitest 文档](https://vitest.dev/api/vi#vi-mock)。
::

如果您需要模拟 Nuxt 导入并在测试之间提供不同的实现，可以通过使用 [`vi.hoisted`](https://vitest.dev/api/vi#vi-hoisted) 创建和暴露模拟对象来实现，然后在 `mockNuxtImport` 中使用这些模拟对象。这样您就可以访问被模拟的导入项，并在测试之间更改实现。请注意在每次测试之前或之后[恢复模拟](https://vitest.dev/api/mock#mockrestore)，以撤销运行之间的模拟状态变化。

```ts twoslash
import { vi } from 'vitest'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

const { useStateMock } = vi.hoisted(() => {
  return {
    useStateMock: vi.fn(() => {
      return { value: 'mocked storage' }
    }),
  }
})

mockNuxtImport('useState', () => {
  return useStateMock
})

// Then, inside a test
useStateMock.mockImplementation(() => {
  return { value: 'something else' }
})
```

如果您只需要在测试内部模拟行为，也可以使用以下方法。

```ts twoslash
import { beforeEach, vi } from 'vitest'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport(useRoute, original => vi.fn(original))

beforeEach(() => {
  vi.resetAllMocks()
})

// Then, inside a test
const useRouteOriginal = vi.mocked(useRoute).getMockImplementation()!
vi.mocked(useRoute).mockImplementation(
  (...args) => ({ ...useRouteOriginal(...args), path: '/mocked' }),
)
```

#### `mockComponent`

`mockComponent` 允许您模拟 Nuxt 组件。
第一个参数可以是 PascalCase 形式的组件名称，或组件的相对路径。
第二个参数是一个工厂函数，该函数返回被模拟的组件。

例如，要模拟 `MyComponent`，您可以：

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', {
  props: {
    value: String,
  },
  setup (props) {
    // ...
  },
})

// relative path or alias also works
mockComponent('~/components/my-component.vue', () => {
  // or a factory function
  return defineComponent({
    setup (props) {
      // ...
    },
  })
})

// or you can use SFC for redirecting to a mock component
mockComponent('MyComponent', () => import('./MockComponent.vue'))

// your tests here
```

> **注意**：您不能在工厂函数中引用局部变量，因为它们被提升了。如果您需要访问 Vue API 或其他变量，则需要在工厂函数中导入它们。

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', async () => {
  const { ref, h } = await import('vue')

  return defineComponent({
    setup (props) {
      const counter = ref(0)
      return () => h('div', null, counter.value)
    },
  })
})
```

#### `registerEndpoint`

`registerEndpoint` 允许您创建返回模拟数据的 Nitro 端点。如果您想测试一个向 API 发送请求以显示数据的组件，这非常有用。

第一个参数是指点名（例如 `/test/`）。
第二个参数是一个工厂函数，该函数返回被模拟的数据。

例如，要模拟 `/test/` 端点，您可以这样做：

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', () => ({
  test: 'test-field',
}))
```

默认情况下，您的请求将使用 `GET` 方法发送。您可以通过设置一个对象作为第二个参数而不是函数来使用其他方法。

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', {
  method: 'POST',
  handler: () => ({ test: 'test-field' }),
})
```

该对象接受以下属性：

- `handler`：事件处理函数
- `method`：（可选）匹配的 HTTP 方法（例如，'GET'、'POST'）
- `once`：（可选）如果为 true，处理程序仅会在第一个匹配请求时使用，然后自动移除

> **注意**：如果组件中的请求指向外部 API，您可以使用 `baseURL`，然后通过 [Nuxt 环境覆盖配置](/docs/getting-started/configuration#environment-overrides)（`$test`）将其置为空，这样所有请求都将发送到 Nitro 服务器。

#### 与端到端测试的冲突

`@nuxt/test-utils/runtime` 和 `@nuxt/test-utils/e2e` 需要在不同的[测试环境](#test-environments)中运行，因此无法在同一文件中使用。

如果您希望同时使用 `@nuxt/test-utils` 的端到端测试和单元测试功能，请将测试文件拆分为独立文件，并确保每个文件仅对应一个项目：Nuxt-environment 测试应对应 `defineVitestProject` 项目，端到端测试应对应普通的 `environment: 'node'` 项目。有关基于文件夹和后缀的布局方式，请参阅 [Organizing Your Tests](#organizing-your-tests)。

`app.nuxt.spec.ts`

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useState', () => {
  return () => {
    return { value: 'mocked storage' }
  }
})
```

`app.e2e.spec.ts`

```ts twoslash
import { $fetch, setup } from '@nuxt/test-utils/e2e'

await setup({
  setupTimeout: 10000,
})

// ...
```

### 使用 `@vue/test-utils`

如果您希望在 Nuxt 中进行单元测试时单独使用 `@vue/test-utils`，并且只测试不依赖 Nuxt 组合式函数、自动导入或上下文的组件，可以遵循以下步骤进行配置。

### Vitest 浏览器模式

`@nuxt/test-utils` 通过 `@nuxt/test-utils/browser` 提供了在 [Vitest 浏览器模式](https://vitest.dev/guide/browser/) 中进行测试的辅助工具。

#### 配置

1. 安装 Vitest 浏览器包和浏览器提供器：

   ::code-group{sync="pm"}
   ```bash [npm]
   npm i --save-dev @vitest/browser-playwright
   ```
   ```bash [yarn]
   yarn add --dev @vitest/browser-playwright
   ```
   ```bash [pnpm]
   pnpm add -D @vitest/browser-playwright
   ```
   ```bash [bun]
   bun add --dev @vitest/browser-playwright
   ```
   ::

2. 在 `vitest.config.ts` 中配置浏览器模式：

   ```ts twoslash
   // @errors: 2307
   // ---cut---
   import { defineConfig } from 'vitest/config'
   import { defineVitestProject } from '@nuxt/test-utils/config'
   import { playwright } from '@vitest/browser-playwright'

   export default defineConfig({
     test: {
       projects: [
         await defineVitestProject({
           test: {
             name: 'browser',
             include: ['test/browser/**/*.{test,spec}.ts'],
             browser: {
               enabled: true,
               provider: playwright(),
               instances: [{ browser: 'chromium' }],
             },
             // If you want to enable `page.render` and automatic cleanup, add this setup file
             setupFiles: ['@nuxt/test-utils/browser'],
           },
         }),
       ],
     },
   })
   ```

   ::note
   当将 `@nuxt/test-utils/browser` 添加到 `setupFiles` 时，如果 TypeScript 无法自动识别 `page.render` 的类型，可以在 `nuxt.config.ts` 中的 `typescript.tsConfig.compilerOptions.types` 中添加 `@nuxt/test-utils/browser`。
   ::

   ::note
   如果您的 Vitest 浏览器模式测试位于 `test/nuxt/` 之外（例如 `test/browser/`），请参阅 [Adding other test directories](#adding-other-test-directories) 将其添加到 TypeScript 上下文。
   ::

#### 使用方式

您可以使用 `vitest/browser` 中的 `page.render`：

```ts twoslash [test/browser/components/MyCounter.nuxt.spec.ts]
// @noErrors
import type { Component } from 'vue'

declare module '#components' {
  export const MyCounter: Component
}
// ---cut---
import { expect, it } from 'vitest'
import { page } from 'vitest/browser'
// If you added the setup file, the following import is not needed
import '@nuxt/test-utils/browser'

import { MyCounter } from '#components'

it('counter button increments the count', async () => {
  const screen = await page.render(MyCounter)
  await screen.getByRole('button', { name: 'Increment' }).click()
  await expect.element(screen.getByText('Count: 1')).toBeVisible()
})
```

您也可以直接从 `@nuxt/test-utils/browser` 导入 `render`：

```ts twoslash
// @noErrors
import type { Component } from 'vue'

declare module '#components' {
  export const MyCounter: Component
}
// ---cut---
import { expect, it } from 'vitest'
import { render } from '@nuxt/test-utils/browser'
import { MyCounter } from '#components'

it('can render using the render helper', async () => {
  const screen = await render(MyCounter)
  await screen.getByRole('button', { name: 'Increment' }).click()
  await expect.element(screen.getByText('Count: 1')).toBeVisible()
})
```

选项对象接受 `@vue/test-utils` 的挂载选项（使用 `container` 代替 `attachTo`）和以下属性：

  - `route`：初始路由，或设置为 `false` 以跳过初始路由变化（默认值为 `/`）。
  - `spy`: 启用组合式函数设置状态（默认为 `false`）。参见上方的 [`mountSuspended`](#mountsuspended) 示例。
  - `container`: 用于渲染的自定义 `HTMLElement` 容器（请使用此选项，而非 `@vue/test-utils` 的 `attachTo`）。
  - `baseElement`: 自定义基础 `HTMLElement`（默认为 `document.body`）。

返回对象包含以下属性：

  - `container`: 组件被渲染的容器 `HTMLElement`。
  - `baseElement`: 基础 `HTMLElement`（默认为 `document.body`）。
  - `locator`: 根元素 `Locator`。
  - `setupState`: 组件设置值的返回值，当 `spy` 选项启用时会被模拟。
  - `debug()`: 将格式化的 DOM 输出到控制台。
  - `unmount()`: 卸载组件。同时记录 `nuxt.unmount` 跟踪标记。
  - `emitted()`: 获取已发射的事件。
  - `rerender(props)`: 使用新属性重新渲染组件。同时记录 `nuxt.rerender` 跟踪标记。

## 端到端测试

对于端到端测试，我们支持 [Vitest](https://github.com/vitest-dev/vitest)、[Jest](https://jestjs.io)、[Cucumber](https://cucumber.io) 和 [Playwright](https://playwright.dev/) 作为测试运行器。

### 设置

在利用 `@nuxt/test-utils/e2e` 辅助方法的每个 `describe` 块中，你需要在开始之前设置测试上下文。

```ts twoslash [test/my-test.spec.ts]
import { describe, test } from 'vitest'
import { $fetch, setup } from '@nuxt/test-utils/e2e'

describe('My test', async () => {
  await setup({
    // test context options
  })

  test('my test', () => {
    // ...
  })
})
```

在幕后，`setup` 在 `beforeAll`、`beforeEach`、`afterEach` 和 `afterAll` 中执行多项任务，以正确设置 Nuxt 测试环境。

请使用以下选项来调用 `setup` 方法。

#### Nuxt 配置

- `rootDir`: 用于测试的 Nuxt 应用程序所在目录路径。
  - 类型: `string`
  - 默认值: `'.'`
- `configFile`: 配置文件的名称。
  - 类型: `string`
  - 默认值: `'nuxt.config'`

<!--
- `config`: 包含配置覆盖的对象。
  - 类型: `NuxtConfig`
  - 默认值: `{}` -->

#### 时间限制

- `setupTimeout`: 允许 `setupTest` 完成工作的时间长度（以毫秒为单位）（根据传递的选项，可能包括构建或生成 Nuxt 应用程序的文件）。
  - 类型: `number`
  - 默认值: 在 Windows 上为 `120000` 或 `240000`。

- `teardownTimeout`: 允许关闭浏览器等测试环境清理的时间长度（以毫秒为单位）。
  - 类型: `number`
  - 默认值: `30000`

#### 功能特性

- `build`: 是否执行单独的构建步骤。
  - 类型: `boolean`
  - 默认值: `true`（`browser` 或 `server` 被禁用，或提供了 `host` 时设为 `false`)

- `server`: 是否启动服务器以响应测试套件中的请求。
  - 类型: `boolean`
  - 默认值: `true`（`host` 被提供时设为 `false`)

- `port`: 如果提供，将测试服务器端口设置为该值。
  - 类型: `number | undefined`
  - 默认值: `undefined`

- `host`: 如果提供，则使用 URL 作为测试目标，而不是构建并运行新服务器。适用于针对已部署版本的应用程序或正在运行的本地服务器进行“真实”端到端测试（这可能会显著减少测试执行时间）。请参阅下面的 [目标主机端到端示例](/docs/getting-started/testing#target-host-end-to-end-example)。
  - 类型: `string`
  - 默认值: `undefined`

- `browser`: 实际上，Nuxt 测试工具使用 [`playwright`](https://playwright.dev) 进行浏览器测试。如果设置此选项，将启动浏览器并在后续测试套件中控制它。
  - 类型: `boolean`
  - 默认值: `false`
- `browserOptions`
  - 类型: `object`，包含以下属性
    - `type`: 要启动的浏览器类型——`chromium`、`firefox` 或 `webkit`
    - `launch`: 在启动浏览器时传递给 playwright 的选项对象。请参阅 [完整 API 参考](https://playwright.dev/docs/api/class-browsertype#browser-type-launch)。
- `runner`: 指定测试套件的运行器。目前推荐使用 [Vitest](https://vitest.dev)。
  - 类型: `'vitest' | 'jest' | 'cucumber'`
  - 默认值: `'vitest'`

- `logLevel`: 覆盖服务器子进程的 consola 日志级别。（使用 NUXT_TEST_LOG_LEVEL 环境变量进行覆盖）
  - 类型: `number`
  - 默认值: `1`
- `captureServerLogs`: 是否捕获服务器进程输出而不是继承 stdio。当 `true`（默认）时，服务器 stdout/stderr 从控制台隐藏并通过 `getServerLogs()` 访问。设置为 `false` 可恢复旧的继承 stdio 行为（在本地调试测试时非常有用）。
  - 类型: `boolean`
  - 默认值：`true`

##### 端到端测试目标 `host` 示例

端到端测试的常见应用场景是针对在通常用于生产的相同环境中运行的已部署应用程序进行测试。

对于本地开发或自动化部署管道，使用独立的本地服务器进行测试可能更有效率，通常比让测试框架在测试之间重新构建更快。

要使用独立的目标主机进行端到端测试，只需将 `setup` 函数的 `host` 属性设置为所需的 URL 即可。

```ts
import { createPage, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('login page', async () => {
  await setup({
    host: 'http://localhost:8787',
  })

  it('displays the email and password fields', async () => {
    const page = await createPage('/login')
    expect(await page.getByTestId('email').isVisible()).toBe(true)
    expect(await page.getByTestId('password').isVisible()).toBe(true)
  })
})
```

### API 接口

#### `$fetch(url)`

获取服务器渲染的页面的 HTML 内容。

```ts twoslash
import { $fetch } from '@nuxt/test-utils/e2e'

const html = await $fetch('/')
```

#### `fetch(url)`

获取服务器渲染的页面的响应内容。

```ts twoslash
import { fetch } from '@nuxt/test-utils/e2e'

const res = await fetch('/')
const { body, headers } = res
```

#### `url(path)`

获取指定页面的完整 URL（包括测试服务器运行的端口）。

```ts twoslash
import { url } from '@nuxt/test-utils/e2e'

const pageUrl = url('/page')
// 'http://localhost:6840/page'
```

#### `getServerLogs()`

返回自上次 `startServer()` 调用（或 `clearServerLogs()`）以来从服务器子进程的标准输出/标准错误中捕获的行。仅当 `captureServerLogs` 为 `true`（默认值）时才会显示。

```ts twoslash
import { expect, it, vi } from 'vitest'
import { $fetch, clearServerLogs, getServerLogs } from '@nuxt/test-utils/e2e'

it('captures console.log output from a server route', async () => {
  clearServerLogs()
  await $fetch('/api/log-test')
  await vi.waitFor(() => {
    expect(getServerLogs().some(line => line.includes('[test] server-log-marker'))).toBe(true)
  })
})
```

#### `clearServerLogs()`

清除已捕获的服务器日志行。在请求之间使用此功能时非常有用，以便仅针对特定操作产生的日志进行断言。

### 在浏览器中测试

我们在 `@nuxt/test-utils` 中提供了使用 Playwright 的内置支持，可以通过编程方式或 Playwright 测试运行器来使用。

#### `createPage(url)`

在 `vitest`、`jest` 或 `cucumber` 中，可以使用 `createPage` 创建一个配置的 Playwright 浏览器实例，并（可选）将其指向运行中的服务器的路径。有关可用 API 方法的更多信息，请参见 [Playwright 文档](https://playwright.dev/docs/api/class-page)。

当传递路径时，`createPage` 会在 Nuxt 应用完成 hydration 后才会解析。在后续导航中，将 `waitUntil: 'hydration'` 传递给 `page.goto` 以再次等待 hydration 完成。

```ts twoslash
import { createPage, url } from '@nuxt/test-utils/e2e'

const page = await createPage('/page')
// you can access all the Playwright APIs from the `page` variable

await page.goto(url('/other-page'), { waitUntil: 'hydration' })
```

::tip
在页面完成 hydration 之前与其交互（例如，在事件处理器绑定之前点击按钮）会导致测试不稳定。
::

#### 使用 Playwright 测试运行器进行测试
