Nuxt 的核心特性之一是层结构和扩展支持。你可以扩展默认的 Nuxt 应用，以复用组件、工具和配置。层结构几乎与标准 Nuxt 应用相同，这使得它们易于编写和维护。

## 使用场景

- 使用 `nuxt.config` 和 `app.config` 在多个项目之间共享可复用的配置预设
- 使用 [`app/components/`](/docs/directory-structure/app/components) 目录创建组件库
- 使用 [`app/composables/`](/docs/directory-structure/app/组合式函数) 和 [`app/utils/`](/docs/directory-structure/app/utils) 目录创建工具和组合式函数库
- 创建 Nuxt 模块预设
- 在多个项目之间共享标准设置
- 创建 Nuxt 主题
- 通过实现模块化架构并支持大规模项目中的领域驱动设计（DDD）模式来提升代码组织。

## 使用方式

默认情况下，项目中的 `~~/layers` 目录下的任何层都会自动在项目中注册为层。

::note
层自动注册功能是在 Nuxt v3.12.0 中引入的。
::

此外，这些层的 `srcDir` 会自动创建对应的命名层别名。例如，你可以通过 `#layers/test` 访问 `~~/layers/test` 层。

::note
命名层别名是在 Nuxt v3.16.0 中引入的。
::

此外，你可以通过在 [`nuxt.config`](/docs/directory-structure/nuxt-config) 文件中添加 [extends](/docs/api/nuxt-config#extends) 属性来自定义层。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // Extend from a local layer
    '../base',
    // Extend from an installed npm package
    '@my-themes/awesome',
    // Extend from a git repository
    'github:my-themes/awesome#v1',
  ],
})
```

如果你从私有 GitHub 仓库扩展层，也可以传递认证令牌：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // per layer configuration
    ['github:my-themes/private-awesome', { auth: process.env.GITHUB_TOKEN }],
  ],
})
```

::note
如果未指定分支，这将克隆 `main` 分支。
::

::tip
你可以通过在层来源旁边的选项中选择来覆盖层的别名。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    [
      'github:my-themes/awesome',
      {
        meta: {
          name: 'my-awesome-theme',
        },
      },
    ],
  ],
})
```

::

Nuxt 使用 [unjs/c12](https://github.com/unjs/c12) 和 [unjs/giget](https://github.com/unjs/giget) 来扩展远程层。请查阅文档以获取更多信息和所有可用选项。

## 层优先级

当使用多个层时，了解覆盖顺序非常重要。当层定义相同的文件或组件时，具有**更高优先级**的层会覆盖低优先级的层。

### 优先级顺序

从最高到最低优先级：

1. **你的项目文件** - 具有最高优先级
2. `~~/layers` 目录中的**自动扫描层** - 按字母顺序排序（Z 的优先级高于 A）
3. `extends` 配置中的**层** - 第一个条目比第二个具有更高优先级

### 实际示例

考虑多个定义相同组件的层：

```bash [Directory structure]
layers/
  1.base/
    app/components/Button.vue    # Base button style
  2.theme/
    app/components/Button.vue    # Themed button (overrides base)
app/
  components/Button.vue          # Project button (overrides all layers)
```

在这种情况下：
- 如果只有层存在，则使用 `2.theme/Button.vue`（字母顺序上更高）
- 如果你的项目中有 `app/components/Button.vue`，它会覆盖所有层

### 控制优先级

你可以在层目录前加上数字来控制顺序：

```bash [Directory structure]
layers/
  1.base/        # Lowest priority
  2.features/    # Medium priority
  3.admin/       # Highest priority (among layers)
```

::tip
这种模式适用于创建具有默认值的基础层，这些默认值可以被更具体的层逐步覆盖。
::

或者，你可以通过在 [`extends`](/docs/api/nuxt-config#extends)中引用这些目录，而不需要重命名目录，从 `nuxt.config` 控制 `~~/layers` 目录的顺序。这些条目像其他 `extends` 层一样排序，但**第一个条目具有最高优先级**：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '~~/layers/admin', // highest priority
    '~~/layers/features',
    '~~/layers/base', // lowest priority (among the listed layers)
  ],
})
```

既支持 `~~/...` 形式（推荐），也支持 `~/...` 别名和相对路径（`./layers/admin`）。`~~/layers` 中未列出的任何层保持其字母顺序，排在你在 `extends` 中列出的层之下。

### 何时使用每种方式

- **`~~/layers` 目录** - 用于作为项目一部分的本地层
- **`extends`** - 用于外部依赖（npm 包、远程仓库）或项目目录外的层

### 带有 `extends` 的完整示例

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '../base', // Local layer outside project
    '@my-themes/awesome', // NPM package
    'github:my-themes/awesome#v1', // Remote repository
  ],
})
```

如果你还有 `~~/layers/custom`，优先级顺序为：
- 你的项目文件（最高）
- `~~/layers/custom`
- `../base`
- `@my-themes/awesome`
- `github:my-themes/awesome#v1`（最低）
