Nuxt 允许从应用程序中选择部分页面在构建时进行渲染。当请求时，Nuxt 将提供已构建的页面，而不是实时生成它们。

:read-more{title="Nuxt rendering modes" to="/docs/guide/concepts/rendering"}

## 基于爬虫的预渲染

使用 [`nuxt generate` 命令](/docs/api/commands/generate)通过 [Nitro](/docs/guide/concepts/server-engine) 爬虫构建并预渲染你的应用程序。此命令类似于将 `nitro.static` 选项设置为 `true` 的 `nuxt build`，或运行 `nuxt build --prerender`。

这将构建你的网站，启动一个 nuxt 实例，并且默认情况下会预渲染根页面 `/` 以及任何链接到的网站页面。

::code-group{sync="pm"}

```bash [npm]
npx nuxt generate
```

```bash [yarn]
yarn nuxt generate
```

```bash [pnpm]
pnpm nuxt generate
```

```bash [bun]
bun x nuxt generate
```

```bash [deno]
deno x nuxt generate
```

::

现在你可以将 `.output/public` 目录部署到任何静态托管服务中，或者使用 `npx serve .output/public` 在本地预览。

静态和预渲染构建还会生成 `200.html` 和 `404.html` SPA 回退文件。请参阅 [什么是 200.html 和 404.html？](/docs/guide/concepts/rendering#what-are-200html-and-404html)。

Nitro 爬虫的工作方式：

1. 加载应用程序根路径 (`/`) 的 HTML，`~/pages` 目录中的任何非动态页面，以及 `prerender.routes` 数组中的其他路由的 HTML。
2. 将 HTML 和 `_payload.json` 保存到 `~/.output/public/` 目录中，以便静态提供。
3. 在 HTML 中找到所有锚点标签 (`<a href="...">`) 以导航到其他路由。
4. 对找到的每个锚点标签重复步骤 1-3，直到没有更多的锚点标签需要爬虫遍历。

理解这一点很重要，因为未链接到可发现页面的页面无法自动预渲染。

::read-more{to="/docs/api/commands/generate"}
了解更多关于 `nuxt generate` 命令的信息。
::

### 选择性预渲染

你可以手动指定 Nuxt 在构建期间将获取和预渲染的路由，或者忽略你不希望预渲染的路由，例如在 `nuxt.config` 文件中的 `/dynamic`：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  prerender: {
    routes: ['/user/1', '/user/2'],
    ignore: ['/dynamic'],
  },
})
```

你可以结合使用 `crawlLinks` 选项来预渲染爬虫无法发现的路由集合，例如你的 `/sitemap.xml` 或 `/robots.txt`：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  prerender: {
    crawlLinks: true,
    routes: ['/sitemap.xml', '/robots.txt'],
  },
})
```

顶级 `prerender` 选项适用于你使用的任何 `server.builder`。特定于构建器的选项，如 Nitro 的 `concurrency` 或 `failOnError`，可以在 `nitro.prerender` 中设置。

::read-more{to="https://nitro.build/config#prerender"}
在 Nitro 文档中了解更多关于预渲染的信息。
::

最后，您可以使用 routeRules 手动配置此功能。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    // Set prerender to true to configure it to be prerendered
    '/rss.xml': { prerender: true },
    // Set it to false to configure it to be skipped for prerendering
    '/this-DOES-NOT-get-prerendered': { prerender: false },
    // Everything under /blog gets prerendered as long as it
    // is linked to from another page
    '/blog/**': { prerender: true },
  },
})
```

::read-more{to="https://nitro.build/config#routerules"}
了解更多关于 Nitro 的 `routeRules` 配置信息。
::

作为简写方式，您也可以在页面文件中使用 [`defineRouteRules`](/docs/api/utils/define-route-rules) 进行配置。

::read-more{to="/docs/guide/going-further/experimental-features#inlinerouterules" icon="i-lucide-star"}
此功能处于实验阶段，要使用它，必须在 `nuxt.config` 中启用 `experimental.inlineRouteRules` 选项。
::

```vue [app/pages/index.vue]
<script setup>
// Or set at the page level
defineRouteRules({
  prerender: true,
})
</script>

<template>
  <div>
    <h1>Homepage</h1>
    <p>Pre-rendered at build time</p>
  </div>
</template>
```

这将被翻译为：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },
  },
})
```

## 负载提取

当 Nuxt 在服务器上渲染页面时，它会将您的数据获取结果（[`useAsyncData`](/docs/api/组合式函数/use-async-data）和 [`useFetch`](/docs/api/组合式函数/use-fetch)）以及应用状态（[`useState`](/docs/api/组合式函数/use-state））序列化为负载，以便客户端在不重新获取的情况下进行 hydration。当启用负载提取时，Nuxt 还会将此负载写入 `_payload.json` 文件，并随路由的 HTML 一起保存。

- 预渲染的路由在构建时生成其负载文件。
- 使用 [ISR 或 SWR 缓存](/docs/guide/concepts/rendering#hybrid-rendering) 的路由在首次渲染时生成其负载文件，即使是在混合（非静态）站点中也是如此。

在客户端导航期间，Nuxt 会获取目标路由的 `_payload.json` 文件，并重用提取的数据，而不是在浏览器中再次执行数据获取操作。

您可以使用 [`experimental.payloadExtraction`](/docs/guide/going-further/experimental-features#payloadextraction) 选项控制此行为：

- `'client'` - 负载在初始渲染时直接嵌入到 HTML 中，并在客户端导航时提取为 `_payload.json` 文件。首次加载时不会产生额外的网络请求。
- `true` - 负载在初始渲染和客户端导航时都提取到独立的 `_payload.json` 文件中。HTML 文件更小，负载文件可以通过 CDN 缓存，但首次加载时会产生一次额外的请求。
- `false` - 禁用负载提取。负载始终直接嵌入到 HTML 中，不会生成 `_payload.json` 文件。

默认值为 `true`，当设置 `compatibilityVersion: 5` 时也为 `'client'`。当设置 `ssr: false` 时，强制为 `false`。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    payloadExtraction: 'client',
  },
})
```

需要注意一些实际影响：

- 在完全静态的网站中，客户端导航会复用构建时捕获的数据，因此数据可能在下一次构建之前仍然处于过时状态。
- 对于 ISR/SWR 路由，CDN 可以缓存有效载荷文件与 HTML 文件，从而提升缓存路由的客户端导航性能。像 `pages/[...slug].vue` 这样的动态路由可以通过 `'/**': { isr: true }` 这样的通配模式启用。
- 有效载荷通过 [devalue](https://github.com/Rich-Harris/devalue) 进行序列化，因此自定义类型（如类实例）需要带有自定义reducer和reviver的载荷插件才能通过往返传输。

:read-more{title="Payload reducers and revivers" to="/docs/api/composables/use-nuxt-app#payload"}

## 运行时预渲染配置

### `prerenderRoutes`

你可以在运行时在 [Nuxt 上下文](/docs/guide/going-further/nuxt-app#the-nuxt-context)中使用此功能，为 Nitro 添加更多需要预渲染的路由。

```vue [app/pages/index.vue]
<script setup>
prerenderRoutes(['/some/other/url'])
prerenderRoutes('/api/content/article/my-article')
</script>

<template>
  <div>
    <h1>This will register other routes for prerendering when prerendered</h1>
  </div>
</template>
```

:read-more{title="prerenderRoutes" to="/docs/api/utils/prerender-routes"}

### `prerender:routes` Nuxt hook

在预渲染之前调用此钩子，用于注册额外的路由。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    async 'prerender:routes' (ctx) {
      const { pages } = await fetch('https://api.some-cms.com/pages').then(
        res => res.json(),
      )
      for (const page of pages) {
        ctx.routes.add(`/${page.name}`)
      }
    },
  },
})
```

### `prerender:generate` Nitro hook

在预渲染过程中，每个路由都会调用此函数。你可以利用它来精细控制每个被预渲染的路由。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    hooks: {
      'prerender:generate' (route) {
        if (route.route?.includes('private')) {
          route.skip = true
        }
      },
    },
  },
})
```
