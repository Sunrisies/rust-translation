Nuxt 的核心特性之一是文件系统路由器。位于 [`app/pages/`](/docs/directory-structure/app/pages) 目录内的每个 Vue 文件都会生成对应的 URL（或路由），从而显示该文件的内容。通过为每个页面使用动态导入，Nuxt 利用代码分割技术仅传输所需路由所需的最少 JavaScript 代码。

::note
代码分割默认启用，并且对大多数应用来说都是推荐的。如果您有特定的理由需要打包成一个单独的包，可以在 [`nuxt.config`](/docs/api/nuxt-config) 中将其禁用。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    $client: {
      build: {
        rolldownOptions: {
          output: {
            codeSplitting: false,
          },
        },
      },
    },
  },
})
```

这种方式将所有 JavaScript 打包在一个文件中。通常这并不有益——即使在慢速连接下，也会增加初始下载量，因此只有当你证明代码分割对你有帮助时，才应禁用它。
::

## 页面

Nuxt 路由基于 [vue-router](https://router.vuejs.org)，并根据 [`app/pages/` 目录](/docs/directory-structure/app/pages) 中创建的每个组件的文件名生成路由。

这种文件系统路由使用命名约定来创建动态和嵌套路由。

::code-group

```bash [Directory Structure]
-| pages/
---| about.vue
---| index.vue
---| posts/
-----| [id].vue
```

```json [Generated Router File]
{
  "routes": [
    {
      "path": "/about",
      "component": "pages/about.vue"
    },
    {
      "path": "/",
      "component": "pages/index.vue"
    },
    {
      "path": "/posts/:id",
      "component": "pages/posts/[id].vue"
    }
  ]
}
```

::

## 导航

[`<NuxtLink>`](/docs/api/components/nuxt-link) 组件用于连接页面。它渲染一个带有 `href` 属性设置为页面路由的 `<a>` 标签。当应用完成初始化后，页面过渡通过 JavaScript 更新浏览器 URL 来实现，从而防止整个页面刷新并允许动画过渡。

当 [`<NuxtLink>`](/docs/api/components/nuxt-link) 在客户端侧进入视口时，Nuxt 会自动提前预加载链接页面的组件和负载（生成的页面），从而实现更快的导航。

```vue [app/pages/index.vue]
<template>
  <header>
    <nav>
      <ul>
        <li><NuxtLink to="/about">About</NuxtLink></li>
        <li><NuxtLink to="/posts/1">Post 1</NuxtLink></li>
        <li><NuxtLink to="/posts/2">Post 2</NuxtLink></li>
      </ul>
    </nav>
  </header>
</template>
```

:read-more{to="/docs/api/components/nuxt-link"}

## 路由参数

[`useRoute()`](/docs/api/组合式函数/use-route) 组合式函数可以在 `<script setup>` 块或 Vue 组件的 `setup()` 方法中使用，以访问当前路由详情。

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
const route = useRoute()

// When accessing /posts/1, route.params.id will be 1
console.log(route.params.id)
</script>
```

:read-more{to="/docs/api/composables/use-route"}

## 路由中间件

Nuxt 提供可自定义的路由中间件框架，你可以在整个应用中使用它，非常适合提取那些在导航到特定路由之前需要运行的代码。

::note
路由中间件在 Nuxt 应用的 Vue 部分运行。尽管名称相似，它们与服务器中间件完全不同，后者在应用的 Nitro 服务器部分运行。
::

::important
路由中间件不会针对服务器路由（例如 `/api/*`）或其他服务器请求运行。若需将中间件应用于这些请求，请使用 [服务器中间件](/docs/directory-structure/server#server-中间件)。
::

路由中间件有三种类型：

1. 匿名（或内联）路由中间件，直接定义在使用的页面中。
2. 命名路由中间件，放置在 [`app/middleware/`](/docs/directory-structure/app/中间件) 目录中，在页面使用时通过异步导入自动加载。（**注意**：路由中间件名称会被规范为 kebab-case，因此 `someMiddleware` 变为 `some-middleware`。）
3. 全局路由中间件，放置在 [`app/middleware/`](/docs/directory-structure/app/中间件) 目录中（带有 `.global` 后缀），会在每次路由更改时自动运行。

保护 `/dashboard` 页面使用的 `auth` 中间件示例：

::code-group

```ts twoslash [middleware/auth.ts]
function isAuthenticated (): boolean { return false }
// ---cut---
export default defineNuxtRouteMiddleware((to, from) => {
  // isAuthenticated() is an example method verifying if a user is authenticated
  if (isAuthenticated() === false) {
    return navigateTo('/login')
  }
})
```

```vue twoslash [pages/dashboard.vue]
<script setup lang="ts">
definePageMeta({
  middleware: 'auth',
})
</script>

<template>
  <h1>Welcome to your dashboard</h1>
</template>
```

::

## 路由验证

Nuxt 通过 [`definePageMeta()`](/docs/api/utils/define-page-meta) 中的 `validate` 属性为需要验证的每一页提供路由验证功能。

`validate` 属性接受 `route` 作为参数。你可以返回一个布尔值，以确定该路由是否合法且应被此页面渲染。若返回 `false`，将引发 404 错误。你还可以直接返回一个包含 `status`/`statusText` 的对象来自定义返回的错误信息。

如果你有更复杂的用例，则可以使用匿名路由中间件。

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
definePageMeta({
  validate (route) {
    // Check if the id is made up of digits
    return typeof route.params.id === 'string' && /^\d+$/.test(route.params.id)
  },
})
</script>
```
