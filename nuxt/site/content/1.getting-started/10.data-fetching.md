Nuxt 包含两个组合式函数和内置库，可在浏览器或服务器环境中执行数据获取：`useFetch`、`[useAsyncData](/docs/api/composables/use-async-data) 和 `$fetch`。

简而言之：

- `[$fetch](/docs/api/utils/dollarfetch)` 是进行网络请求的最简单方式。
- `[useFetch](/docs/api/composables/use-fetch)` 是一个围绕 `$fetch` 的包装器，在[通用渲染](/docs/guide/concepts/rendering#universal-rendering)模式下仅执行一次数据获取。
- `[useAsyncData](/docs/api/composables/use-async-data)` 与 `useFetch` 类似，但提供更细粒度的控制。

`useFetch` 和 `useAsyncData` 共享一组常见的选项和模式，我们将在后续章节中详细介绍。

## `useFetch` 和 `useAsyncData` 的必要性

Nuxt 是一个框架，可以在服务器和客户端环境中运行同构（或通用）代码。如果使用 `[$fetch` 函数](/docs/api/utils/dollarfetch)在 Vue 组件的 setup 函数中执行数据获取，可能会导致数据被获取两次：一次在服务器上（用于渲染 HTML），另一次在客户端上（当 HTML 完成 hydration 时）。这可能导致 hydration 问题，增加交互时间并导致不可预测的行为。

`[useFetch](/docs/api/composables/use-fetch)` 和 `[useAsyncData](/docs/api/composables/use-async-data)` 组合式函数通过确保服务器上的 API 调用时，数据被包含在 payload 中并转发给客户端来解决此问题。

payload 是一个通过 `[useNuxtApp().payload](/docs/api/composables/use-nuxt-app#payload)` 可访问的 JavaScript 对象。它在客户端使用，以避免在浏览器中执行代码时[在 hydration 过程中](/docs/guide/concepts/rendering#universal-rendering)重新获取相同数据。

::tip
使用 [Nuxt DevTools](/modules/devtools) 在 **Payload 标签页**中检查此数据。
::

```vue [app/app.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/data')

async function handleFormSubmit () {
  const res = await $fetch('/api/submit', {
    method: 'POST',
    body: {
      // My form data
    },
  })
}
</script>

<template>
  <div v-if="data == undefined">
    No data
  </div>
  <div v-else>
    <form @submit="handleFormSubmit">
      <!-- form input tags -->
    </form>
  </div>
</template>
```

在上面的示例中，`useFetch` 确保请求在服务器上发生，并正确转发到浏览器。`$fetch` 没有这样的机制，当请求仅由浏览器发起时，使用 `$fetch` 是更好的选择。

### 悬停效果

Nuxt 在内部使用了 Vue 的 [`<Suspense>`](https://vuejs.org/guide/built-ins/suspense) 组件，以防止在异步数据完全可用于视图之前进行导航。数据获取组合式函数可以帮助你利用此功能，并根据每次调用的情况选择最合适的处理方式。

::note
你可以添加 [`<NuxtLoadingIndicator>`](/docs/api/components/nuxt-loading-indicator) 来在页面导航之间显示进度条。
::

### 关于 `await` 的说明

本文档中的示例通常包含对 `useFetch` 和 `useAsyncData` 的 `await` 调用，但并非总是必要。

`await` **不会**改变服务器渲染的 HTML。在服务器渲染过程中，Nuxt 会在请求解决之前等待页面序列化（通过 [`<Suspense>`]和 `onServerPrefetch` 实现），因此完整的结果始终会被发送到浏览器。

`await` **确实**会改变你自己的 `<script setup>` 中的后续行为，以及客户端导航的行为方式：

- **使用 `await`**时，执行会暂停直到数据准备好，因此调用之后的任何代码都可以依赖 `data` 已经填充。在客户端导航时，这会阻止导航直到数据解决：用户停留在当前页面（可选带有 [`<NuxtLoadingIndicator>`](/docs/api/components/nuxt-loading-indicator)），然后进入一个完全填充的页面。这是默认行为。
- **不使用 `await`**时，执行会立即继续，而请求在后台运行，因此 `data` 以默认值开始，并在请求解决后填充。在客户端导航时，这意味着导航立即发生，你需要负责处理加载和错误状态，通常通过返回的 `status` 和 `error` 引用来实现。
- **Without `await`**, execution continues immediately while the request runs in the background, so `data` starts as its default value and fills in once the request resolves. On client-side navigation, this means navigation happens immediately and you are responsible for handling the loading and error states, typically via the returned `status` and `error` refs.

这两种方式没有一种普遍更优；正确的选择取决于你希望该路由提供的体验。

不等待具有与 [`lazy`](#lazy) 选项类似的用户可见效果（导航不会被阻止，你可以自己处理加载状态），但两者并不相同：`lazy` 是一个明确的标志，表示将请求延迟到组件挂载时，而不使用 `await` 则会在设置期间开始请求。如果你希望非阻塞行为，建议使用 `lazy`（或 [`useLazyFetch`](/docs/api/组合式函数/use-lazy-fetch) / [`useLazyAsyncData`](/docs/api/组合式函数/use-lazy-async-data)），因为这样能明确表达意图。

::warning
`await` 和 `lazy` 是独立的，在客户端等待 `lazy` 函数时不会产生预期效果。如果你 `await` 一个 `lazy` 调用（例如 `await useLazyFetch(...)` 或 `await useFetch(..., { lazy: true })`），它仍然会像平常一样阻塞服务器渲染，但在**客户端导航**时，`await` 会立即解析，无需等待请求。在 `await` 之后，`data` 仍会保持其默认值，你必须通过 `status` 来处理加载状态。如果你实际上希望导航等待数据，应去掉 `lazy` 选项，而不是依赖 `await`。
::

## `$fetch`

Nuxt 包含了 [ofetch](https://github.com/unjs/ofetch) 库，并在整个应用中自动导入为 `$fetch` 别名。

```vue twoslash [pages/todos.vue]
<script setup lang="ts">
async function addTodo () {
  const todo = await $fetch('/api/todos', {
    method: 'POST',
    body: {
      // My todo data
    },
  })
}
</script>
```

::warning
请注意，仅使用 `$fetch` 无法提供[网络调用去重和导航预防](/docs/getting-started/data-fetching#the-need-for-usefetch-and-useasyncdata)。 :br
建议在客户端交互（基于事件）或结合 [`useAsyncData`](/docs/getting-started/data-fetching#useasyncdata) 获取初始组件数据时使用 `$fetch`。
::

::read-more{to="/docs/api/utils/dollarfetch"}
了解更多关于 `$fetch` 的信息。
::

### 为包含 `$fetch` 的值定义类型

要定义包含 `$fetch` 本身的值，例如传递给插件或通过 `provide`/`inject` 提供的 `$fetch` 实例，请使用 `$Fetch` 类型（是 `TypedFetch` 的别名）：

```ts
import type { $Fetch } from '#app'

function createClient (fetcher: $Fetch) {
  return {
    todos: () => fetcher('/api/todos'),
  }
}
```

### 将客户端头信息传递给 API

在服务器上调用 `useFetch` 时，Nuxt 会使用 [`useRequestFetch`](/docs/api/组合式函数/use-request-fetch) 来代理客户端头信息和 Cookie（除了不打算转发 olan 头信息，如 `host`）。

```vue
<script setup lang="ts">
const { data } = await useFetch('/api/echo')
</script>
```

```ts
// /api/echo.ts
export default defineEventHandler(event => parseCookies(event))
```

或者，下面的示例展示了如何使用 [`useRequestHeaders`](/docs/api/组合式函数/use-request-headers) 从服务器端请求（由客户端发起）访问和发送 Cookie 到 API。通过使用同构 `$fetch` 调用，确保 API 端点能够获取用户浏览器最初发送的相同 `cookie` 头信息。这仅在不使用 `useFetch` 时必要。

```vue
<script setup lang="ts">
const headers = useRequestHeaders(['cookie'])

async function getCurrentUser () {
  return await $fetch('/api/me', { headers })
}
</script>
```

::tip
你也可以使用 [`useRequestFetch`](/docs/api/组合式函数/use-request-fetch) 来自动代理头信息。
::

::caution
在将头信息代理到外部 API 之前，请非常小心，只包含所需的头信息。并非所有头信息都可以安全绕过，可能会引入不期望的行为。以下是不应被代理的常见头信息列表：

- `host`, `accept`
- `content-length`, `content-md5`, `content-type`
- `x-forwarded-host`, `x-forwarded-port`, `x-forwarded-proto`
- `cf-connecting-ip`, `cf-ray`
::

## `useFetch`

该组合式函数 [`useFetch`](/docs/api/组合式函数/use-fetch) 在设置函数中使用 `$fetch` 来执行安全的 SSR 网络调用。

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { data: count } = await useFetch('/api/count')
</script>

<template>
  <p>Page visits: {{ count }}</p>
</template>
```

该组合式函数是 [`useAsyncData`](/docs/api/组合式函数/use-async-data) 和 `$fetch` 工具包的包装器。

## `useAsyncData`

`useAsyncData` 组合式函数负责封装异步逻辑，并在其解析后返回结果。

::tip
`useFetch(url)` 几乎等同于 `useAsyncData(url, () => event.$fetch(url))`。 :br
这是针对最常见使用场景的开发者体验优化。（您可以在 [`useRequestFetch`](/docs/api/组合式函数/use-request-fetch) 中了解有关 `event.fetch` 的更多信息。）
::

:video-accordion{title="Watch a video from Alexander Lichter to dig deeper into the difference between useFetch and useAsyncData" videoId="0X-aOpSGabA"}

有些情况下使用 [`useFetch`](/docs/api/组合式函数/use-fetch) 组合式函数并不合适，例如当 CMS 或第三方提供自己的查询层时。在这种情况下，您可以使用 [`useAsyncData`](/docs/api/组合式函数/use-async-data) 来封装调用，同时保留该组合式函数提供的优势。

```vue [app/pages/users.vue]
<script setup lang="ts">
const { data, error } = await useAsyncData('users', () => myGetFunction('users'))

// This is also possible:
const { data, error } = await useAsyncData(() => myGetFunction('users'))
</script>
```

::note
`useAsyncData` 的第一个参数是一个唯一键，用于缓存第二个参数即查询函数的响应。通过直接传递查询函数，可以忽略该键，系统将自动生成该键。
:br :br
由于自动生成的键仅考虑 `useAsyncData` 被调用的位置，建议始终创建自己的键以避免不期望的行为，例如当您创建自定义组合式函数封装 `useAsyncData` 时。
:br :br
设置键有助于在使用 [`useNuxtData`](/docs/api/组合式函数/use-nuxt-data) 的组件之间共享相同数据，或[刷新特定数据](/docs/api/utils/refresh-nuxt-data#refresh-specific-data)。
::

```vue [app/pages/users/[id\\].vue]
<script setup lang="ts">
const { id } = useRoute().params

const { data, error } = await useAsyncData(`user:${id}`, () => {
  return myGetFunction('users', { id })
})
</script>
```

`useAsyncData` 组合式函数是一种很好的方式，用于封装并等待多个 `$fetch` 请求完成，然后处理结果。

```vue
<script setup lang="ts">
const { data: discounts, status } = await useAsyncData('cart-discount', async (_nuxtApp, { signal }) => {
  const [coupons, offers] = await Promise.all([
    $fetch('/cart/coupons', { signal }),
    $fetch('/cart/offers', { signal }),
  ])

  return { coupons, offers }
})
// discounts.value.coupons
// discounts.value.offers
</script>
```

::note
`useAsyncData` 用于获取和缓存数据，而不是触发副作用，如调用 Pinia 动作，因为这可能导致意外行为，例如带有空值值的重复执行。如果您需要触发副作用，请使用 [`callOnce`](/docs/api/utils/call-once) 工具函数来实现。

```vue
<script setup lang="ts">
const offersStore = useOffersStore()

// you can't do this
await useAsyncData(() => offersStore.getOffer(route.params.slug))
</script>
```
::

## 返回值

`useFetch` 和 `useAsyncData` 的返回值如下。

- `data`: 传入的异步函数的结果。
- `refresh`/`execute`: 用于刷新 `handler` 函数返回数据的函数。
- `clear`: 用于将 `data` 设置为 `undefined`（或提供时 `options.default()` 的值），将 `error` 设置为 `undefined`，将 `status` 设置为 `idle`，并取消所有当前待处理的请求。
- `error`: 数据获取失败的错误对象。
- `status`: 表示数据请求状态的字符串（`"idle"`、`"pending"`、`"success"`、`"error"`）。

::note
`data`、`error` 和 `status` 是 Vue refs，可在 `<script setup>` 中通过 `.value` 访问。
::

默认情况下，Nuxt 在 `refresh` 完成之前不会再次执行。

::note
如果您未在服务器上获取数据（例如使用 `server: false`），则数据*不会*在 hydration 完成前被获取。这意味着即使您在客户端侧等待 `useFetch`，`data` 在 `<script setup>` 中仍将为 undefined。
::

## 选项

`useAsyncData` (/docs/api/组合式函数/use-async-data) 和 `useFetch` (/docs/api/组合式函数/use-fetch) 返回相同的对象类型，并接受一组通用的选项作为其最后一个参数。它们可以帮助您控制组合式函数的行为，如导航阻塞、缓存或执行。

### Lazy

默认情况下，数据获取组合式函数会在使用 Vue 的 Suspense 导航到新页面之前等待其异步函数完成。通过 `lazy` 选项可以在客户端侧导航时忽略此功能。在这种情况下，您必须手动使用 `status` 值处理加载状态。

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { status, data: posts } = useFetch('/api/posts', {
  lazy: true,
})
</script>

<template>
  <!-- you will need to handle a loading state -->
  <div v-if="status === 'pending'">
    Loading ...
  </div>
  <div v-else>
    <div v-for="post in posts">
      <!-- do something -->
    </div>
  </div>
</template>
```

您还可以使用 [`useLazyFetch`](/docs/api/组合式函数/use-lazy-fetch) 和 `useLazyAsyncData` 作为便捷方法来实现相同的功能。

```vue twoslash
<script setup lang="ts">
const { status, data: posts } = useLazyFetch('/api/posts')
</script>
```

### 仅客户端获取

默认情况下，数据获取组合式函数会在客户端和服务器环境中执行其异步函数。将 `server` 选项设置为 `false` 即可仅在客户端侧执行调用。在初始加载时，在 hydration 完成前不会获取数据，因此您需要处理待处理状态；不过在后续的客户端侧导航中，数据将在页面加载前被等待。

结合 `lazy` 选项，这适用于在首次渲染时不需要的数据（例如，非 SEO 敏感数据）。

```ts twoslash
/* This call is performed before hydration */
const articles = await useFetch('/api/article')

/* This call will only be performed on the client */
const { status, data: comments } = useFetch('/api/comments', {
  lazy: true,
  server: false,
})
```

`useFetch` 组合式函数应在 setup 方法中调用，或在生命周期钩子中直接在函数顶层调用，否则应使用 [`$fetch` 方法](/docs/getting-started/data-fetching#fetch)。

### 最小化负载大小

`pick` 选项有助于通过仅选择您希望从组合式函数中返回的字段来减少 HTML 文档中存储的负载大小。

```vue
<script setup lang="ts">
/* only pick the fields used in your template */
const { data: mountain } = await useFetch('/api/mountains/everest', {
  pick: ['title', 'description'],
})
</script>

<template>
  <h1>{{ mountain.title }}</h1>
  <p>{{ mountain.description }}</p>
</template>
```

如果您需要更多控制或需要对多个对象进行映射，可以使用 `transform` 函数来修改查询结果。

```ts
const { data: mountains } = await useFetch('/api/mountains', {
  transform: (mountains) => {
    return mountains.map(mountain => ({ title: mountain.title, description: mountain.description }))
  },
})
```

::note
`pick` 和 `transform` 都不会阻止不需要的数据被初始获取。但它们会防止不需要的数据被添加到从服务器传输到客户端的负载中。
::

### 缓存和重新请求

#### 键

[`useFetch`](/docs/api/组合式函数/use-fetch) 和 [`useAsyncData`](/docs/api/组合式函数/use-async-data) 使用键来防止重复获取相同数据。

- [`useFetch`](/docs/api/组合式函数/use-fetch) 从 URL、fetch 选项以及源代码中调用位置生成键。这意味着在不同组件中使用相同 URL 的两次 `useFetch` 调用将具有**不同的**键，并各自执行各自的请求。要在多个组件之间共享相同数据，请在作为最后一个参数传递的 `options` 对象中提供相同的显式 `key`。
- [`useAsyncData`](/docs/api/组合式函数/use-async-data) 如果第一个参数是字符串，则将其作为键使用。如果第一个参数是执行查询的处理器函数，那么将为您生成一个唯一于源代码中 `useAsyncData` 调用位置的键。

::tip
要按键获取缓存数据，可以使用 [`useNuxtData`](/docs/api/组合式函数/use-nuxt-data)。
::

:video-accordion{title="Watch a video from Vue School on caching data with the key option" videoId="1026410044" platform="vimeo"}

#### 共享状态和选项一致性

当多个组件使用 `useAsyncData` 或 `useFetch` 的相同键时，它们将共享相同的 `data`、`error` 和 `status` 引用。这确保了组件间的一致性，但要求某些选项保持一致。

以下选项**必须在所有使用相同键的调用中保持一致**：
- `handler` 函数
- `deep` 选项
- `transform` 函数
- `pick` 数组
- `getCachedData` 函数
- `default` 值

```ts
// ❌ This will trigger a development warning
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: false })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: true })
```

以下选项**可以安全地不同**，而不会引发警告：
- `server`
- `lazy`
- `immediate`
- `dedupe`
- `watch`

```ts
// ✅ This is allowed
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: true })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: false })
```

如果您需要独立的实例，请使用不同的键：

```ts
// These are completely independent instances
const { data: users1 } = useAsyncData('users-1', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
const { data: users2 } = useAsyncData('users-2', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
```

#### 响应式键

您可以将计算引用、普通引用或获取函数作为键，从而实现动态数据获取，当依赖项发生变化时数据会自动更新：

```ts
// Using a computed property as a key
const userId = ref('123')
const { data: user } = useAsyncData(
  computed(() => `user-${userId.value}`),
  () => fetchUser(userId.value),
)

// When userId changes, the data will be automatically refetched
// and the old data will be cleaned up if no other components use it
userId.value = '456'
```

#### 刷新与执行

如果您希望手动获取或刷新数据，请使用组合式函数提供的 `execute` 或 `refresh` 函数。

```vue twoslash
<script setup lang="ts">
const { data, error, execute, refresh } = await useFetch('/api/users')
</script>

<template>
  <div>
    <p>{{ data }}</p>
    <button @click="() => refresh()">
      Refresh data
    </button>
  </div>
</template>
```

`execute` 函数是 `refresh` 的别名，功能完全相同，但在获取[不是立即发生](/docs/getting-started/data-fetching#not-immediate)的情况下更具语义性。

::tip
要全局重新获取或使缓存数据失效，请参见 [`clearNuxtData`](/docs/api/utils/clear-nuxt-data)和 [`refreshNuxtData`](/docs/api/utils/refresh-nuxt-data)。
::

#### 清除

如果您出于某种原因需要清除提供的数据，而不需要知道传递给 `clearNuxtData` 的具体键，可以使用组合式函数提供的 `clear` 函数。

```vue twoslash
<script setup lang="ts">
const { data, clear } = await useFetch('/api/users')

const route = useRoute()
watch(() => route.path, (path) => {
  if (path === '/') {
    clear()
  }
})
</script>
```

#### 监听

要每次应用程序中的其他响应式值发生变化时重新运行获取函数，请使用 `watch` 选项。您可以将它用于一个或多个*可监听*元素。

```vue twoslash
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch('/api/users', {
  /* Changing the id will trigger a refetch */
  watch: [id],
})
</script>
```

请注意，**监听一个响应式值不会改变获取的 URL**。例如，这将保持获取用户的相同初始 ID，因为 URL 是在函数被调用时构建的。

```vue
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch(`/api/users/${id.value}`, {
  watch: [id],
})
</script>
```

如果您需要根据响应式值更改 URL，可能更适合使用[计算式 URL](/docs/getting-started/data-fetching#computed-url)。

当提供响应式获取选项时，它们将自动被监听并触发重新获取。在某些情况下，通过指定 `watch: false` 可以禁用此行为。

```ts
const id = ref(1)

// Won't automatically refetch when id changes
const { data, execute } = await useFetch('/api/users', {
  query: { id }, // id is watched by default
  watch: false, // disables automatic watching of id
})

// doesn't trigger refetch
id.value = 2
```

#### 计算式 URL

有时您可能需要从响应式值计算出一个 URL，并在这些值每次变化时刷新数据。与其手动处理，不如将每个参数作为响应式值附加。Nuxt 将自动使用该响应式值，并在其发生变化时重新获取。

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch('/api/user', {
  query: {
    user_id: id,
  },
})
</script>
```

在更复杂的 URL 构建情况下，您可以将其作为一个[计算式获取器](https://vuejs.org/guide/essentials/computed)的回调函数，该回调返回 URL 字符串。

每当依赖项发生变化时，数据将使用新构建的 URL 获取。结合 [非即时](/docs/getting-started/data-fetching#not-immediate) 功能，你可以等待反应式元素发生变化后再进行获取。

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch(() => `/api/users/${id.value}`, {
  immediate: false,
})
</script>

<template>
  <div>
    <!-- disable the input while fetching -->
    <input
      v-model="id"
      type="number"
      :disabled="status === 'pending'"
    >

    <div v-if="status === 'idle'">
      Type a user ID
    </div>

    <div v-else-if="status === 'pending'">
      Loading ...
    </div>

    <div v-else>
      {{ data }}
    </div>
  </div>
</template>
```

如果其他反应式值发生变化时需要强制刷新，你还可以 [监视其他值](/docs/getting-started/data-fetching#watch)。

### 非即时

`useFetch` 组合式函数将在被调用时立即开始获取数据。你可以通过设置 `immediate: false` 来阻止此行为，例如等待用户交互。

为此，你需要使用 `status` 来处理获取生命周期，`execute` 用于启动数据获取。

```vue
<script setup lang="ts">
const { data, error, execute, status } = await useLazyFetch('/api/comments', {
  immediate: false,
})
</script>

<template>
  <div v-if="status === 'idle'">
    <button @click="execute">
      Get data
    </button>
  </div>

  <div v-else-if="status === 'pending'">
    Loading comments...
  </div>

  <div v-else>
    {{ data }}
  </div>
</template>
```

为了获得更精细的控制，`status` 变量可以设置为：

- `idle`：当获取尚未开始时
- `pending`：当获取已开始但尚未完成时
- `error`：当获取失败时
- `success`：当获取成功完成时

## 传递头部和 Cookie

在浏览器中调用 `$fetch` 时，用户头部如 `cookie` 将直接发送到 API。

通常，在服务器端渲染过程中，出于安全考虑，`$fetch` 不会包含用户的浏览器 Cookie，也不会在获取响应中传递 Cookie。

然而，当在服务器上使用相对 URL 调用 `useFetch` 时，Nuxt 将使用 [`useRequestFetch`](/docs/api/组合式函数/use-request-fetch) 来代理头部和 Cookie（除了不应被转发掉的头部，如 `host`）。

### 在 SSR 响应中通过服务器端 API 调用传递 Cookie

 如果你希望从内部请求向客户端传递/代理 Cookie，你需要自己处理这一点。

```ts [app/composables/fetch.ts]
import { appendResponseHeader } from 'h3'
import type { H3Event } from 'h3'

export const fetchWithCookie = async (event: H3Event, url: string) => {
  /* Get the response from the server endpoint */
  const res = await $fetch.raw(url)
  /* Get the cookies from the response */
  const cookies = res.headers.getSetCookie()
  /* Attach each cookie to our incoming Request */
  for (const cookie of cookies) {
    appendResponseHeader(event, 'set-cookie', cookie)
  }
  /* Return the data of the response */
  return res._data
}
```

```vue
<script setup lang="ts">
// This composable will automatically pass cookies to the client
const event = useRequestEvent()

const { data: result } = await useAsyncData(() => fetchWithCookie(event!, '/api/with-cookie'))

onMounted(() => console.log(document.cookie))
</script>
```

export default defineNuxtComponent({

## 从服务器到客户端的数据序列化

当使用 `useAsyncData` 和 `useLazyAsyncData` 将服务器获取的数据传输到客户端时（以及任何利用 [Nuxt payload](/docs/api/组合式函数/use-nuxt-app#payload) 的情况），数据会通过 [`devalue`](https://github.com/sveltejs/devalue) 进行序列化。这使我们不仅可以传输基本 JSON 数据，还可以序列化并恢复/反序列化更高级的数据类型，如正则表达式、日期、Map 和 Set、`ref`、`reactive`、`shallowRef`、`shallowReactive` 和 `NuxtError` 等。

对于 Nuxt 不支持的类型，您也可以定义自己的序列化/反序列化函数。您可以在 [`useNuxtApp`](/docs/api/组合式函数/use-nuxt-app#payload) 文档中了解更多内容。

::note
请注意，当使用 `$fetch` 或 `useFetch` 获取来自服务器路由的数据时，此规则并不适用——请参见下一节以获取更多信息。
::

## API 路由数据的序列化

当从 `server` 目录获取数据时，响应数据通过 `JSON.stringify` 进行序列化。然而，由于序列化仅适用于 JavaScript 基本类型，Nuxt 会尽力将 `$fetch` 和 [`useFetch`](/docs/api/组合式函数/use-fetch) 的返回类型转换为实际值。

::read-more{icon="i-simple-icons-mdnwebdocs" to="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify#description" target="_blank"}
了解更多关于 `JSON.stringify` 限制的信息。
::

### 示例

```ts [server/api/foo.ts]
export default defineEventHandler(() => {
  return new Date()
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Type of `data` is inferred as string even though we returned a Date object
const { data } = await useFetch('/api/foo')
</script>
```

### 自定义序列化函数

要自定义序列化行为，可以在返回的对象上定义 `toJSON` 函数。如果您定义了 `toJSON` 方法，Nuxt 会尊重该函数的返回类型，不会尝试转换类型。

```ts [server/api/bar.ts]
export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    toJSON () {
      return {
        createdAt: {
          year: this.createdAt.getFullYear(),
          month: this.createdAt.getMonth(),
          day: this.createdAt.getDate(),
        },
      }
    },
  }
  return data
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Type of `data` is inferred as
// {
//   createdAt: {
//     year: number
//     month: number
//     day: number
//   }
// }
const { data } = await useFetch('/api/bar')
</script>
```

### 使用替代序列化器

目前 Nuxt 不支持替代 `JSON.stringify` 的序列化器。不过，您可以将有效载荷作为普通字符串返回，并使用 `toJSON` 方法来保持类型安全。

在下面的示例中，我们使用 [superjson](https://github.com/flightcontrolhq/superjson) 作为序列化器。

```ts [server/api/superjson.ts]
import superjson from 'superjson'

export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    // Workaround the type conversion
    toJSON () {
      return this
    },
  }

  // Serialize the output to string, using superjson
  return superjson.stringify(data) as unknown as typeof data
})
```

```vue [app/app.vue]
<script setup lang="ts">
import superjson from 'superjson'

// `date` is inferred as { createdAt: Date } and you can safely use the Date object methods
const { data } = await useFetch('/api/superjson', {
  transform: (value) => {
    return superjson.parse(value as unknown as string)
  },
})
</script>
```

## 配方

### 通过 POST 请求消费 SSE（服务器发送事件）

::tip
如果您通过 GET 请求消费 SSE，可以使用 [`EventSource`](https://developer.mozilla.org/en-US/docs/Web/API/EventSource) 或 VueUse 组合式函数 [`useEventSource`](https://vueuse.org/core/useeventsource/)。
::

当通过 POST 请求消费 SSE 时，您需要手动处理连接。以下是实现方法：

```ts
// Make a POST request to the SSE endpoint
const response = await $fetch<ReadableStream>('/chats/ask-ai', {
  method: 'POST',
  body: {
    query: 'Hello AI, how are you?',
  },
  responseType: 'stream',
})

// Create a new ReadableStream from the response with TextDecoderStream to get the data as text
const reader = response.pipeThrough(new TextDecoderStream()).getReader()

// Read the chunk of data as we get it
while (true) {
  const { value, done } = await reader.read()

  if (done) { break }

  console.log('Received:', value)
}
```

### 并行请求

当请求之间不依赖彼此时，可以使用 `Promise.all()` 并行执行它们以提高性能。

```ts
const { data } = await useAsyncData((_nuxtApp, { signal }) => {
  return Promise.all([
    $fetch('/api/comments/', { signal }),
    $fetch('/api/author/12', { signal }),
  ])
})

const comments = computed(() => data.value?.[0])
const author = computed(() => data.value?.[1])
```
