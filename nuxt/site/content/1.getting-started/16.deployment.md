Nuxt 应用可以部署在 Node.js 服务器上，用于静态托管的前置渲染，或者部署到无服务器或边缘（CDN）环境。

::tip
如果您需要支持 Nuxt 的云提供商列表，请查看 [托管提供商](/deploy) 部分。
::

## Node.js 服务器

使用 Nitro 的 Node.js 服务器预设，可以在任何 Node 托管环境中进行部署。

- **默认输出格式**：如果未指定或自动检测 <br>
- 仅加载必要的代码块以优化冷启动时间 <br>
- 适用于将 Nuxt 应用部署到任何 Node.js 托管环境

### 入口点

当使用 Node 服务器预设运行 `nuxt build` 时，结果将是一个可运行的 Node 服务器入口点。

```bash [Terminal]
NODE_ENV=production node .output/server/index.mjs
```

这将启动您的生产环境 Nuxt 服务器，默认监听 3000 端口。

::important
在运行服务器时设置 `NODE_ENV=production`。某些依赖项（尤其是 Vue Router）只有在设置此变量时才会移除仅开发环境的警告，因此不设置该变量可能会导致日志中出现类似 `[Vue Router warn]: No match found for location with path …` 的未匹配路由信息。
::

它遵循以下运行时环境变量：

- `NITRO_PORT` 或 `PORT`（默认值为 `3000`）
- `NITRO_HOST` 或 `HOST`（默认值为 `'0.0.0.0'`）
- `NITRO_SSL_CERT` 和 `NITRO_SSL_KEY` - 如果两者都存在，将以 HTTPS 模式启动服务器。在绝大多数情况下，除非用于测试，否则不应使用此模式，且 Nuxt 服务器应运行在 nginx 或 Cloudflare 等反向代理后面，这些代理会终止 SSL。

### 在多个路径上提供相同的构建结果

对于常规的子路径部署，设置 [`app.baseURL`](/docs/api/nuxt-config#baseurl) 或 `NUXT_APP_BASE_URL` 环境变量。

如果反向代理故意在多个公共路径上显示相同的渲染页面，Nuxt 可能会将浏览器 URL 替换为用于服务器渲染的路径。您可以通过在服务器插件中移除渲染后的路径来保留浏览器 URL：

```ts [app/plugins/preserve-proxy-url.server.ts]
export default defineNuxtPlugin((nuxtApp) => {
  delete nuxtApp.payload.path
})
```

仅在代理已经处理所有公共路径的资源和路由时使用此方法。如果没有渲染后的路径，Nuxt 无法纠正请求 URL 与服务器渲染路由之间的真实不匹配。

### PM2

[PM2](https://pm2.keymetrics.io/) (Process Manager 2) 是一种快速且简单的解决方案，可用于在服务器或虚拟机上托管你的 Nuxt 应用。

要使用 `pm2`，请使用 `ecosystem.config.cjs`：

```ts [ecosystem.config.cjs]
module.exports = {
  apps: [
    {
      name: 'NuxtAppName',
      port: '3000',
      exec_mode: 'cluster',
      instances: 'max',
      script: './.output/server/index.mjs',
      env: {
        NODE_ENV: 'production',
      },
    },
  ],
}
```

### Cluster Mode

你可以设置 `NITRO_PRESET=node_cluster`，以利用 Node.js [cluster](https://nodejs.org/dist/latest/docs/api/cluster.html) 模块实现多进程性能优化。

默认情况下，工作负载通过轮询策略分配到工作进程。

## 静态托管

有两种方法可以将 Nuxt 应用部署到任何静态托管服务中：

- 静态站点生成（SSG），设置 `ssr: true` 会在构建时预渲染应用的路由。（这是运行 `nuxt generate` 时的默认行为。）它还会生成 `/200.html` 和 `/404.html` 单页应用回退页面，这些页面可以在客户端渲染动态路由或 404 错误（不过你可能需要在静态托管服务上配置此设置）。请参阅 [200.html 和 404.html 是什么？](/docs/guide/concepts/rendering#what-are-200html-and-404html)。
- 或者，你可以设置 `ssr: false` 来预渲染网站（静态单页应用）。这将生成包含空 `<div id="__nuxt"></div>` 的 HTML 页面，而 Vue 应用通常会在其中渲染。这样会失去预渲染带来的许多 SEO 优势，因此建议使用 [`<ClientOnly>`](/docs/api/components/client-only) 包裹无法在服务器上渲染的网站部分（如果有的话）。

预渲染的路由还会生成 `_payload.json` 文件，其中包含了构建时捕获的数据，Nuxt 会在客户端导航时复用这些数据。更多关于 [payload 提取](/docs/getting-started/prerendering#payload-extraction) 的信息请参考。

### 静态回退页面

Nuxt 可以为静态托管服务生成两个回退页面：

- `200.html` 是单页应用回退页面。你可以配置托管服务在未匹配的路由下提供该文件，以便客户端路由处理 URL。
- `404.html` 是未找到的回退页面。你可以配置托管服务在应保持 404 状态的路由下提供该文件。

`nuxt generate` 和 `nuxt build --prerender` 会自动生成这些文件。如果你使用带有路由规则的 `nuxt build` 来预渲染选定的路由，请明确添加回退页面：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/200.html': { prerender: true },
  },
})
```

默认情况下，两种备用页面都是空的壳层。在构建时，将 [`experimental.prerenderErrorPages`](/docs/guide/concepts/rendering#server-rendering-the-error-page) 设置为服务器渲染，使你的 `error.vue` 文件被转换为 `404.html`。

某些提供商会使用 `200.html`，有些使用 `404.html`，还有一些允许你同时配置两者。部署后，请检查你的托管提供商的静态备用页面或重写设置。

:read-more{title="Nuxt prerendering" to="/docs/getting-started/prerendering"}

### 仅客户端端渲染

如果你不想预先渲染路由，使用静态托管的另一种方法是在 `nuxt.config` 文件中将 `ssr` 属性设置为 `false`。然后，`nuxt generate` 命令会生成 `.output/public/index.html` 入口点和 JavaScript 包，就像传统的客户端端 Vue.js 应用一样。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  ssr: false,
})
```

## 预设

除了 Node.js 服务器和静态托管服务之外，Nuxt 项目还可以使用几种经过充分测试的预设和少量配置进行部署。

你可以在 [`nuxt.config.ts`](/docs/directory-structure/nuxt-config) 文件中明确设置所需的预设：

```ts twoslash [nuxt.config.ts]
// @errors: 2353
export default defineNuxtConfig({
  nitro: {
    preset: 'node-server',
  },
})
```

... 或者在运行 `nuxt build` 时使用 `NITRO_PRESET` 环境变量：

```bash [Terminal]
NITRO_PRESET=node-server nuxt build
```

🔎 请查看 [Nitro 部署](https://nitro.build/deploy) 了解所有可能的部署预设和提供商。

## CDN 代理

在大多数情况下，Nuxt 可以处理由第三方内容生成的文件，这些内容并非由 Nuxt 自身生成或创建。但有时此类内容可能会引起问题，尤其是 Cloudflare 的“压缩和安全选项”。

因此，你应该确保 Cloudflare 中的以下选项未被勾选/禁用。否则，不必要的重新渲染或 hydration 错误可能会影响你的生产环境应用。

1. 速度 > 设置 > 内容优化 > 禁用 “Rocket Loader™”
2. 安全 > 设置 > 禁用 “电子邮件地址混淆”

通过这些设置，你可以确保 Cloudflare 不会向你的 Nuxt 应用注入可能带来不良副作用的脚本。

::tip
Cloudflare 仪表板上的位置有时会变化，所以不要犹豫，随时查看。
::
