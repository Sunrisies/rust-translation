Nuxt 是一个免费且[开源框架](https://github.com/nuxt/nuxt)，它提供了一种直观且可扩展的方式来创建类型安全、高效且符合生产标准的全栈 Web 应用和网站，使用 [Vue.js](https://vuejs.org)。

我们设计了所有功能，让你能够从零开始编写 `.vue` 文件，在开发过程中享受热模块替换，而在生产环境中通过默认的服务器端渲染实现高性能应用。

Nuxt 没有供应商锁定问题，你可以将应用部署[到任何地方，甚至边缘环境](/blog/nuxt-on-the-edge)。

::tip
如果你希望在浏览器中尝试 Nuxt，可以在我们的在线沙箱环境中[进行体验](/docs/getting-started/installation#play-online)。
::

## 自动化与规范

Nuxt 使用规范及明确的目录结构来自动化重复任务，使开发者能够专注于功能开发。配置文件仍然可以自定义并覆盖其默认行为。

- **基于文件的路由：**根据 [`app/pages/` 目录](/docs/directory-structure/app/pages)的结构定义路由。这有助于更好地组织应用，避免手动配置路由的需要。
- **代码分割：** Nuxt 会自动将代码分割成较小的块，从而有助于减少应用的初始加载时间。
- **内置的服务器端渲染：**Nuxt 自带 SSR 功能，因此无需自行设置独立服务器。
- **自动导入：**在相应的目录中编写 Vue 组合式函数和组件，即可使用它们，无需通过导入来启用摇树优化和优化的 JS 包优势。
- **数据获取工具：**Nuxt 提供组合式函数来处理与 SSR 兼容的数据获取以及不同的策略。
- **无需配置的 TypeScript 支持：**无需学习 TypeScript，利用我们自动生成的类型和 `tsconfig.json` 即可编写类型安全的代码。
- **配置好的构建工具：**默认使用 [Vite](https://vite.dev) 来支持开发过程中的热模块替换 (HMR)，并采用最佳实践对代码进行生产环境打包。

Nuxt 会处理这些事情，并提供前端和后端功能，让你能够专注于最重要的事情：**构建你的 Web 应用**。

## 服务器端渲染

默认情况下，Nuxt 就具备内置的服务器端渲染 (SSR) 功能，无需自行配置服务器，这对 Web 应用有很多好处：

- **更快的初始页面加载时间：** Nuxt 会将完全渲染好的 HTML 页面发送给浏览器，从而立即显示。这可以在较慢的网络或设备上提供更快的感知页面加载时间和更好的用户体验 (UX)。
- **提升 SEO 效果：** 搜索引擎能更好地索引 SSR 页面，因为 HTML 内容可以立即获取，而不需要 JavaScript 在客户端端渲染内容。
- **在低性能设备上获得更好的性能：** 它减少了需要在客户端端下载和执行的 JavaScript 量，这对处理繁重的 JavaScript 应用的低性能设备非常有利。
- **更好的可访问性：** 内容在初始页面加载时即可获取，从而改善依赖屏幕阅读器或其他辅助技术的用户的可访问性。
- **更简单的缓存机制：** 页面可以在服务器端进行缓存，通过减少生成和发送内容到客户端的时间来进一步提升性能。

总体而言，服务器端渲染可以提供更快、更高效的用户体验，同时还能改善搜索引擎优化和可访问性。

由于 Nuxt 是一个多功能框架，你可以通过 `nuxt generate` 将整个应用静态渲染到静态托管服务中。
可以通过 `ssr: false` 选项全局禁用 SSR，或者通过设置 `routeRules` 选项来使用混合渲染方式。

:read-more{title="Nuxt 渲染模式" to="/docs/guide/concepts/rendering"}

### 服务器引擎

Nuxt 服务器引擎 [Nitro](https://nitro.build/) 解锁了全新的全栈功能。

在开发过程中，它使用 Rollup 和 Node.js 工作进程来处理服务器代码和上下文隔离。它还会从 `server/api/` 文件和 `server/middleware/` 中读取服务器中间件来生成服务器 API。

在生产环境中，Nitro 将你的应用和服务器合并到同一个通用 `.output` 目录中。这个输出文件很轻量：经过压缩处理，并从任何 Node.js 模块中移除（polyfills 除外）。你可以将这个输出部署到任何支持 JavaScript 的系统上，包括 Node.js、Serverless、Workers、边缘渲染或纯静态环境。

:read-more{title="Nuxt 服务器引擎" to="/docs/guide/concepts/server-engine"}

### 可生产使用

Nuxt 应用可以部署在 Node 或 Deno 服务器上，也可以预先渲染后托管在静态环境中，或者部署到无服务器和边缘服务提供商上。

:read-more{title="部署章节" to="/docs/getting-started/deployment"}

### 架构

Nuxt 由不同的 [核心包](https://github.com/nuxt/nuxt/tree/main/packages)组成：

- 核心引擎：[nuxt](https://github.com/nuxt/nuxt/tree/main/packages/nuxt)
- 打包工具：[@nuxt/vite-builder](https://github.com/nuxt/nuxt/tree/main/packages/vite)、[@nuxt/rspack-builder](https://github.com/nuxt/nuxt/tree/main/packages/rspack) 和 [@nuxt/webpack-builder](https://github.com/nuxt/nuxt/tree/main/packages/webpack)
- 命令行界面：[@nuxt/cli](https://github.com/nuxt/cli)
- 服务器引擎：[nitro](https://github.com/nitrojs/nitro)
- 开发工具包：[@nuxt/kit](https://github.com/nuxt/nuxt/tree/main/packages/kit)

我们建议阅读每个概念，以便全面了解 Nuxt 的功能以及各个包的作用范围。
