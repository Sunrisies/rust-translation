在应用运行期间，某些错误可能会在运行时意外出现。在这种情况下，可以使用 `error.vue` 文件来覆盖默认的错误文件，并美观地显示错误。

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps<{ error: NuxtError }>()
</script>

<template>
  <div>
    <h1>{{ error.status }}</h1>
    <NuxtLink to="/">Go back home</NuxtLink>
  </div>
</template>
```

::note
尽管它被称为“错误页面”，但它不是路由，不应放在 `~/pages` 目录中。出于同样的原因，也不应在该页面中使用 `definePageMeta`。不过，你仍然可以在错误文件中使用布局，通过利用 [`NuxtLayout`](/docs/api/components/nuxt-layout) 组件并指定布局名称来实现。
::

错误页面有一个单一属性 - `error`，其中包含需要你处理的错误信息。

`error` 对象提供以下字段：
```ts
interface NuxtError {
  status: number
  fatal: boolean
  unhandled: boolean
  statusText?: string
  data?: unknown
  cause?: unknown
  // legacy/deprecated equivalent of `status`
  statusCode: number
  // legacy/deprecated equivalent of `statusText`
  statusMessage?: string
}
```

在生产环境中，当服务器渲染错误页面时，它仅接收由 `createError` 创建的 `message` 和 `data` 信息。应用抛出的其他任何错误，例如失败的 `$fetch` 操作，都会被标记为 `unhandled`，并传递其状态及通用消息到错误页面和负载中。为了显示其详细信息，需要捕获该错误并生成一个客户端可见的 `createError`。

如果你有包含自定义字段的错误，这些字段将会丢失；你应该将其分配给 `data`：

```ts
throw createError({
  status: 404,
  statusText: 'Page Not Found',
  data: {
    myCustomField: true,
  },
})
```
