Nuxt 提供 `app/app.config.ts` 配置文件，可在运行时通过生命周期函数或使用 nuxt 插件通过 HMR（热模块替换）编辑该文件，从而在应用程序中暴露响应式配置。

您可以使用 `app.config.ts` 文件轻松提供运行时应用程序配置。该文件的扩展名可以是 `.ts`、`.js` 或 `.mjs`。

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  foo: 'bar',
})
```

::caution
不要将任何敏感值放在 `app.config` 文件中，因为它会被暴露给用户客户端包。
::

::note
当配置自定义 [`srcDir`](/docs/api/nuxt-config#srcdir) 时，请确保将 `app.config` 文件放置在新的 `srcDir` 路径的根目录。
::

## 使用方式

为了将配置和环境变量暴露给应用程序的其他部分，您需要在 `app.config` 文件中定义配置。

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  theme: {
    primaryColor: '#ababab',
  },
})
```

现在，无论是在服务器渲染页面时还是在浏览器中，我们都可以使用 [`useAppConfig`](/docs/api/组合式函数/use-app-config) 组合式函数来访问 `theme`。

```vue [app/pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()

console.log(appConfig.theme)
</script>
```

`updateAppConfig` (/docs/api/utils/update-app-config) 工具可用于在运行时更新 `app.config`。

```vue [app/pages/index.vue]
<script setup>
const appConfig = useAppConfig() // { foo: 'bar' }

const newAppConfig = { foo: 'baz' }

updateAppConfig(newAppConfig)

console.log(appConfig) // { foo: 'baz' }
</script>
```

::read-more{to="/docs/api/utils/update-app-config"}
了解更多关于 `updateAppConfig` 工具的信息。
::

## App 配置的类型定义

Nuxt 会尝试从提供的应用程序配置自动生成 TypeScript 接口，因此您无需自行定义类型。

完全推断出的类型仅适用于应用程序代码（组件、组合式函数、插件等）。在服务器路由、`shared/` 目录和 `nuxt.config` 中的代码中，`app.config` 文件中定义的键被定义为 `unknown`：在那里定义类型会要求在应用程序上下文之外对应用程序代码进行类型检查，而此时无法使用应用程序自动导入。在 `nuxt.config` 的 `appConfig` 选项中内联定义的键则在所有地方都被定义为特定类型。如果您需要在应用程序代码之外定义其他键，可以如下所述扩展 `SharedAppConfig` 接口。增强文件的位置决定了哪些上下文可以访问它：`shared/` 目录中的 `.d.ts` 文件覆盖应用程序代码、共享代码和服务器路由。

然而，有些情况下您可能希望自行定义类型。可能有两种需要定义类型的场景。

### App 配置输入

`AppConfigInput` 可能被模块作者用于声明设置应用程序配置时有效的 _输入_ 选项。这不会影响 `useAppConfig()` 的类型。

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfigInput {
    /** Theme configuration */
    theme?: {
      /** Primary app color */
      primaryColor?: string
    }
  }
}

// It is always important to ensure you import/export something when augmenting a type
export {}
```

### App Config 输出

如果您希望在应用代码中输入调用 [`useAppConfig()`](/docs/api/组合式函数/use-app-config) 的结果，则您需要扩展 `AppConfig`。在应用代码之外（服务器路由、`shared/` 目录和 `nuxt.config`）中，`useAppConfig()` 返回 `SharedAppConfig`，因此请扩展该接口。

::warning
在输入 `AppConfig` 时请注意，因为会覆盖 Nuxt 根据实际定义的应用配置推断出的类型。
::

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfig {
    // This will entirely replace the existing inferred `theme` property
    theme: {
      // You might want to type this value to add more specific types than Nuxt can infer,
      // such as string literal types
      primaryColor?: 'red' | 'blue'
    }
  }
}

// It is always important to ensure you import/export something when augmenting a type
export {}
```

## 合并策略

Nuxt 为应用程序中的 [层](/docs/getting-started/layers) 内的 `AppConfig` 使用自定义合并策略。

该策略通过 [函数合并器](https://github.com/unjs/defu#function-merger) 实现，允许为 `app.config` 中值为数组的每一个键定义自定义合并策略。

::note
函数合并器仅可在扩展层中使用，而不能在项目中的主 `app.config` 中使用。
::

以下是使用示例：

::code-group

```ts twoslash [layer/app/app.config.ts]
export default defineAppConfig({
  // Default array value
  array: ['hello'],
})
```

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  // Overwrite default array value by using a merger function
  array: () => ['bonjour'],
})
```

::

## 已知限制

从 Nuxt v3.3 开始，`app.config.ts` 文件与 Nitro 共享，导致以下限制：

1. 无法在 `app.config.ts` 中直接导入 Vue 组件。
2. 某些自动导入在 Nitro 环境中不可用。

这些限制是因为 Nitro 处理应用配置时没有完整的 Vue 组件支持。

虽然可以在 Nitro 配置中使用 Vite 插件作为 workaround，但此方法不推荐：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    vite: {
      plugins: [vue()],
    },
  },
})
```

::warning
使用这种 workaround 可能导致意外行为和错误。Vue 插件是众多在 Nitro 环境中不可用的插件之一。
::

相关问题：
- [Issue #19858](https://github.com/nuxt/nuxt/issues/19858)
- [Issue #19854](https://github.com/nuxt/nuxt/issues/19854)

::note
Nitro v3 将通过移除对应用配置的支持来解决这些限制。
您可以在 [此 pull request](https://github.com/nitrojs/nitro/pull/2521) 中跟踪进展。
::
