Nuxt 会自动读取 `app/plugins/` 目录中的文件，并在创建 Vue 应用时加载这些文件。

::note
所有插件都会自动注册，无需在 `nuxt.config` 中单独添加它们。
::

::note
可以在文件名中添加 `.server` 或 `.client` 后缀，以仅在服务器或客户端侧加载插件。
::

## 已注册的插件

只有目录顶层的文件（或任何子目录中的索引文件）才会被自动注册为插件。

```bash [Directory structure]
-| plugins/
---| foo.ts      // scanned
---| bar/
-----| baz.ts    // not scanned
-----| foz.vue   // not scanned
-----| index.ts  // currently scanned but deprecated
```

仅 `foo.ts` 和 `bar/index.ts` 会被注册。

要在子目录中添加插件，可以在 `nuxt.config.ts` 中使用 [`app/plugins`](/docs/api/nuxt-config#plugins-1) 选项。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  plugins: [
    '~/plugins/bar/baz',
    '~/plugins/bar/foz',
  ],
})
```

## 创建插件

传递给插件的唯一参数就是 [`nuxtApp`](/docs/api/组合式函数/use-nuxt-app)。

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  // Doing something with nuxtApp
})
```

### 对象语法插件

对于更高级的使用场景，也可以使用对象语法来定义插件。例如：

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  enforce: 'pre', // or 'post'
  async setup (nuxtApp) {
    // this is the equivalent of a normal functional plugin
  },
  hooks: {
    // You can directly register Nuxt app runtime hooks here
    'app:created' () {
      const nuxtApp = useNuxtApp()
      // do something in the hook
    },
  },
  env: {
    // Set this value to `false` if you don't want the plugin to run when rendering server-only or island components.
    islands: true,
  },
})
```

:video-accordion{title="亚历山大·利希特关于 Nuxt 插件对象语法的视频" videoId="2aXZyXB1QGQ"}

::note
如果使用对象语法，属性会被静态分析，从而生成更优化的构建结果。因此不应在运行时定义这些属性。 :br
例如，设置 `enforce: import.meta.server ? 'pre' : 'post'` 会破坏 Nuxt 对插件进行的任何优化。
使用对象语法时，Nuxt 会静态预加载所有钩子监听器，使您能够定义钩子而无需担心插件注册的顺序。
::

## 注册顺序

可以通过在文件名前加上“按字母顺序”的数字来控制插件的注册顺序。

```bash [Directory structure]
plugins/
 | - 01.myPlugin.ts
 | - 02.myOtherPlugin.ts
```

在这个例子中，`02.myOtherPlugin.ts` 可以访问 `01.myPlugin.ts` 注入的所有内容。

这在您有一个依赖另一个插件的插件时非常有用。

::note
如果您不熟悉“按字母顺序”的数字，请记住文件名是作为字符串排序的，而不是数字值。例如，`10.myPlugin.ts` 会在 `2.myOtherPlugin.ts` 之前。这就是为什么示例中将个位数数字前加 `0` 的原因。
::

## 加载策略

### 并行插件

默认情况下，Nuxt 按顺序加载插件。您可以将插件定义为 `parallel`，这样 Nuxt 不会在等待插件执行完成后再加载下一个插件。

```ts twoslash [plugins/my-plugin.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  parallel: true,
  async setup (nuxtApp) {
    // the next plugin will be executed immediately
  },
})
```

### 带有依赖的插件

如果某个插件在运行前需要等待另一个插件，可以将该插件的名称添加到 `dependsOn` 数组中。

```ts twoslash [plugins/depending-on-my-plugin.ts]
export default defineNuxtPlugin({
  name: 'depends-on-my-plugin',
  dependsOn: ['my-plugin'],
  async setup (nuxtApp) {
    // this plugin will wait for the end of `my-plugin`'s execution before it runs
  },
})
```

## 使用组合式函数

你可以在 Nuxt 插件中使用 [组合式函数](/docs/directory-structure/app/组合式函数) 以及 [工具函数](/docs/directory-structure/app/utils)：

```ts [app/plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const foo = useFoo()
})
```

不过，请注意存在一些限制和差异：

::important
**如果某个组合式函数依赖于稍后注册的另一个插件，它可能无法正常工作。** :br

插件按顺序依次被调用，位于其他所有内容之前。你可能会使用依赖于尚未被调用的插件的组合式函数。
::

::important
**如果某个组合式函数依赖于 Vue.js 生命周期，它将无法工作。** :br

通常，Vue.js 组合式函数与当前组件实例绑定，而插件仅与 [`nuxtApp`](/docs/api/组合式函数/use-nuxt-app) 实例绑定。
::

## 提供辅助函数

如果你希望在 [`NuxtApp`](/docs/api/组合式函数/use-nuxt-app) 实例上提供辅助函数，请在插件中通过 `provide` 键返回它。

::code-group
```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin(() => {
  return {
    provide: {
      hello: (msg: string) => `Hello ${msg}!`,
    },
  }
})
```
```ts twoslash [plugins/hello-object-syntax.ts]
export default defineNuxtPlugin({
  name: 'hello',
  setup () {
    return {
      provide: {
        hello: (msg: string) => `Hello ${msg}!`,
      },
    }
  },
})
```
::

然后你可以在组件中使用该辅助函数：

```vue [app/components/Hello.vue]
<script setup lang="ts">
// alternatively, you can also use it here
const { $hello } = useNuxtApp()
</script>

<template>
  <div>
    {{ $hello('world') }}
  </div>
</template>
```

::important
请注意，我们强烈建议使用 [组合式函数](/docs/directory-structure/app/组合式函数) 而不是提供辅助函数，以避免污染全局命名空间并保持主包大小最小化。
::

::warning
**如果您的插件提供了 `ref` 或 `computed`，它们不会在组件 `<template>` 中被解包。** :br
这是由于 Vue 处理非顶级模板中的 ref 的方式。你可以查阅 [Vue 文档](https://vuejs.org/guide/essentials/reactivity-fundamentals#caveat-when-unwrapping-in-templates)了解更多相关信息。
::

## 为插件添加类型注解

如果您从插件中返回辅助函数，它们将自动被添加类型注解；你会发现 `useNuxtApp()` 的返回值以及模板中的函数都被添加了类型注解。

::note
如果需要在另一个插件中使用提供的辅助函数，可以调用 [`useNuxtApp()`](/docs/api/组合式函数/use-nuxt-app) 来获取带类型注解的版本。但通常应避免此做法，除非您确定插件的调用顺序。
::

对于高级用例，您可以像这样声明注入属性的类型：

```ts [index.d.ts]
declare module '#app' {
  interface NuxtApp {
    $hello (msg: string): string
  }
}

declare module 'vue' {
  interface ComponentCustomProperties {
    $hello (msg: string): string
  }
}

export {}
```

## Vue 插件

如果您想使用 Vue 插件，例如 [vue-gtag](https://github.com/MatteoGabriele/vue-gtag) 来添加 Google Analytics 标签，可以使用 Nuxt 插件来实现。

首先，安装 Vue 插件依赖：

::code-group{sync="pm"}
```bash [npm]
npm install --save-dev vue-gtag-next
```
```bash [yarn]
yarn add --dev vue-gtag-next
```
```bash [pnpm]
pnpm add -D vue-gtag-next
```
```bash [bun]
bun add -D vue-gtag-next
```
```bash [deno]
deno add -D npm:vue-gtag-next
```
::

然后创建插件文件：

```ts [app/plugins/vue-gtag.client.ts]
import VueGtag, { trackRouter } from 'vue-gtag-next'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(VueGtag, {
    property: {
      id: 'GA_MEASUREMENT_ID',
    },
  })
  trackRouter(useRouter())
})
```

## Vue Directives

同样，你可以在插件中注册自定义 Vue 指令。

```ts twoslash [plugins/my-directive.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.directive('focus', {
    mounted (el) {
      el.focus()
    },
    getSSRProps (binding, vnode) {
      // you can provide SSR-specific props here
      return {}
    },
  })
})
```

::warning
如果你注册了 Vue 指令，则必须在客户端和服务器端都进行注册，除非你仅在一方渲染时使用该指令。如果指令仅在客户端有效，你可以将其移动到 `~/plugins/my-directive.client.ts`，并在 `~/plugins/my-directive.server.ts` 中提供用于服务器的“占位”指令。
::
