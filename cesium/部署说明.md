## 二、完整构建流程（官方源码更新后照这个走）

### 步骤 1：拉取最新版本源文件

git clone 在这台机器上会因 schannel 网络问题失败，用 gh API 并发下载：

```bash
cd D:/hy-mt2-bench/cesium-docs
python fetch_sources.py        # 从 main 分支拉取 985 个文档源 js 到 repo/
```

脚本只下载 JSDoc 源（`packages/engine/Source` + `packages/widgets/Source`，排除 ThirdParty/Workers），约 12MB，2 分钟。

### 步骤 2：增量翻译

```bash
# 先确认翻译服务在跑（8999 端口）
curl http://127.0.0.1:8999/health

python jsdoc_translator.py --stats    # 看有多少待翻
python jsdoc_translator.py --all      # 只翻哈希变化的（增量）
```

- 首次全量约 1.5 小时（984 文件，10226 注释块）
- 官方小更新时通常只有几十个文件变化，几分钟搞定
- 每翻完一篇存 `cache.json`，中断可重跑

### 步骤 3：质量修复（必做）

```bash
python fix_links.py      # 修复 {@link 类名} 被误翻成中文（会回退成英文原文）
python fix_types.py      # 修复类型表达式里 undefined->未定义 等
```

然后全量校验（确认代码零改动）：

```bash
python -c "
from pathlib import Path
src=Path('repo'); out=Path('translated')
bad=0; badline=0
for f in src.rglob('*.js'):
    of=out/f.relative_to(src)
    if not of.exists(): continue
    a=f.read_text(encoding='utf-8',errors='surrogateescape').splitlines()
    b=of.read_text(encoding='utf-8',errors='surrogateescape').splitlines()
    if len(a)!=len(b): badline+=1; continue
    bad+=sum(1 for x,y in zip(a,b) if x!=y and '*' not in x and '//' not in x)
print('行数不一致:',badline,'非注释行被改:',bad)
"
# 两个数字都必须是 0
```

### 步骤 4：生成中文 API 站

```bash
# 把译文同步到构建目录
cp -r translated/packages/engine/Source/. build/packages/engine/Source/
cp -r translated/packages/widgets/Source/. build/packages/widgets/Source/

# 用 JSDoc 生成（注意：版本号从源码 package.json 查，别猜）
cd build
CESIUM_VERSION="1.147.0" CESIUM_PACKAGES="engine,widgets" \
  npx jsdoc --configure Tools/jsdoc/conf.json --destination ../site-final2
```

关键点：
- `Tools/jsdoc/conf.json` 里 `allowUnknownTags: true`（新版有 @internal/@link 等标签）
- `build/node_modules` 软链到旧仓库 `/d/project/github/cesium/node_modules`（含 jsdoc + 模板依赖）
- 生成约 1 分钟，357 页

### 步骤 5：后处理（图片 + 统计 + 版本）

```bash
cd ..
cp -r site-final/Images site-final2/          # 44 张文档插图，JSDoc 不会自动复制
python inject_umami.py                        # 注入统计脚本（需先改成指向 site-final2）
python add_version_badge.py                   # 版本徽章 + 修正源码链接版本号
tar -czf cesium-api-zh.tar.gz -C site-final2 .
```

- Umami（Cesium 专用 id）：`252ee09e-9fd1-4687-9498-62fab5b83dd5`
- 版本标识：`Cesium v1.147 · 中文`（每个页面标题旁）+ 首页横幅
- 源码链接里的版本号一并修正（生成时传错会 404）

### 步骤 6：部署到服务器

```bash
# 上传
scp -P 22 cesium-api-zh.tar.gz root@175.27.135.250:/tmp/

# 部署（SSH 到服务器后）
ssh -p 22 root@175.27.135.250
D=/home/docker/caddy/www/cesium-docs
mv "$D" "${D}_old_$(date +%Y%m%d-%H%M%S)"   # 备份旧站
mkdir -p "$D"
tar -xzf /tmp/cesium-api-zh.tar.gz -C "$D"

# 验证
grep -c 252ee09e "$D/Appearance.html"        # 应为 1
grep -rl 'Cesium v1.147' "$D" --include='*.html' | wc -l   # 应为 357
```

静态文件更新**不需要 reload Caddy**。

## 三、踩过的坑（维护时注意）

1. **JSDoc 类型名被翻译**：`Destroyable`、`Cartographic` 被译成"可销毁""地图坐标"，导致链接失效。根因是嵌套花括号 `{{destroy: Function}}` 解析错位，`jsdoc_translator.py` 已修（平衡括号切分），旧译文用 `fix_links.py` 回退。
2. **模型输出标记泄漏**：`<##n>` 标记写在行中间导致泄漏、译文拆行导致行数错位——重翻那 13 个文件修复。
3. **图片缺失**：JSDoc 模板引用 `Images/CesiumLogo.png` 但不复制，必须手动 `cp -r site-final/Images site-final2/`。
4. **版本号别猜**：从源码 `package.json` 读真实版本（1.147.0），我一开始写 1.140.0 导致源码链接全错。
5. **服务器端口别连错**：22/root 才是完整权限，19002/zhuzhongqian 是受限环境。
