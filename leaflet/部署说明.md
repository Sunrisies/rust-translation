# Leaflet 1.9.4 中文文档 — 构建与部署手册

## 一、项目概况

- **翻译对象**：Leaflet **1.9.4 稳定版**（tag `v1.9.4`）
  - API 参考：源码 JSDoc/Leafdoc 注释（83 个 js，1484 行描述翻译）
  - 教程文档：`docs/examples/` 下 65 个 Jekyll markdown
  - 导航页：Overview / Tutorials / Install（从官网精准翻译，保留地图/公告/代码块结构）
  - Plugins 清单太大（8 万字），导航指向官网英文页
- **站点**：`https://leaflet.sunrise1024.top/`（23 个 HTML 页）
- **本地模型**：Hy-MT2-1.8B Q4_K_M（llama-server，端口 8999）
- **统计**：Umami `script.js` + 专用 website-id `e10dcfc1-d201-4f73-bf64-5ad26aa9e853`

## 三、完整重建流程（官方更新后照此走）

### 0. 前置

翻译服务需在 8999 端口运行：
```bash
cd /d/hy-mt2-bench && ./cuda/llama-server.exe -m Hy-MT2-1.8B-Q4_K_M.gguf \
  --host 127.0.0.1 --port 8999 -ngl 99 -c 4096 -fa on --threads 4
```

GitHub 访问走 gh API（git clone 在此环境不稳）。当前代理端口以 7897 为准（环境变量里的 61856 已失效）：
```bash
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push ...
```

### 1. 拉源

```bash
cd D:/hy-mt2-bench/leaflet-docs
python fetch_sources.py          # 从 v1.9.4 tag 拉 83 js + 65 md
```
> 若要升级版本，改脚本顶部的 `TAG` 常量。注意版本切换会触发增量重翻（哈希变化的文件）。

### 2. 翻译

```bash
python leafdoc_translator.py --all   # API 注释（SHA256 缓存，只翻变化的）
python tutorial_translator.py --all  # 教程 markdown
python leafdoc_translator.py --stats # 查看进度
```
质量校验（应全部 0）：
```bash
python -c "
from pathlib import Path
src=Path('repo/src'); out=Path('translated/src')
bad=leak=0
for f in src.rglob('*.js'):
    of=out/f.relative_to(src)
    if not of.exists(): continue
    a=f.read_text(encoding='utf-8',errors='surrogateescape').splitlines()
    b=of.read_text(encoding='utf-8',errors='surrogateescape').splitlines()
    if len(a)!=len(b): bad+=1; continue
    for x,y in zip(a,b):
        if x!=y and not x.strip().startswith(('//','*','/*')): bad+=1
    if '<##' in '\n'.join(b): leak+=1
print('非注释行改动',bad,'标记泄漏',leak)
"
```

### 3. 生成 API 参考页（Leafdoc）

```bash
cd site-build
cp -r ../translated/src/. src/        # 同步译文源码（覆盖）
node build-docs.js                    # 生成 reference.html（Jekyll 片段）
cd ..
```
注意：`leafdoc` 安装的 **2.4.0** 导出是 `require('leafdoc').default`，build-docs.js 已处理。

### 4. 导航页与整页翻译（版本升级时才需重做）

```bash
# 官网首页/教程/安装页：精准翻译（保留地图/公告/代码块结构）
python translate_html_page.py official-pages/index.html nav-translated/index-full.html
python translate_nav_pages.py    # 生成 nav-translated/*.html（注意检查漏翻的连接词）
```
> install 页用的是 v1.9.4 tag 的 `docs/download.md`（不是官网当前 2.0 beta 的 install.html）；examples 用官网 `examples-v1.html`（1.9 版）。

### 5. 组装站点

```bash
python build_site_official.py    # 输出 site-official/（23 HTML）
```
此脚本会：用官网外壳 + 自建 zh.css 布局、注入 umami id、版本徽章、导航高亮、plugins 跳转页。

### 6. 本地预览

```bash
node serve.mjs                   # http://127.0.0.1:3500
```

### 7. 部署到公网（47.111.168.59）

服务器信息：
- SSH：`root@47.111.168.59`（免密，22 端口）
- Caddy 跑在 Docker 容器 `caddy` 里
- 站点目录：主机 `/var/www/leaflet-docs`，容器内同路径（两份都要更新）
- Caddyfile：主机 `/home/www/caddy/Caddyfile` → 容器 `/etc/caddy/Caddyfile`（**bind mount 不同步，改完主机必须手动同步进容器**）

```bash
# 打包上传
cd D:/hy-mt2-bench/leaflet-docs
tar -czf leaflet-docs-zh.tar.gz -C site-official .
scp leaflet-docs-zh.tar.gz root@47.111.168.59:/tmp/

# 主机 + 容器解压
ssh root@47.111.168.59 '
mkdir -p /var/www/leaflet-docs && tar -xzf /tmp/leaflet-docs-zh.tar.gz -C /var/www/leaflet-docs
docker exec caddy mkdir -p /var/www/leaflet-docs
docker cp /var/www/leaflet-docs/. caddy:/var/www/leaflet-docs/
'
```

Caddy 站点配置（已添加，仅需版本升级时确认）：
```caddyfile
leaflet.sunrise1024.top {
    root * /var/www/leaflet-docs
    encode gzip zstd
    try_files {path} {path}.html {path}/ =404
    handle_errors {
        rewrite * /404.html
        file_server
    }
    file_server {
        index index.html
    }
}
```

若需改 Caddyfile（关键坑：主机改了容器不自动同步）：
```bash
# 主机追加/修改后，同步进容器：
ssh root@47.111.168.59 '
cp /home/www/caddy/Caddyfile /home/www/caddy/Caddyfile.bak-$(date +%Y%m%d-%H%M%S)
docker cp /home/www/caddy/Caddyfile caddy:/tmp/Caddyfile.new
docker exec caddy sh -c "cat /tmp/Caddyfile.new > /etc/caddy/Caddyfile"
docker exec caddy caddy validate --config /etc/caddy/Caddyfile
docker exec caddy caddy reload --config /etc/caddy/Caddyfile
'
```
> 不能直接 `docker cp` 到 `/etc/caddy/Caddyfile`（Resource busy，bind mount），要先 cp 到 `/tmp` 再 `cat >` 覆写 inode。

## 四、踩坑记录

1. **Leafdoc 老式注释 ≠ 标准 JSDoc**：1.9.4 用 `/* @class` / `// @option name: Type = default`，和 Cesium 的 JSDoc 不同，翻译器需单独写。选 1.9.4 而非 2.0 beta 的原因：后者注释有嵌套花括号（如 `{lat: number}`），正是 Cesium 踩过的误翻坑。
2. **官网 CSS 结构不匹配**：Leafdoc 生成的是老式片段（h4 + 裸 table，无 article/section），官网 main.css 为新版结构写的。解决方法：保留官网 header/footer/CSS，但 main 区域自建「左目录+右内容」布局（zh.css）。
3. **官网弹窗**：site.js 会弹声明对话框，要在生成时删掉 `<template id="dialog-template">`（在 `</main>` 之后）。
4. **精准翻译整页**：首页的地图/公告/代码块靠完整 HTML 结构渲染，不能提取纯文本翻译——用 `translate_html_page.py` 占位符方式只翻文本节点。
5. **Caddyfile bind mount 不同步**：改主机文件后容器不更新，必须 docker cp 到 /tmp 再 cat 覆写。
6. **favicon.ico 404**：官网只有 favicon.svg，补一个 favicon.ico 兜底避免 handle_errors 报 404。
7. **翻译质量偶发瑕疵**：8B 模型偶尔漏翻连接词（如 "and" 在两个 <a> 之间的独立节点），生成后抽查公告/重点段落。
