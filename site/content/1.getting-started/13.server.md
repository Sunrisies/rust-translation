## 由 Nitro 驱动

![Server engine](/assets/docs/getting-started/server.svg)

Nuxt 的服务器是 [Nitro](https://github.com/nitrojs/nitro)。它最初是为 Nuxt 创建的，但现在已成为 [UnJS](https://unjs.io) 的一部分，并且其他框架也可以使用——甚至可以独立使用。

使用 Nitro 使 Nuxt 拥有强大的功能：

- 对应用的服务器端部分拥有完全控制权
- 可在任何提供方上实现通用部署（许多无需配置）
- 混合渲染

Nitro 内部使用 [h3](https://github.com/h3js/h3)，这是一个为高性能和可移植性而构建的极简 HTTP 框架。

## 服务器端点与中间件

你可以轻松管理 Nuxt 应用的仅服务器端部分，从 API 端点到中间件。

端点和中间件都可以这样定义：

```ts twoslash [server/api/test.ts]
export default defineEventHandler(async (event) => {
  // ... Do whatever you want here
})
```

你可以直接返回 `text`、`json`、`html` 甚至 `stream`。

它开箱即用，支持 **热模块替换** 和 **自动导入**，就像 Nuxt 应用的其他部分一样。

## 混合渲染

Nuxt 有一个强大的功能 `routeRules`，允许你定义一组规则来定制 Nuxt 应用的每个路由的渲染方式（以及更多）。Nuxt 会编译这些规则，而默认的服务器构建器（Nitro）则应用服务器端规则。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    // Generated at build time for SEO purpose
    '/': { prerender: true },
    // Cached for 1 hour
    '/api/*': { cache: { maxAge: 60 * 60 } },
    // Redirection to avoid 404
    '/old-page': {
      redirect: { to: '/new-page', statusCode: 302 },
    },
    // ...
  },
})
```

::read-more{to="/docs/guide/concepts/rendering#hybrid-rendering"}
了解所有可用于自定义路由渲染模式的路由规则。
::

此外，还有一些特定于 Nuxt 的路由规则（例如 `ssr`、`appMiddleware` 和 `noScripts`），用于改变将页面渲染为 HTML 时的行为。

某些路由规则（`appMiddleware`、`redirect` 和 `prerender`）也影响客户端行为。

Nitro 用于构建服务器端渲染及预渲染的应用程序。
