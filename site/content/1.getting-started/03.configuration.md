默认情况下，Nuxt 已配置为覆盖大多数使用场景。`[nuxt.config.ts](/docs/directory-structure/nuxt-config)` 文件可以覆盖或扩展此默认配置。

## Nuxt 配置

`[nuxt.config.ts](/docs/directory-structure/nuxt-config)` 文件位于 Nuxt 项目的根目录，可以覆盖或扩展应用程序的行为。

一个极简的配置文件导出 `defineNuxtConfig` 函数，其中包含一个包含你配置的对象。`defineNuxtConfig` 辅助函数无需导入即可全局使用。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  // My Nuxt config
})
```

此文件通常在文档中提及，例如用于添加自定义脚本、注册模块或更改渲染模式。

::read-more{to="/docs/api/nuxt-config"}
每个选项都在 **配置参考** 中有描述。
::

::note
你不必使用 TypeScript 来构建 Nuxt 应用程序。然而，强烈建议将 `nuxt.config` 文件的扩展名设为 `.ts`。这样你可以利用 IDE 中的提示功能，在编辑配置时避免拼写错误和错误。
::

### 环境覆盖

你可以在 `nuxt.config` 中配置完全类型化的、针对环境的覆盖设置。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  $production: {
    routeRules: {
      '/**': { isr: true },
    },
  },
  $development: {
    //
  },
  $env: {
    staging: {
      //
    },
  },
})
```

要在运行 Nuxt CLI 命令时选择环境，只需将名称传递给 `--envName` 标志，例如：`nuxt build --envName staging`。

如需了解这些覆盖机制背后的原理，请参考 [特定环境配置](https://github.com/unjs/c12?tab=readme-ov-file#environment-specific-configuration) 中的 `c12` 文档。

:video-accordion{title="Watch a video from Alexander Lichter about the env-aware nuxt.config.ts" videoId="DFZI2iVCrNc"}

::note
如果你正在编写层，还可以使用 `$meta` 键提供元数据，供你或你的层的消费者使用。
::

### 环境变量和私有令牌

`runtimeConfig` API 将环境变量等值暴露给应用程序的其他部分。默认情况下，这些键仅可在服务器端使用。`runtimeConfig.public` 和 `runtimeConfig.app`（Nuxt 内部使用）中的键也可在客户端使用。

这些值应在 `nuxt.config` 中定义，并可以通过环境变量进行覆盖。

::code-group

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // The private keys which are only available server-side
    apiSecret: '123',
    // Keys within public are also exposed client-side
    public: {
      apiBase: '/api',
    },
  },
})
```

```ini [.env]
# This will override the value of apiSecret
NUXT_API_SECRET=api_secret_token
```

::

这些变量通过 [`useRuntimeConfig()`](/docs/api/组合式函数/use-runtime-config) 组合式函数暴露给应用程序的其他部分。

```vue [app/pages/index.vue]
<script setup lang="ts">
const runtimeConfig = useRuntimeConfig()
</script>
```

:read-more{to="/docs/guide/going-further/runtime-config"}

## 应用配置

位于源目录中的 `app.config.ts` 文件（默认在 `app/` 下）用于暴露可在构建时确定的公共变量。与 `runtimeConfig` 选项不同，这些变量无法通过环境变量覆盖。

一个极简的配置文件导出 `defineAppConfig` 函数，该函数包含一个包含你配置的对象。`defineAppConfig` 辅助函数无需导入即可全局使用。

```ts [app/app.config.ts]
export default defineAppConfig({
  title: 'Hello Nuxt',
  theme: {
    dark: true,
    colors: {
      primary: '#ff0000',
    },
  },
})
```

这些变量通过 [`useAppConfig`](/docs/api/组合式函数/use-app-config) 组合式函数暴露给应用程序的其他部分。

```vue [app/pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()
</script>
```

:read-more{to="/docs/directory-structure/app/app-config"}

## `runtimeConfig` 与 `app.config`

如上所述，`runtimeConfig` 和 `app.config` 都用于向应用程序其他部分暴露变量。要判断应该使用哪一个，可以参考以下指导原则：

- `runtimeConfig`：需要在使用环境变量后通过构建指定私有或公共令牌。
- `app.config`：在构建时确定的公共令牌，如网站配置（如主题变体、标题）以及非敏感的项目配置。

| 功能                   | `runtimeConfig` | `app.config` |
|---------------------------|-----------------|--------------|
| 客户端侧                | 已注入        | 已打包      |
| 环境变量               | ✅ 是           | ❌ 否         |
| 响应式支持              | ✅ 是           | ✅ 是        |
| 类型支持               | ✅ 部分        | ✅ 是        |
| 请求级别的配置          | ❌ 否            | ✅ 是        |
| 热模块替换              | ❌ 否            | ✅ 是        |
| 非原始 JS 类型          | ❌ 否            | ✅ 是        |

## 外部配置文件

Nuxt 使用 [`nuxt.config.ts`](/docs/directory-structure/nuxt-config) 文件作为配置的单一来源，并跳过读取外部配置文件。在构建项目过程中，你可能需要配置这些文件。下表列出了常见的配置方式，以及如何在 Nuxt 中配置它们。

| 名称                              | 配置文件             | 配置方法                                                          |
|-----------------------------------|-------------------------|---------------------------------------------------------------------------|
| [Nitro](https://nitro.build)      | ~~`nitro.config.ts`~~   | 在 `nuxt.config` 中使用 [`nitro`](/docs/api/nuxt-config#nitro) 键       |
| [PostCSS](https://postcss.org)    | ~~`postcss.config.js`~~ | 在 `nuxt.config` 中使用 [`postcss`](/docs/api/nuxt-config#postcss) 键   |
| [Vite](https://vite.dev)          | ~~`vite.config.ts`~~    | 在 `nuxt.config` 中使用 [`vite`](/docs/api/nuxt-config#vite) 键         |
| [webpack](https://webpack.js.org) | ~~`webpack.config.ts`~~ | 在 `nuxt.config` 中使用 [`webpack`](/docs/api/nuxt-config#webpack-1) 键 |

以下是其他常见配置文件的列表：

| 名称                                         | 配置文件               | 配置方法                                                              |
|----------------------------------------------|-----------------------|-------------------------------------------------------------------------------|
| [TypeScript](https://www.typescriptlang.org) | `tsconfig.json`       | [更多信息](/docs/directory-structure/tsconfig)                           |
| [ESLint](https://eslint.org)                 | `eslint.config.js`    | [更多信息](https://eslint.org/docs/latest/use/configure/configuration-files) |
| [Prettier](https://prettier.io)              | `prettier.config.js`  | [更多信息](https://prettier.io/docs/configuration.html)                      |
| [Stylelint](https://stylelint.io)            | `stylelint.config.js` | [更多信息](https://stylelint.io/user-guide/configure/)                       |
| [TailwindCSS](https://tailwindcss.com)       | `tailwind.config.js`  | [更多信息](https://tailwindcss.nuxtjs.org/tailwindcss/configuration/)        |
| [Vitest](https://vitest.dev)                 | `vitest.config.ts`    | [更多信息](https://vitest.dev/config/)                                       |
| [Vite+](https://viteplus.dev)                | `vite.config.ts`      | [更多信息](https://viteplus.dev/config/)                                     |

如果您使用 Vite+，其 `vite.config.ts` 会配置 Vite+ 命令，如 `vp lint`、`vp fmt` 和 `vp test`。Nuxt 不会从该文件读取 Vite 选项，因此请在 `nuxt.config` 中使用 [`vite`](/docs/api/nuxt-config#vite) 键来配置您的应用中的 Vite。

## Vue 配置

### 使用 Vite

如果您需要向 `@vitejs/plugin-vue` 或 `@vitejs/plugin-vue-jsx` 传递选项，可以在 `nuxt.config` 文件中完成。

- `@vitejs/plugin-vue` 的 `vite.vue`。查看 [可用选项](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue)。
- `vite.vueJsx` 用于 `@vitejs/plugin-vue-jsx`。请查看 [可用选项](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue-jsx)。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    vue: {
      customElement: true,
    },
    vueJsx: {
      mergeProps: true,
    },
  },
})
```

:read-more{to="/docs/api/nuxt-config#vue"}

### 使用 webpack

如果您使用 webpack 并需要配置 `vue-loader`，可以在 `nuxt.config` 文件中使用 `webpack.loaders.vue` 键来实现。可用选项在 [此处定义](https://github.com/vuejs/vue-loader/blob/main/src/index.ts#L32-L62)。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  webpack: {
    loaders: {
      vue: {
        hotReload: true,
      },
    },
  },
})
```

:read-more{to="/docs/api/nuxt-config#loaders"}

### 启用实验性 Vue 功能

您可能需要在 `nuxt.config.ts` 中启用实验性 Vue 功能，例如 `propsDestructure`。无论您使用哪种构建工具，Nuxt 都提供了简便的方法来实现这一点：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vue: {
    propsDestructure: true,
  },
})
```

#### 从 Vue 3.4 和 Nuxt 3.9 开始迁移到实验性 `reactivityTransform`

自 Nuxt 3.9 和 Vue 3.4 以来，`reactivityTransform` 已从 Vue 转移到 Vue Macros，该工具具有 [Nuxt 集成](https://vue-macros.dev/guide/nuxt-integration.html)。
