Nuxt 使用两个目录来处理样式表、字体或图片等资产。

- [`public/`](/docs/directory-structure/public) 目录中的内容将直接以原样在服务器根目录上提供。
- [`app/assets/`](/docs/directory-structure/app/assets) 目录按惯例包含所有您希望构建工具（Vite 或 webpack）处理的资产。

## 公共目录

[`public/`](/docs/directory-structure/public) 目录被用作静态资产的公共服务器，这些资产在应用程序的指定 URL 下可公开访问。

您可以通过应用程序代码或浏览器通过根 URL `/` 从 [`public/`](/docs/directory-structure/public) 目录获取文件。

### 示例

例如，引用 `public/img/` 目录中的图像文件，该文件可通过静态 URL `/img/nuxt.png` 访问。

```vue [app/app.vue]
<template>
  <img
    src="/img/nuxt.png"
    alt="Discover Nuxt"
  >
</template>
```

## 资产目录

Nuxt 使用 [Vite](https://vite.dev/guide/assets)（默认）或 [webpack](https://webpack.js.org/guides/asset-management/) 来构建和打包应用程序。这些构建工具的主要功能是处理 JavaScript 文件，但可以通过 [插件](https://vite.dev/plugins/)（针对 Vite）或 [加载器](https://webpack.js.org/loaders/)（针对 webpack）来扩展，以处理其他类型的资产，如样式表、字体或 SVG。此步骤主要出于性能或缓存目的（例如样式表压缩或浏览器缓存失效）对原始文件进行转换。

按惯例，Nuxt 使用 [`app/assets/`](/docs/directory-structure/app/assets) 目录来存储这些文件，但该目录没有自动扫描功能，您可以使用其他任何名称。

在应用程序代码中，您可以通过 `~/assets/` 路径引用位于 [`app/assets/`](/docs/directory-structure/app/assets) 目录中的文件。

### 示例

例如，引用一个图像文件，如果构建工具被配置为处理此文件扩展名，则该文件将被处理。

```vue [app/app.vue]
<template>
  <img
    src="~/assets/img/nuxt.png"
    alt="Discover Nuxt"
  >
</template>
```

::note
Nuxt 不会在 `/assets/my-file.png` 这样的静态 URL 下提供 [`app/assets/`](/docs/directory-structure/app/assets) 目录中的文件。如果您需要静态 URL，请使用 [`public/`](/docs/getting-started/assets#public-directory) 目录。
::

### 静态与动态 `src`

当模板中的 `src` 是一个静态字符串字面量时，构建工具会将其改写为运行时辅助函数，以解析最终的 URL。例如 `/img/nuxt.png` 这种公共路径会被包装，以便在页面渲染时应用 [`app.baseURL`](/docs/api/nuxt-config#baseurl)，而像 `~/assets/img/nuxt.png` 这样的打包路径则成为导入项，并指向哈希后的输出文件。

```vue
<template>
  <!-- Static paths are rewritten: app.baseURL is applied at runtime, and the bundled file is hashed. -->
  <img src="/img/nuxt.png">
  <img src="~/assets/img/nuxt.png">
</template>
```

由于 `app.baseURL` 在运行时应用，即使基础 URL 仅在部署时知晓（例如通过 `NUXT_APP_BASE_URL` 设置），静态公共路径也能正常工作，且无论文件是否经过构建处理，该机制都能生效。这种解析仅适用于构建工具能够看到的字面路径。

在运行时组装值的绑定 `:src` 对构建工具来说是不透明的，因此不会进行任何改写。字符串按原样使用：

```vue
<template>
  <!-- This does not work: the path is built at runtime, so Vite never sees it as an import. -->
  <img :src="`~/assets/img/${name}.png`">
</template>
```

因此，像 `/img/${name}.png` 这样的运行时生成的公共路径**不会**以 [`app.baseURL`](/docs/api/nuxt-config#baseurl) 作为前缀。如果您的应用部署在 origin 根之下，请自行使用 [`useRuntimeConfig().app.baseURL`](/docs/api/组合式函数/use-runtime-config) 进行前缀处理（例如通过 [`joinURL`](https://github.com/unjs/ufo#joinurl)）。

以下部分介绍了在路径仅在运行时知晓时的处理方法。

#### 公共资源

如果文件不需要被处理或哈希，请将它们放在 [`public/`](/docs/directory-structure/public) 目录中，并通过 URL 引用：

```vue [app/app.vue]
<script setup lang="ts">
const props = defineProps<{
  name: string
}>()

const imageUrl = computed(() => `/img/${props.name}.png`)
</script>

<template>
  <img
    :src="imageUrl"
    :alt="props.name"
  >
</template>
```

`public/` 中的文件保留其原始文件名。

#### 使用 Vite 的打包资源

以下方法特定于 Vite，即 Nuxt 的默认构建器。

当已知可能的文件时，明确列出它们的导入项：

```vue [app/app.vue]
<script setup lang="ts">
const props = defineProps<{
  theme: 'light' | 'dark'
}>()

const logos = {
  light: () => import('./assets/img/logo-light.png?url'),
  dark: () => import('./assets/img/logo-dark.png?url'),
}

const logoUrl = (await logos[props.theme]()).default
</script>

<template>
  <img
    :src="logoUrl"
    alt="Nuxt"
  >
</template>
```

每个导入项都有字面路径，因此 Vite 可以在构建时找到所有文件，而在运行时仅加载选定的模块。

当多个文件共享同一个目录和扩展名时，使用 [变量动态导入](https://vite.dev/guide/features.html#dynamic-import) 而不是列出每个文件：

```ts
async function getImageUrl (name: string) {
  const image = await import(`./assets/img/${name}.png?url`)
  return image.default
}
```

在这个例子中，只有文件名可以是动态的。在导入项中保留目录和扩展名，使 Vite 能够在构建时找到可能的文件。

对于更通用的模式或可用的文件明确映射，请使用 [`import.meta.glob`](https://vite.dev/guide/features.html#glob-import)：

```ts
const images = import.meta.glob<string>('./assets/img/*.{png,jpg,svg}', {
  query: '?url',
  import: 'default',
})

async function getImageUrl (name: string) {
  const load = images[`./assets/img/${name}.png`]

  if (!load) {
    throw new Error(`Unknown image: ${name}`)
  }

  return await load()
}
```

默认情况下，全局导入是延迟加载的。如果必须同步获取 URL，请添加 `eager: true`：

```ts
const images = import.meta.glob<string>('./assets/img/*.{png,jpg,svg}', {
  query: '?url',
  import: 'default',
  eager: true,
})
```

每个匹配的资源仍会被包含在构建输出中。延迟导入会按需加载每个匹配项，而即时全局导入则会在之前加载所有匹配项，从而可能增加初始 JavaScript 大小或内联小资源的体积。

::warning
在服务器渲染标记中使用其 URL 之前，请等待该导入完成加载。Vite 的 [`new URL(..., import_meta.meta.url)` 模式](https://vite.dev/guide/assets.html#new-url-url-import-meta-url) 在 SSR 场景下无法使用。
::
