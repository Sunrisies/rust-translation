Nuxt 是一个全栈框架，这意味着存在多种无法预防的用户运行时错误，这些错误可能发生在不同的环境中：

- Vue 渲染生命周期中的错误（SSR 和 CSR）
- 服务器和客户端启动错误（SSR + CSR）
- Nitro 服务器生命周期中的错误（[`server/`](/docs/directory-structure/server) 目录）
- JS 块下载错误

::tip
**SSR** 代表 **服务端渲染**，**CSR** 代表 **客户端渲染**。
::

## Vue 错误

你可以使用 [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured) 来捕获 Vue 错误。

此外，Nuxt 提供了一个 [`vue:error`](/docs/api/advanced/hooks#app-hooks-runtime) 钩子，当任何错误传播到顶层时，该钩子将被调用。

如果你使用错误报告框架，可以通过 [`vueApp.config.errorHandler`](https://vuejs.org/api/application#app-config-errorhandler) 提供全局处理程序。即使错误已被处理，它仍然会接收所有 Vue 错误。

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.config.errorHandler = (error, instance, info) => {
    // handle error, e.g. report to a service
  }

  // Also possible
  nuxtApp.hook('vue:error', (error, instance, info) => {
    // handle error, e.g. report to a service
  })
})
```

::note
请注意，`vue:error` 钩子基于 [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured) 生命周期钩子。
::

## 启动错误

如果启动 Nuxt 应用时出现任何错误，Nuxt 会调用 `app:error` 钩子。

这包括：
- 运行 [Nuxt 插件](/docs/directory-structure/app/plugins)
- 处理 `app:created` 和 `app:beforeMount` 钩子
- 将你的 Vue 应用渲染为 HTML（在 SSR 期间）
- 在客户端挂载应用，不过你可以通过 `onErrorCaptured` 或 `vue:error` 来处理这种情况
- 处理 `app:mounted` 钩子

## Nitro 服务器错误

目前无法为这些错误定义服务器端处理程序，但可以渲染错误页面，请参阅 [渲染错误页面](/docs/getting-started/error-handling#error-page) 部分。

## JS 块错误

你可能会遇到由于网络连接失败或新部署导致块加载错误的现象（这会使旧的哈希 JS 块 URL 失效）。Nuxt 提供了内置的支持，当在路由导航期间块无法加载时，通过执行硬重载来处理块加载错误。

你可以通过将 `experimental.emitRouteChunkError` 设置为 `false`（完全禁用对这些错误的捕获）或 `manual` 来更改此行为，后者表示你想自己处理这些错误。如果你想要手动处理块加载错误，可以查看 [自动实现方案](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/plugins/chunk-reload.client.ts) 以获取灵感。

## 错误页面

::note
当 Nuxt 遇到致命错误（服务器上的任何未处理错误，或在客户端使用 `fatal: true` 创建的错误）时，它将要么渲染 JSON 响应（如果请求包含 `Accept: application/json` 头），要么触发全屏错误页面。在 `future.compatibilityVersion: 5` 模式下，页面错误总是会触发错误页面，而在服务器路由或服务器中间件中抛出的错误则返回 JSON 响应。
::

以下情况可能在服务器生命周期过程中发生错误：
- 处理你的 Nuxt 插件
- 将你的 Vue 应用渲染为 HTML
- 服务器 API 路由抛出错误

在客户端侧也可能发生以下情况：
- 处理你的 Nuxt 插件
- 在应用挂载之前（`app:beforeMount` 钩子）
- 如果错误未通过 `onErrorCaptured` 或 `vue:error` 钩子处理，则进行应用挂载
- Vue 应用在浏览器中初始化并挂载（`app:mounted`）

::read-more{to="/docs/api/advanced/hooks"}
了解所有 Nuxt 生命周期钩子。
::

通过在你的应用源目录中添加 `~/error.vue`，并与 `app.vue` 一起使用，可以自定义默认错误页面。

<!-- TODO:twoslash: Twoslash does not support tsconfig paths yet -->

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps({
  error: Object as () => NuxtError,
})

const handleError = () => clearError({ redirect: '/' })
</script>

<template>
  <div>
    <h2>{{ error?.status }}</h2>
    <button @click="handleError">
      Clear errors
    </button>
  </div>
</template>
```

::read-more{to="/docs/directory-structure/app/error"}
了解更多关于 `error.vue` 及其用法的信息。
::

对于自定义错误，我们强烈推荐使用 `onErrorCaptured` 组合式函数，该函数在页面/组件设置函数中调用，或 `vue:error` 运行时 nuxt 钩子，可以在 nuxt 插件中配置。

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('vue:error', (err) => {
    //
  })
})
```

当你准备移除错误页面时，可以调用 [`clearError`](/docs/api/utils/clear-error) 辅助函数，该函数接受一个可选的重定向路径（例如，如果你想导航到‘安全’页面）。

::important
在使用任何依赖 Nuxt 插件的组件之前，请务必检查，例如 `$route` 或 `useRouter`，因为如果插件抛出错误，则不会在清除错误前重新运行。
::

::note
渲染错误页面是一个完全独立的页面加载过程，意味着所有注册的中间件将再次运行。你可以在中间件中使用 [`useError`](/docs/getting-started/error-handling#useerror) 来检查是否正在处理错误。
::

::note
如果你在 Node 16 上运行，并且在渲染错误页面时设置任何 Cookie，它们将[覆盖之前设置的 Cookie](https://github.com/nuxt/nuxt/pull/20585)。我们建议使用较新版本的 Node，因为 Node 16 在 2023 年 9 月达到终点生命周期。
::

## 错误工具库

### `useError`

```ts [TS Signature]
function useError (): Ref<Error | { url, status, statusText, message, description, data }>
```

此函数将返回正在处理的全局 Nuxt 错误。

::read-more{to="/docs/api/composables/use-error"}
了解更多关于 `useError` 组合式函数的信息。
::

### `createError`

```ts [TS Signature]
function createError (err: string | { cause, data, message, name, stack, status, statusText, fatal }): Error
```

创建一个包含额外元数据的错误对象。你可以传递一个字符串作为错误 `message`，或者一个包含错误属性的对象。该函数在你的应用中的 Vue 和 Server 部分都可以使用，并且应该被抛出。

如果你使用 `createError` 创建错误并抛出：
- 在服务器端，它将触发全屏错误页面，你可以通过 [`clearError`](/docs/getting-started/error-handling#clearerror)清除该页面。
- 在客户端侧，它将抛出一个非致命错误供你处理。如果你需要触发全屏错误页面，可以设置 `fatal: true`。

在开发环境中，错误 `cause` 会被保留并暴露给你的错误页面，以便你追踪原始错误；在生产环境中，原因不会包含在错误响应或错误页面数据中。

```vue twoslash [pages/movies/[slug\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data } = await useFetch(`/api/movies/${route.params.slug}`)

if (!data.value) {
  throw createError({
    status: 404,
    statusText: 'Page Not Found',
  })
}
</script>
```

::tip
`statusText` 属性用于简短的符合 HTTP 标准的状态文本（例如，“Not Found”）。它应仅包含水平制表符、空格和可见的 ASCII 字符（`[\t\u0020-\u007E]`）。

对于详细的描述、多行消息或包含非 ASCII 字符的内容，你应该始终使用 `message` 属性。
::

::read-more{to="/docs/api/utils/create-error"}
了解更多关于 `createError` 工具的信息。
::

### `showError`

```ts [TS Signature]
function showError (err: string | Error | { status, statusText }): Error
```

你可以在客户端任意时刻调用此函数，或者在服务器端直接在中间件、插件或 `setup()` 函数中调用。它将触发全屏错误页面，你可以通过 [`clearError`](/docs/getting-started/error-handling#clearerror)清除该页面。

建议改用 `throw createError()`。

::read-more{to="/docs/api/utils/show-error"}
了解更多关于 `showError` 工具的信息。
::

### `clearError`

```ts [TS Signature]
function clearError (options?: { redirect?: string }): Promise<void>
```

此函数将清除当前正在处理的 Nuxt 错误。它还可以接受一个可选的重定向路径（例如，如果你想导航到‘安全’页面）。

::read-more{to="/docs/api/utils/clear-error"}
了解更多关于 `clearError` 工具的信息。
::

## 在组件中渲染错误

Nuxt 还提供了一个 [`<NuxtErrorBoundary>`](/docs/api/components/nuxt-error-boundary) 组件，允许你在应用中处理客户端错误，而无需用错误页面替换整个网站。

此组件负责处理其默认插槽中发生的错误。在客户端侧，它会防止错误冒泡到顶层，并渲染 `#error` 插槽。

`#error` 插槽将接收 `error` 作为属性。 (如果你设置 `error = null`，它将触发默认插槽的重新渲染；你需要确保错误完全解决，否则错误插槽将再次被渲染。)

::tip
如果你导航到另一个路由，错误将自动清除。
::

```vue [app/pages/index.vue]
<template>
  <!-- some content -->
  <NuxtErrorBoundary @error="someErrorLogger">
    <!-- You use the default slot to render your content -->
    <template #error="{ error, clearError }">
      You can display the error locally here: {{ error }}
      <button @click="clearError">
        This will clear the error.
      </button>
    </template>
  </NuxtErrorBoundary>
</template>
```
