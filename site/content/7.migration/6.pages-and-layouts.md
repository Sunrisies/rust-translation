## `app.vue`

Nuxt 3 通过 `~/app.vue` 提供了应用程序的中央入口点。

::note
如果您的源代码目录中没有 `app.vue` 文件，Nuxt 将使用其默认版本。
::

此文件是放置任何需要在应用程序启动时运行一次的自定义代码以及所有出现在应用程序每个页面上的组件的好地方。例如，如果您只有一种布局，可以将它移动到 `app.vue` 中。

:read-more{to="/docs/directory-structure/app/app"}

:link-example{to="/docs/examples/hello-world"}

### 迁移

考虑创建 `app.vue` 文件，并将需要在应用程序顶层运行的任何逻辑包含进去。您可以查看 [这里的示例](/docs/directory-structure/app/app)。

## 布局

如果您在应用程序中为多个页面使用布局，只需进行轻微修改即可。

在 Nuxt 2 中，`<Nuxt>` 组件在布局内用于渲染当前页面。而在 Nuxt 3 中，布局使用 slots 代替，因此您需要将该组件替换为 `<slot />`。这还允许使用具有命名和作用域 slots 的高级用例。[了解更多关于布局的信息](/docs/directory-structure/app/layouts)。

您还需要更改使用 `definePageMeta` 编译宏定义页面使用的布局方式。布局将采用 kebab-cased 格式。因此，在页面中引用 `app/layouts/customLayout.vue` 时，它将变为 `custom-layout`。

### 迁移

1. 将 `<Nuxt />` 替换为 `<slot />`
    ```diff [app/layouts/custom.vue]
      <template>
        <div id="app-layout">
          <main>
    -       <Nuxt />
    +       <slot />
          </main>
        </div>
      </template>
    ```
2. 使用 [`definePageMeta`](/docs/api/utils/define-page-meta) 选择页面使用的布局。
    ```diff [app/pages/index.vue]
    + <script setup>
    + definePageMeta({
    +   layout: 'custom'
    + })
    - <script>
    - export default {
    -   layout: 'custom'
    - }
      </script>
    ```
3. 将 `~/layouts/_error.vue` 移动到 `~/error.vue`。请参阅 [错误处理文档](/docs/getting-started/error-handling)。如果您希望确保此页面使用布局，可以在 `error.vue` 中直接使用 [`<NuxtLayout>`](/docs/directory-structure/app/layouts)：
    ```vue [error.vue]
    <template>
      <div>
        <NuxtLayout name="default">
          <!-- -->
        </NuxtLayout>
      </div>
    </template>
    ```

## 页面

Nuxt 3 带有可选的 `vue-router` 集成，该集成由源代码目录中存在 `[app/pages/`](/docs/directory-structure/app/pages) 目录触发。如果您只有单个页面，可以考虑将其移动到 `app.vue` 以简化构建。

### 动态路由

在 Nuxt 3 中定义动态路由的格式与 Nuxt 2 略有不同，因此您可能需要重新命名 `app/pages/` 中的某些文件。

1. 如果您之前使用 `_id` 来定义动态路由参数，现在则使用 `[id]`。
2. 如果您之前使用 `_.vue` 来定义通用路由，现在则使用 `[...slug].vue`。

### 嵌套路由

在 Nuxt 2 中，您会使用 `<Nuxt>` 和 `<NuxtChild>` 来定义任何具有父组件和子组件的嵌套路由。在 Nuxt 3 中，这些已被替换为单一的 `<NuxtPage>` 组件。

### 页面键和 Keep-alive 属性

如果您之前向 `<Nuxt>` 传递自定义页面键或 Keep-alive 属性，现在则使用 `definePageMeta` 来设置这些选项。

:read-more{to="/docs/directory-structure/app/pages#special-metadata"}

### 页面和布局过渡

如果您在组件选项中直接定义页面或布局的过渡效果，现在则需要使用 `definePageMeta` 来设置过渡效果。自 Vue 3 起，[-enter 和 -leave CSS 类已重新命名](https://v3-migration.vuejs.org/breaking-changes/transition.html)。当在 `<slot>` 中使用 `<Nuxt>` 的 `style` 属性时，该属性不再适用于过渡效果，因此请将样式添加到 `-active` 类中。

:read-more{to="/docs/getting-started/transitions"}

### 迁移

1. 将所有具有动态参数的页面名称改为符合新格式。
2. 将 `<Nuxt>` 和 `<NuxtChild>` 更新为 `<NuxtPage>`。
3. 如果您使用 Composition API，还可以将 `this.$route` 和 `this.$router` 迁移为使用 [`useRoute`](/docs/api/组合式函数/use-route) 和 [`useRouter`](/docs/api/组合式函数/use-router) 组合式函数。

#### 示例：动态路由

::code-group

``` [Nuxt 2]
- URL: /users
- Page: /pages/users/index.vue

- URL: /users/some-user-name
- Page: /pages/users/_user.vue
- Usage: params.user

- URL: /users/some-user-name/edit
- Page: /pages/users/_user/edit.vue
- Usage: params.user

- URL: /users/anything-else
- Page: /pages/users/_.vue
- Usage: params.pathMatch
```

``` [Nuxt 3]
- URL: /users
- Page: /pages/users/index.vue

- URL: /users/some-user-name
- Page: /pages/users/[user].vue
- Usage: params.user

- URL: /users/some-user-name/edit
- Page: /pages/users/[user]/edit.vue
- Usage: params.user

- URL: /users/anything-else
- Page: /pages/users/[...slug].vue
- Usage: params.slug
```

::

#### 示例：嵌套路由和 `definePageMeta`

::code-group

```vue [Nuxt 2]
<template>
  <div>
    <NuxtChild
      keep-alive
      :keep-alive-props="{ exclude: ['modal'] }"
      :nuxt-child-key="$route.slug"
    />
  </div>
</template>

<script>
export default {
  transition: 'page', // or { name: 'page' }
}
</script>
```

```vue [Nuxt 3]
<template>
  <div>
    <NuxtPage />
  </div>
</template>

<script setup lang="ts">
// This compiler macro works in both <script> and <script setup>
definePageMeta({
  // you can also pass a string or a computed property
  key: route => route.slug,
  transition: {
    name: 'page',
  },
  keepalive: {
    exclude: ['modal'],
  },
})
</script>
```

::

## `<NuxtLink>` 组件

全局 [NuxtLink](/docs/api/components/nuxt-link) 组件的语法和功能大部分与 `<NuxtLink>` 相同。如果您一直使用快捷方式 `<NLink>` 格式，应将其更新为 `<NuxtLink>`。

`<NuxtLink>` 现在可以直接替代所有链接，包括外部链接。您可以阅读更多关于它的内容，以及如何扩展它以提供自定义链接组件。

:read-more{to="/docs/api/components/nuxt-link"}

## 程序化导航

在从 Nuxt 2 迁移到 Nuxt 3 时，您必须更新程序化导航用户的方式。在 Nuxt 2 中，您可以通过 `this.$router` 访问底层的 Vue Router。在 Nuxt 3 中，可以使用 `navigateTo()` 实用方法，该方法允许您将路由和参数传递给 Vue Router。

::warning
确保始终在 [`navigateTo`](/docs/api/utils/navigate-to) 上使用 `await`，或通过从函数中返回来链接其结果。
::

::code-group

```vue [Nuxt 2]
<script>
export default {
  methods: {
    navigate () {
      this.$router.push({
        path: '/search',
        query: {
          name: 'first name',
          type: '1',
        },
      })
    },
  },
}
</script>
```

```vue [Nuxt 3]
<script setup lang="ts">
function navigate () {
  return navigateTo({
    path: '/search',
    query: {
      name: 'first name',
      type: '1',
    },
  })
}
</script>
```

::
