## 类型检查

出于性能考虑，默认情况下 Nuxt 在运行 [`nuxt dev`](/docs/api/commands/dev) 或 [`nuxt build`](/docs/api/commands/build) 时不会进行类型检查。

要在构建或开发时启用类型检查，需将 `vue-tsc` 和 `typescript` 作为开发依赖项安装：

::code-group{sync="pm"}

  ```bash [npm]
  npm install --save-dev vue-tsc typescript
  ```

  ```bash [yarn]
  yarn add --dev vue-tsc typescript
  ```

  ```bash [pnpm]
  pnpm add -D vue-tsc typescript
  ```

  ```bash [bun]
  bun add -D vue-tsc typescript
  ```

  ```bash [deno]
  deno add -D npm:vue-tsc npm:typescript
  ```

::

然后，运行 [`nuxt typecheck`](/docs/api/commands/typecheck) 命令来检查你的类型：

```bash [Terminal]
npx nuxt typecheck
```

要在构建或开发时启用类型检查，你也可以在 `nuxt.config` 文件中使用 [`typescript.typeCheck`](/docs/api/nuxt-config#typecheck) 选项：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    typeCheck: true,
  },
})
```

## 自动生成的类型

Nuxt 项目依赖自动生成的类型才能正常运行。这些类型存储在 [`.nuxt`](/docs/directory-structure/nuxt) 目录中，在运行开发服务器或构建应用程序时生成。你也可以通过运行 `nuxt prepare` 手动生成这些文件。

位于 [`.nuxt`](/docs/directory-structure/nuxt) 目录中的生成的 `tsconfig.json` 文件包含适用于你的项目的**推荐的基本 TypeScript 配置**，以及对 [自动导入](/docs/guide/concepts/auto-imports)、[API 路由类型](/docs/guide/concepts/server-engine#typed-api-routes)、路径别名如 `#imports`、`~/file` 或 `#build/file` 等的引用。

::warning
Nuxt 依赖此配置，[Nuxt 模块](/docs/guide/modules) 也可以扩展它。因此，不建议直接修改你的 `tsconfig.json` 文件，因为这样做可能会覆盖重要的设置。相反，应通过 `nuxt.config.ts` 进行扩展。[在此了解有关扩展配置的更多信息](/docs/directory-structure/tsconfig)。
::

::

## 项目引用

Nuxt 使用 [TypeScript 项目引用](https://www.typescriptlang.org/docs/handbook/project-references.html) 来提高类型检查性能并提供更好的 IDE 支持。此功能允许 TypeScript 将你的代码库拆分为更小、更易于管理的部分。

### Nuxt 如何使用项目引用

当你运行 `nuxt dev`、`nuxt build` 或 `nuxt prepare` 时，Nuxt 将为应用程序的不同部分生成多个 `tsconfig.json` 文件。

- **`.nuxt/tsconfig.app.json`** - 用于 `app/` 目录中应用程序代码的配置
- **`.nuxt/tsconfig.node.json`** - 用于其他上下文之外的 `nuxt.config.ts` 文件及文件的配置
- **`.nuxt/tsconfig.server.json`** - 用于服务器端代码（当适用时）的配置
- **`.nuxt/tsconfig.shared.json`** - 用于应用程序与服务器上下文之间共享的代码（如类型和非环境特定工具函数）

这些文件均被配置为引用适当的依赖项，并为其特定上下文提供最佳的类型检查功能。

::note
为了向后兼容，Nuxt 仍然生成 `.nuxt/tsconfig.json`。然而，我们建议使用 [TypeScript 项目引用](/docs/directory-structure/tsconfig) 配合新的配置文件（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json` 等），以获得更好的类型安全性和性能。此旧版文件将在 Nuxt 的后续版本中移除。
::

### 使用项目引用的优势

- **更快的构建过程**：TypeScript 可以跳过未更改项目的重新构建
- **更好的 IDE 性能**：IDE 可以提供更快速的 IntelliSense 和错误检查功能
- **独立的编译**：应用程序某部分的错误不会阻止其他部分的编译
- **更清晰的依赖管理**：每个项目都明确声明其依赖项

### 通过项目引用增强类型

由于项目被划分为**多个类型上下文**，在正确的上下文中**增强类型**非常重要，以确保它们被正确识别。除非明确包含在这些上下文中，否则 TypeScript 不会识别这些目录之外的类型增强内容。

例如，如果您希望为 `app` 上下文增强类型，则增强文件应放在 `app/` 目录中。

类似地：
- 对于 `server` 上下文，将增强文件放在 `server/` 目录中。
- 对于在应用程序和服务器之间**共享的类型**，将文件放在 `shared/` 目录中。

::read-more{to="/docs/guide/modules/recipes-advanced#extend-typescript-config"}
有关从**这些上下文之外的文件**中增强特定类型上下文的更多信息，请参阅模块作者指南。
::

## 严格检查

TypeScript 包含某些检查机制，可为您提供更高的安全性和程序分析能力。

在启用 [`typescript.typeCheck`](/docs/guide/concepts/typescript#type-checking) 选项以提供更高的类型安全性时，Nuxt 默认会启用严格检查。

如果您正在将代码库转换为 TypeScript，可以在 `nuxt.config` 中将 `strict` 设置为 `false`，以暂时禁用严格检查。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    strict: false,
  },
})
```
