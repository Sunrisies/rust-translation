在构建 Nuxt 时，我们创建了一个新的服务器引擎：[Nitro](https://nitro.build/)。

它包含许多功能：

- 支持 Node.js、浏览器、服务工作器等跨平台环境。
- 开箱即用的无服务器支持。
- 支持 API 路由。
- 自动代码分割和异步加载的 chunk。
- 适用于静态网站与无服务器网站的混合模式。
- 带有热模块重新加载的开发服务器。

## API 层

服务器 [API 端点](/docs/directory-structure/server#server-routes)和[中间件](/docs/directory-structure/server#server-中间件)由 Nitro 添加，内部使用 [h3](https://github.com/h3js/h3)。

主要特性包括：

- 处理器可以直接返回对象/数组，以生成自动处理的 JSON 响应。
- 处理器可以返回 Promise，这些 Promise 将被等待（`res.end()` 和 `next()` 也受支持）。
- 用于体解析、cookie 处理、重定向、头部等辅助函数。

更多信息请查看 [h3 文档](https://github.com/h3js/h3)。

::read-more{to="/docs/directory-structure/server#server-routes"}
在 `server/` 目录中可了解有关 API 层的更多信息。
::

## 直接 API 调用

Nitro 允许通过全局可用的 [`$fetch`](/docs/api/utils/dollarfetch) 辅助函数直接调用路由。如果在浏览器中运行，则会对服务器进行 API 调用；但在服务器中运行时，则会直接调用相关函数，**避免额外的 API 调用**。

[`$fetch`](/docs/api/utils/dollarfetch) API 使用 [ofetch](https://github.com/unjs/ofetch)，主要特性包括：

- 自动解析 JSON 响应（如需可访问原始响应）。
- 请求体和参数会自动处理，并带有正确的 `Content-Type` 头部。

有关 `$fetch` 特性的更多信息，请查看 [ofetch](https://github.com/unjs/ofetch)。

## 类型化的 API 路由

当使用 API 路由（或中间件）时，只要您返回值而不是使用 `res.end()` 发送响应，Nitro 就会为这些路由生成类型定义。

在使用 [`$fetch()`](/docs/api/utils/dollarfetch) 或 [`useFetch()`](/docs/api/组合式函数/use-fetch) 时，您可以访问这些类型。

## 独立服务器

Nitro 生成了一个独立于 `node_modules` 的独立服务器分发文件。

Nuxt 2 中的服务器不是独立的，需要 Nuxt 核心的部分参与，通过运行 `nuxt start`（使用 [`nuxt-start`](https://www.npmjs.com/package/nuxt-start) 或 [`nuxt`](https://www.npmjs.com/package/nuxt) 分发版本）或自定义程序化使用方式来实现，这种方式脆弱且容易崩溃，不适合无服务器和服务工作器环境。

当在 [`.output`](/docs/directory-structure/output) 目录中运行 `nuxt build` 时，Nuxt 会生成此 dist 文件。

该输出包含运行时代码，可在任何环境中运行你的 Nuxt 服务器（包括实验性浏览器服务工作器！）并提供静态文件服务，使其成为 JAMstack 领域的真正混合框架。此外，Nuxt 还实现了原生存储层，支持多源驱动和本地资源。
