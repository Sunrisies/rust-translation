title: 服务器组件
description: 仅在服务器上渲染各个组件，使其 JavaScript 不进入客户端包中。
---

默认情况下，Nuxt 在服务器上渲染应用，然后将每个组件的 JavaScript 发送到浏览器，从而 hydration 整个页面。对于内容丰富的组件（如 Markdown 渲染、语法高亮、CMS 输出）在客户端不会发生变化的情况，这种操作是浪费工作：用户下载、解析并执行仅用于生成已存在于页面的 HTML 的代码。

服务器组件（也称为岛屿组件）则相反。服务器组件在服务器上被渲染，其 HTML 嵌入到页面中，且没有任何 JavaScript 发送到客户端。其依赖项（如 Markdown 解析器、高亮库）也保留在服务器上。

::tip{icon="i-lucide-newspaper" to="https://roe.dev/blog/nuxt-server-components" target="_blank"}
阅读 Daniel Roe 关于 Nuxt 服务器组件的指南。
::

## 启用服务器组件

岛屿组件由 [`experimental.componentIslands`](/docs/guide/going-further/experimental-features#componentislands) 控制。默认值为 `'auto'`，当应用包含服务器组件或岛屿时，该功能会自动启用，因此大多数情况下无需任何配置。

如果您希望使用远程岛屿或选择性客户端 hydration，可以明确设置此选项：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    componentIslands: {
      selectiveClient: true, // or 'deep', to enable `nuxt-client`
      remoteIsland: false, // allow rendering islands from a remote source
    },
  },
})
```

::read-more{icon="i-simple-icons-github" to="https://github.com/nuxt/nuxt/issues/19772" target="_blank"}
服务器组件仍被标记为实验性组件。您可以在 GitHub 上查看开发路线图。
::

## `.server.vue` 组件

在组件后添加 `.server` 后缀可将其变为独立的服务器组件：

```bash [Directory Structure]
-| app/
---| components/
-----| HighlightedMarkdown.server.vue
```

像使用其他组件一样使用它：

```vue [app/pages/example.vue]
<template>
  <div>
    <!--
      rendered on the server; the markdown parsing and highlighting
      libraries are not included in your client bundle
     -->
    <HighlightedMarkdown markdown="# Headline" />
  </div>
</template>
```

位于 `~/components/islands/` 内的组件也会被注册为岛屿，并可以直接使用 [`<NuxtIsland>`](/docs/api/components/nuxt-island) 进行渲染，例如 `~/components/islands/MyIsland.vue` 可以使用 `<NuxtIsland name="MyIsland" />`。

您还可以将 `.server.vue` 组件与同名的 `.client.vue` 组件配对使用，以实现[独立的服务器和客户端实现](/docs/directory-structure/app/components#paired-with-a-client-component)。在这种情况下，该组件不是岛屿：客户端部分正常进行 hydration。

::warning
服务器组件（和岛屿）必须有一个根元素。（HTML 注释也被视为元素。）
::

## 岛屿的渲染方式

服务器组件在底层使用 [`<NuxtIsland>`](/docs/api/components/nuxt-island)。渲染岛屿时会向专门的岛屿端点发送请求，该端点：

- 在服务器上创建一个**新的、独立的 Vue 应用**，仅用于渲染该组件
- 创建一个“岛屿上下文”，您可以通过 `nuxtApp.ssrContext.islandContext` 在岛屿内部访问该上下文
- 再次运行您的插件，除非它们设置了 `env: { islands: false }`（对象语法插件）

由于岛屿与应用程序的其余部分是独立的：

- 您无法在页面和岛屿之间共享状态（提供/注入、Pinia、`useState`）；应通过 props 传递数据
- 在岛屿内部使用的 [`useRoute()`](/docs/api/组合式函数/use-route) 反映的是岛屿自身的请求，而不是用户当前所在的页面。如果岛屿需要路由信息，请通过 props 或 `<NuxtIsland>` 的 `context` prop 明确传递（从 `nuxtApp.ssrContext.islandContext` 在岛屿内部读取）
- 在渲染岛屿时，路由中间件不会运行

Props 会被序列化并作为**GET 查询参数**发送。这使得岛屿响应可缓存，但这也意味着：

- props 必须支持 JSON 序列化
- props 受到 URL 长度的限制，因此应避免传递大量数据
- props 可能出现在服务器访问日志、CDN 缓存和 `Referer` 头部中

::note
由于 props 来自请求（URL 查询或正文），请将它们视为不可信的输入。Nuxt 会拒绝那些很可能无意中泄露的 props：顶级 `as` 属性且岛屿未声明（未声明的 props 会作为属性附加到岛屿的根元素上），以及启用 `vue.runtimeCompiler` 时 props 中的 `template`。除此之外，避免将未验证的 props 用于动态组件解析（`<component :is>`{lang=vue}、`h()`、`resolveDynamicComponent()` 或多态性 `as` / `asChild` prop），因为字符串可以解析为任何已注册组件或 HTML 元素。

将 props 视为不可信包括其大小问题：在使用它们驱动 `v-for` 或其他随值增长的工作之前，请验证或限制数值和数组 props 的大小。Nuxt 在岛屿渲染中将数值 `v-for` 的源数量限制在 10,000 次，但这仅作为安全机制，而非验证手段。

组件未声明的 props 会作为属性附加到其单个根元素上，因此根为多态组件的岛屿（例如来自 `reka-ui` / `@nuxt/ui`）可能会接收您未绑定的属性。可以在此类岛屿上设置 `defineOptions({ inheritAttrs: false })`{lang=ts}，或声明您接受的 props。与任何 Vue 组件一样，通过 fall-through 的属性包括事件处理程序属性，如 `onclick` 或 `onfocus`，浏览器会将其作为 JavaScript 执行，因此不要将您无法控制的对象（如 `route.query`）传播到服务器组件或 `<NuxtIsland>`{lang=vue} 的 `props` 中。

为了根据调用者输入切换组件，应通过导入组件的允许列表来映射识别器，而不是传递原始属性：

```vue
<script setup lang="ts">
import type { Component } from 'vue'
import CardA from './CardA.vue'
import CardB from './CardB.vue'

const props = defineProps<{ variant: string }>()
const allowed: Record<string, Component> = { a: CardA, b: CardB }
const component = allowed[props.variant] ?? CardA
</script>

<template>
  <component :is="component" />
</template>
```
::

更改岛屿的属性会触发网络请求，从而在服务器上重新渲染组件并直接更新其 HTML。

::read-more{to="/docs/api/components/nuxt-island"}
阅读完整的 `<NuxtIsland>` API 文档，包括属性、插槽、事件及已知限制。
::

## 使用 `nuxt-client` 实现选择性 hydration

默认情况下岛屿是静态的，但可以通过添加 `nuxt-client` 属性来使其中的单个组件进行 hydration。这需要启用 `experimental.componentIslands.selectiveClient`。

```vue [app/components/ServerWithClient.server.vue]
<template>
  <div>
    <HighlightedMarkdown markdown="# Headline" />
    <!-- Counter will be loaded and hydrated client-side -->
    <Counter
      nuxt-client
      :count="5"
    />
  </div>
</template>
```

带有 `nuxt-client` 属性的组件作为岛屿的一部分在服务器上被渲染，然后由主客户端应用进行 hydration。只有该组件的代码块被发送到客户端；其余部分保持静态。

设置 `selectiveClient: 'deep'` 还可以将插槽传递给 `nuxt-client` 组件。这些插槽在服务器上被渲染，但在客户端**不具有交互性**。

::warning
仅在本地 `.vue` SFC 文件中使用 `nuxt-client`。像 [`<NuxtLink>`](/docs/api/components/nuxt-link)这样的内置组件跳过岛屿转换。在客户端导航后，可能会看到 `Failed to locate Teleport target`，或者链接消失且没有错误提示。将内置组件包裹在自己的 `.vue` 文件中，并在该包装器上添加 `nuxt-client`。参见 [#29251](https://github.com/nuxt/nuxt/issues/29251)和 [#26002](https://github.com/nuxt/nuxt/issues/26002)。
::

## 插槽

如果插槽在岛屿中声明，则可以将插槽传递给岛屿组件。插槽内容由父组件提供，因此属于主客户端应用并**具有**交互性（它被包裹在一个带有 `display: contents;` 的 `<div>` 中）。

`<NuxtIsland>` 保留 `#fallback` 插槽用于指定在岛屿加载之前（当设置 `lazy` 时）或获取岛屿失败时的内容。

## 客户端导航往返过程

在初始服务器渲染页面加载时，岛屿直接内联显示，没有额外的请求。然而，在**客户端导航**时，目标页面上的每个岛屿必须从服务器获取（你可以在网络标签页中看到这些请求）。这会带来实际成本：

- 除非你传递 `lazy` 属性并添加 `#fallback` 插槽以非阻塞方式渲染岛屿，否则它们在网络导航往返过程中会阻塞。
- 每页包含多个岛形的应用会在每次导航时发送大量请求。

岛形组件在完整页面加载时可访问的页面上（如内容页面和营销页面）或每页岛形数量较少时效果最佳。如果某个组件需要在客户端频繁更新，使用岛形可能不是合适的选择。

当使用 `<NuxtLink>` 指向 [仅服务器端的页面](/docs/directory-structure/app/pages#server-only-pages) 时，其岛形响应也会被预取，因此用户导航前就会发生往返操作，而不是在导航过程中进行。预取的响应会根据岛形的名称、属性和上下文进行缓存，这些属性与岛形挂载时使用的键相同。预取失败不会导致故障：岛形会在挂载时再次获取。

::note
这适用于渲染整个 `.server.vue` 页面的岛形。页面内使用的岛形在挂载时仍会被获取。
::

## 预渲染和缓存

岛形与静态和缓存渲染方式配合得很好：

- 在预渲染过程中（`nuxt generate` 或 `prerender` 路由规则），岛形响应会被缓存，因此相同的岛形（相同的名称、属性和上下文）只渲染一次并重复使用。
- 由于属性作为 GET 查询参数传递，岛形响应也可以由您的服务器或 CDN 在岛形端点级别进行缓存。
- 具有相同属性的两个相同岛形实例共享一个服务器渲染和负载项。

请注意，岛形响应仅基于名称、属性和上下文进行缓存，这使其能够独立于出现的页面进行缓存；这也是它们无法看到当前路由的原因。

如果您正在构建大部分为静态的网站，岛形与 `prerender` 和 `noScripts` 路由规则结合得很好。

::read-more{to="/docs/guide/recipes/mostly-static-sites"}
请参阅关于组合预渲染、`noScripts`、岛形和延迟 hydration 的静态网站指南。
::

需要注意的一个问题：岛形插槽和 `nuxt-client` 组件依赖于一个小内联脚本，在 hydration 前将传送的内容重新定位到正确位置。在使用 [`noScripts`](/docs/guide/going-further/features#noscripts) 渲染的路由中，该脚本被省略，因此完全交互式的 `nuxt-client` 组件不会在那里进行 hydration。普通的静态岛形则不受影响。

## 当前限制

服务器组件处于实验阶段，一些未完善之处已在开放问题中被跟踪。

- 大多数仅用于服务器组件和独立组件的功能，例如 slots 和 `nuxt-client` 组件，仅适用于单文件组件。
- 使用独立组件可以显著增加构建时生成的 chunk 数量 ([#34855](https://github.com/nuxt/nuxt/issues/34855))。
- 使用 webpack 和 Rspack 时，服务器组件 slot 中的 scoped `:slotted()` 样式可能会失败，因为服务器和客户端构建可能生成不同的范围 ID ([#31510](https://github.com/nuxt/nuxt/issues/31510))。
- Template refs 无法从父组件引用服务器组件内的元素 ([#31512](https://github.com/nuxt/nuxt/issues/31512))。
- `inject`/`provide` 无法跨越独立边界，因此从页面注入到独立服务器组件中无效 ([#22751](https://github.com/nuxt/nuxt/issues/22751))。
- 通过自动生成的包装器渲染的服务器组件不会暴露 load 和 error 事件；如果需要其 `error` 事件和 `refresh()` 方法，请直接使用 `<NuxtIsland>` ([#25744](https://github.com/nuxt/nuxt/issues/25744))。
- [`useId`](https://vuejs.org/api/composition-api-helpers#useid) 在独立组件内部存在已知限制；请参阅 [`<NuxtIsland>` 文档](/docs/api/components/nuxt-island#known-limitations)。
- 每个嵌套的独立组件都会增加额外的开销，因此在其他独立组件内嵌套独立组件时需谨慎操作。
