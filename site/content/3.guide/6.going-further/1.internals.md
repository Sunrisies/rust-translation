本指南帮助您更好地理解 Nuxt 内部机制，以便在 Nuxt 上开发新的解决方案和模块集成。

## Nuxt 接口

当您使用 [`nuxt dev`](/docs/api/commands/dev) 以开发模式启动 Nuxt，或使用 [`nuxt build`](/docs/api/commands/build) 构建生产应用时，
会创建一个常见的上下文，内部称为 `nuxt`。它包含与 `nuxt.config` 文件合并的标准化选项、一些内部状态，以及由 [unjs/hookable](https://github.com/unjs/hookable) 提供的强大的 [钩子系统](/docs/api/advanced/hooks)。
some internal state, and a powerful [hooking system](/docs/api/advanced/hooks) powered by [unjs/hookable](https://github.com/unjs/hookable)
这使得不同组件能够相互通信。您可以将其视为 **构建核心**。

此上下文全局可用，并可通过 [Nuxt Kit](/docs/guide/going-further/kit) 组合式函数使用。
因此，每个进程只能运行一个 Nuxt 实例。

为了扩展 Nuxt 接口并在构建过程的不同阶段进行钩子操作，我们可以使用 [Nuxt 模块](/docs/guide/modules)。

更多详情，请查看 [源代码](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/core/nuxt.ts)。

## NuxtApp 接口

在浏览器或服务器上渲染页面时，会创建一个共享上下文，称为 `nuxtApp`。
此上下文包含 Vue 实例、运行时钩子以及用于 hydration 的内部状态，如 ssrContext 和 payload。
您可以将其视为 **运行时核心**。

此上下文可以通过 Nuxt 插件中的 [`useNuxtApp()`](/docs/api/组合式函数/use-nuxt-app) 组合式函数、`<script setup>` 以及 Vue 组合式函数访问。
全局使用在浏览器中可行，但在服务器上不可行，以避免用户之间共享上下文。

由于 [`useNuxtApp`](/docs/api/组合式函数/use-nuxt-app) 在上下文当前不可用时会抛出异常，如果您的组合式函数不总是需要 `nuxtApp`，您可以改用 [`tryUseNuxtApp`](/docs/api/组合式函数/use-nuxt-app#tryusenuxtapp)，它会返回 `null` 而不是抛出异常。

为了扩展 `nuxtApp` 接口并在不同阶段进行钩子操作或访问上下文，我们可以使用 [Nuxt 插件](/docs/directory-structure/app/plugins)。

有关此接口的更多信息，请查看 [Nuxt App](/docs/api/组合式函数/use-nuxt-app)。

`nuxtApp` 具有以下属性：

```ts
interface NuxtApp {
  vueApp // the global Vue application: https://vuejs.org/api/application.html#application-api

  versions // an object containing Nuxt and Vue versions

  // These let you call and add runtime NuxtApp hooks
  // https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts#L18
  hooks
  hook
  callHook

  // Only accessible on server-side
  ssrContext: {
    url
    req
    res
    runtimeConfig
    noSSR
  }

  // This will be stringified and passed from server to client
  payload: {
    serverRendered: true
    data: {}
    state: {}
  }

  provide: (name: string, value: any) => void
}
```

如需更多细节，请查看 [源代码](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts)。

## 运行时上下文与构建上下文

Nuxt 使用 Node.js 进行项目构建和打包，同时也有运行时层面。

虽然这两个方面都可以扩展，但运行时上下文与构建时上下文是隔离的。因此，它们不应共享状态、代码或上下文，除非是运行时配置！

`nuxt.config` 和 [Nuxt 模块](/docs/guide/modules) 可用于扩展构建上下文，而 [Nuxt 插件](/docs/directory-structure/app/plugins) 可用于扩展运行时功能。

在为生产环境构建应用程序时，`nuxt build` 将在 `.output` 目录中生成独立的构建文件，该文件与 `nuxt.config` 和 [Nuxt 模块](/docs/guide/modules) 无关。
