---
title: 模块依赖关系
description: 使用版本约束和配置合并来声明对其他模块的依赖。
---

如果您的模块依赖于其他模块，可以使用 `moduleDependencies` 选项来声明它们。Nuxt 会确保这些模块按正确顺序安装，验证您提供的版本约束，并合并相应的配置。

## 基本用法

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'

const resolver = createResolver(import.meta.url)

export default defineNuxtModule<ModuleOptions>({
  meta: {
    name: 'my-module',
  },
  moduleDependencies: {
    '@nuxtjs/tailwindcss': {
      // You can specify a version constraint for the module
      version: '>=6',
      // Any configuration that should override `nuxt.options`
      overrides: {
        exposeConfig: true,
      },
      // Any configuration that should be set. It will override module defaults but
      // will not override any configuration set in `nuxt.options`
      defaults: {
        config: {
          darkMode: 'class',
          content: {
            files: [
              resolver.resolve('./runtime/components/**/*.{vue,mjs,ts}'),
              resolver.resolve('./runtime/*.{mjs,js,ts}'),
            ],
          },
        },
      },
    },
  },
  setup (options, nuxt) {
    // We can inject our CSS file which includes Tailwind's directives
    nuxt.options.css.push(resolver.resolve('./runtime/assets/styles.css'))
  },
})
```

::callout{type="info"}
`moduleDependencies` 选项取代了已废弃的 `installModule` 函数。
::

每个条目的键标识需要依赖的模块。您可以使用 npm 包名、本地模块目录路径或 Nuxt 别名，如 `~` 或 `@`。

## 依赖于本地模块

当依赖位于 [`modules/` 目录](/docs/directory-structure/modules)中时，使用文件路径来声明依赖：

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  moduleDependencies: {
    // Path relative to the project root
    './modules/my-local-module': {},
    // Or using a Nuxt alias
    '~/modules/another-local-module': {},
  },
  // ...
})
```

::important
**相对路径是从项目的 `rootDir` 解析的**，而不是从声明依赖的文件解析。位于 `modules/foo.ts` 中的模块引用 `modules/bar.ts` 时，必须使用 `'./modules/bar'`，而不是 `'./bar'`。使用 Nuxt 别名如 `~/modules/bar` 可以避免这种歧义。
::

## 选项

`moduleDependencies` 中的每个条目接受以下字段：

- `version`: 一个 semver 范围。如果解析出的模块版本不符合此范围，Nuxt 会抛出错误。版本检查仅在依赖可以解析为 `package.json` 时生效，因此对于项目本地模块来说，这些检查是无效的。
- `overrides`: 在 `nuxt.options` 之上应用的配置，其优先级高于用户配置。
- `defaults`: 在 `nuxt.options` 之下应用的配置。用户配置优先于这些配置。
- `optional`: 如果为 `true`，当该模块缺失时不会自动安装。如果模块在其他位置已安装，则仍然应用 `overrides` 和 `defaults`。
