## 创建模块

我们建议你使用我们的 [入门模板](https://github.com/nuxt/starter/tree/module) 开始使用 Nuxt 模块：

::code-group{sync="pm"}

```bash [npm]
npm create nuxt -- -t module my-module
```

```bash [yarn]
yarn create nuxt -t module my-module
```

```bash [pnpm]
pnpm create nuxt -t module my-module
```

```bash [bun]
bun create nuxt --template=module my-module
```
::

这将创建一个 `my-module` 项目，包含开发 và 发布模块所需的所有基础文件。

**下一步：**

1. 在你选择的 IDE 中打开 `my-module`
2. 使用你喜欢的包管理器安装依赖项
3. 使用 `npm run dev:prepare` 准备开发所需的本地文件
4. 阅读此文档以了解更多关于 Nuxt 模块的信息

### 开发你的模块

虽然模块源代码位于 `src` 目录中，但要开发模块，通常需要一个 Nuxt 应用来测试它。这就是 `playground` 目录的作用。这是一个你可以随意修改的 Nuxt 应用，已经配置好可以随你的模块一起运行。

你可以像操作任何 Nuxt 应用一样与 playground 交互。

- 使用 `npm run dev` 启动其开发服务器，当你在 `src` 目录中修改模块时，它会自动重新加载。
- 使用 `npm run dev:build` 构建它。

::note
所有其他 `nuxt` 命令都可以用于 `playground` 目录（例如 `nuxt <COMMAND> playground`）。你可以自由地在 `package.json` 中声明额外的 `dev:*` 脚本，以便更方便地使用。
::

### 运行测试

模块入门模板自带基本的测试套件：

- 由 [ESLint](https://eslint.org) 驱动的 linter，使用 `npm run lint` 运行。
- 由 [Vitest](https://vitest.dev) 驱动的测试运行器，使用 `npm run test` 或 `npm run test:watch` 运行。

::tip
你可以根据需求扩展这些默认测试策略以更好地满足你的需求。
::

### 构建你的模块

Nuxt 模块自带由 [`@nuxt/module-builder`](https://github.com/nuxt/module-builder#readme) 提供的构建工具。该构建工具不需要你在端进行任何配置，支持 TypeScript，并且确保你的资源被正确打包以便分发到其他 Nuxt 应用。

你可以通过运行 `npm run prepack` 来构建模块。

::tip
虽然在某些情况下构建模块很有用，但大多数时候你不需要自己构建它：`playground` 会在开发过程中处理这件事，而发布脚本在发布时也会处理此事。
::

### 发布到 npm

::important
在将模块发布到 npm 之前，请确保您拥有 [npmjs.com](https://www.npmjs.com) 账户，并且通过 `npm login` 在本地进行了认证。
::

虽然您可以通过升级版本并使用 `npm publish` 命令来发布模块，但模块 starter 附带了一个发布脚本，可帮助您确保将功能正常的模块版本发布到 npm 及其他平台。

要使用发布脚本，首先将所有更改提交（我们建议您遵循 [Conventional Commits](https://www.conventionalcommits.org) 以利用自动版本升级和变更日志更新）。然后，使用 `npm run release` 运行发布脚本。

运行发布脚本时，将发生以下操作：

- 首先，它将通过以下方式运行测试套件：
  - 运行代码检查工具 (`npm run lint`)
  - 运行单元测试、集成测试和端到端测试 (`npm run test`)
  - 构建模块 (`npm run prepack`)
- 然后，如果测试套件运行正常，它将继续通过以下方式发布模块：
  - 升级模块版本并根据 Conventional Commits 生成变更日志
  - 将模块发布到 npm（为此目的，模块将再次构建，以确保其更新版本号被纳入发布产物中）
  - 将代表新发布版本的 git 标签推送到您的 git 远程仓库 origin 上

::tip
与其他脚本一样，您可以在 `package.json` 中调整默认的 `release` 脚本，以更好地满足您的需求。
::
