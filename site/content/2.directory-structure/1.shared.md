`shared/` 目录允许你共享可在 Vue 应用和 Nitro 服务器中使用的代码。

::note
`shared/` 目录在 Nuxt v3.14+ 中可用。
::

::important
`shared/` 目录中的代码无法导入任何 Vue 或 Nitro 代码。
::

## 为何不能混合使用 Vue 和 Nitro 代码

Nuxt 构建两个独立的包：Vue 应用（客户端和服务器端渲染）以及 Nitro 服务器（API 路由、服务器中间件、服务器插件）。它们独立打包并在不同的环境中运行。`shared/` 目录中的代码被用于这两个包中，因此无法从任一包导入。

### Nitro 中的 Vue 应用代码

组件和组合式函数需要 Vue 应用运行时环境，通常还需要 Nuxt 上下文（例如 `useNuxtApp()` 或 `useRoute()`），而这两者都不存在于 Nitro 中。将它们导入到服务器代码中可能导致构建或运行错误，并且会将 Vue 应用的依赖项引入到服务器包中。

### Vue 应用中的 Nitro 代码

仅服务器使用的代码（如 Node API、Nitro 工具或服务器路由处理器）不得在浏览器中运行。将其导入到应用中可能会破坏客户端构建，导致浏览器中的运行错误，或者将服务器逻辑泄露到客户端包中。

### 纯类型导入

`import type` 在编译时会被删除，不会将运行时代码引入另一个包，因此仅跨边界导入类型可能看起来有效。即便如此，请将共享类型（如 API 响应类型）放在 `shared/types/` 中，这样它们在两个环境中都会自动导入。这能保持边界清晰，避免后来误将类型导入转换为值导入，并且符合 Nuxt 针对应用、服务器和共享代码的独立 [类型上下文](/docs/guide/concepts/typescript#project-references)。

仅在一个环境中使用的类型可以放在该环境旁边：`app/types/` 仅在 Vue 应用中自动导入，而 [`server/types/`](/docs/directory-structure/server#server-types) 仅在 Nitro 服务器中自动导入。当某种类型在两者中都需要时，请使用 `shared/types/`。

## 使用方法

**方法 1：** 命名导出

```ts twoslash [shared/utils/capitalize.ts]
export const capitalize = (input: string) => {
  return input[0] ? input[0].toUpperCase() + input.slice(1) : ''
}
```

**方法 2：** 默认导出

```ts twoslash [shared/utils/capitalize.ts]
export default function (input: string) {
  return input[0] ? input[0].toUpperCase() + input.slice(1) : ''
}
```

现在你可以在 Nuxt 应用和 `server/` 目录中使用 [自动导入](/docs/directory-structure/shared) 的工具。

```vue [app/app.vue]
<script setup lang="ts">
const hello = capitalize('hello')
</script>

<template>
  <div>
    {{ hello }}
  </div>
</template>
```

```ts [server/api/hello.get.ts]
export default defineEventHandler((event) => {
  return {
    hello: capitalize('hello'),
  }
})
```

## 文件如何被扫描

只有位于 `shared/utils/` 和 `shared/types/` 目录中的文件才会被自动导入。这些目录下的子目录中的文件则不会被自动导入，除非你将这些目录添加到 `imports.dirs` 和 `nitro.imports.dirs` 中。

::tip
`shared/utils` 和 `shared/types` 的自动导入机制与扫描方式与 [`app/composables/`](/docs/directory-structure/app/组合式函数) 和 [`app/utils/`](/docs/directory-structure/app/utils) 目录相同。
::

:read-more{to="/docs/directory-structure/app/composables#how-files-are-scanned"}

```bash [Directory Structure]
-| shared/
---| capitalize.ts        # Not auto-imported
---| formatters
-----| lower.ts           # Not auto-imported
---| utils/
-----| lower.ts           # Auto-imported
-----| formatters
-------| upper.ts         # Not auto-imported
---| types/
-----| bar.ts             # Auto-imported
```

在 `shared/` 文件夹中创建的任何其他文件必须使用 `#shared` 别名手动导入（由 Nuxt 自动配置）：

```ts [Importing From #shared]
// For files directly in the shared directory
import capitalize from '#shared/capitalize'

// For files in nested directories
import lower from '#shared/formatters/lower'

// For files nested in a folder within utils
import upper from '#shared/utils/formatters/upper'
```

该别名可确保应用程序中的导入一致，无论导入文件的位置如何。
