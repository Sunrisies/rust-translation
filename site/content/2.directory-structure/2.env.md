## 开发、构建和生成时

在开发模式以及运行 [`nuxt build`](/docs/api/commands/build) 和 [`nuxt generate`](/docs/api/commands/generate) 时，Nuxt CLI 通过 [c12](https://github.com/unjs/c12) 内置支持 `.env` 文件。

除了进程环境变量外，如果您在项目根目录中有 `.env` 文件，它将在 **开发、构建和生成时** 自动加载。在此处设置的任何环境变量都可以在 `nuxt.config` 文件和模块中访问。

```ini [.env]
MY_ENV_VARIABLE=hello
```

::note
请注意，从 `.env` 中删除变量或完全移除 `.env` 文件不会取消已设置的值。
::

## 自定义文件

如果您想使用不同的文件——例如 `.env.local` 或 `.env.production`——可以通过在使用 Nuxt CLI 时传递 `--dotenv` 标志来实现。

```bash [Terminal]
npx nuxt dev --dotenv .env.local
```

在开发模式下更新 `.env` 时，Nuxt 实例会自动重启，以便将新值应用到 `process.env` 中。

::important
在应用程序代码中，您应该使用 [运行时配置](/docs/guide/going-further/runtime-config) 而不是简单的环境变量。
::

## 生产环境

**在服务器构建完成后**，您需要在运行服务器时设置环境变量。

此时不会读取您的 `.env` 文件。每种环境的具体做法各不相同。

这一设计决策是为了确保在各种部署环境中保持兼容性，其中一些环境可能没有传统的文件系统，例如无服务器平台或像 Cloudflare Workers 这样的边缘网络。

由于 `.env` 文件在生产环境中不使用，您必须使用托管环境提供的工具和方法显式设置环境变量。以下是一些常见的方法：

* 您可以通过终端将环境变量作为参数传递：

   `$ NODE_ENV=production DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs`

* 您可以在 `.bashrc` 或 `.profile` 等 shell 配置文件中设置环境变量。

* 许多云服务提供商，如 Vercel、Netlify 和 AWS，都提供通过仪表板、CLI 工具或配置文件设置变量的接口。

::important
`runtimeConfig` [在生产环境中不会获取以 `NUXT_` 开头的之外的环境变量] (/docs/guide/going-further/runtime-config#environment-variables)。
::

## 生产预览版

为了进行本地生产预览，我们建议使用 [`nuxt preview`](/docs/api/commands/preview)，因为使用此命令后 `.env` 文件会被加载到 `process.env` 中，方便使用。请注意，此命令要求在包目录中安装依赖项。

或者您可以通过终端将环境变量作为参数传递。例如，在 Linux 或 macOS 上：

```bash [Terminal]
NODE_ENV=production DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs
```

请注意，对于纯静态网站，在项目预渲染后无法设置运行时配置。

:read-more{to="/docs/guide/going-further/runtime-config"}

::note
如果您希望使用构建时设置的环境变量，但不关心后续更新（或只需在应用内部进行响应式更新），那么 `appConfig` 可能是更好的选择。您可以在 `nuxt.config` 中定义 `appConfig`（使用环境变量），也可以在项目的 `~/app.config.ts` 文件中定义。
:read-more{to="/docs/directory-structure/app/app-config"}
::
