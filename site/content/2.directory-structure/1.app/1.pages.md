::note
为了减少应用程序的包大小，此目录是**可选的**，这意味着如果你只使用 [`app.vue`](/docs/directory-structure/app/app)，[vue-router](https://router.vuejs.org) 将不会被包含。若需要强制使用页面系统，请在 `nuxt.config` 中设置 `pages: true`，或使用 [`router.options.ts`](/docs/guide/recipes/custom-routing#using-routeroptions)。
::

## 使用方式

页面是 Vue 组件，可以拥有 Nuxt 支持的任何[有效扩展名](/docs/api/nuxt-config#extensions)（默认为 `.vue`, `.js`, `.jsx`, `.mjs`, `.ts` 或 `.tsx）。

Nuxt 会自动为 `~/pages/` 目录中的每一页创建路由。

::tip
只有在未禁用 `prerender.crawlLinks` 且 `prerender.routes` 列表中至少有一个页面时，页面才会被自动注册用于预渲染。请参阅[预渲染指南](/docs/getting-started/prerendering)。
::

::code-group

```vue [app/pages/index.vue]
<template>
  <h1>Index page</h1>
</template>
```

```ts twoslash [pages/index.ts]
// https://vuejs.org/guide/extras/render-function.html
export default defineComponent({
  render () {
    return h('h1', 'Index page')
  },
})
```

```tsx twoslash [pages/index.tsx]
// /docs/examples/advanced/jsx
// https://vuejs.org/guide/extras/render-function.html#jsx-tsx
export default defineComponent({
  render () {
    return <h1>Index page</h1>
  },
})
```

::

`app/pages/index.vue` 文件将被映射到应用程序的 `/` 路由。

如果你使用 [`app.vue`](/docs/directory-structure/app/app)，请确保使用 [`<NuxtPage/>`](/docs/api/components/nuxt-page) 组件来显示当前页面：

```vue [app/app.vue]
<template>
  <div>
    <!-- Markup shared across all pages, ex: NavBar -->
    <NuxtPage />
  </div>
</template>
```

页面**必须有一个根元素**，以便在不同页面之间进行[路由过渡](/docs/getting-started/transitions)。HTML 注释也被视为元素。

这意味着当路由由服务器渲染或静态生成时，你可以正确看到其内容；但在客户端导航时访问该路由时，路由之间的过渡会失败，且该路由将不会被渲染。

以下是一些示例，说明具有单个根元素的页面是什么样子：

::code-group

```vue [app/pages/working.vue]
<template>
  <div>
    <!-- This page correctly has only one single root element -->
    Page content
  </div>
</template>
```

```vue [app/pages/bad-1.vue]
<template>
  <!-- This page will not render when route changes during client side navigation, because of this comment -->
  <div>Page content</div>
</template>
```

```vue [app/pages/bad-2.vue]
<template>
  <div>This page</div>
  <div>Has more than one root element</div>
  <div>And will not render when route changes during client side navigation</div>
</template>
```

::

## 动态路由

如果你在方括号中放置任何内容，它将被转换为[动态路由](https://router.vuejs.org/guide/essentials/dynamic-matching)参数。你可以混合使用多个参数，甚至可以在文件名或目录中包含非动态文本。

如果希望参数为_可选_，则必须用双方括号包裹它——例如 `~/pages/[[slug]]/index.vue` 或 `~/pages/[[slug]].vue` 将匹配 `/` 和 `/test`。

```bash [Directory Structure]
-| pages/
---| index.vue
---| users-[group]/
-----| [id].vue
```

根据上述示例，您可以通过 `$route` 对象在组件内访问 group/id：

```vue [app/pages/users-[group\\]/[id\\].vue]
<template>
  <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>
```

导航到 `/users-admins/123` 将显示：

```html
<p>admins - 123</p>
```

如果您想使用 Composition API 访问路由，有一个全局 [`useRoute`](/docs/api/组合式函数/use-route) 函数，可以像 Options API 中的 `this.$route` 一样访问路由。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

if (route.params.group === 'admins' && !route.params.id) {
  console.log('Warning! Make sure user is authenticated!')
}
</script>
```

::note
具有名称的父路由会优先于嵌套的动态路由。对于 `/foo/hello` 路由，`~/pages/foo.vue` 将优先于 `~/pages/foo/[slug].vue`。:br 使用 `~/pages/foo/index.vue` 和 `~/pages/foo/[slug].vue` 可以匹配 `/foo` 和 `/foo/hello` 对应的不同页面。
::

## 捕获所有路由

如果您需要捕获所有路由的路由，可以通过使用类似 `[...slug].vue` 的文件来创建它。这将匹配该路径下的所有路由。

```vue [app/pages/[...slug\\].vue]
<template>
  <p>{{ $route.params.slug }}</p>
</template>
```

导航到 `/hello/world` 将显示：

```html
<p>["hello", "world"]</p>
```

## 嵌套路由

可以使用 `<NuxtPage>` 显示 [嵌套路由](https://router.vuejs.org/guide/essentials/nested-routes)。

示例：

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
---| parent.vue
```

此文件树将生成以下路由：

```js
[
  {
    path: '/parent',
    component: '~/pages/parent.vue',
    name: 'parent',
    children: [
      {
        path: 'child',
        component: '~/pages/parent/child.vue',
        name: 'parent-child',
      },
    ],
  },
]
```

要显示 `child.vue` 组件，您需要在 `app/pages/parent.vue` 中插入 `<NuxtPage>` 组件：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>I am the parent view</h1>
    <NuxtPage :foobar="123" />
  </div>
</template>
```

```vue {}[pages/parent/child.vue]
<script setup lang="ts">
const props = defineProps({
  foobar: String,
})

console.log(props.foobar)
</script>
```

### 子路由键

如果您希望更灵活地控制 `<NuxtPage>` 组件的重新渲染时机（例如用于过渡效果），可以通过 `pageKey` 属性传递字符串或函数，或者通过 `definePageMeta` 定义 `key` 值：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>I am the parent view</h1>
    <NuxtPage :page-key="route => route.fullPath" />
  </div>
</template>
```

或者：

```vue twoslash {}[pages/parent/child.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
})
</script>
```

## 命名视图 :badge[v4.5]{color="info" size="xs" class="align-middle"}

单个路由可以在父组件中渲染多个 `<NuxtPage>` 出口，只需为每个出口指定 `name`，并为每个 `name` 提供对应的子页面文件。

使用 `name@view.vue` 作为文件名约定来声明命名视图，并与其默认路由文件一起使用：

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
-----| child@sidebar.vue
---| parent.vue
```

然后从父组件按名称渲染每个出口：

```vue [pages/parent.vue]
<template>
  <div>
    <NuxtPage />
    <aside>
      <NuxtPage name="sidebar" />
    </aside>
  </div>
</template>
```

当用户导航到 `/parent/child` 时，`child.vue` 将渲染为默认的 `<NuxtPage />`，而 `child@sidebar.vue` 将渲染为 `<NuxtPage name="sidebar" >`。没有对应命名视图的出口将保持为空。

::note
`definePageMeta` 仅从默认路由文件读取。在 `name@view.vue` 子文件中声明的元数据对路由没有影响。
::

:read-more{title="Named Views" to="https://router.vuejs.org/guide/essentials/named-views.html" target="_blank"}

## 路由组

在某些情况下，您可能希望将一组路由组合在一起，而不会影响基于文件的路由。为此，您可以将文件放在由括号 `(` 和 `)` 包裹的文件夹中。

例如：

```bash [Directory structure]
-| pages/
---| index.vue
---| (marketing)/
-----| about.vue
-----| contact.vue
```

这将在你的应用中生成 `/`、`/about` 和 `/contact` 页面。在 URL 结构方面，`marketing` 组会被忽略。

### 访问路由组 :badge[v4.3]{color="info" size="xs" class="align-middle"}

路由组会自动以 `route.meta.groups` 的形式出现在路由元数据中。
这允许你在组件中访问组信息，用于条件逻辑、样式设置或其他目的。

```vue {}[pages/(marketing)/about.vue]
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.groups) // Output: ['marketing']
</script>

<template>
  <div>
    <p v-if="route.meta.groups?.includes('marketing')">
      This is a marketing page
    </p>
  </div>
</template>
```

## 页面元数据

你可能需要在你的应用中为每个路由定义元数据。你可以使用 `definePageMeta` 宏来实现这一点，该宏可以在 `<script>` 和 `<script setup>` 中使用：

```vue twoslash
<script setup lang="ts">
definePageMeta({
  title: 'My home page',
})
</script>
```

然后你可以在整个应用的其他部分通过 `route.meta` 对象访问这些数据。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.title) // My home page
</script>
```

如果你使用嵌套路由，所有这些路由的页面元数据将合并成一个对象。关于路由元数据的更多内容，请参见 [vue-router 文档](https://router.vuejs.org/guide/advanced/meta)。

与 `defineEmits` 或 `defineProps`（参见 [Vue 文档](https://vuejs.org/api/sfc-script-setup#defineprops-defineemits)）类似，`definePageMeta` 是一个 **编译器宏**。它会被编译掉，因此你无法在组件内部引用它。相反，传递给它的元数据会被提升到组件外部。
因此，页面元对象不能引用组件。然而，它可以引用导入的绑定以及本地定义的 **纯函数**。

::warning
确保不要引用任何会导致副作用的反应式数据或函数。这可能会导致意外行为。
::

```vue
<script setup lang="ts">
import { someData } from '~/utils/example'

function validateIdParam (route) {
  return route.params.id && !Number.isNaN(Number(route.params.id))
}

const title = ref('')

definePageMeta({
  validate: validateIdParam,
  someData,
  title, // do not do this, the ref will be hoisted out of the component
})
</script>
```

### 特殊元数据

当然，你可以为整个应用中的其他用途定义元数据。但是使用 `definePageMeta` 定义的某些元数据有特定的用途：

#### `alias`

你可以定义页面别名。它们允许你从不同的路径访问同一个页面。它可以是字符串或字符串数组，如 [vue-router 文档](https://router.vuejs.org/guide/essentials/redirect-and-alias#Alias) 中所述。

#### `keepalive`

如果你在 `definePageMeta` 中设置 `keepalive: true`，Nuxt 会自动将你的页面包裹在 [Vue `<KeepAlive>` 组件](https://vuejs.org/guide/built-ins/keep-alive#keepalive) 中。例如，在具有动态子路由的父路由中，如果你想在路由变化时保留页面状态，这可能会很有用。

当您的目标是为父路由保留状态时，请使用以下语法：`<NuxtPage keepalive >`。您也可以设置传递给 `<KeepAlive>` 的 props（参见 [完整列表](https://vuejs.org/api/built-in-components#keepalive)）。

您可以在 `nuxt.config` 中设置此属性的默认值 [位于](/docs/api/nuxt-config#keepalive)。

#### `key`

[参见上文](/docs/directory-structure/app/pages#child-route-keys)。

#### `layout`

您可以定义用于渲染路由的布局。这可以是 false（禁用任何布局）、字符串或 ref/computed，如果您希望以某种方式使其具有反应性。[更多关于布局的信息](/docs/directory-structure/app/layouts)。

#### `layoutTransition` 和 `pageTransition`

您可以定义包裹页面和布局的 `<transition>` 组件的过渡属性，或者传递 `false` 以禁用该路由的 `<transition>` 包装器。您可以在 [可传递的选项列表](https://vuejs.org/api/built-in-components#transition) 中查看，或阅读 [关于过渡工作原理的更多内容](https://vuejs.org/guide/built-ins/transition#transition)。

您可以在 `nuxt.config` 中设置这些属性的默认值 [位于](/docs/api/nuxt-config#layouttransition)。

#### `middleware`

您可以定义在加载此页面之前应用的中间件。它将与任何匹配的父/子路由中使用的所有其他中间件合并。它可以是一个字符串、一个函数（匿名/内联的中间件函数，遵循 [全局 before guard 模式](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)），或是一组字符串/函数。[更多关于命名中间件的信息](/docs/directory-structure/app/中间件)。

#### `name`

您可以为此页面的路由定义一个名称。

#### `path`

如果您有更复杂的路径模式而文件名无法表达，可以定义路径匹配器。有关更多信息，请参见 [`vue-router` 文档](https://router.vuejs.org/guide/essentials/route-matching-syntax#Custom-regex-in-params)。

#### `props`

允许将路由 `params` 作为 props 传递给页面组件。有关更多信息，请参见 [`vue-router` 文档](https://router.vuejs.org/guide/essentials/passing-props)。

### 自定义元数据的类型定义

如果您为页面添加自定义元数据，可能希望以类型安全的方式实现。可以扩展 `definePageMeta` 所接受对象的类型：

```ts [index.d.ts]
declare module '#app' {
  interface PageMeta {
    pageType?: string
  }
}

// It is always important to ensure you import/export something when augmenting a type
export {}
```

## 导航

要在应用页面之间导航，应使用 [`<NuxtLink>`](/docs/api/components/nuxt-link) 组件。

该组件由 Nuxt 包含，因此无需像其他组件那样进行导入。

`app/pages` 文件夹中指向 `index.vue` 页面的简单链接示例：

```vue
<template>
  <NuxtLink to="/">Home page</NuxtLink>
</template>
```

::read-more{to="/docs/api/components/nuxt-link"}
了解更多关于 `<NuxtLink>` 的使用方法。
::

## 程序化导航

Nuxt 通过 `navigateTo()` 工具方法允许程序化导航。使用此工具方法，你可以以程序化方式在应用中引导用户。这对于从用户处获取输入并在整个应用程序中动态导航非常有用。在此示例中，我们有一个名为 `navigate()` 的简单方法，当用户提交搜索表单时调用。

::note
务必在调用 `navigateTo` 时始终使用 `await`，或通过函数返回来链式处理其结果。
::

```vue twoslash
<script setup lang="ts">
const name = ref('')
const type = ref(1)

function navigate () {
  return navigateTo({
    path: '/search',
    query: {
      name: name.value,
      type: type.value,
    },
  })
}
</script>
```

## 仅客户端页面

你可以通过添加 `.client.vue` 后缀将页面定义为 [仅客户端](/docs/directory-structure/app/components#client-components) 页面。该页面的所有内容都不会在服务器上渲染。

## 仅服务器页面

你可以通过添加 `.server.vue` 后缀将页面定义为 [仅服务器](/docs/directory-structure/app/components#server-components) 页面。虽然你可以使用 `vue-router` 控制的客户端导航来访问该页面，但页面将自动由服务器组件渲染，这意味着渲染该页面所需的代码不会包含在客户端 bundles 中。

::warning
仅服务器页面必须有一个根元素。（HTML 注释也被视为元素。）
::

访问仅服务器页面需要请求来渲染它，因此当使用 `<NuxtLink>` 指向该页面时，Nuxt 也会预取该响应。

::read-more{to="/docs/guide/concepts/server-components#the-client-navigation-round-trip"}
::

## 多个页面目录

默认情况下，所有页面应位于项目的根目录下的 `app/pages` 目录中。

不过，你可以使用 [Nuxt Layers](/docs/getting-started/layers) 来将应用页面分组。

```bash [Directory Structure]
-| some-app/
---| nuxt.config.ts
---| pages/
-----| app-page.vue
-| nuxt.config.ts
```

```ts twoslash [some-app/nuxt.config.ts]
// some-app/nuxt.config.ts
export default defineNuxtConfig({
})
```

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['./some-app'],
})
```
