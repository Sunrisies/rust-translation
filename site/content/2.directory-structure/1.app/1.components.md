Nuxt 会自动导入该目录中的任何组件（以及由您使用的模块注册的组件）。

```bash [Directory Structure]
-| components/
---| AppHeader.vue
---| AppFooter.vue
```

```html [app/app.vue]
<template>
  <div>
    <AppHeader />
    <NuxtPage />
    <AppFooter />
  </div>
</template>
```

## 组件名称

如果您在嵌套目录中有组件，例如：

```bash [Directory Structure]
-| components/
---| base/
-----| foo/
-------| Button.vue
```

... 那么组件的名称将基于其路径目录和文件名，重复的片段将被移除。因此，组件的名称将是：

```html
<BaseFooButton />
```

::note
为了清晰起见，我们建议组件的文件名与其名称一致。因此，在上面的示例中，您可以将 `Button.vue` 重命名为 `BaseFooButton.vue`。
::

如果您希望将组件分组到目录中而不影响其名称，可以使用括号 `(` `)` 来命名分组目录。

```bash [Grouping Directory]
-| components/
---| base/
-----| (foo)/
-------| Button.vue
```

... 那么组件的名称将跳过分组目录，结果如下：

```html
<BaseButton />
```

如果您只想根据组件名称而不是路径来自动导入组件，则需要使用配置对象的扩展形式将 `pathPrefix` 选项设置为 `false`：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      pathPrefix: false, // [!code ++]
    },
  ],
})
```

这种注册方式采用与 Nuxt 2 相同的策略。例如，`~/components/Some/MyComponent.vue` 将可用为 `<MyComponent>，而不是 `<SomeMyComponent>`。

## 动态组件

如果您想使用 Vue `<component :is="someComputedComponent">{lang=vue}` 语法，需要使用 Vue 提供的 `resolveComponent` 辅助函数，或者直接从 `#components` 导入组件并将其传递给 `is` 属性。

例如：

```vue [app/pages/index.vue]
<script setup lang="ts">
import { SomeComponent } from '#components'

const MyButton = resolveComponent('MyButton')
</script>

<template>
  <component :is="clickable ? MyButton : 'div'" />
  <component :is="SomeComponent" />
</template>
```

::important
如果您使用 `resolveComponent` 来处理动态组件，请确保只插入组件的名称，该名称必须是字面字符串，而不是变量或包含变量。该字符串在编译阶段会被静态分析。
::

:video-accordion{title="Watch Daniel Roe's short video about resolveComponent()" videoId="4kq8E5IUM2U"}

或者，虽然不推荐，您也可以全局注册所有组件，这将为所有组件创建异步块并使其在整个应用程序中可用。

```diff
  export default defineNuxtConfig({
    components: {
+     global: true,
+     dirs: ['~/components']
    },
  })
```

您还可以将某些组件选择性地注册到全局，将其放在 `~/components/global` 目录中，或在其文件名后添加 `.global.vue` 后缀。如上所述，每个全局组件都会渲染在独立的块中，因此请注意不要过度使用此功能。

::note
`global` 选项也可以针对每个组件目录进行设置。
::

## 动态导入

要动态导入组件（也称为懒加载组件），只需在组件名称前添加 `Lazy` 前缀即可。如果组件并非始终需要，此方法特别有用。

使用 `Lazy` 前缀可以延迟加载组件代码，直到合适的时机，这有助于优化 JavaScript 包的大小。

```vue [app/pages/index.vue]
<script setup lang="ts">
const show = ref(false)
</script>

<template>
  <div>
    <h1>Mountains</h1>
    <LazyMountainsList v-if="show" />
    <button
      v-if="!show"
      @click="show = true"
    >
      Show List
    </button>
  </div>
</template>
```

## 延迟（或懒） hydration

懒加载组件非常适合控制应用中的块大小，但并不总是能提升运行时性能，因为除非条件渲染，否则它们仍会立即加载。在实际应用中，某些页面可能包含大量内容和组件，大多数情况下并非所有组件在页面加载时都需要互动。如果所有组件都立即加载，可能会对性能产生负面影响。

为了优化应用，您可能希望延迟某些组件的 hydration 操作，直到它们可见或浏览器完成更重要的任务后再进行。

Nuxt 支持通过懒（或延迟）hydration 来实现这一点，使您能够控制组件何时变得可互动。

### Hydration 策略

Nuxt 提供多种内置 hydration 策略。每个懒加载组件只能使用一种策略。

::note
对懒加载组件的任何 prop 更改都会立即触发 hydration。（例如，在具有 `hydrate-never` 的组件上更改 prop 会导致其进行 hydration）
::

::warning
目前 Nuxt 的内置懒 hydration 仅适用于单文件组件（SFC），并且需要在模板中定义 prop（而不是通过 `v-bind` 传递 prop 对象）。它也不适用于从 `#components` 直接导入组件。
::

#### `hydrate-on-visible`

在组件在视口中可见时进行 hydration。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-visible />
  </div>
</template>
```

::read-more{to="https://developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver/IntersectionObserver" title="IntersectionObserver配置选项"}
了解更多关于 `hydrate-on-visible` 选项的信息。
::

::note
实际上，这是使用 Vue 内置的 [`hydrateOnVisible` 策略](https://vuejs.org/guide/components/async#hydrate-on-visible)。
::

#### `hydrate-on-idle`

在浏览器处于空闲状态时进行 hydration。如果希望组件尽快加载，但不阻塞关键渲染路径，则适合使用此策略。

您还可以传递一个数字作为最大超时时间。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-idle />
  </div>
</template>
```

::note
实际上，这是使用 Vue 内置的 [`hydrateOnIdle` 策略](https://vuejs.org/guide/components/async#hydrate-on-idle)。
::

#### `hydrate-on-interaction`

在指定的交互行为发生后（例如点击、鼠标悬停）对组件进行 hydration 处理。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-interaction="mouseover" />
  </div>
</template>
```

如果您不传递事件或事件列表，则默认在 `pointerenter`、`click` 和 `focus` 时进行 hydration 处理。

::note
实际上，这是使用 Vue 内置的 [`hydrateOnInteraction` 策略](https://vuejs.org/guide/components/async#hydrate-on-interaction)。
::

#### `hydrate-on-media-query`

当窗口符合媒体查询条件时，对组件进行 hydration 处理。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-media-query="(max-width: 768px)" />
  </div>
</template>
```

::note
实际上，这是使用 Vue 内置的 [`hydrateOnMediaQuery` 策略](https://vuejs.org/guide/components/async#hydrate-on-media-query)。
::

#### `hydrate-after`

在指定的延迟时间（以毫秒为单位）后对组件进行 hydration 处理。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-after="2000" />
  </div>
</template>
```

#### `hydrate-when`

根据布尔条件对组件进行 hydration 处理。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-when="isReady" />
  </div>
</template>

<script setup lang="ts">
const isReady = ref(false)
function myFunction () {
  // trigger custom hydration strategy...
  isReady.value = true
}
</script>
```

#### `hydrate-never`

绝不会对组件进行 hydration 处理。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-never />
  </div>
</template>
```

### 监听 Hydration 事件

所有延迟 hydration 的组件在完成 hydration 后会发出 `@hydrated` 事件。

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent
      hydrate-on-visible
      @hydrated="onHydrate"
    />
  </div>
</template>

<script setup lang="ts">
function onHydrate () {
  console.log('Component has been hydrated!')
}
</script>
```

### 注意事项与最佳实践

延迟 hydration 可以带来性能优势，但正确使用非常重要：

1. **优先使用视口内内容：** 对于至关重要的、必须立即显示的内容，避免延迟 hydration。适合那些不需要立即使用的内容。

2. **条件渲染：** 当在懒加载组件中使用 `v-if="false"` 时，可能不需要延迟 hydration，可以直接使用普通的懒加载组件。

3. **共享状态：** 注意多个组件之间的共享状态（`v-model`）。一个组件中的模型更新可能会触发所有绑定该模型的组件进行 hydration。

4. **使用每种策略的适用场景：** 每种策略都针对特定用途进行了优化。
    * `hydrate-when` 最适合那些不一定需要 hydration 的组件。
    * `hydrate-after` 适用于可以等待特定时间的组件。
    * `hydrate-on-idle` 适用于在浏览器空闲时可以进行 hydration 的组件。

5. **避免在交互式组件上设置 `hydrate-never`：** 如果组件需要用户交互，不应设置为永远不进行 hydration。

## 直接导入

如果您希望或需要绕过 Nuxt 的自动导入功能，也可以显式从 `#components` 中导入组件。

```vue [app/pages/index.vue]
<script setup lang="ts">
import { LazyMountainsList, NuxtLink } from '#components'

const show = ref(false)
</script>

<template>
  <div>
    <h1>Mountains</h1>
    <LazyMountainsList v-if="show" />
    <button
      v-if="!show"
      @click="show = true"
    >
      Show List
    </button>
    <NuxtLink to="/">Home</NuxtLink>
  </div>
</template>
```

## 自定义目录

默认情况下，仅扫描 `~/components` 目录。如果您想添加其他目录，或者更改该目录下的子文件夹中组件的扫描方式，可以在配置中添加额外的目录。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/calendar-module/components/event/Update.vue => <EventUpdate />
    { path: '~/calendar-module/components' },

    // ~/user-module/components/account/UserDeleteDialog.vue => <UserDeleteDialog />
    { path: '~/user-module/components', pathPrefix: false },

    // ~/components/special-components/Btn.vue => <SpecialBtn />
    { path: '~/components/special-components', prefix: 'Special' },

    // It's important that this comes last if you have overrides you wish to apply
    // to sub-directories of `~/components`.
    //
    // ~/components/Btn.vue => <Btn />
    // ~/components/base/Btn.vue => <BaseBtn />
    '~/components',
  ],
})
```

::note
所有嵌套目录必须首先被添加，因为它们是按顺序被扫描的。
::

每个目录条目还接受 `pattern` 和 `ignore` 通配符选项，这些选项控制在 `path` 中扫描哪些文件。当你的组件位于不遵循默认布局的嵌套文件夹中时，例如领域驱动结构，这非常有用。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/domains/blog/components/PostCard.vue => <PostCard />
    {
      path: '~/domains',
      pattern: '*/components/**',
      pathPrefix: false,
    },
  ],
})
```

::note
如果指定了 `pattern`，`extensions` 选项将不起作用，因此请确保你的模式与你想扫描的文件扩展名匹配。
::

## npm 包

如果你想自动从 npm 包导入组件，可以在 [本地模块](/docs/directory-structure/modules) 中使用 [`addComponent`](/docs/api/kit/components#addcomponent) 来注册它们。

::code-group

```ts twoslash [~/modules/register-component.ts]
import { addComponent, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    // import { MyComponent as MyAutoImportedComponent } from 'my-npm-package'
    addComponent({
      name: 'MyAutoImportedComponent',
      export: 'MyComponent',
      filePath: 'my-npm-package',
    })
  },
})
```

```vue [app/app.vue]
<template>
  <div>
    <!--  the component uses the name we specified and is auto-imported  -->
    <MyAutoImportedComponent />
  </div>
</template>
```

::

## 组件扩展

默认情况下，在 `[nuxt.config.ts` 的 `extensions` 键中指定的扩展名下的任何文件都被视为组件。
如果你需要限制应被注册为组件的文件扩展名，可以使用组件目录声明的高级形式及其 `extensions` 键：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      extensions: ['.vue'], // [!code ++]
    },
  ],
})
```

## 客户端组件

如果某个组件仅应在客户端端渲染，可以在组件后添加 `.client` 后缀。

```bash [Directory Structure]
| components/
--| Comments.client.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!-- this component will only be rendered on client side -->
    <Comments />
  </div>
</template>
```

::note
此功能仅适用于 Nuxt 自动导入和 `#components` 导入。从实际路径显式导入这些组件不会将其转换为仅用于客户端的组件。
::

::important
`.client` 组件只有在挂载后才会被渲染。要使用 `onMounted()` 访问渲染后的模板，请在 `onMounted()` 钩子的回调中添加 `await nextTick()`。
::

::read-more{to="/docs/api/components/client-only"}
你也可以使用 `<ClientOnly>` 组件实现类似的效果。
::

## 服务器组件

服务器组件允许在客户端应用内对单个组件进行服务器渲染。即使你在生成静态网站，也可以在 Nuxt 中使用服务器组件。这使得构建混合动态组件、服务器渲染的 HTML 甚至静态标记块的复杂网站成为可能。

服务器组件可以单独使用，也可以与 [客户端组件](/docs/directory-structure/app/components#paired-with-a-client-component) 搭配使用。

:video-accordion{title="Watch Learn Vue video about Nuxt Server Components" videoId="u1yyXe86xJM"}

::tip{icon="i-lucide-newspaper" to="https://roe.dev/blog/nuxt-server-components" target="_blank"}
阅读 Daniel Roe 关于 Nuxt 服务器组件的指南。
::

### 独立服务器组件

独立服务器组件总是会在服务器上渲染，也称为 Islands 组件。

当它们的属性发生变化时，这将导致网络请求，从而就地更新渲染的 HTML。

使用带有 `.server` 后缀的服务器专用组件，它们将在你的应用程序中自动被使用。

```bash [Directory Structure]
-| components/
---| HighlightedMarkdown.server.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!--
      this will automatically be rendered on the server, meaning your markdown parsing + highlighting
      libraries are not included in your client bundle.
     -->
    <HighlightedMarkdown markdown="# Headline" />
  </div>
</template>
```

服务器专用组件在内部使用 [`<NuxtIsland>`](/docs/api/components/nuxt-island)，这意味着 `lazy` 属性和 `#fallback` 插槽都会被传递给它。

::warning
服务器组件（和岛屿组件）必须有一个根元素。（HTML 注释也被视为元素。）
::

::read-more{to="/docs/guide/concepts/server-components"}
关于岛屿组件的渲染方式、孤立岛屿上下文、`nuxt-client` 的选择性 hydration、插槽、缓存以及当前限制，请参考专门的服务器组件指南。
::

### 与客户端组件配对使用

在这种情况下，`.server` + `.client` 组件是组件的两部分，可以在高级用例中用于在服务器和客户端分别实现组件。

```bash [Directory Structure]
-| components/
---| Comments.client.vue
---| Comments.server.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!-- this component will render Comments.server on the server then Comments.client once mounted in the browser -->
    <Comments />
  </div>
</template>
```

## 库作者

创建具有自动摇树优化和组件注册的 Vue 组件库非常容易。✨

你可以使用来自 `@nuxt/kit` 的 [`addComponentsDir`](/docs/api/kit/components#addcomponentsdir) 方法在 Nuxt 模块中注册你的组件目录。

想象一个这样的目录结构：

```bash [Directory Structure]
-| node_modules/
---| awesome-ui/
-----| components/
-------| Alert.vue
-------| Button.vue
-----| nuxt.ts
-| pages/
---| index.vue
-| nuxt.config.ts
```

然后在 `awesome-ui/nuxt.ts` 中，你可以使用 `addComponentsDir` 钩子：

```ts twoslash
import { addComponentsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const resolver = createResolver(import.meta.url)

    // Add ./components dir to the list
    addComponentsDir({
      path: resolver.resolve('./components'),
      prefix: 'awesome',
    })
  },
})
```

就是这样！现在在你的项目中，你可以在 `nuxt.config` 文件中将你的 UI 库作为 Nuxt 模块导入：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['awesome-ui/nuxt'],
})
```

……并直接在 `app/pages/index.vue` 中使用模块组件（以 `awesome-` 为前缀）：

```vue
<template>
  <div>
    My <AwesomeButton>UI button</AwesomeButton>!
    <awesome-alert>Here's an alert!</awesome-alert>
  </div>
</template>
```

只有当组件被使用时，它才会自动导入这些组件，并且在更新 `node_modules/awesome-ui/components/` 中的组件时还支持 HMR。
