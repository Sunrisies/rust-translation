## alias

通过定义额外的 alias，您可以提高开发效率，以便访问 JavaScript 和 CSS 中的自定义目录。

- **类型**: `object`
- **默认**
```json
{
  "~": "/<rootDir>/app",
  "@": "/<rootDir>/app",
  "~~": "/<rootDir>",
  "@@": "/<rootDir>",
  "#shared": "/<rootDir>/shared",
  "#server": "/<rootDir>/server",
  "assets": "/<rootDir>/app/assets",
  "public": "/<rootDir>/public",
  "#build": "/<rootDir>/.nuxt",
  "#internal/nuxt/paths": "/<rootDir>/.nuxt/paths.mjs"
}
```

::callout
**注意**: 在 webpack 环境中（图像源、CSS——但不包括 JavaScript），您必须通过在 alias 前加上 `~` 来访问它。
这些 alias 将自动添加到生成的 TypeScript 配置中（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json` 等），从而提供完整的类型支持和路径补全功能。如果您需要进一步扩展生成配置提供的选项，请确保在 `nuxt.config` 中的 `typescript.tsConfig` 属性或此处添加它们。
::

::callout
<!-- @case-police-ignore tsConfig -->
**Note**: These aliases will be automatically added to the generated TypeScript configurations (`.nuxt/tsconfig.app.json`, `.nuxt/tsconfig.server.json`, etc.) so you can get full type support and path auto-complete. In case you need to extend options provided by the generated configurations further, make sure to add them here or within the `typescript.tsConfig` property in `nuxt.config`.
::

**示例**:
```ts
import { fileURLToPath } from 'node:url'

export default defineNuxtConfig({
  alias: {
    'images': fileURLToPath(new URL('./assets/images', import.meta.url)),
    'style': fileURLToPath(new URL('./assets/style', import.meta.url)),
    'data': fileURLToPath(new URL('./assets/other/data', import.meta.url)),
  },
})
```

```html
<template>
  <img src="~images/main-bg.jpg">
</template>

<script>
import data from 'data/test.json'
</script>

<style>
// Uncomment the below
//@import '~style/variables.scss';
//@import '~style/utils.scss';
//@import '~style/base.scss';
body {
  background-image: url('~images/main-bg.jpg');
}
</style>
```

## analyzeDir

当运行 `nuxt analyze` 时，Nuxt 将把生成的文件存储在该目录中。

如果指定了相对路径，它将相对于您的 `rootDir` 定位。

- **类型**: `string`
- **默认**: `"/<rootDir>/.nuxt/analyze"`

## app

Nuxt App 配置。

### `baseURL`

您的 Nuxt 应用程序的基础路径。

例如：

- **类型**: `string`
- **默认**: `"/"`

**示例**:
```ts
export default defineNuxtConfig({
  app: {
    baseURL: '/prefix/',
  },
})
```

您也可以通过设置 `NUXT_APP_BASE_URL` 环境变量在运行时设置此值。

**示例**:
```bash
NUXT_APP_BASE_URL=/prefix/ node .output/server/index.mjs
```

::note
由于 Nitro 的限制，`nuxt.config.ts` 中不支持直接使用相对路径（如 `./`）。对于具有相对资源路径的静态托管，请使用以下方法之一：

```bash
# Option 1: Environment variable at build time
NUXT_APP_BASE_URL=./ npm run generate
```

```ts
// Option 2: Runtime config
export default defineNuxtConfig({
  runtimeConfig: {
    app: {
      baseURL: './',
    },
  },
})
```
::

### `buildAssetsDir`

用于构建站点资产的文件夹名称，相对于 `baseURL`（或 `cdnURL`，如果已设置）。该名称在构建时确定，运行时不应进行自定义。

- **类型**: `string`
- **默认**: `"/_nuxt/"`

### `cdnURL`

从公共文件夹提供的绝对 URL（仅用于生产环境）。

例如：

- **类型**: `string`
- **默认**: `""`

**示例**:
```ts
export default defineNuxtConfig({
  app: {
    cdnURL: 'https://mycdn.org/',
  },
})
```

您可以通过设置 `NUXT_APP_CDN_URL` 环境变量在运行时将其设置为不同的值。

**示例**:
```bash
NUXT_APP_CDN_URL=https://mycdn.org/ node .output/server/index.mjs
```

### `head`

为每个页面设置 `<head>` 的默认配置。

- **类型**: `object`
- **默认**
```json
{
  "meta": [
    {
      "name": "viewport",
      "content": "width=device-width, initial-scale=1"
    },
    {
      "charset": "utf-8"
    }
  ],
  "link": [],
  "style": [],
  "script": [],
  "noscript": []
}
```

**示例**:
```ts
export default defineNuxtConfig({
  app: {
    head: {
      meta: [
      // <meta name="viewport" content="width=device-width, initial-scale=1">
        { name: 'viewport', content: 'width=device-width, initial-scale=1' },
      ],
      script: [
      // <script src="https://myawesome-lib.js"></script>
        { src: 'https://awesome-lib.js' },
      ],
      link: [
      // <link rel="stylesheet" href="https://myawesome-lib.css">
        { rel: 'stylesheet', href: 'https://awesome-lib.css' },
      ],
      // please note that this is an area that is likely to change
      style: [
      // <style>:root { color: red }</style>
        { textContent: ':root { color: red }' },
      ],
      noscript: [
      // <noscript>JavaScript is required</noscript>
        { textContent: 'JavaScript is required' },
      ],
    },
  },
})
```

## appConfig

额外的应用配置。

为了程序化使用和类型支持，您可以通过此选项直接提供应用配置。它将作为默认值与 `app.config` 文件合并。

### `nuxt`

对于多应用项目，这是 Nuxt 应用的唯一 ID。

默认为 `nuxt-app`。

- **类型**: `string`
- **默认值**: `"nuxt-app"`

## build

共享的构建配置。

### `analyze`

Nuxt 允许您可视化您的打包文件及优化方法。

将 `true` 设置为启用打包分析，或传递包含选项的对象：[针对 webpack](https://github.com/webpack/webpack-bundle-analyzer#options-for-plugin) 或 [针对 vite](https://github.com/btd/rollup-plugin-visualizer#options)。

- **类型**: `object`
- **默认值**
```json
{
  "template": "treemap",
  "projectRoot": "/<rootDir>",
  "filename": "/<rootDir>/.nuxt/analyze/{name}.html"
}
```

**示例**:
```ts
export default defineNuxtConfig({
  analyze: {
    analyzerMode: 'static',
  },
})
```

### `templates`

建议使用 `@nuxt/kit` 中的 `addTemplate` 选项，而非此选项。

- **类型**: `array`

**示例**:
```ts
export default defineNuxtConfig({
  build: {
    templates: [
      {
        src: '~~/modules/support/plugin.js', // `src` can be absolute or relative
        dst: 'support.js', // `dst` is relative to project `.nuxt` dir
      },
    ],
  },
})
```

### `transpile`

如果您想使用 Babel 对特定依赖进行转译，可以在此处添加它们。`transpile` 中的每一项可以是包名、函数、字符串或匹配依赖文件名的正则表达式对象。

您也可以使用函数进行条件性转译。该函数将接收一个对象 ({ isDev, isServer, isClient, isModern, isLegacy })。

- **类型**: `array`

**示例**:
```ts
export default defineNuxtConfig({
  build: {
    transpile: [({ isLegacy }) => isLegacy && 'ky'],
  },
})
```

## buildDir

定义您的构建后的 Nuxt 文件将存放的目录。

许多工具假设 `.nuxt` 是一个隐藏目录（因为它以 `.` 开头）。如果这是一个问题，可以使用此选项来避免这种情况。

- **类型**: `string`
- **默认值**: `"/<rootDir>/.nuxt"`

**示例**:
```ts
export default defineNuxtConfig({
  buildDir: 'nuxt-build',
})
```

## buildId

与构建过程对应的唯一标识符。它可能包含项目当前状态的哈希值。

- **类型**: `string`
- **默认值**: `"4a2e2d30-418f-41df-8e58-ed5df06de7fd"`

## builder

用于打包应用程序 Vue 部分的构建器。

Nuxt 支持多种客户端应用构建器。默认使用 Vite，但您也可以切换为 webpack、Rspack，甚至提供自定义构建器实现。

- **类型**: `'vite' | 'webpack' | 'rspack' | string | { bundle: (nuxt: Nuxt) => Promise<void> }`
- **默认值**: `"@nuxt/vite-builder"`

**使用支持的构建器:**

```ts
export default defineNuxtConfig({
  // default - uses @nuxt/vite-builder
  // builder: 'vite',

  // uses @nuxt/webpack-builder
  // builder: 'webpack',

  // uses @nuxt/rspack-builder
  builder: 'rspack',
})
```

如果您使用 `webpack` 或 `rspack`，请确保 `@nuxt/webpack-builder` 或 `@nuxt/rspack-builder` 已明确安装在项目中。

**使用自定义构建器对象:**

您可以通过传递包含 `bundle` 函数的对象来提供自定义构建器：

```ts
export default defineNuxtConfig({
  builder: {
    async bundle (nuxt) {
      const entry = await resolvePath(resolve(nuxt.options.appDir, 'entry'))

      // Build client and server bundles
      await buildClient(nuxt, entry)
      if (nuxt.options.ssr) {
        await buildServer(nuxt, entry)
      }

      // ... it's a bit more complicated than that, of course!
    },
  },
})
```

**创建自定义构建器包:**

要将自定义构建器作为独立包创建，应导出 `bundle` 函数。然后你可以在 `nuxt.config.ts` 中指定包名称：

```ts
export default defineNuxtConfig({
  builder: 'my-custom-builder',
})
```

为你的应用指定一个兼容日期。

此选项用于控制 Nitro、Nuxt Image 及其他模块中的预设行为，这些模块可能在不升级主要版本的情况下改变行为。

配置 Nuxt 组件自动注册。

在此配置的目录中的任何组件都可以在页面、布局（及其他组件）中直接使用，无需显式导入。

- **类型**：`object`
- **默认值**

## css

你可以定义想要全局设置的 CSS 文件、模块或库（这些文件将包含在每个页面中）。

Nuxt 会根据扩展名自动识别文件类型并使用相应的预处理器。如果你需要使用它们，仍然需要安装所需的加载器。

- **类型**：`array`

**示例**：
```ts
export default defineNuxtConfig({
  css: [
  // Load a Node.js module directly (here it's a Sass file).
    'bulma',
    // CSS file in the project
    '~/assets/css/main.css',
    // SCSS file in the project
    '~/assets/css/main.scss',
  ],
})
```

## hooks

Hooks 是 Nuxt 事件的监听器，通常用于模块中，但也可在 `nuxt.config` 中使用。

内部而言，Hooks 遵循使用冒号命名的模式（例如，build:done）。
为了便于配置，您也可以在 `nuxt.config` 中将它们构造成层次对象（如下所示）。

**示例**:
```ts
import fs from 'node:fs'
import path from 'node:path'

export default defineNuxtConfig({
  hooks: {
    build: {
      done (builder) {
        const extraFilePath = path.join(
          builder.nuxt.options.buildDir,
          'extra-file',
        )
        fs.writeFileSync(extraFilePath, 'Something extra')
      },
    },
  },
})
```

## ignore

比 `ignorePrefix` 更可定制：所有匹配 `ignore` 数组中指定的通配符模式的文件将在构建过程中被忽略。

- **类型**: `array`
- **默认**
```json
[
  "**/*.stories.{js,cts,mts,ts,jsx,tsx}",
  "**/*.{spec,test}.{js,cts,mts,ts,jsx,tsx}",
  "**/*.d.{cts,mts,ts}",
  "**/*.d.vue.{cts,mts,ts}",
  "**/.{pnpm-store,vercel,netlify,output,git,cache,data}",
  "**/*.sock",
  ".nuxt/analyze",
  ".nuxt",
  "**/-*.*"
]
```

## ignoreOptions

直接将选项传递给 `node-ignore`（Nuxt 用于忽略文件的工具）。

**参见**: [node-ignore](https://github.com/kaelzhang/node-ignore)

**示例**:
```ts
export default defineNuxtConfig({
  ignoreOptions: {
    ignorecase: false,
  },
})
```

## ignorePrefix

如果 `app/pages/`、`app/layouts/`、`app/middleware/` 和 `public/` 目录中的任何文件的文件名以 `ignorePrefix` 指定的前缀开头，则将在构建过程中被忽略。这旨在防止某些文件在构建后的应用程序中处理或提供。默认情况下，`ignorePrefix` 设置为 `-`，即忽略所有以 `-` 开头的文件。

- **类型**: `string`
- **默认**: `"-"`

## server

Nuxt 服务器构建器的配置。

### `builder`

指定用于打包应用程序服务器部分的服务器构建器。

默认情况下，Nuxt 使用 `@nuxt/nitro-server`，它提供独立的 Nitro 集成。这种架构允许不同的 Nitro 集成模式，例如将 Nitro 作为 Vite 插件使用（通过 Vite 环境 API）。

`"nitro"` 和 `"vite"` 是 `@nuxt/nitro-server` 和 `@nuxt/vite-server` 的简写。后者是实验性版本，仅通过 Vite 实现：当设置 `ssr: false` 时，它生成静态 SPA；当启用 SSR 时，它使用 Nuxt SSR 渲染器构建服务器，其入口导出 Web 标准 `{ fetch }`（`.output/server/index.mjs` 在其前提供静态输出，而 `nuxt preview` 运行该输出）。所有依赖项都打包到该输出中，因此无需 `node_modules`。`nuxt generate` 在构建结束时扫描该服务器并生成静态 `.output/public` 文件。它不包含服务器运行时，因此服务器路由、除 `prerender` 外的路由规则、内联样式和服务器组件不可用，需要服务器的模块也无法工作。

- **类型**: `string | { bundle: (nuxt: Nuxt) => Promise<void> }`
- **默认值**: `"@nuxt/nitro-server"`

::callout{type="warning"}
此选项仅用于内部使用，API 尚未确定。在依赖当前实现之前，请打开问题报告。
::

您可以使用此选项通过共享选项扩展生成的 tsconfig 文件。`compilerOptions` 适用于所有生成的 tsconfig 文件（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json`、`.nuxt/tsconfig.node.json` 和 `.nuxt/tsconfig.shared.json`），而 `include`、`exclude` 和 `vueCompilerOptions` 仅适用于 `.nuxt/tsconfig.app.json`（以及旧的 `.nuxt/tsconfig.json`）。两组 `compilerOptions` 是例外：DOM 和 Vue 特定的选项（如 `lib`、`jsx` 和 `jsxImportSource`）仅适用于 `.nuxt/tsconfig.app.json`，而 `types`、`paths` 和 `noEmit` 由 Nuxt 按上下文管理，因此无法在 `node`、`shared` 和 `server` tsconfig 中全局设置。使用 `appTsConfig`、`serverTsConfig`、`nodeTsConfig` 或 `sharedTsConfig` 进行特定上下文的覆盖；它们优先于此选项。

**参见**：[tsconfig.json 信息](/docs/directory-structure/tsconfig)

### `typeCheck`

启用构建时类型检查。

如果设置为 true，将在开发过程中进行类型检查。您可以将此设置限制为仅在构建时进行类型检查，将其设置为 `build`。需要安装 `typescript` 和 `vue-tsc` 作为开发依赖。

- **类型**：`boolean`
- **默认值**：`false`

**参见**：[Nuxt TypeScript 文档](/docs/guide/concepts/typescript)

## typesDir

定义生成的类型和 `tsconfig.json` 文件将存放的目录。

默认情况下，该目录为您的 `buildDir`，但它是独立的，因此即使 Nuxt 在其他地方构建项目时（如同在已开发过的项目中构建时），项目 `tsconfig.json` 中引用的配置仍然保持原样。

如果指定了相对路径，则该路径将相对于您的 `rootDir` 计算。

- **类型**：`string`
- **默认值**：`"/<rootDir>/.nuxt"`
