::note
`<NuxtLink>` 是 Vue Router 的 `<RouterLink>` 组件和 HTML 的 `<a>` 标签的替代方案。它能够智能地判断链接是 _内部_ 还是 _外部_，并根据可用的优化功能（预取、默认属性等）进行相应渲染。
::

:read-more{title="Nuxt accessibility" to="/docs/guide/best-practices/accessibility#links"}

## 内部路由

在这个示例中，我们使用 <NuxtLink> 组件来链接到应用程序的另一个页面。

::code-group
```vue [app/pages/index.vue]
<template>
  <NuxtLink to="/about">About page</NuxtLink>
</template>
```

```html [(Renders as) index.html]
<!-- (Vue Router & Smart Prefetching) -->
<a href="/about">About page</a>
```
::

### 向动态路由传递参数

在这个示例中，我们将 `id` 参数传递给 `~/pages/posts/[id].vue` 路由。

::code-group
```vue [app/pages/index.vue]
<template>
  <NuxtLink :to="{ name: 'posts-id', params: { id: 123 } }">
    Post 123
  </NuxtLink>
</template>
```

```html [(Renders as) index.html]
<a href="/posts/123">Post 123</a>
```
::

::tip
在 Nuxt DevTools 的 Pages 面板中查看路由名称及其可能接受的参数。
::

::tip
当您将对象传入 `to` 属性时，<NuxtLink> 将继承 Vue Router 对查询参数的处理。键和值将自动编码，因此无需手动调用 `encodeURI` 或 `encodeURIComponent`。
::

### 处理静态文件和跨应用链接

默认情况下，<NuxtLink> 使用 Vue Router 的客户端导航来处理相对路由。当链接到 `/public` 目录中的静态文件或同一域下的其他应用程序时，可能会导致意外的 404 错误，因为它们不属于客户端路由。在这种情况下，您可以使用 <NuxtLink> 的 `external` 属性来绕过 Vue Router 的内部路由机制。

`external` 属性明确表明链接是外部的。<NuxtLink> 将把链接渲染为标准的 HTML `<a>` 标签。这确保了链接正确工作，绕过 Vue Router 的逻辑，直接指向资源。

#### 链接到静态文件

对于 `/public` 目录中的静态文件，如 PDF 或图片，使用 `external` 属性以确保链接正确解析。

```vue [app/pages/index.vue]
<template>
  <NuxtLink
    to="/example-report.pdf"
    external
  >
    Download Report
  </NuxtLink>
</template>
```

#### 链接到跨应用 URL

当指向同一域下的不同应用程序时，使用 `external` 属性可确保正确的行为。

```vue [app/pages/index.vue]
<template>
  <NuxtLink
    to="/another-app"
    external
  >
    Go to Another App
  </NuxtLink>
</template>
```

使用 `external` 属性或依赖自动处理可以确保正确的导航，避免意外的路由问题，并改善与静态资源或跨应用场景的兼容性。

## 外部路由

在这个示例中，我们使用 <NuxtLink> 组件来链接到网站。

```vue [app/app.vue]
<template>
  <NuxtLink to="https://nuxtjs.org">
    Nuxt website
  </NuxtLink>
  <!-- <a href="https://nuxtjs.org" rel="noopener noreferrer">...</a> -->
</template>
```

## `rel` 和 `noRel` 属性

具有 `target` 属性的链接或绝对链接（例如以 `http://`、`https://` 或 `//` 开头的链接）默认会应用 `rel` 属性值为 `noopener noreferrer`。
- `noopener` 解决了旧浏览器中的[安全漏洞](https://mathiasbynens.github.io/rel-noopener)。
- `noreferrer` 通过不向链接网站发送 `Referer` 头信息，提高了用户的隐私保护。

这些默认设置对 SEO 没有负面影响，并被视为[最佳实践](https://developer.chrome.com/docs/lighthouse/best-practices/external-anchors-use-rel-noopener)。

当需要覆盖此行为时，可以使用 `rel` 或 `noRel` 属性。

```vue [app/app.vue]
<template>
  <NuxtLink to="https://twitter.com/nuxt_js">
    Nuxt Twitter
  </NuxtLink>
  <!-- <a href="https://twitter.com/nuxt_js" rel="noopener noreferrer">...</a> -->

  <NuxtLink
    to="https://discord.nuxtjs.org"
    rel="noopener"
  >
    Nuxt Discord
  </NuxtLink>
  <!-- <a href="https://discord.nuxtjs.org" rel="noopener">...</a> -->

  <NuxtLink
    to="/about"
    target="_blank"
  >About page</NuxtLink>
  <!-- <a href="/about" target="_blank" rel="noopener noreferrer">...</a> -->
</template>
```

`noRel` 属性可用于防止默认 `rel` 属性被添加到绝对链接中。

```vue [app/app.vue]
<template>
  <NuxtLink
    to="https://github.com/nuxt"
    no-rel
  >
    Nuxt GitHub
  </NuxtLink>
  <!-- <a href="https://github.com/nuxt">...</a> -->
</template>
```

::note
`noRel` 和 `rel` 不能同时使用。`rel` 将被忽略。
::

## 预加载链接

Nuxt 会自动执行智能预加载。这意味着它能够检测到链接何时可见（默认情况下），无论是在视口内还是滚动时，并预加载这些页面的 JavaScript 代码，以便用户点击链接时页面已准备好。Nuxt 仅在浏览器不繁忙时加载资源，如果连接处于离线状态或只有 2g 连接速度，则跳过预加载。

当使用 `custom` 属性时，`<NuxtLink>` 不会自动附加预加载处理程序。你可以从自定义插槽中调用 `prefetch` 函数。

```vue [app/pages/index.vue]
<NuxtLink to="/about" no-prefetch>
About page not pre-fetched
</NuxtLink>

<NuxtLink to="/about" :prefetch="false">
About page not pre-fetched
</NuxtLink>
```

### 自定义预加载触发器

自 `v3.13.0` 版本起，我们现在支持 `<NuxtLink>` 的自定义预加载触发器。你可以使用 `prefetchOn` 属性来控制何时预加载链接。

```vue
<template>
  <NuxtLink prefetch-on="visibility">
    This will prefetch when it becomes visible (default)
  </NuxtLink>

  <NuxtLink prefetch-on="interaction">
    This will prefetch when hovered or when it gains focus
  </NuxtLink>
</template>
```

- `visibility`: 当链接在视口中可见时进行预加载。使用[Intersection Observer API](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)监控元素与视口的相交情况。当元素被滚动到可视区域时触发预加载。
- `interaction`: 当链接被悬停或聚焦时进行预加载。这种方法监听 `pointerenter` 和 `focus` 事件，在用户表示交互意图时主动预加载资源。

你也可以使用对象来配置 `prefetchOn`：

```vue
<template>
  <NuxtLink :prefetch-on="{ interaction: true }">
    This will prefetch when hovered or when it gains focus
  </NuxtLink>
</template>
```

你可能不希望两者同时启用！

```vue
<template>
  <NuxtLink :prefetch-on="{ visibility: true, interaction: true }">
    This will prefetch when hovered/focus - or when it becomes visible
  </NuxtLink>
</template>
```

此配置会观察元素进入视口的情况，并监听 `pointerenter` 和 `focus` 事件。这可能会导致不必要的资源使用或重复预加载，因为两种触发器在不同条件下可能预加载相同的资源。

当使用 `custom` 时，预取功能由你的 slot 实现控制 :badge[v4.5]{color="info" size="xs" class="align-middle"}:

```vue
<template>
  <NuxtLink
    v-slot="{ href, navigate, prefetch, shouldPrefetch }"
    to="/about"
    custom
  >
    <a
      :href="href"
      @click="navigate"
      @pointerenter="shouldPrefetch('interaction') && prefetch()"
      @focus="shouldPrefetch('interaction') && prefetch()"
    >
      About page
    </a>
  </NuxtLink>
</template>
```

### 启用跨源预取

要启用跨源预取，可以在 `nuxt.config` 中设置 `crossOriginPrefetch` 选项。这将使用 [推测规则 API](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API) 启用跨源预取。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    crossOriginPrefetch: true,
  },
})
```

### 全局禁用预取

你也可以全局地启用/禁用应用中所有链接的预取功能。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    defaults: {
      nuxtLink: {
        prefetch: false,
      },
    },
  },
})
```

## Props

### RouterLink

当不使用 `external` 时，`<NuxtLink>` 支持 Vue Router 的所有 [`RouterLink props](https://router.vuejs.org/api/interfaces/routerlinkprops)

- `to`: 任何 URL 或来自 Vue Router 的 [route location object](https://router.vuejs.org/api/type-aliases/routelocation)
- `custom`: 是否让 `<NuxtLink>` 将其内容包裹在 `<a>` 元素中。它允许完全控制链接的渲染方式以及点击时的导航行为。其工作原理与 [Vue Router 的 `custom` prop](https://router.vuejs.org/api/interfaces/routerlinkprops#custom-) 相同。
- `exactActiveClass`: 应用于精确激活链接的类。其工作原理与内部链接中的 [Vue Router 的 `exactActiveClass` prop](https://router.vuejs.org/api/interfaces/routerlinkprops#exactActiveClass-) 相同。默认值为 Vue Router 的默认值（`"router-link-exact-active"`）
- `activeClass`: 应用于激活链接的类。其工作原理与内部链接中的 [Vue Router 的 `activeClass` prop](https://router.vuejs.org/api/interfaces/routerlinkprops#activeClass-) 相同。默认值为 Vue Router 的默认值（`"router-link-active"`）
- `replace`: 其工作原理与内部链接中的 [Vue Router 的 `replace` prop](https://router.vuejs.org/api/interfaces/routelocationoptions#replace-) 相同。
- `ariaCurrentValue`: 应用于精确激活链接的 `aria-current` 属性值。其工作原理与内部链接中的 [Vue Router 的 `ariaCurrentValue` prop](https://router.vuejs.org/api/interfaces/routerlinkprops#ariaCurrentValue-) 相同。

### NuxtLink

- `href`: `to` 的别名。如果与 `to` 一起使用，`href` 将被忽略。
- `noRel`: 如果设置为 `true`，则不会向外部链接添加 `rel` 属性。
- `external`: 强制链接以 `<a>` 标签形式渲染，而不是 Vue Router `RouterLink`。
- `prefetch`: 启用时，将预加载中间件、布局和视口中链接的有效载荷（当使用 [payloadExtraction](/docs/guide/going-further/experimental-features#payloadextraction）时）。由实验性 [crossOriginPrefetch](/docs/guide/going-further/experimental-features#crossoriginprefetch) 配置使用。
- `prefetchOn`: 允许自定义控制何时预加载链接。可能的选项为 `interaction` 和 `visibility`（默认）。您也可以传递一个对象以实现完全控制，例如： `{ interaction: true, visibility: true }`。此属性仅在 `prefetch` 启用（默认）且未设置 `noPrefetch` 时使用。
- `noPrefetch`: 禁用预加载。
- `prefetchedClass`: 应用于已预加载的链接的类名。

::note
通过 `custom` 属性，`prefetch`、`prefetchOn` 和 `prefetchedClass` 不会自动附加处理器或类。您可以使用自定义插槽中的 `prefetch`、`prefetched` 和 `shouldPrefetch` 值来实现此行为。
::

### 锚点

- `target`: 应用于链接的 `target` 属性值。
- `rel`: 应用于链接的 `rel` 属性值。外部链接的默认值为 `"noopener noreferrer"`。

::tip
默认值可以被覆盖，如果您希望更改它们，请参阅 [覆盖默认值](/docs/api/components/nuxt-link#overwriting-defaults)。
::

## 覆盖默认值

### 在 Nuxt 配置中

您可以在 [`nuxt.config`](/docs/guide/going-further/experimental-features#defaults) 中覆盖某些 `<NuxtLink>` 默认值。

::important
这些选项未来可能会移动到其他位置，例如进入 `app.config` 或 `app/` 目录。
::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    defaults: {
      nuxtLink: {
        // default values
        componentName: 'NuxtLink',
        externalRelAttribute: 'noopener noreferrer',
        activeClass: 'router-link-active',
        exactActiveClass: 'router-link-exact-active',
        prefetchedClass: undefined, // can be any valid string class name
        trailingSlash: undefined, // can be 'append' or 'remove'
        prefetch: true,
        prefetchOn: { visibility: true },
      },
    },
  },
})
```

### 自定义链接组件

您可以通过使用 `defineNuxtLink` 创建自己的链接组件来覆盖 `<NuxtLink>` 默认值。

```ts [app/components/MyNuxtLink.ts]
export default defineNuxtLink({
  componentName: 'MyNuxtLink',
  /* see signature below for more */
})
```

该组件根据其文件名自动导入，因此您可以像往常一样使用 `<MyNuxtLink />` 并采用新的默认值。`componentName` 仅设置组件的内部名称（如 Vue DevTools 中所示）；它不会改变组件在模板中的使用方式。

### `defineNuxtLink` 签名

```ts
interface NuxtLinkOptions {
  componentName?: string
  externalRelAttribute?: string
  activeClass?: string
  exactActiveClass?: string
  trailingSlash?: 'append' | 'remove'
  prefetch?: boolean
  prefetchedClass?: string
  prefetchOn?: Partial<{
    visibility: boolean
    interaction: boolean
  }>
}
function defineNuxtLink (options: NuxtLinkOptions): Component {}
```

- `componentName`: 组件的内部名称，如 Vue DevTools 中所示。它不会改变在模板中使用的名称（该名称来自组件的文件名）。默认值为 `NuxtLink`。
- `externalRelAttribute`: 应用于外部链接的默认 `rel` 属性值。默认值为 `"noopener noreferrer"`。将其设置为 `""` 可禁用此属性。
- `activeClass`: 应用于活动链接的默认类。其功能与 [Vue Router 的 `linkActiveClass` 选项](https://router.vuejs.org/api/interfaces/routeroptions#linkActiveClass-) 相同。默认值为 Vue Router 的默认值 `"router-link-active"`。
- `exactActiveClass`: 应用于精确激活的链接的默认类。其功能与 [Vue Router 的 `linkExactActiveClass` 选项](https://router.vuejs.org/api/interfaces/routeroptions#linkExactActiveClass-) 相同。默认值为 Vue Router 的默认值 `"router-link-exact-active"`。
- `trailingSlash`: 一个选项，用于添加或移除 `href` 中的尾斜杠。如果未设置或不符合有效值 `append` 或 `remove`，则会被忽略。
- `prefetch`: 是否默认进行链接预加载。
- `prefetchOn`: 对默认应用的预加载策略进行精细控制。
- `prefetchedClass`: 应用于已进行预加载的链接的默认类。
