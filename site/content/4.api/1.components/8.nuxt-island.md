当渲染岛屿组件时，该组件的内容是静态的，因此不会在客户端下载 JS。

更改岛屿组件的 props 会触发重新获取岛屿组件，使其再次渲染。

::tip
仅服务器使用的组件在内部使用 `<NuxtIsland>`。
::

::read-more{to="/docs/guide/concepts/server-components"}
请阅读关于服务器组件和岛屿的专用指南。
::

## Props

- `name` : 要渲染的组件名称。
  - **type**: `string`
  - **required**
- `lazy`: 使组件非阻塞式加载。
  - **type**: `boolean`
  - **default**: `false`
- `props`: 用于向组件传递以进行渲染的 props。
  - **type**: `Record<string, any>`
- `source`: 远程来源，用于调用岛屿组件进行渲染。
  - **type**: `string`
- **dangerouslyLoadClientComponents**: 从远程来源加载客户端组件所需的属性。
  - **type**: `boolean`
  - **default**: `false`

::note
远程岛屿需要在 `nuxt.config` 中将 `experimental.componentIslands` 设置为 `'local+remote'`。
::

::warning{icon="i-ph-warning-duotone"}
使用 `source` prop 从远程服务器渲染内容本质上具有风险。当指定远程 `source` 时，您完全依赖该服务器提供安全的 HTML 内容，这些内容将直接在您的应用中渲染。

这类似于使用 `v-html` 处理外部内容——远程服务器可以注入任何 HTML，包括潜在的恶意内容。**仅应在您完全信任并控制的服务器上使用 `source`。**

`dangerouslyLoadClientComponents` prop 控制了额外的风险层面：是否同时从远程来源下载并执行客户端组件。即使禁用了 `dangerouslyLoadClientComponents`（默认状态），您仍然依赖远程服务器的 HTML 输出。
::

::note
组件 props 和上下文作为 GET 查询参数发送，以实现缓存。查询参数可能出现在服务器访问日志、CDN 缓存和 HTTP `Referer` 头中。
::

::note
默认情况下，组件岛屿从 `~/components/islands/` 目录扫描。因此，`~/components/islands/MyIsland.vue` 组件可以通过 `<NuxtIsland name="MyIsland" />` 进行渲染。
::

## 已知限制

### 岛屿和服务器组件中的 `useId`

每个岛屿都在服务器的独立 Vue 应用中渲染，因此 Vue 的 [`useId`](https://vuejs.org/api/composition-api-helpers#useid) 计数器会为每个岛屿重新启动。因此，岛屿内部生成的 Id 可能会与同一页面上的其他岛屿或应用程序中的其他 Id 产生冲突。

**变通方案**：通过服务器插件在岛屿的 Vue 应用中设置独特的 [`idPrefix`](https://vuejs.org/api/application#app-config-idprefix)，该值基于岛屿上下文 id 确定：

```ts [plugins/island-id-prefix.server.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const islandContext = nuxtApp.ssrContext?.islandContext
  if (islandContext) {
    nuxtApp.vueApp.config.idPrefix = `${islandContext.id}-v`
  }
})
```

- **相同的岛屿仍共享相同的 ids**。两个具有相同名称、 props 和上下文的岛屿实例在服务器渲染时共享同一个渲染结果（及数据载荷），因此它们的 HTML——包括任何由 `useId` 生成的 ids——都是相同的，且作为前缀使用的岛屿上下文 id 也相同。这导致 DOM 中出现重复的 `id` 属性，可能会破坏两个实例之间的 `aria-*` 引用和 `<label for>` 关联。目前没有针对此情况的变通方案。

- **在岛屿内的交互式组件中，`useId` 不起作用**。使用 [`nuxt-client` 属性](/docs/guide/concepts/server-components#selective-hydration-with-nuxt-client)加载的组件在岛屿的 app 中进行服务器渲染，但由主客户端应用进行 hydration，因此 `useId` 在服务器和客户端返回不同的值，导致 hydration 不匹配。

### 跨越岛屿边界的 `provide` / `inject`

每个岛屿都在其自己的 Vue 应用中渲染，因此 `provide` 和 `inject` 不会跨越岛屿边界。独立的 `.server` 组件在底层使用 `<NuxtIsland>`，并且也在父 Vue 应用之外运行，因此无法访问父应用提供的值。在岛屿内部提供的值在外部也无法使用。可以通过 props 传递数据，或者通过一个在两种环境中均运行的 [Nuxt 插件](/docs/directory-structure/app/plugins)来暴露该值。

## Slots

如果声明了，Slots 可以传递给岛屿组件。

每个 Slots 都是交互式的，因为是由父组件提供。

某些 Slots 被保留给 `NuxtIsland` 用于特殊情况。

- `#fallback`：指定在岛屿加载之前要渲染的内容（如果组件是延迟加载的）或当 `NuxtIsland` 无法获取组件时。

## Ref

- `refresh()`
  - **类型**：`() => Promise<void>`
  - **描述**：通过重新获取服务器组件来强制重新获取。

## Events

- `error`
  - **参数**：
    - **error**：
      - **类型**：`unknown`
  - **描述**：当 `NuxtIsland` 无法获取新岛屿时发出。
