`<NuxtPage>` 是 Nuxt 内置的组件，它允许你显示位于 [`app/pages/`](/docs/directory-structure/app/pages) 目录中的顶级或嵌套页面。

::note
`<NuxtPage>` 是 `[<RouterView>](https://router.vuejs.org/api/interfaces/routerviewprops)` 的包装器。应使用 `<NuxtPage>` 而非 `<RouterView>`，因为前者会处理内部状态。否则，`useRoute()` 可能会返回错误的路径。
::

`<NuxtPage>` 包含以下组件：

```vue
<template>
  <RouterView v-slot="{ Component }">
    <!-- Optional, when using transitions -->
    <Transition>
      <!-- Optional, when using keep-alive -->
      <KeepAlive>
        <Suspense>
          <component :is="Component" />
        </Suspense>
      </KeepAlive>
    </Transition>
  </RouterView>
</template>
```

默认情况下，Nuxt 不会启用 `<Transition>` 和 `<KeepAlive>`。你可以在 `nuxt.config` 文件中启用它们，或者直接在 `<NuxtPage>` 上设置 `transition` 和 `keepalive` 属性。如果你想要定义特定的页面，可以在页面组件中的 `definePageMeta` 中设置。

::warning
如果在页面组件中启用 `<Transition>`，请确保该页面具有唯一的根元素。
::

由于 `<NuxtPage>` 在底层使用 `<Suspense>`，因此页面切换时的组件生命周期行为与典型的 Vue 应用不同。

在典型的 Vue 应用中，新的页面组件**仅在**之前的页面完全卸载之后才会挂载。而在 Nuxt 中，由于 Vue `<Suspense>` 的实现方式，新的页面组件会在之前的页面卸载之前就挂载。

## 属性

- `name`：告诉 `<RouterView>` 在匹配路由记录的 components 选项中使用相应的名称来渲染组件。关于 `name@view.vue` 文件名规范，请参见 [Named Views](/docs/directory-structure/app/pages#named-views)。
  - type: `string`
- `route`：所有组件都已解析的路由位置。
  - type: `RouteLocationNormalized`
- `pageKey`：控制 `NuxtPage` 组件何时重新渲染。
  - type: `string` 或 `function`
- `transition`：为使用 `<NuxtPage>` 组件渲染的所有页面定义全局过渡效果。
  - type: `boolean` 或 [`TransitionProps`](https://vuejs.org/api/built-in-components#transition)
- `keepalive`：控制使用 `<NuxtPage>` 组件渲染的页面状态保留方式。
  - type: `boolean` 或 [`KeepAliveProps`](https://vuejs.org/api/built-in-components#keepalive)

::tip
Nuxt 通过扫描并渲染 `/pages` 目录中的所有 Vue 组件文件，自动解析 `name` 和 `route`。
::

## 示例

例如，如果您传递一个不会变化的键，`<NuxtPage>` 组件将只渲染一次——即在其首次挂载时。

```vue [app/app.vue]
<template>
  <NuxtPage page-key="static" />
</template>
```

您也可以基于当前路由使用动态键：

```html
<NuxtPage :page-key="route => route.fullPath" />
```

::warning
此处不要使用 `$route` 对象，因为它可能导致 `<NuxtPage>` 在渲染包含 `<Suspense>` 的页面时出现问题。
::

或者，可以通过 `/pages` 目录中 Vue 组件的 `<script>` 部分使用 [`definePageMeta`](/docs/api/utils/define-page-meta) 将 `pageKey` 作为 `key` 值传递。

```vue [app/pages/my-page.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
})
</script>
```

## 页面的 Ref

要获取页面组件的 `ref`，可通过 `ref.value.pageRef` 访问。

````vue [app/app.vue]
<script setup lang="ts">
const page = ref()

function logFoo () {
  page.value.pageRef.foo()
}
</script>

<template>
  <NuxtPage ref="page" />
</template>
````

````vue [my-page.vue]
<script setup lang="ts">
const foo = () => {
  console.log('foo method called')
}

defineExpose({
  foo,
})
</script>
````

## 自定义属性

`<NuxtPage>` 还接受自定义属性，这些属性可能需要在更深的层级中传递。

例如，在下面的示例中，`foobar` 的值将被传递给 `NuxtPage` 组件，然后传递给页面组件。

```vue [app/app.vue]
<template>
  <NuxtPage :foobar="123" />
</template>
```

我们可以在页面组件中访问 `foobar` 属性：

```vue [app/pages/page.vue]
<script setup lang="ts">
const props = defineProps<{ foobar: number }>()

console.log(props.foobar) // Outputs: 123
```

如果您没有使用 `defineProps` 定义该属性，那么任何传递给 `NuxtPage` 的属性仍然可以直接从页面 `attrs` 中访问。

```vue [app/pages/page.vue]
<script setup lang="ts">
const attrs = useAttrs()
console.log(attrs.foobar) // Outputs: 123
</script>
```
