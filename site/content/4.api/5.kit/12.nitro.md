Nitro 是一个开源的 TypeScript 框架，用于构建极速的 Web 服务器。Nuxt 使用 Nitro 作为其服务器引擎。你可以使用 `useNitro` 访问 Nitro 实例（或者如果模块无需 Nitro 也能正常工作，则使用 `tryUseNitro`），`addServerHandler` 添加服务器处理程序，`addDevServerHandler` 添加仅在开发模式下使用的服务器处理程序，`addNitroPlugin` 添加插件以扩展 Nitro 的运行行为，以及 `addPrerenderRoutes` 添加由 Nitro 预渲染的路由。

## `addServerHandler`

添加 Nitro 服务器处理程序。如果你想要创建服务器中间件或自定义路由，可以使用此功能。

### 使用方式

```ts twoslash
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

### 类型

```ts
function addServerHandler (handler: ServerHandlerInput): void
```

### 参数

**handler**: 一个包含以下属性的处理程序对象：

| 属性         | 类型      | 必填   | 描述                                                                                                                                   |
|--------------|-----------|----------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `handler`    | `string \| { nuxt?: string, nitro2?: string, nitro3?: string }`  | `true`   | 事件处理程序的路径，或每个服务器 API 的一个路径。Nuxt 注册该实现，使应用程序的服务器能够运行。                     |
| `route`      | `string`  | `false`  | 要精确匹配的路由。在末尾加上 `/**` 以匹配其下方的路径。如果使用空字符串，则处理程序被注册为中间件。 |
| `middleware` | `boolean` | `false`  | 指定这是中间件处理程序。每个路由都会调用中间件，通常不应返回任何内容以传递给下一个处理程序。 |
| `lazy`       | `boolean` | `false`  | 使用懒加载来导入处理程序。当你只想按需加载处理程序时，这非常有用。                                      |
| `method`     | `string`  | `false`  | 路由器方法匹配器。如果处理程序名称包含方法名称，则将其作为默认值使用。                                              |

以 `/**` 结尾的路由也会匹配其基础路径，因此 `route: '/_fonts/**'` 会服务 `/_fonts` 及其下方所有内容。在 Nitro 2 主机上，其路由器仅匹配基础路径下方的路径，Nuxt 会将基础路径注册为第二个路由，以便两种情况下行为一致。

::read-more{to="/docs/guide/modules/server-compatibility"}
了解何时为每个服务器 API 注册一个路径，以及应针对哪个键编写处理程序。
::

### 示例

#### 基本用法

您可以使用 `addServerHandler` 从模块中添加服务器处理程序。

::code-group

```ts twoslash [module.ts]
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

```ts twoslash [runtime/robots.get.ts]
export default defineEventHandler(() => {
  return {
    body: `User-agent: *\nDisallow: /`,
  }
})
```

::

当访问 `/robots.txt` 时，它将返回以下响应：

```txt
User-agent: *
Disallow: /
```

## `addDevServerHandler`

添加一个仅在开发模式下使用的 Nitro 服务器处理程序。此处理程序将在生产构建中被排除。

### 用法

```ts twoslash
import { addDevServerHandler, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    addDevServerHandler({
      handler: {
        nuxt: () => new Response(`Response generated at ${new Date().toISOString()}`),
      },
      route: '/_handler',
    })
  },
})
```

### 类型

```ts
function addDevServerHandler (handler: DevServerHandlerInput): void
```

### 参数

**handler**: 一个包含以下属性的处理程序对象：

| 属性 | 类型 | 必填 | 描述 |
|------|------|------|------|
| `handler` | `EventHandler \| { nuxt?: (event: RequestEvent) => unknown, nitro2?: EventHandler, nitro3?: EventHandler }` | `true` | 处理程序，或每个服务器 API 的一个处理程序。Nuxt 会注册应用程序服务器可以运行的实现。 |
|-----------|----------------|----------|------------------------------------------------------------------------------|
| `handler` | `EventHandler \| { nuxt?: (event: RequestEvent) => unknown, nitro2?: EventHandler, nitro3?: EventHandler }` | `true`   | Event handler, or one handler per server API. Nuxt registers the implementation the application's server can run. |
| `route`   | `string`       | `false`  | 要匹配的路由。在末尾添加 `/**` 以匹配其下方的路径。在 `nitropack` v2 主机上，没有 `/**` 的路由也会匹配其下方的路径。如果使用空字符串，处理程序将作为中间件注册。 |
| `method`  | `string`       | `false`  | 要匹配的 HTTP 方法，例如 `'POST'`。在 `nitropack` v2 主机上，处理程序适用于所有方法。 |
| `middleware` | `boolean`   | `false`  | 在路由处理程序之前运行处理程序。不返回任何内容以将请求传递给下一个处理程序。在 `nitropack` v2 主机上，每个开发处理程序作为中间件运行。 |
| `meta`    | `object`       | `false`  | 路由元数据，例如 OpenAPI 操作信息。Nitro v3 将其附加到非中间件的处理程序中。 |

::read-more{to="/docs/guide/modules/server-compatibility#dev-server-handlers"}
了解如何为每个服务器 API 编写开发服务器处理程序，以及每个处理程序匹配哪些路径。
::

### 示例

#### 基本用法

在某些情况下，您可能希望为开发目的专门创建服务器处理程序，例如 Tailwind 配置查看器。

```ts
import { joinURL } from 'ufo'
import { addDevServerHandler, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    const route = joinURL(nuxt.options.app?.baseURL, '/_tailwind')

    // @ts-expect-error - tailwind-config-viewer does not have correct types
    const createServer = await import('tailwind-config-viewer/server/index.js').then(r => r.default || r) as any
    const viewerDevMiddleware = createServer({ tailwindConfigProvider: () => options, routerPrefix: route }).asMiddleware()

    addDevServerHandler({ route, handler: viewerDevMiddleware })
  },
})
```

## `useNitro`

返回 Nitro 实例。

::warning
您只能在 `ready` 钩子之后调用 `useNitro()`。
::

::note
对 Nitro 实例配置的更改不会生效。
::

### 用法

```ts
import { defineNuxtModule, useNitro } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.hook('ready', () => {
      const nitro = useNitro()
      // Do something with Nitro instance
    })
  },
})
```

### 类型

```ts
function useNitro (): Nitro
```

## `tryUseNitro`

返回 Nitro 实例，如果没有则返回 `undefined`。

在 `ready` 钩子运行之前没有 Nitro 实例，当
配置过的 [`server.builder`](/docs/api/nuxt-config#builder-1) 不使用 Nitro 时，也没有任何实例。
一个用于生成仅客户端可访问 SPA 的构建器。对于任何不需要服务器的情况，请使用此构建器而非 `useNitro()`。
在这种情况下，服务器路由、路由规则和预渲染功能都不需要。
此时这些功能不存在。

### 使用方式

```ts
import { defineNuxtModule, tryUseNitro } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.hook('ready', () => {
      const nitro = tryUseNitro()
      if (!nitro) {
        // no server: skip anything that would only run there
        return
      }
    })
  },
})
```

### 类型

```ts
function tryUseNitro (): Nitro | undefined
```

## `addNitroPlugin`

添加插件以扩展 Nitro 的运行时行为。

::note
在 Nuxt v4.6 之前，此功能被命名为 `addServerPlugin`。
::

::tip
您可以在 [Nitro 文档](https://nitro.build/guide/plugins)中了解有关 Nitro 插件的更多信息。
::

::warning
必须在插件文件中显式导入来自 `nitropack/runtime` 的 `defineNitroPlugin`。对于诸如 `useRuntimeConfig` 这样的工具函数，也有相同的要求。
::

### 使用方式

```ts twoslash
import { addNitroPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addNitroPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

### 类型

```ts
function addNitroPlugin (plugin: string | { nitro2?: string, nitro3?: string }): void
```

### 参数

| 属性 | 类型 | 是否必填 | 描述 |
|------|------|----------|------|
| `plugin` | `string \| { nitro2?: string, nitro3?: string }` | `true` | 插件的路径，或者每个 major 版本对应的模块路径。插件必须导出一个默认函数，该函数接受 Nitro 实例作为参数。 |
|----------|----------|----------|---------------------------------------------------------------------------------------------------------------|
| `plugin` | `string \| { nitro2?: string, nitro3?: string }` | `true`   | Path to the plugin, or one path per nitro major for a module shipping an implementation for each. The plugin must export a default function that accepts the Nitro instance as an argument. |

### 示例

::code-group

```ts [module.ts]
import { addNitroPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addNitroPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

```ts [runtime/plugin.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    console.log('on request', event.path)
  })

  nitroApp.hooks.hook('beforeResponse', (event, { body }) => {
    console.log('on response', event.path, { body })
  })

  nitroApp.hooks.hook('afterResponse', (event, { body }) => {
    console.log('on after response', event.path, { body })
  })
})
```

::

## `addPrerenderRoutes`

添加将预渲染到 Nitro 的路由。

### 使用方式

```ts
import { addPrerenderRoutes, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'nuxt-sitemap',
    configKey: 'sitemap',
  },
  defaults: {
    sitemapUrl: '/sitemap.xml',
    prerender: true,
  },
  setup (options) {
    if (options.prerender) {
      addPrerenderRoutes(options.sitemapUrl)
    }
  },
})
```

### 类型

```ts
function addPrerenderRoutes (routes: string | string[]): void
```

### 参数

| 属性 | 类型 | 是否必填 | 描述 |
|------|------|----------|------|
| `routes` | `string \| string[]{lang="ts"}` | `true` | 要预渲染的路由或路由数组。 |
|----------|---------------------------------|----------|---------------------------------------------|
| `routes` | `string \| string[]`{lang="ts"} | `true`   | A route or an array of routes to prerender. |

## `addServerImports`

添加服务器所需的导入项。这样即可在 Nitro 中直接使用这些导入，无需手动导入。

::warning
如果您希望提供一个在服务器和客户端环境中都能使用的工具函数，并且可以在 [`shared/`](/docs/directory-structure/shared) 目录中使用，则该函数必须从同一源文件中导入，用于 [`addImports`](/docs/api/kit/autoimports#addimports) 和 `addServerImports`，并且应具有相同的签名。该源文件不应导入任何特定于上下文的内容（即 Nitro 上下文或 Nuxt 应用上下文），否则可能会在类型检查时引发错误。
::

### 使用方式

```ts twoslash
import { addServerImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const names = [
      'useStoryblok',
      'useStoryblokApi',
      'useStoryblokBridge',
      'renderRichText',
      'RichTextSchema',
    ]

    names.forEach(name =>
      addServerImports({ name, as: name, from: '@storyblok/vue' }),
    )
  },
})
```

### 类型

```ts
function addServerImports (dirs: NuxtImport | NuxtImport[]): void
```

### 参数

`imports`: 一个对象或包含以下属性的对象数组：

| 属性 | 类型 | 是否必填 | 描述 |
|------|------|----------|------|
| `plugin` | `string \| { nitro2?: string, nitro3?: string }` | `true` | 插件的路径，或者每个 major 版本对应的模块路径。插件必须导出一个默认函数，该函数接受 Nitro 实例作为参数。 |
|------------|-----------------------|----------|-----------------------------------------------------------------------------------------------------------------|
| `name`     | `string`              | `true`   | 将被检测的导入名称。                                                                                     |
| `from`     | `string`              | `true`   | 要从哪个模块导入。                                                                                        |
| `priority` | `number`              | `false`  | 导入的优先级；如果多个导入具有相同的名称，则使用优先级最高的那个。 |
| `disabled` | `boolean`             | `false`  | 如果禁用此导入。                                                                                     |
| `meta`     | `Record<string, any>` | `false`  | 导入的元数据。                                                                                         |
| `type`     | `boolean`             | `false`  | 如果此导入是纯类型导入。                                                                           |
| `typeFrom` | `string`              | `false`  | 在生成类型声明时用作 `from` 值。                                                 |
| `as`       | `string`              | `false`  | 以此名称进行导入。                                                                                            |

## `addServerImportsDir`

将某个目录添加到由 Nitro 自动导入的扫描中。

### 使用方式

```ts twoslash
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

### 类型

```ts
function addServerImportsDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 参数

| 属性 | 类型                            | 必需 | 描述                                                                                                         |
|----------|---------------------------------|----------|---------------------------------------------------------------------------------------------------------------------|
| `dirs`   | `string \| string[]`{lang="ts"} | `true`   | 要注册并由 Nitro 扫描的目录或目录数组。                                          |
| `opts`   | `{ prepend?: boolean }`         | `false`  | 导入目录的选项。如果 `prepend` 为 `true`，则将该目录添加到扫描列表的开头。 |

### 示例

您可以使用 `addServerImportsDir` 添加一个由 Nitro 扫描的目录。当您希望 Nitro 从自定义服务器目录自动导入函数时，这非常有用。

::code-group

```ts twoslash [module.ts]
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

```ts twoslash [runtime/server/composables/index.ts]
export function useApiSecret () {
  const { apiSecret } = useRuntimeConfig()
  return apiSecret
}
```

::

然后可以在服务器代码中使用 `useApiSecret` 函数：

```ts twoslash [runtime/server/api/hello.ts]
const useApiSecret = (): string => ''
// ---cut---
export default defineEventHandler(() => {
  const apiSecret = useApiSecret()
  // Do something with the apiSecret
})
```

## `addServerScanDir`

添加由 Nitro 扫描的目录。它将检查子目录，这些子目录将被注册。
就像 `~~/server` 文件夹一样。

::note
仅扫描 `~~/server/api`、`~~/server/routes`、`~~/server/middleware` 和 `~~/server/utils`。
::

### 使用方式

```ts twoslash
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

### 类型

```ts
function addServerScanDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 参数

| 属性 | 类型 | 必填 | 描述                                                                                                         |
|----------|---------------------------------|----------|---------------------------------------------------------------------------------------------------------------------|
| `dirs`   | `string \| string[]`{lang="ts"} | `true`   | 要由 Nitro 作为服务器目录进行扫描的目录或目录数组。                       |
| `opts`   | `{ prepend?: boolean }`         | `false`  | 导入目录的选项。如果 `prepend` 为 `true`，该目录将被添加到扫描列表的开头。 |

### 示例

您可以使用 `addServerScanDir` 来添加由 Nitro 扫描的目录。当您需要添加自定义服务器目录时，这非常有用。

::code-group

```ts twoslash [module.ts]
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

```ts twoslash [runtime/server/utils/index.ts]
export function hello () {
  return 'Hello from server utils!'
}
```
::

然后您可以在服务器代码中使用 `hello` 函数。

```ts twoslash [runtime/server/api/hello.ts]
function hello () {
  return 'Hello from server utils!'
}
// ---cut---
export default defineEventHandler(() => {
  return hello() // Hello from server utils!
})
```
